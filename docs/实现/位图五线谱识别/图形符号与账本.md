# contour 认领账本与图形符号（位图五线谱识别）

> [位图五线谱识别](../位图五线谱识别.md)的分篇。

## contour 层与认领账本：**量得出「还有什么是我们从没看见的」**

`src/rasteromr/contour.ts` + `ledger.ts`，不参与任何识别判据——只描述、只记账。

现有的每一个数量的都是「**认出来的**对不对」（音符 68.1%、符头认领率 97.4%），
没有一个数量得出「印在纸上而我们从没看见的那些」。实测弧线、三连音的数字、
松叶、力度记号至今一个都不认，在别的报表上一点痕迹都不留。

做法：去谱线图上一团墨就是一个 **contour**（外轮廓 + 孔洞 + 形状特征），识别每认出
一样东西就按它的盒记一笔；一页跑完，**没有任何一笔的就是无主 contour**。

- **在去谱线图上取，不能在原图上**：原图上五条谱线把整行谱的符头符干小节线连成一团，
  一页只剩十几个 contour。
- **标号图（像素 → 块）必须由 `connectedComponents` 顺手落下来**（新加的 `out` 参数），
  不能拿它给的包围盒自己再 flood 一遍：面积不到下限的小块在那边被丢掉、却仍占着像素，
  照「盒里第一个没标号的前景像素」找种子会种到那种小块上，整团墨的标号就空了
  （实测 35 个块的周长因此掉到个位数、团状度算出 480）。
- **认领按盒查标号图，不按盒相交**：盒相交会把路过盒角的符干、隔壁的符号一并算进来。
  两条门槛过一条即可——落进盒里的像素占**本团墨**两成，或占**盒内全部墨**两成：
  符头的盒只盖住「符头+符干+符杠」那一大团的一小截（占团低、占盒高），
  歌词字格反过来。
- **段只记挂上标记的**（`Staff`/`Leger`/`Stem`/`BarLine`/`SysLine`/`Tail`/`Beam`），
  不记 `findPrimitives` 抽出来的原始段。横段里混着**松叶的臂、弧线的一截**
  ——照抽出来就记，要找的东西反倒成了「有主的」。
- **歌词字格不论有没有 OCR 缓存都要切、都要记**：切出字格这件事本身就是
  「这块墨是歌词」的判断，与认不认得出那个字是两回事。缓存没命中就不记的话，
  整页歌词都成了「从没看见的墨」（实测宁静墨覆盖 79.5% → **86.5%**）。
- **覆盖率的口径偏乐观**：认领过的 contour 的**全部**像素都算已解释。
  它量的是「还剩多少团墨完全没人看过」，不是像素级的解释率。

### 实测（`../dev/scripts/raster-unclaimed.mjs`，干净位图四份）

## 松叶（wedge）：按 contour 认，不拼线段

`src/rasteromr/wedge.ts`。**这一路是 contour 层的第一个用处**——无主报表里一眼看见
「又宽又扁、从没人认领」的那一批，其中一半是弧线、一半是松叶。

- **不从 `hSegs` 里配对两条臂**：`findPrimitives` 对横笔画有一道「块高不过 `thin*2`」
  （约 0.8 格）的闸，而松叶的开口实测有 1.5~2 格高——**整条松叶连着尖端是一团**，
  块高一超限整个被那道闸滤掉，压根没进 `hSegs`。它原样留在图上，
  正好是一个完整的 contour（实测宁静 p2 那条 376×30 px = 20.7×1.66 格、团状度 0.01）。
- **判据是逐列的墨迹跨度**：两条臂从尖端往开口张开，跨度近似线性地涨。
  弧线同样又宽又扁、团状度也低，但它**逐列只有一段墨**、跨度处处等于线宽
  ——「一列几段墨」（≥35% 的列有两段）与「跨度涨不涨」（开口 ≥0.55 格、
  尖端 ≤0.42 格、且开口是尖端的两倍以上）两条一起用，一刀分得开。
  实测宁静 p2 的弧线：两段列 0%、左右跨度都是 0.11 格，一条都不误收。
- 尖端在左是 `crescendo`、在右是 `diminuendo`。
- **尖端没连上的那些，两条臂各成一团**（印得细的时候常见）——单团的判据对一条臂
  无能为力（一条臂逐列只有一段墨、跨度处处等于线宽，与弧线一模一样）。
  `pairArms` 按**两条臂的关系**配：斜率一正一负、x 上盖着一半以上、
  一头挨着（≤0.45 格）另一头张开（≥0.55 格）。臂本身要**直**
  （离两端连线最远处 ≤0.18 格，弧线拱得高，一量就出局）。
- 形状闸扫过两档（`MIN_W`/`OPEN_MIN`/`TIP_MAX`/`TWO_RUN_FRAC` = 2.5/0.55/0.42/0.35
  与 1.8/0.45/0.5/0.25）：检出 **38/77 → 54/77**、序列 46.0% → 47.2%，取松的这一档。
  代价是**过检**（破碎有一条谱表识别出 15 条而 GT 只有 8 条），序列档因此涨得少。

**挂接与导出**：`attachWedges`（`staffomr/notations.ts`，与力度共用一套判据：
**先定是哪一行谱**——记号印在它那行谱的下方，而下面一行谱的上缘往往比它自己那行的
下缘还近，不先定谱行整条松叶会挂到下一行去；**那一行在这个位置没有音符就退回
「纵向够得着的谱行里 x 最近的那个」**——只按 y 定谱行、找不到就丢，
实测松叶从 38 掉到 **14**，人声那一行常常正好在休止。这一条把力度也带上去了：
检出 18 → **21**、序列 33.7% → **37.9%**）把起讫挂到音符上，`toxml.ts` 出
`<direction><direction-type><wedge>`。**止排在起之前**——同一个音符上前一条收尾、
下一条起头是常事，反过来写两条会重叠。矢量路的 `slur.ts::findWedges` 只给松叶打标
（免得被当成弧线），**从来没进过 MusicXML**，这一条两条路都是新的。

## 力度（dynamics）：字典早就认得出，缺的是挂接与**连字**

`src/rasteromr/dynamics.ts`。两件事：

1. **位图路从来没调过 `findNotations` / `attachDynamics`**（矢量路 `index.ts` 一直在调）。
   而字典本来就认得出：`rasterglyphs.json` 里 `dynamicForte` 26 个实例、`dynamicMP` 8 个，
   实测宁静 p2 那个 `f` 到 Maestro 模板的距离只有 **19**。补上这一句，力度 0 → 21 个。
2. **`mf` 印出来是两个字母**（`m` 一块、`f` 一块），只认 `f` 就把 `mf` 读成 `f`。
   `m` 那块本身认不出——它落进字典的 `dynamicForte` 类（实测距离 71~98，真 `f` 只有 19），
   或者干脆被当成实心符头（1.87×1.17 格，正在符头的尺寸档里）。

所以不靠字典认 `m`，**靠版式**：从字典认出来的那个字母往外长，按宽高比认旁边的字母
（与锚同高 = 又一个 `f`；只有 0.33~0.62 倍高、又宽 = `m`；中间那一档 = `p`），
拼不出一个像样的力度（`VALID` 那张表）就整串丢掉——**宁可少，不可编**。

> **间隙的上限卡在「贴着」（0.15 格），不是「近」。** 力度字母是斜体连写的，
> 实测 `mf` 的两块在 x 上还**重叠** 9 px；而歌词里紧挨着的汉字有半格以上的字距
> ——照 0.7 格的间隙，宁静 p2 那个 `f` 会把右边 0.5 格处的「在」字拼进来成 `ff`
> （汉字约 2×2 格，正落在「又一个 f」那一档里）。
> **纵向比中心不比底边**：斜体 `f` 上下都出头，与 `m` 的底边差 0.72 格，中心却分毫不差。

### 实测（`chorus-symbols.mjs` 新增两档，干净位图）

| | 检出 | 序列 |
|---|---|---|
| 松叶 | **54/77** | 47.2% |
| 力度 | **21/54** | 37.9% |

两档都是从 **0** 起步的。序列那一档与拍号同口径：不比位置（位图路的小节号本来就不可靠），
比**出现的次序**。识别各档（音符/音级/歌词/自检/谱号/时值/附点/升降/拍号）一分不动。

> 松叶剩下的一半多是**两条臂没连上**的（尖端断开成两个 contour，各自是一条直线），
> 与弧线在单团的判据下分不开；要认得靠配对，还没做。

## 弧线（slur / tie）：逐列一段墨、而且**拱着**

`src/rasteromr/slur.ts`。无主报表里最大的一类带外图形就是它（6~15 格宽、1~3 格高、
团状度 0.03~0.07），而位图路至今**一条都不认**——GT 里宁静 283 条、破碎 326 条。

与松叶是同一批候选里分出来的两类，判据正好相反：

| | 逐列的墨 | 直不直 |
|---|---|---|
| 松叶（整条一团） | **两段**（两条臂） | — |
| 松叶（一条臂） | 一段 | **直**（离两端连线 ≤0.18 格） |
| **弧线** | 一段 | **拱**（≥0.25 格） |

再加一条「跨度大的列不能多」（逐列墨迹跨度 >0.6 格的列不超过 15%）——
那是松叶或实心块。宽度下限扫过 2.0 / 1.4 / 1.2 / 1.0 格：
圆滑线 37.6 / **39.4** / 39.4 / 39.4%，取 1.4。

**两端的 y 只取最外那三十分之一**。弧的两头是尖的，往里取一段端点的 y 会被拉向弧背，
`validateSlurNote` 的「在符头上方/下方三格以内」就判偏了：
扫过 1/6、1/12、1/30、1/60、一列——圆滑线 34.0 / 36.6 / **37.6** / 37.6 / 37.8%。

认出来之后**交给矢量路现成的那一套**（`staffomr/slur.ts`）：`attachSlurs` 挂两端、
`reconnectSlurs` 接回跨行的、`markSlurNotes` 落到音符上，`toxml` 出 `<slur>` / `<tied>`
——那边一行不改，只是这边要造一个假 `PObj` 装着盒（与 `adapt.ts` 造假字形同一路数）。
连音线（tie）也白捡：`attachSlurs` 判两端同音级就改判成 tie。

**实测**（`chorus-symbols.mjs` 新增一档，只在音高对上的位置比，与时值同口径）：
圆滑线 **0% → 39.4%**（GT 497 起，凭空多出 25）。检出侧宁静 204/283、破碎 235/326，
其中七成挂上了端点——**挂接**才是剩下的大头，不是检出。

### 虚线弧：等宽、等距、排成一线的短横划（`findRasterDashedSlurs`）

诗歌本里第二段起唱法不同的几处，圆滑线 / 连音线画成**虚线**（Holy, Holy, Holy 十二条）。每截只有 0.7×0.25 格，
单看是噪点；成串看才认得出：0.35~1.0 格宽、不高过 0.5 格、宽高比 ≥1.4 的短横划，相邻两截隔 0.25~0.9 格、
竖向错开 ≤0.35 格、宽度比 0.6~1.6，**至少三截、各间隔相差不过 0.3 格**。弧两头那截是斜的（8×5 像素，0.42 格高、宽高比 1.6），
形状闸按它放。两端那截常粘在符头、符干上或被歌词字格认去，所以候选是无主块**加上只被歌词认过的块**；认出来的多半只是中段，
端点仍落在两个音符之间，`attachSlurs` 照样挂得上。上方还是下方看近旁最近的符头（三格内）；离谱表四格半开外的不认
（歌词带里成串的连字符）。导出 `line-type="dashed"`（`StaffNote.slurDashed` / `tieDashed`）。
在其余 44 首独唱谱、合唱谱上一条都没多出来。还没认的：压在谱线上的虚线延音线（短划被谱线认走）、
两个声部的虚线弧上下叠着时上面那条判错边（离下声部的头更近），见[现状与待办](现状与待办.md)「查了没修的」。

## 贴着符头的演奏法记号（`artic.ts`）

保持音、断奏、顿音、重音、延长记号都很小，单看形状与谱线残段、加线、歌词里的连字符、附点分不开——
形状字典里叫 `articTenuto*` 的那一类（193 例）九成是谱线残段，原先照 `attachNotations` 的「x 最近」挂上去，
六首平白多出 455 个保持音。现在这几样不走那一路，按**与符头的关系**判：

- **两侧都认**。头这一侧（符干的另一头）：对着头心（±0.4 格）、离头心 0.6~1.75 格。干这一侧：在干尖或符杠外缘之外 0.15~1.5 格
  ——人声谱的记号一律印在谱表上方，干朝上的音就落在这一侧；断奏点对着干，保持音对着头，横向放到「头、干之外半格」。
- **谱表里的要落在间里**（离最近的谱线不到 0.27 格的是谱线残段）；谱表外正在加线位置上的短横，同一列更外面还有头的是那个头的加线。
- **候选不止无主的墨**：钢琴谱表上方的断奏点、人声行下方的保持音常落在歌词带里被字格认领，字典认成附点却没挂上头的也算；
  歌词带里的要孤立（一格内没有别的歌词墨，字自己的点画旁边必有同一个字的笔画）。
- **断奏点不能贴着别的墨**（0.45 格内，音符自己的头、干、杠、谱线除外）：扫描件上手写简谱数字底下的低音点、弧线的尖、
  力度字母的收笔原先都成了断奏（破碎扫描版多出 21 → 1）。四周一格内另有无主小墨团的按噪点不认。
- **延长记号是一弯月牙加正中一点**，量外缘（拱朝上的看上缘，中间比两端高出半个盒高以上），不量中线——月牙中间厚两头尖。
  这个组合够特别，候选不限无主：粗月牙常被符杠那一路、歌词带认领过（爱是从神而来末页三个全是）。在松叶、弧线之前摘走。
- 尺寸从实测取：保持音 1.04~1.30 × 0.30~0.40 格，断奏点 0.34~0.44 格，顿音 0.43~0.53 × 0.64~0.80 格，延长记号的点 0.55~0.65 格。

还没解决的：跨谱表连杠（钢琴两行之间的杠）上下的断奏点（是爱 p5 七个）；重音「>」贴着谱线时与谱线并成一团（`seg:Staff`），
干尖外的大号重音离头太远；望十架第二份底本的保持音 0/6。

## 反复记号与房子（`repeats.ts`）

下游 `classifyBarlines` 靠「小节线笔画的线宽 + 谱表里成对的圆点符号」认反复，位图路两样都常缺。`makeBars` 之后回到图上量，
结果直接写到 `Bar` 上：

- **反复**：第二、三间各一个圆点、左右对齐，旁边一格内一细一粗两根贯穿谱表的竖线（与 `findDots::repeatPair` 同一组门槛）。
  点在线左是 `:|`，在线右是 `|:`；印在行首的 `|:` 记给第一小节。同系统有一行认出来，各行同 x 的小节线都算。
- **终止线、复纵线同系统拉齐**：有一行在这个 x 认出样式，没认出的各行照它。
- **粗笔的门槛**（`staffomr/barlines.ts`）：三分之一线距，与本行小节线中位线宽的 1.8 倍取大。粗线低分辨率页（烛光颂曲线距 10px、
  小节线 4px）原先每根小节线都过了三分之一线距，整首每行都是终止线。**代价**：合唱谱扫描档小节自检 69.34 → 68.3，全在烛光颂曲
  （34 → 27.6%）——原先的假终止线让 `markSplitBars` 把不满的小节当成「段落边上的半截小节」放过，那个读数是虚的。
  认了三连音之后扫描档回到 68.79。
- **房子**：横线不在线段表里（又长又细，取图时与谱线一道抹掉了），从竖钩顶端回原图往右量（≥3 格），钩要对着一根小节线、
  钩顶离谱表 1.2~7 格、钩顶往左没有横线（第 1 房的线一直画到第 2 房的钩上，这种算上一房到此为止）。
  换行后接着的那一房印在行首，没有小节线可对，钩落在第一小节里就算（是爱第 2 房）。**钩底也往右拉着横线的是文字框**
  （宁静框住的 `Interlude`、排练号，原先出了两个假房子）。数字不认：前一小节右端是 `:|` 的是第 2 房；
  罩着的最后一小节以 `:|` 收尾的是第 1 房；都看不出、又印在行首的是第 2 房。同系统各行照抄。
  爱是从神而来、是爱的 `|: [1 :| [2` 都对上。

## 带方括号的三连音（`tuplet.ts`）

四分音符以上的三连音不打符杠，画一条被数字断开的方括号。下游 `findTuplets` 要一个数字符号加两截横段，位图路两样都没有
（「3」不在形状字典里，括号常是斜的、两端带小钩，成不了横段）。按**结构**认：一个数字大小的墨块（0.45~1.2 × 0.8~1.6 格），
左右一格多之内各贴着一条细长的墨（长过一格、平均粗细不到 0.4 格），三样纵向排成一线；括号上下 6 格内那行谱、跨度里同一声部正好三个音才算。
数字不认字形。候选是无主的加上只被歌词带罩住的（括号常落在歌词带里），放在歌词之后跑。
爱是从神而来 21/24，别的五首一组都没多出；该曲小节自检 91.5 → 94.5%。没有括号、只在符杠旁印一个「3」的那种还不认。

## 文字指示、节拍器记号（`words.ts`）

与声部标签同一套架构：**只按固定几何裁带**（两行谱之间的整段空当、页首行上方与页末行下方各 7 格），定位与认字交给 DBNet + rec，
离线按条的内容指纹落盘（私有仓库 `gen-rasterwords.mjs` → `rasterwords.json`，六首 689 条带约 7 分钟），在线走 `ocrlive.ts::ocrWordStrips`。
带里还压着歌词、和弦字母、力度、小节号，按内容分：

- **只留拉丁文**：夹着汉字的是歌词或署名；至少三个字母（声部缩写 `S.` `TB` `Ch.` 之类另列）；整串都是力度字母的不算。
- **力度交回力度那一路**：行首是 `mp` / `mf` / `f`…、后面没有别的或紧跟汉字（歌词行行首的力度与头一个字读成一行，`mf夫`）的，
  按 `attachDynamicTexts` 补挂——三格内字形那一路已经认到的不重复。
- **英文歌词**：一行歌词被 DBNet 切成好几段，同一高度上排着三段以上拉丁文（歌词带里两段）就是歌词行，只留含术语的；
  术语前粘着的歌词剪掉（`paid so willingly poco rit.` → `poco rit.`）。试过「落在歌词带里就要含术语」：歌词条切得宽，
  谱表上方的 `Flute`、`delicately, freely` 也被筛掉，文字从 319 掉到 173，撤了。
- **和弦记号**：整行去掉空格后正好是和弦记号（`CHORD_TOKEN_RE`）。一页里至少三行、其中一行带后缀才认——
  否则排练号 `A`、`B` 与把谱号读成的单个字母都成了和弦。和弦带那一路（`harmony.ts`）认到和弦的页不用这一份。
- **词界**：rec 不出空格。逐字位置只有六分之一行高的精度（词内间隙 0~0.34、词间 0.33~0.5，分不开），改按字行的列投影：
  连着 0.17 倍行高没有墨就是词界。斜体字相邻字母上下错着，仍有粘成一个词的（`1sttimeSA Unison`），评测比对时不看空格。
- **叠着的两行并成一条**（`1st time SA Unison` / `2nd time Parts`）；rec 给元音添的重音符（`póco`）去掉。
- **归位**：定谱行按谱表边到字心的距离；定音符取字行左端右边最近的那个音。写出 `<direction><words>`，节拍器 `<metronome>` + `<sound tempo>`。

还没解决的：低分辨率页（烛光颂曲）读出一批碎字（`phen`、`feos`）；节拍器只在「速度语 + 括号」里认得出等号；
`Fine` / `D.S. al Coda` / `To Coda` 只出文字、没出 `<sound>` 跳转属性，播放次序不跟；segno、coda 两个图形记号不认；
独唱谱那批没生成这份缓存（回归脚本不带 `wordOcr`，读数不受影响）。
