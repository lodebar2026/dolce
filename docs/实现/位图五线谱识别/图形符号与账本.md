# contour 认领账本与图形符号（位图五线谱识别）

> [位图五线谱识别](../位图五线谱识别.md)的分篇。

## contour 层与认领账本：**量得出「还有什么是我们从没看见的」**

`src/rasteromr/contour.ts` + `ledger.ts`，不参与任何识别判据——只描述、只记账。

现有的每一个数量的都是「**认出来的**对不对」（音符 68.1%、符头认领率 97.4%），
没有一个数量得出「印在纸上而我们从没看见的那些」。实测弧线、三连音的数字、
松叶、力度记号至今一个都不认，在别的报表上一点痕迹都不留。

做法：去谱线图上一团墨就是一个 **contour**（外轮廓 + 孔洞 + 形状特征），识别每认出
一样东西就按它的盒记一笔；一页跑完，**没有任何一笔的就是无主 contour**。

- **在去谱线图上取，不能在原图上**：原图上五条谱线把整行谱的符头符干小节线连成一团，
  一页只剩十几个 contour。
- **标号图（像素 → 块）必须由 `connectedComponents` 顺手落下来**（新加的 `out` 参数），
  不能拿它给的包围盒自己再 flood 一遍：面积不到下限的小块在那边被丢掉、却仍占着像素，
  照「盒里第一个没标号的前景像素」找种子会种到那种小块上，整团墨的标号就空了
  （实测 35 个块的周长因此掉到个位数、团状度算出 480）。
- **认领按盒查标号图，不按盒相交**：盒相交会把路过盒角的符干、隔壁的符号一并算进来。
  两条门槛过一条即可——落进盒里的像素占**本团墨**两成，或占**盒内全部墨**两成：
  符头的盒只盖住「符头+符干+符杠」那一大团的一小截（占团低、占盒高），
  歌词字格反过来。
- **段只记挂上标记的**（`Staff`/`Leger`/`Stem`/`BarLine`/`SysLine`/`Tail`/`Beam`），
  不记 `findPrimitives` 抽出来的原始段。横段里混着**松叶的臂、弧线的一截**
  ——照抽出来就记，要找的东西反倒成了「有主的」。
- **歌词字格不论有没有 OCR 缓存都要切、都要记**：切出字格这件事本身就是
  「这块墨是歌词」的判断，与认不认得出那个字是两回事。缓存没命中就不记的话，
  整页歌词都成了「从没看见的墨」（实测宁静墨覆盖 79.5% → **86.5%**）。
- **覆盖率的口径偏乐观**：认领过的 contour 的**全部**像素都算已解释。
  它量的是「还剩多少团墨完全没人看过」，不是像素级的解释率。

## 松叶（wedge）：按 contour 认，不拼线段

`src/rasteromr/wedge.ts`。**这一路是 contour 层的第一个用处**——无主报表里一眼看见
「又宽又扁、从没人认领」的那一批，其中一半是弧线、一半是松叶。

- **不从 `hSegs` 里配对两条臂**：`findPrimitives` 对横笔画有一道「块高不过 `thin*2`」
  （约 0.8 格）的闸，而松叶的开口实测有 1.5~2 格高——**整条松叶连着尖端是一团**，
  块高一超限整个被那道闸滤掉，压根没进 `hSegs`。它原样留在图上，
  正好是一个完整的 contour（实测宁静 p2 那条 376×30 px = 20.7×1.66 格、团状度 0.01）。
- **判据是逐列的墨迹跨度**：两条臂从尖端往开口张开，跨度近似线性地涨。
  弧线同样又宽又扁、团状度也低，但它**逐列只有一段墨**、跨度处处等于线宽
  ——「一列几段墨」（≥35% 的列有两段）与「跨度涨不涨」（开口 ≥0.55 格、
  尖端 ≤0.42 格、且开口是尖端的两倍以上）两条一起用，一刀分得开。
  实测宁静 p2 的弧线：两段列 0%、左右跨度都是 0.11 格，一条都不误收。
- 尖端在左是 `crescendo`、在右是 `diminuendo`。
- **尖端没连上的那些，两条臂各成一团**（印得细的时候常见）——单团的判据对一条臂
  无能为力（一条臂逐列只有一段墨、跨度处处等于线宽，与弧线一模一样）。
  `pairArms` 按**两条臂的关系**配：斜率一正一负、x 上盖着一半以上、
  一头挨着（≤0.45 格）另一头张开（≥0.55 格）。臂本身要**直**
  （离两端连线最远处 ≤0.18 格，弧线拱得高，一量就出局）。
- 形状闸扫过两档（`MIN_W`/`OPEN_MIN`/`TIP_MAX`/`TWO_RUN_FRAC` = 2.5/0.55/0.42/0.35
  与 1.8/0.45/0.5/0.25）：检出 **38/77 → 54/77**、序列 46.0% → 47.2%，取松的这一档。
  代价是**过检**（破碎有一条谱表识别出 15 条而 GT 只有 8 条），序列档因此涨得少。

**挂接与导出**：`attachWedges`（`staffomr/notations.ts`，与力度共用一套判据：
**先定是哪一行谱**——记号印在它那行谱的下方，而下面一行谱的上缘往往比它自己那行的
下缘还近，不先定谱行整条松叶会挂到下一行去；**那一行在这个位置没有音符就退回
「纵向够得着的谱行里 x 最近的那个」**——只按 y 定谱行、找不到就丢，
实测松叶从 38 掉到 **14**，人声那一行常常正好在休止。这一条把力度也带上去了：
检出 18 → **21**、序列 33.7% → **37.9%**）把起讫挂到音符上，`toxml.ts` 出
`<direction><direction-type><wedge>`。**止排在起之前**——同一个音符上前一条收尾、
下一条起头是常事，反过来写两条会重叠。矢量路的 `slur.ts::findWedges` 只给松叶打标
（免得被当成弧线），**从来没进过 MusicXML**，这一条两条路都是新的。

### 第八批（2026-10-07）：写出带 `<staff>`、不切成两半、挂到自己那行

- **钢琴两行合一个 part 时 `<direction>` 要带 `<staff>`**（`toxml.ts::emitVoices`），松叶两行各用自己的编号（`number` = 谱表号）。
  不带的话读入端（测评也一样）把力度、文字、松叶算到整个 part 的每一行，或一律落到第一行；同号松叶两行还互相套住。合唱谱 3323 → 3186 步。
- **粘在小节线上的松叶**（`findFusedWedges`）：开口顶到小节线、或从钢琴大谱表两行之间横穿小节线的松叶，与小节线连成一团、整团被小节线认领，
  无主的团里找不到它。把团里竖着贯穿（最长竖游程过 2 格）的列跳过，**两侧跨度与纵向中心接得上的并成一条再判**，不切成两半；
  认领只按切出的那一段记（按整团的大框记会把框里的音也记成松叶）。
- **止端只在起端那行里找**：两端分头找各自退回别的行，一条松叶会起在女高、止在钢琴。
- **人声的松叶往上 9 格找自己那行**（`WEDGE_REACH`）：合唱谱的松叶印在自己那行歌词**下面**，离下一行谱表反而更近。
  印在自己谱表上方（= 上一行歌词下面）的也有（破碎 p4 m30 女低那条挂到了女高）：与矢量路同一条 `ownerStaff` 判据，
  各行谱下方歌词行的下沿交给它，松叶中心低过上一行歌词下沿半格、下方三格内就是一行谱的归下面那行；
  让半格是因为与歌词同一高度、印在末字右边的松叶，中心比字的下沿还低几个像素（爱是从神而来 p5 m63）。
- 读数：漏认 131 → 102，挂偏 38 → 57，合唱谱合计持平。**GT 的松叶按拍记、与印出来的线段常对不齐**（破碎 p2 m4 印在小节中段，
  GT 从小节头拉到小节末），认出来的越多「挪」越多。试过「止在右端处或其后的第一个音」：多 8 步，已撤（第十一批连同不隔小节线、收在小节末、评分按时刻一起做，见下）。

### 第九批（2026-10-07）：跨行的弧、贴线的弧、弧尾越线

- **跨行弧按系统配**（`staffomr/slur.ts::reconnectSlurs`，矢量路同用）：原来配「下一行谱」，合唱谱、钢琴谱里那是同一系统的下一个声部。
  现在本系统第 k 行行尾悬空的配下一系统第 k 行行首悬空的（两个系统行数相同才配）；同一行几条悬空时，行尾取最靠右的、行首取最靠左的，
  各取同样几条再按离谱表顶的高低配（行里别处也有一端没挂上的弧；按高低直接配会挑中它们，矢量路弧线档掉 0.03）。没有系统划分时照旧。
- **行首行尾的半截弧**（`slur.ts::findStubSlurs`）：跨系统的延音线、圆滑线在下一行开头只画一小截，一格来宽、拱得浅，过不了宽度与拱度两道闸。
  只在各行谱第一个音左边 3 格、最后一个音之后到行尾的窗口里放宽：宽 ≥0.8 格、拱 ≥0.08 格、逐列单段占六成（贴着线的那截去线后有几列断开）。
  破碎 p2 m11–12 钢琴右手 A4 延音线因此接上。
- **弧尾平着斜穿谱线**（`extendArcEnds`）：从端头那一列真实的墨点起步（端点 y 是最外一小截的平均，斜着的弧尾比端列的墨高两三像素，第一步就落空）；
  越线途中找墨的垂直窗口放到 0.3 格（平着进线的弧在线带里走一格来宽，出线时更陡）；越过线之后找到的墨要细（竖向不过 0.35 格），
  不然顺着贴着的符头跟过去（我灵镇静一条延音线左端挂到前一个 E4）。宁静 p1 m2–m4 钢琴右手长弧止端由 C5 改挂到 B4。
- **歌词账上来的弧用文字框免判**：「挂上的端要贴着音」那条是防字的弯笔；歌词条的认领框比字宽，钢琴右手上方隔着顿音点、离音两格半的延音线
  也记在歌词账上（破碎 p4 m33）。贴着谱表（离上下线 2 格内）、又碰不着任何文字框（外放半格）的免掉。只凭字框不够：
  DBNet 在密排三段歌词上常整片漏检（你的信实广大一页只检出 45 个框），单用字框裁决独唱谱掉 4 首。
- 读数：合唱谱 3034 → 2805 步（其中宁静、破碎电子版 GT 删去谱面没印的序言 194 步；识别改动 35 步：破碎扫描 971 → 958、宁静 → 201、破碎电子版 → 347），
  独唱谱 90.98 → 91.01%（记号 44.41 → 46.38），矢量路各档不低于基线。

### 第十批（2026-10-07）：弧的编号、行首行尾的弧端、跨谱表大弧

- **`<slur number>` 按谱表号**（`toxml.ts`）：钢琴两行合一个 part 时一律写 `number="1"`，右手一条长弧还开着、左手又起又止一条，
  读入端按编号配对就配串了（宁静 m32–36）。跨谱表的弧（左手起、右手收）止端按**起端那行**编号（`StaffNote.slurStopFrom`），两端才配得上。
- **行首行尾越出音符的弧端**（`slurattach.ts::attachEdgeSlurEnds` / `attachEdgeSlurStarts`）：一行最后两个音上的弧画在杠上方，右端越过末音近一格到行尾；
  一行第一个音起的长弧左端在头左缘外一格多。两端挂不上，都像跨行弧的半截，被 `reconnectSlurs` 互相接上（宁静 p1 m4、p3 m36–37）。
  止端兜底在跨行配对**之前**：越过末音不过 1.2 格的挂末音（真跨行的伸得更远，破碎 p2 m11 两条 1.3、1.8 格）。
  起端兜底在跨行配对**之后**、只管没配上的：首音左边 1.5 格内、弧不短于 3 格、纵向离首音 2.5 格内（跨行进来的按上一行的高度走，
  望十架 p2 女高那条高出首音 3.8 格），页上第一个系统不做（可能接的是上一页）。
- **跨谱表大弧续端之后再并截**：钢琴左手起、穿过两行谱表间到右手的弧，被右手第一线切成两截；下截续过线之后端点才挨着上截，
  并截改在 `extendArcEnds` 之后再跑一次，并加一条「两截端点 0.6 格内相挨」（续端只挪端点、盒子不跟着长）；
  接头不能同时是两截各自的谷底（弧在上方时），免得把首尾共用一个音的前后两条弧并成一条。
- **没做**：和弦延音线挂错多半是和弦里的音没认出来（是爱 p4 m47、m49 穿加线的空心二分和弦上方的音；望十架 p3 m30），属符头那一路；
  扫描件里画在两根干之间、压着谱线的小弧（望十架 p7 m55 一行五条），抠粗笔时连线一起被抠断，在修补图上找也一样，要换抠法。
- 读数：合唱谱 2805 → 2734 步（宁静 201 → 177 等；含文字指示与计分口径两项，见[位图五线谱识别](../位图五线谱识别.md)第十批）。

### 第十一批（2026-10-18）：两端照排版惯例挂、跨系统的截、续段

破碎干净版逐条对图（`attachWedges`、`wedge.ts`）：156 → 122 步，其中松叶 69 → 37 步。

- **两端挂哪个音照排版惯例**（Gould《Behind Bars》：松叶起在它开始的那个音下、收在它通向的那个音之前）：
  起端挂左端处或之前的音（音头左缘在左端右边半格内也算），止端挂右端处或之后的第一个音（音头左缘在右端左边半格内也算），
  **都不隔小节线去找**；右端过了小节里末一个音、收在小节线前的，挂末音、写在它**之后**（`StaffNote.wedgeStopAfter`，= 小节末时刻）。
  从前两端各挂 x 最近的音：起端印在某个音右边一点挂到下一个音，收在小节线前的挂到下一小节头一个音。
  试过「离音头中心最近」（142 步）与「整个音头在端点外」（129 步），都不如这一套（123 步）。
  GT（Finale 导出）的起止本来就这样写：起写在起端那个音前、`offset +⅛ 拍`，止写在画到的那个音前、`offset −⅛ 拍`。
  宁静、破碎、破碎扫描的 GT 后来照同一套惯例逐条对图订正过（漏记的补上、挂偏的挪正）；GT 的起端取「离左端最近的音（按音头中心）」，
  两可处留原 GT，与这里的起端判据在两可处取舍不同。GT 写法见私有仓库「识别手动操作」的「GT 里松叶的挂法」。
- **右端压过小节线 2.5 格内的收在小节线前**（`WEDGE_PAST_BAR`）：开口顶着小节线、与它连成一团认出来的，右端常在小节线右边一两格。
- **歌词下沿那条归属只在下一行谱顶 2.6 格内生效**（`WEDGE_NEXT_REACH`，力度仍是 3 格）：印在下一行谱上方的离谱顶 1.0~2.54 格
  （宣主荣耀、牵我的手、破碎 p4 m30），破碎印在自己歌词下面、被挪给下一行的四条离 2.80~2.92 格（钢琴两条长渐强、m40 女高一、m92 女高二）。
- **起端落在长音中间**（离最近的音超过 4 格）：本行左边 12 格内有音就挂它（破碎 m98 女高一、二，原来整条丢掉）。
- **跨系统的松叶**：行首那截是渐强、左端在本行第一个音头之前半格以上——不写起（渐弱在行首本来就是开口那头，
  单看这一截分不出起还是续：宁静 m107 真从行首起、破碎 m30 / m90 是续段，几何一样，照起点写；后来按上一系统、上一页同一行认续段，见第十三批）；行尾那截右端离谱表右端 0.4 格内、又在末音之后——不写止。
  MusicXML 里同号的起止跨行自然接上（弧线同此，跨页也成）。0.4 格是量出来的：续下去的直画到谱表尽头（m64、m72 差 3 像素），
  收在系统末小节线前的留着空（m80 差 0.65 格）。
- **行首、行尾那一截的尖端放宽到 0.9 格**（`pairArms` 的 `atRowEdge`，不过开口的一半）：续段那头本来就张开着（m65 起点 0.47 格）。
  臂的两端改按前后四分之一段均值**外推到端点**（长臂按段均值当端点，尖端差出两三个像素）；斜率下限 0.03 → 0.015
  （钢琴两行之间二十来格长的续段一条臂只有 0.016）。

## 力度（dynamics）：字典早就认得出，缺的是挂接与**连字**

`src/rasteromr/dynamics.ts`。两件事：

1. **位图路从来没调过 `findNotations` / `attachDynamics`**（矢量路 `index.ts` 一直在调）。
   而字典本来就认得出：`rasterglyphs.json` 里 `dynamicForte` 26 个实例、`dynamicMP` 8 个，
   实测宁静 p2 那个 `f` 到 Maestro 模板的距离只有 **19**。补上这一句，力度 0 → 21 个。
2. **`mf` 印出来是两个字母**（`m` 一块、`f` 一块），只认 `f` 就把 `mf` 读成 `f`。
   `m` 那块本身认不出——它落进字典的 `dynamicForte` 类（实测距离 71~98，真 `f` 只有 19），
   或者干脆被当成实心符头（1.87×1.17 格，正在符头的尺寸档里）。

所以不靠字典认 `m`，**靠版式**：从字典认出来的那个字母往外长，按宽高比认旁边的字母
（与锚同高 = 又一个 `f`；只有 0.33~0.62 倍高、又宽 = `m`；中间那一档 = `p`），
拼不出一个像样的力度（`VALID` 那张表）就整串丢掉——**宁可少，不可编**。

> **间隙的上限卡在「贴着」（0.15 格），不是「近」。** 力度字母是斜体连写的，
> 实测 `mf` 的两块在 x 上还**重叠** 9 px；而歌词里紧挨着的汉字有半格以上的字距
> ——照 0.7 格的间隙，宁静 p2 那个 `f` 会把右边 0.5 格处的「在」字拼进来成 `ff`
> （汉字约 2×2 格，正落在「又一个 f」那一档里）。
> **纵向比中心不比底边**：斜体 `f` 上下都出头，与 `m` 的底边差 0.72 格，中心却分毫不差。

### 挂接（`staffomr/notations.ts::attachDynamicTexts`，矢量路同用）

  字框右缘到音 3.9 格），或印在前面休止小节的末尾（宁静 p4、p5 几处 `mf`）；原来按左缘找三格内最近的音，这几个都挂不上。

### 字典按整块查不着的：拿本页认出的字形当模板在块里找（`findGluedDynamics`）

字典按**整块**查，力度一粘上别的墨就查不着；也有本是单独一个 `f`、却先被别的判据认领、没进符号表的。
思路是先把认得出的拆出来、剩下的再认：**本页字典已认出的 `f`、`mp` 就是这本书这个字号的字形**，拿它们的像素当模板，
在够大的块里逐像素滑窗——模板的墨漏不过一成（差一个像素的笔画不算漏）、窗里多出来的墨不多，就是它。

- `f` 当一个字母：窗里多出来的墨上限 0.45（穿过的细弧、相邻字母探进来的一角）；一个窗说不通的，找并排的另一个 `f` 一起算
  （`ff` 横笔连成一块，两个窗互相探进对方：宁静 p8 m97 钢琴）。找到的 `f` 扣掉，块里剩下的墨与旁边单独成块的
  在同一条字行上照 `letterOf` 认 `m`/`p` 拼起来（宁静 p3 m41 钢琴 `mf`：`m` 单独一块、`f` 没进符号表）。
- `mp` 整字：上限 0.15（真的 `mp` 粘了弧也是 0；符杠连干那一片盖住 `mp` 模板时多出三成多，破碎 p12）。破碎 p5 m49 钢琴 `mp` 粘着弧。
- `p` 字典里没有，本页也没有单独印的可借——**从 `mp` 那一块里切出来**：中段墨最少的那一列切开、取右边。只认谱表外、
  块不比模板大四成的（一个圈带一竖，谱表里带干的符头、歌词字的一角都能盖住它：望十架扫描版放开时多认十几个）。破碎 p2 m1、m8 钢琴 `p`。
- 字形那一路认出来**却没挂上**的（印在终止线外），OCR 读出的那份照补（原来三格内有字形的就不补：爱是从神而来 p5 m63 `p`）。

读数：宁静、破碎干净版**力度全对**（合唱谱干净档记号 85.93 → 86.43、手动操作 98.51 → 98.56），扫描档 87.82 → 87.93（望十架、爱是、破碎扫描各少几步）。

## 弧线（slur / tie）：逐列一段墨、而且**拱着**

`src/rasteromr/slur.ts`。无主报表里最大的一类带外图形就是它（6~15 格宽、1~3 格高、
团状度 0.03~0.07），而位图路至今**一条都不认**——GT 里宁静 283 条、破碎 326 条。

与松叶是同一批候选里分出来的两类，判据正好相反：

| | 逐列的墨 | 直不直 |
|---|---|---|
| 松叶（整条一团） | **两段**（两条臂） | — |
| 松叶（一条臂） | 一段 | **直**（离两端连线 ≤0.18 格） |
| **弧线** | 一段 | **拱**（≥0.25 格） |

再加一条「跨度大的列不能多」（逐列墨迹跨度 >0.6 格的列不超过 15%）——
那是松叶或实心块。宽度下限扫过 2.0 / 1.4 / 1.2 / 1.0 格：
圆滑线 37.6 / **39.4** / 39.4 / 39.4%，取 1.4。

**两端的 y 只取最外那三十分之一**。弧的两头是尖的，往里取一段端点的 y 会被拉向弧背，
`validateSlurNote` 的「在符头上方/下方三格以内」就判偏了：
扫过 1/6、1/12、1/30、1/60、一列——圆滑线 34.0 / 36.6 / **37.6** / 37.6 / 37.8%。

认出来之后**交给矢量路现成的那一套**（`staffomr/slur.ts`）：`attachSlurs` 挂两端、
`reconnectSlurs` 接回跨行的、`markSlurNotes` 落到音符上，`toxml` 出 `<slur>` / `<tied>`
——那边一行不改，只是这边要造一个假 `PObj` 装着盒（与 `adapt.ts` 造假字形同一路数）。
连音线（tie）也白捡：`attachSlurs` 判两端同音级就改判成 tie。

**实测**（`chorus-symbols.mjs` 新增一档，只在音高对上的位置比，与时值同口径）：
圆滑线 **0% → 39.4%**（GT 497 起，凭空多出 25）。检出侧宁静 204/283、破碎 235/326，
其中七成挂上了端点——**挂接**才是剩下的大头，不是检出。

### 第六批（2026-10-07）：修补图上取弧、宽弧挂端、并截

- **修补图**（`prims.ts::repairLineCuts`）：去线逐列判「线带上下紧挨着有墨才留」，弧贴着线斜穿时中间几列整段落在线带里、上下不连墨，被当线抹掉，
  弧断成几截——第五批的拼碎弧、弧端延长都是事后补这个洞。修补图在去线图上把**存疑**的线带像素补回：
  ① 线带竖向墨厚比本线实测线宽厚出一像素以上、左右 0.75 格内线带紧上方或紧下方有墨（有东西压着线）；
  ② 线带上方挨着的一截细墨与下方挨着的一截（纵向都不过 0.4 格）横向相隔不过 0.75 格，补两截之间那道缝（斜穿、线带没加厚）；
  ③ 同一侧挨着线的两截细墨相隔不过 1 格、缝那一侧 0.6 格内过半的列是空的：拱顶压线只剩两条腿（破碎扫描版 p1 m2）；
  缝上方整段有墨的是坐在线上的延音线，补了就和线围成一圈（望十架 p4 m33 低音 D3）。
  反过来，线带只有本线厚、又不是穿线段的列在这张图上清掉：去线时因为上下挨着墨留下的谱线残段，粘在弧身上每列成了两段、就不拱了（破碎 p2 m2）。
  ②只补两截之间、不往两旁多补：按「左右 0.75 格内上下都有墨」补，补出一截 30 像素的谱线粘在弧上。
  **只给弧线候选用**，认干、认杠、认头照旧用去线图：修补图上的一块，组成它的去线图碎块全是候选才整块判；连上了符头、干的，
  退回去线图一块一块判，判时只认修补图上也有的像素（谱线残段已清掉）。和谱线完全重合、一点没加厚的笔画（平躺在线上的延音线、还原号横笔）补不回来。
  这一路替掉了 `findSplitArcs`。
- **团状度放行细弧**：一格半宽的小弧盒子扁，团状度天然偏高（破碎 p2 m2 G4–F4 下方那条 0.26 > 0.25），逐列平均墨厚不过 0.2 格的也放进来。
- **一条弧的几截并回**（`slurattach.ts::mergeArcPieces`）：跨谱表的大弧穿过几条谱线，断成几截各挂各的音（宁静 p1 m15 钢琴 D3→C5 被拆成三条）。
  同向两截、首尾互相落在对方盒里（外放 0.3 格）的并成一条，左端取左截、右端取右截。
- **宽弧的端**（`attachWideSlurs`）：一组音上的长圆滑线要躲开中间最低（最高）的音，两端离端头的音三四格（破碎 p2 m15 钢琴右手 G3…G4，右端离 G4 3.9 格），
  三格窗口够不着。宽过 5 格的弧，挂不上的端横向在头左右 1 格内、纵向在弧那一侧 4.5 格内再找一次，取离头盒最近的；
  弧端要在头的顺手一侧（起点不在头左缘外、终点不在头右缘外：p3 m28 终点离 A4 右缘 6 像素、离 C5 头底 3.5 格，挂 C5），贴着头一格内的不论哪侧
  （p2 m15 起点在 G3 左缘外 11 像素、离头底 0.5 格）；弧身那一侧有越过弧的音的不挂。
- **粘连弧补缝**（`findFusedSlurs`）：竖笔抠掉后弧在干、小节线处断开一道窄缝（不过 0.25 格），同一行缝两边都有细墨的补回；小节线那团墨也送进来看（跨小节线的延音线）。

### 对着 MIDI 修延音线（2026-10-16）

识别结果与 GT 各导一份 MIDI 逐音比（私有仓库的 MIDI 比对脚本），干净档两份剩下的全是延音线：漏了、多了、配反了。逐条看原图修完，两份逐音一致。
- **跨小节线的短延音线**（`pagefinish.ts`，`BAR_TIE_REACH`）：连两个八分的延音线只有两格多，弧顶压线，去线时一头断开一小截，
  粘在小节线上那块只剩半条、拱不起来（破碎 p2 m15–16、p3 m19–20 钢琴右手）。修补图上小节线还连着符头和干，整块进不了候选，
  所以在小节线左右两格的窗口里从小节线的像素出发、按八邻接把修补图上连着的墨填出来，当一团送 `findFusedSlurs`（这一路宽度下限 1.5 格）。
  认出的弧两端要分在小节线两边、各伸出 0.3 格（小节线位置取这团里墨最多的那列）：只碰到小节线的是贴着它的符尾（万福泉源歌 m0 八分的旗）。
  外面罩着一条圆滑线时，两条盒子重叠，「已认过」按两端都在半格内判，不按盒重叠。
- **和弦上只印一条延音线的不补齐**（`tieChords` ②）：排版软件只给八度、全音符和弦的外侧那个音印一条的（破碎 p5 m49 钢琴左手、p12 m108 右手），
  「其余同音也补上」会多出几条。补之前要有证据：同一行谱上另有一条弧落在这一段里（左放 1.5 格、右放 3 格、不短于三成——
  一个音一条、外侧的画在和弦外面，是爱 m1/m54/m65），或原图上那个音上下 0.7 格的带里（和弦最外侧那个音往外伸到 2.5 格，望十架 p8 m60）有墨的列过半。
- **二度和弦接单音**（`tieChords` ⓪）：F4/G4 挤着排、G4 错到干另一侧，弧从 G4 外侧起，挂成 G4→F4 圆滑线（破碎 p5 m55、m74 等）。
  一头单音、一头和弦、两头之间这行谱上没有别的音、单音的音级在和弦里、而且与弧挂着的那个音只差一个音级、同一和弦组、干同向，改挂共同音判延音线。
  三度以上不管（新编 073 m20 F4/A4 → A4 是圆滑线），闭合谱另一个声部的音不算（011 m25）。
- **首尾相接的两条弧不并**（`mergeArcPieces`）：圆滑线收在 D5 上、紧接 D5→D5 跨小节线的延音线，两条盒子挨着，原来「盒子互相罩着」那一路不看接头，
  并成一条（破碎 p12 m100 女低、p5 m48 钢琴右手、宁静 m97）。两路都过一道闸：接头处两截都往音符那侧收（比各自的顶低 0.3 格以上）就不并。
- **行首同一处起笔的两条弧拆开**（`slur.ts::splitFork`）：跨行延音线的后半截与一条圆滑线从同一处起笔，墨连成一块（破碎 p3 m17 钢琴右手 E4）。
  一头有至少一格逐列正好两段墨、靠音符那段走到头断了，就拆出来单判，两条都过闸才拆；只在行首行尾窗口里拆（行中间贴着歌词、符尾的地方也有两段墨，高举主大能 m2）。
- **行尾延音线头半格宽**：`findStubSlurs` 宽度下限 0.8 → 0.6 格、平均厚度上限另给 0.3 格（破碎 p2 m16 E4，0.64 格宽、0.28 格厚）。
- **跨页的半截按同音高配延音线**（`toxml.ts::renumberSlurs`，写出选项 `crossPageTies`，只给位图路）：配对先配「两头同音高、起端是本系统末一个音、止端是下一系统头一个音」的，
  再按朝向配（行尾行首各一条延音线、一条圆滑线时按朝向先到先得会配反）；只找到一半的，相邻系统同声部紧挨着那个音同音高也补成延音线。
  矢量路不开：Finale 直出的谱里跨行同音高相邻两音之间也记圆滑线（牵我的手 m24 小提琴 B3→B3），照判反倒退。
- 试过没留：**谷底切开**（一条弧中心线中间有个往音符那侧凹的谷就切成两条）——破碎那两处靠上面 `mergeArcPieces` 那道闸就分开了，它只在高举主大能 m2 切出一条假弧。

### 钢琴跨谱表大弧、行首起笔、按干挂端（2026-10-20）

宁静的伯利恒钢琴几乎每小节一条从左手第一个音陡着升上去、在右手谱表顶上拱过、落到右手小节末和弦上的大弧；
剩下的漏多在这一类与行首起笔的弧上。
- **陡着收不住的弧端往外追**（`slur.ts::traceSteepArcEnds`）：拱顶压着、擦着右手谱表的线（有时整段埋在线里），去线后碎成短块认不成弧，
  只剩下截，右端停在半空、就近挂到中途某个右手音上。弧上方（∩）的右端还在陡升（弦的单位向量竖向分量过 0.6），说明弧在这儿没完：
  在**原图**上从端头往外一像素一步追，起步切线取端头往里 0.6 格处的墨心（弦是整截的走向，端头常已拐平），
  走向按几步之前那个墨点量（单步方向被垂线上半像素的抖动甩到后头去）。垂直于走向半格内找离预计位置最近的一段墨：
  细的（不过 0.6 格）跟上；粗的（擦过音头、符杠）照切线穿过去，连续不过 1.5 格；没墨不过 0.6 格。
  **谱线行上的墨只在竖向比线宽多出两像素时算**：斜穿谱线时线的那一小截也是细墨，不排掉就顺着线走了；弧顶贴在线上那段线加弧比线粗。
  落在线行上又没墨的照切线走（同 `extendArcEnds` 的 1.5 格）。弯向要一路朝一侧弯（∩ 往右斜率只增，回头过 0.8 停，起步那一小段不记），
  收尾往回陡下（竖向分量过 0.85）停：那是顺着符干、头的边走了。追出 1.5 格以上才改端点，路上原先认出的拱顶那截（两端都贴着追过的路）并掉。
- **按游程补认的跨系统半截留着**：那一路要求两端都挂上（挂不全的多是线上残留的墨），行尾 / 行首的半截只有一端也被剔了
  （破碎 p2 m16 钢琴右手行尾那截，墨还被字典认成了保持音；下一页行首那截认出了却配不上）。只挂一端、另一端正伸到行尾行首（`orphanEdge` 不是 `mid`）的留下。
- **长弧末端的细尾续接**（`slur.ts::traceLongArcTails`，在 `traceSteepArcEnds` 之后；长弧下限后来放到 3.5 格）：长弧两头收成发丝细的尾巴，斜着过谱线时那几列被去线连弧一起抹掉，
  认出的端点停在尾巴前头、挂到前一个音上（宁静 p1 m6–8 钢琴右手 A4 起的长弧，尾巴过第一线后画到 m8 F4 前，认出的右端停在 E4 上方）。
  宽过 5 格的弧两端都在原图上顺切线往外追：垂直于走向 0.3 格内找细墨，**谱线行上的墨一概不用**（线加弧那几列竖向一长条，会把走向拽成竖直往下），
  过线当断口照切线走；断口容 0.8 格，断着时按最近几步的转弯速度续着弯；碰上粗墨（过 0.4 格）停、追到音头 0.25 格内停，最多 4 格。
  端头已贴着音头（0.4 格内）的不追，两端各自最近的音头同高（像延音线）的不追：头一版长延音线追过了头挂不上（是爱 p3 m37、p4 m47）。
  宁静 21→16、破碎 40→37；扫描档破碎扫描 +2、望十架 +1。
  先试过「弧端紧挨谱线就追、碰粗墨即停、最多 3 格」（不分长短）：目标那条没接上（起步切线被端头一团墨带偏），反伤破碎 4 步，撤了。
- **隔着一段的两截并成一条**（`slurattach.ts::bridgeArcPieces`）：陡段贴着音头、符干走、并进了音符的墨块，弧只剩陡段两头各一截（宁静 p1 m11 D3→C5）。
  两截同向、接头 5 格内而且是陡的（竖向过 1 格）、左截弦 / 接头弦 / 右截弦三段斜率依次单调（合起来凸向一侧），接头弦上逐列在弦到拱起一侧 0.8 格的带里都有墨（九成），并。
  平的接头（竖向不过 1 格）放到 60 格：一整行的长弧拱顶擦着上方的文字、整段没认出，只剩两头各一截（宁静 p7 m89、m93 女高）；
  这时谱线行上的墨不算（弦贴着谱线时线会把墨带填满），隔开的两条弧中间没墨，并不上。
- **跨行配对只接真在行尾、行首的半截**（`staffomr/slur.ts::reconnectSlurs`，按 `orphanEdge`，写出端早就这么判）：上面那种左截右端悬在行中间，
  原先被当成跨行弧的前半截接到下一系统去了。
- **行首起笔的弧挂首音**（`attachEdgeSlurStarts`）：左端在首音左缘外的上限 1.5 → 2 格（宁静这批起在调号上方，1.65~1.9 格）；
  纵向距离不再量首音，量首音右边 2 格内那组音的外缘（钢琴右手首拍十六分高低交替，弧贴着高的走，离首音 3~5 格），
  弧端比外缘往里不过 1 格也算（弧从头侧边起笔，宁静 p5 m71 低 0.44 格）。宁静 p1 m5、p3 m37、p4 m57、p5 m65/m68/m71 补上。
  上限放到 2.5 格（宁静 p7 m93 女高 2.0 格）。页上第一个系统可能接的是上一页，页内只把候选记在首音上（`slurEdgeCands`），
  整曲拼页时（`song.ts::settleEdgeSlurStarts`）上一页末系统整个没有行尾半截就补；有的话按行对（行数不同从下往上对：多出、隐藏的多是最上面的人声谱表），
  对上的那行没有行尾半截才补（最初行数不同一律当「没有」，望十架补错四条）。纵向上限 2.5 → 3.5 格（宁静 p7 m89 钢琴右手 3.1 格，弧越过一组上行的十六分）。
  试过挂首拍那组里弧那一侧最外的音（十六分高低交替时贴着高音），宁静反倒多 4 步，没留。
- **弧在干那一侧时按干挪端**（`snapSlurEndsToStems`）：干朝上、弧在上方，弧端对着的是干端：一组十六分上方的弧从第一根干右边一点起笔，
  按头盒量第二个音更近。已挂上的端，那个音的干在弧端外侧过 0.25 格、同一行谱上另有同朝向的干落在弧端内侧 1 格内的，改挂干离弧端最近的。
  挂着的音干背着弧（弧在上、干朝下）时：前面（止端：后面）有个干朝弧那侧的音、弧端在它的干外侧 2 格内、离干端纵向 1.5 格内，改挂那个音
  （破碎 p7 m70、p4 m30 钢琴左手「八分 B2 干朝上带旗 + 四分干朝下」，弧从旗尾右边、第二个音头正上方起，GT 起在八分上）。放到 2.5 格破碎干净版反多 4 步、3.5 格多 11 步。
  纵向后来放到 2 格（不伤）；「补齐另一端」之后再过一遍（补的端按头中心就近挂，破碎 p7 m72 钢琴左手 E2 那条）。
  延音线不动（两头贴着头）：头一版没跳过延音线，钢琴左手几条延音线被挪成了圆滑线。
- **按干挂不上的端纵向再放 2 格**（`attachSlursByStem`，只给另一端已挂上的弧，两端都先按三格挂一遍）：破碎 p4 m32 钢琴右手起端细尾断成点，
  停在带旗十六分 D4 右边、下一组 E4 的干左 10 像素，D4 的干端低 3.5 格；GT 起在 D4。先试过放宽「干左」那道闸（0.25 → 0.7 格），挂到 E4，与 GT 不符。
  两端都没挂上的不放：扫描件上的碎墨（爱是 p1 m11）会被挂成一条；宽过 5 格的长弧例外（破碎 p7 m73 钢琴右手两端都差一点够不着，GT 起在带旗的 D4）。
  试过「只看干端贴着弧的干、干在弧端里侧优先」挂起端：挂到了符杠组第一个音 E4，GT 两处（p4 m32、p7 m73）都起在前面那个单独带旗的 D4，撤了。
- **歌词账上的弧按干端量远近**：干朝弧那侧的，弧贴着干端、符杠，离音头五六格，原先按音头量判成离音太远整条摘掉。
- **除跨系统的半截外，一条弧两端都挂、挂在不同的音上**（`slurattach.ts::completeSlurEnds`，在 `reconnectSlurs` 与行首兜底之后）：
  两端挂到同一个音的不是弧（字的弯笔、符尾、点），两端都摘；系统中间只挂了一端的（`orphanEdge` 为 `mid`，写出端整条不写），
  缺的那端挂到弧端那一侧本行谱上头中心离弧端横向最近的音（3 格内，起端在止音左、止端在起音右）。破碎干净版 −2、扫描版 +2、是爱 −1。
- **歌词笔画按归属剔**（`pagefinish.ts`，`inCell`）：一块墨整个落在 OCR 认得出字的那行歌词的一个字格里（外放 0.2 格）、又不是占满整格的，
  是那个字的笔画，不进弧的候选（你的信实广大 m2「你」左上一撇挂成 E4→E4 延音线，m20「广」的一撇挂成 D4→C4）。
  只认读出了字的行（没读出字的「行」可能就是谱表上方一排小弧本身，破碎 p5 钢琴右手）；只认大小正常的格（高不过字号 1.15 倍、宽不过 1.3 倍：
  粘上旁边小弧被撑大的格不算，破碎 p7 m71 女低）；墨块宽高都占到格的九成的是格本身（OCR 把一条小弧读成了字）。
  按游程补认的弧也按它的墨在去线图上归谁判：大半落在歌词账上的块里记成歌词弧（离音远就不挂、按干放宽那遍也不给）。
- 读入端按时刻配起止（见[源格式-musicxml](../../模块/源格式-musicxml.md)「关键判据」）：GT 与识别稿的跨谱表弧原先都错配开一个，宁静读数里那几条「挪连线」其实是读入端的毛病。
- **后一条不从前一条的止音起，除非真贴着它**（`pagefinish.ts`，与原有「止端退回」那条对称）：一条止在 n、下一条从 n 起，
  而后一条左端越过 n 的头右缘半格以上、离 n 后面那个音的头比离 n 更近，起端挪到那个音（宁静 p5 m66、m68、m70 钢琴右手：
  前一条收在 B5，后一条从 B5 右边、正对着下一个 A4 起笔）。前一条两头同音高的不算（是延音线，延音线止在 n、圆滑线从 n 起是常规写法）。
  宁静 27→22。只按「越过头中心」挪伤了破碎四处（共用一个音的两条弧，后一条常从那个头的右半起笔）。
- **跨系统的弧是一条**（排版惯例：一条弧被换行截成两段，起止按整条记）：宁静 GT m97→m103 女高原先在换行处拆成两条，已照惯例改成一条（dev GT 修改记录）。
  试过反过来让识别迁就那份 GT（行末带跨行延音线时罩在上面的长弧止在末音），破碎 GT 正是整条记的，两边打架，撤了。
- **延音线按时间相邻判**：页内跨行接上的两截两头同音高，原先就判延音线，那条 E5…E5 长弧也成了延音线。延音线是同一声部时间上紧挨着的两个音，
  声部到写出端才定，所以位图路页内跨系统的同音两截一律先当圆滑线（`pagefinish.ts`），写出端（`toxml.ts::renumberSlurs`，`crossTies`）
  对起音是这个声部本系统最后一个音、止音是它下一系统第一个音的改写成延音线（跨页的半截原来就这么判）。
  试过在页内按「中间有没有音高相近、干同向的音」或「贴不贴着音头」判，都伤真延音线（破碎 m33→m34 后面还有另一声部的音、牵我的手行尾延音线离音头远），没留。
- **跨谱表大弧近竖的下半截**（同一个 `traceLongArcTails` 的长延伸）：宁静钢琴每小节一条的大弧常只认出拱顶一截，下半截近竖着一路下到低音谱表，
  去线、贴着音头符干的地方断开（p2 m17 第二小节、m19、m22）。续尾可以接着追到 15 格，但这段长延伸**只有落到另一行谱的音头跟前（1.5 格内）才采用**，
  否则退回追满 4 格时的落点。另几处配套：粗细沿走向的垂线量、线行的墨不算（近竖的线按竖向游程量是一长条；垂线近水平时斜穿谱线会顺着线量成一长条）；
  不越过本行谱第一个音头左边、最后一个音头右边半格（行首弧往左追会进谱号调号，宁静 m47、m75、m93 曾因此挂不上首音）；不许回头（横向掉头就是沿弧自己往回爬，
  m22 下截左端追到 C3 又绕回右手谱表）；路上碰到另一截同向弧的近端就并进来（下截追上去越过了上截左端，`bridgeArcPieces` 就并不上了）；
  追到音头 0.5 格内停（0.25 格时破碎 p12 有一条尾巴续过 B4 挂到 A4）。宁静 16→13，破碎 33→34。
  再续：路上擦过音头、符干（粗墨）照切线穿过去（连续不过 1 格），凡穿过粗墨的延伸也要按上面验收，不过就退回第一次碰粗墨前（与 4 格落点取较早的）；
  起步一格内垂线窗口放到 0.7 格（端头往里那段常已拐平，起步切线是平的，真弧在端头处陡着往下，m22 上截左端）；长弧下限 5 → 3.5 格（m23 上截只有 4 格宽）。
  宁静 13→9，破碎 34→35，破碎扫描 +2、是爱 +2。

### 虚线弧：等宽、等距、排成一线的短横划（`findRasterDashedSlurs`）

诗歌本里第二段起唱法不同的几处，圆滑线 / 连音线画成**虚线**（Holy, Holy, Holy 十二条）。每截只有 0.7×0.25 格，
单看是噪点；成串看才认得出：0.35~1.0 格宽、不高过 0.5 格、宽高比 ≥1.4 的短横划，相邻两截隔 0.25~0.9 格、
竖向错开 ≤0.35 格、宽度比 0.6~1.6，**至少三截、各间隔相差不过 0.3 格**。弧两头那截是斜的（8×5 像素，0.42 格高、宽高比 1.6），
形状闸按它放。两端那截常粘在符头、符干上或被歌词字格认去，所以候选是无主块**加上只被歌词认过的块**；认出来的多半只是中段，
端点仍落在两个音符之间，`attachSlurs` 照样挂得上。上方还是下方看近旁最近的符头（三格内）；离谱表四格半开外的不认
（歌词带里成串的连字符）。导出 `line-type="dashed"`（`StaffNote.slurDashed` / `tieDashed`）。
在其余 44 首独唱谱、合唱谱上一条都没多出来。还没认的：压在谱线上的虚线延音线（短划被谱线认走）、
两个声部的虚线弧上下叠着时上面那条判错边（离下声部的头更近），见本地私有仓库的待办「五线谱识别-独唱谱」「查了没修的」。

| 和弦字母（是爱） | 0/86 | 73/86 | 同上（文字带里读出来的和弦记号） |
| 力度 | 干净 34/54（53.0%）、扫描 31/169（14.6%） | 40/54（64.0%）、75/169（35.2%） | 同上（OCR 读出的力度补字形那一路漏的） |

GT 里没有八度记号、踏板、震音、cue 音符。

## 颤音

位图路字典认成 `wiggleTrill` 的块全是高约两格、宽不到一格的竖块（被谱线切下来的八分符尾下半截、琶音的一段：宁静 p3 m39、破碎扫描 p1 m7），
颤音的波浪线是横着走的。高过宽的 `wiggleTrill` 不挂成颤音（`pagefinish.ts`）；语料 GT 里没有颤音。

## 贴着符头的演奏法记号（`artic.ts`）

保持音、断奏、顿音、重音、延长记号都很小，单看形状与谱线残段、加线、歌词里的连字符、附点分不开——
形状字典里叫 `articTenuto*` 的那一类（193 例）九成是谱线残段，原先照 `attachNotations` 的「x 最近」挂上去，
六首平白多出 455 个保持音。现在这几样不走那一路，按**与符头的关系**判：

- **两侧都认**。头这一侧（符干的另一头）：对着头心（±0.4 格）、离头心 0.6~1.75 格。干这一侧：在干尖或符杠外缘之外 0.15~1.5 格
  ——人声谱的记号一律印在谱表上方，干朝上的音就落在这一侧；断奏点对着干，保持音对着头，横向放到「头、干之外半格」。
- **谱表里的要落在间里**（离最近的谱线不到 0.27 格的是谱线残段）；谱表外正在加线位置上的短横，同一列更外面还有头的是那个头的加线。
- **候选不止无主的墨**：钢琴谱表上方的断奏点、人声行下方的保持音常落在歌词带里被字格认领，字典认成附点却没挂上头的也算；
  歌词带里的要孤立（一格内没有别的歌词墨，字自己的点画旁边必有同一个字的笔画）。
- **断奏点不能贴着别的墨**（0.45 格内，音符自己的头、干、杠、谱线除外）：扫描件上手写简谱数字底下的低音点、弧线的尖、
  力度字母的收笔原先都成了断奏（破碎扫描版多出 21 → 1）。四周一格内另有无主小墨团的按噪点不认。
- **延长记号是一弯月牙加正中一点**，量外缘（拱朝上的看上缘，中间比两端高出半个盒高以上），不量中线——月牙中间厚两头尖。
  这个组合够特别，候选不限无主：粗月牙常被符杠那一路、歌词带认领过（爱是从神而来末页三个全是）。在松叶、弧线之前摘走。
- 尺寸从实测取：保持音 1.04~1.30 × 0.30~0.40 格，断奏点 0.34~0.44 格，顿音 0.43~0.53 × 0.64~0.80 格，延长记号的点 0.55~0.65 格。

还没解决的：跨谱表连杠（钢琴两行之间的杠）上下的断奏点（是爱 p5 七个）；重音「>」贴着谱线时与谱线并成一团（`seg:Staff`），
干尖外的大号重音离头太远；望十架第二份底本的保持音 0/6。

## 反复记号与房子（`repeats.ts`）

下游 `classifyBarlines` 靠「小节线笔画的线宽 + 谱表里成对的圆点符号」认反复，位图路两样都常缺。`makeBars` 之后回到图上量，
结果直接写到 `Bar` 上：

- **反复**：第二、三间各一个圆点、左右对齐，旁边一格内一细一粗两根贯穿谱表的竖线（与 `findDots::repeatPair` 同一组门槛）。
  点在线左是 `:|`，在线右是 `|:`；印在行首的 `|:` 记给第一小节。同系统有一行认出来，各行同 x 的小节线都算。认作反复点的圆点记进账本（`repeat:dot`），不再当断奏点的候选。
- **终止线按原图补**：粗笔横向游程超过「细」，进不了竖段，上下贯通大谱表（钢琴）的那根整根成不了小节线，细线就只记成普通线
  （破碎 p12 末系统、宁静 p9 钢琴两行）。细线右边一格内原图上有一道贯穿谱表（九成行有墨）、不窄于 0.3 格的竖墨，就记 `light-heavy`。
- **终止线、复纵线同系统拉齐**：有一行在这个 x 认出样式，没认出的各行照它。
- **粗笔的门槛**（`staffomr/barlines.ts`）：三分之一线距，与**整页**小节线笔画中位线宽的 1.8 倍取大（不按本行取：曲末的短行只有一两处小节线，中位数就是终止线自己）。粗线低分辨率页（烛光颂曲线距 10px、
  小节线 4px）原先每根小节线都过了三分之一线距，整首每行都是终止线。**代价**：合唱谱扫描档小节自检 69.34 → 68.3，全在烛光颂曲
  （34 → 27.6%）——原先的假终止线让 `markSplitBars` 把不满的小节当成「段落边上的半截小节」放过，那个读数是虚的。
  认了三连音之后扫描档回到 68.79。
- **房子**：横线不在线段表里（又长又细，取图时与谱线一道抹掉了），从竖钩顶端回原图往右量（≥3 格），横线厚不过 0.3 格（没挂上标记的符干顶端连着符杠也是「竖段顶上一道长墨」，符杠有半格厚），钩要对着一根小节线、
  钩顶离谱表 1.2~7 格、钩顶往左没有横线（第 1 房的线一直画到第 2 房的钩上，这种算上一房到此为止）。
  换行后接着的那一房印在行首，没有小节线可对，钩落在第一小节里就算（是爱第 2 房）。**钩底也往右拉着横线的是文字框**
  （宁静框住的 `Interlude`、排练号，原先出了两个假房子）。数字不认：前一小节右端是 `:|` 的是第 2 房；
  罩着的最后一小节以 `:|` 收尾的是第 1 房；都看不出、又印在行首的是第 2 房。同系统各行照抄。
  爱是从神而来、是爱的 `|: [1 :| [2` 都对上。

- **复纵线多认**（望十架 13 对 4）：一根小节线在扫描件里常断成上下两截、x 差一两个像素（p5 m42 689 / 690），
  `staffomr/barlines.ts::classifyBarlines` 原来按「x 差过 0.3 个单位就是新的一笔」算成复纵线，再经同系统拉齐扩到每一行。
  门槛改成 `max(0.3, 四分之一格)`：真复纵线两笔隔半格上下。望十架改小节线 50 → 2 步。

还没解决的：烛光颂曲的反复与房子（粗线页一粗一细分不开）。

## 带方括号的三连音（`tuplet.ts`）

四分音符以上的三连音不打符杠，画一条被数字断开的方括号。下游 `findTuplets` 要一个数字符号加两截横段，位图路两样都没有
（「3」不在形状字典里，括号常是斜的、两端带小钩，成不了横段）。按**结构**认：一个数字大小的墨块（0.45~1.2 × 0.8~1.6 格），
左右一格多之内各贴着一条细长的墨（长过一格、平均粗细不到 0.4 格），三样纵向排成一线；括号上下 6 格内那行谱、跨度里同一声部正好三个音才算。
数字不认字形。候选是无主的加上只被歌词带罩住的（括号常落在歌词带里），放在歌词之后跑。
爱是从神而来 21/24，别的五首一组都没多出；该曲小节自检 91.5 → 94.5%。没有括号、只在符杠旁印一个「3」的那种还不认。

## 文字指示、节拍器记号（`words.ts`）

与声部标签同一套架构：**只按固定几何裁带**（两行谱之间的整段空当、页首行上方与页末行下方各 7 格），定位与认字交给 DBNet + rec，
离线按条的内容指纹落盘（私有仓库 `gen-rasterwords.mjs` → `rasterwords.json`，六首 689 条带约 7 分钟），在线走 `ocrlive.ts::ocrWordStrips`。
带里还压着歌词、和弦字母、力度、小节号，按内容分：

- **只留拉丁文**：夹着汉字的是歌词或署名；至少三个字母（声部缩写 `S.` `TB` `Ch.` 之类另列）；整串都是力度字母的不算。
- **力度交回力度那一路**：行首是 `mp` / `mf` / `f`…、后面没有别的或紧跟汉字（歌词行行首的力度与头一个字读成一行，`mf夫`）的，
  按 `attachDynamicTexts` 补挂——三格内字形那一路已经认到的不重复。
- **英文歌词**：一行歌词被 DBNet 切成好几段，同一高度上排着三段以上拉丁文（歌词带里两段）就是歌词行，只留含术语的；
  术语前粘着的歌词剪掉（`paid so willingly poco rit.` → `poco rit.`）。试过「落在歌词带里就要含术语」：歌词条切得宽，
  谱表上方的 `Flute`、`delicately, freely` 也被筛掉，文字从 319 掉到 173，撤了。
- **和弦记号**：整行去掉空格后正好是和弦记号（`CHORD_TOKEN_RE`）。一页里至少三行、其中一行带后缀才认——
  否则排练号 `A`、`B` 与把谱号读成的单个字母都成了和弦。和弦带那一路（`harmony.ts`）认到和弦的页不用这一份。
- **词界**：rec 不出空格。逐字位置只有六分之一行高的精度（词内间隙 0~0.34、词间 0.33~0.5，分不开），改按字行的列投影：
  连着 0.17 倍行高没有墨就是词界。斜体字相邻字母上下错着，仍有粘成一个词的（`1sttimeSA Unison`），评测比对时不看空格。
- **叠着的两行并成一条**（`1st time SA Unison` / `2nd time Parts`）；rec 给元音添的重音符（`póco`）去掉。
- **归位**：定谱行按谱表边到字心的距离；定音符取字行左端右边最近的那个音。写出 `<direction><words>`，节拍器 `<metronome>` + `<sound tempo>`。
- **速度语与节拍器是一个对象**：DBNet 常把它们切成两行（`Allegretto semplicemente` / `= 104`、`Andante con moto` / `( = 82)`），
  各挂各的就成了两个 `<direction>`、还落到不同的音上。同一高度、横向空当不过 3 格的左邻拉丁行并进带等号的那一行（与矢量路
  `textanalyze.ts::attachDirectionTexts` 同一口径），速度语进 `tempoText`、与 `<metronome>` 写进同一个 `<direction>`。
  等号后认 `ca.` / `c.`（写成 `c. 76`）；等号前音符字形读成的 `J` / `d` 剥掉。印在圆括号里的（等号前紧挨左括号、或数后紧跟右括号）写 `<metronome parentheses="yes">`，矢量路同口径；编辑器读写这个属性、排版画成「(♩ = 82)」，评测把括号算进速度那一项。拍子单位只认四分——烛光颂曲的四分读成 `d`，字母分不出。
- **系统之间的字归下一系统**：文字指示、排练号、段落名印在它管的那个系统上方。落在上一系统末行下方、离下一系统首行不比离它远出 1.6 倍的，
  归下一系统（宁静 p5「Interelude」离上面钢琴左手 4 格、离下面 6 格）。
- **框字带**（`findFrameStrips`）：带里的方框（上下两条等长细横、两端竖边相连，框里贴边一圈全白、框外贴上下边一行基本空）另切一条，
  框里的字四周垫白单独送 OCR，指纹前缀 `F`。整条带两千多点宽，DBNet 常漏掉框里孤零零一个字母（宁静 p5 m73 `A`）；整条带里读出来的
  还把框边读成 `[`。框里的单个大写字母是排练号，不受短标记的字高、符干两道闸，也不算和弦（宁静 p7 排练号 `B` 与两个碎字凑够三行，
  整页成了和弦页）；和弦另要框高 1.1 格以上。扫描件里的假框（休止、括号边）靠「框里贴边一圈全白」挡掉。
- **页边截断的带照原高切**：页首行上方、页末行下方那条超出页面的部分填白（盒的 y 可以是负的）。贴页边截成 54 点高的窄带 DBNet 吃亏
  （破碎 p9 页顶「Soprano 1」只读出「Soprano」）。整条都垫白试过：页内的带多出一批谱线残段读成的碎字（`PFEFP`、`FRF`），没留。
- **碎字与英文歌词**：整行是拆开的单个字母（`e E R`，汉字歌词读成的）不收；后面拖着连字短横（字右边 5 格内一截孤立扁横，在字身中段）
  的是英文歌词的头一个音节（宁静 p8 `Glo - - -`），不收；词后单独一个小写 `l` 改成 `1`（破碎扫描版「Soprano l」）。
- **写出时挂到和弦打头的音上**（`staffomr/toxml.ts`）：文字、速度、力度挂在和弦里后写的那个头上，`<direction>` 落在和弦两个音之间，
  读回来成了打头那个音之后的时刻（破碎 m107 `rit.` 挪了两拍）——同松叶、歌词，收到打头那个音前。反过来，读入端（`model/fromxml.ts`）
  也把别人写在和弦中间的 `<direction>`（Finale 导出，牵我的手钢琴 m45 `f`）记到和弦起点，原先算成和弦的终点。

读数（2026-10-18，手动操作口径的文字档）：干净两份 52.38 → 100%（宁静 27.78 → 100、破碎 70.83 → 100）、扫描四份 52.66 → 57.63、
矢量不变。评测同时改了两处口径（`visual-ops.mjs`）：同一个 `<direction>` 里接连几段 `<words>` 连成一条（GT 把花体首字母 `A` 另写一段）、
小节级 `<sound>` 不计（谱面上不印）。宁静 GT 补两处漏记的框字、挪两个压在小节线上的排练号到下一小节头（见该曲 GT 修改记录）。

还没解决的：低分辨率页（烛光颂曲）读出一批碎字（`phen`、`feos`）；首行上方离谱表 7 格以外的节拍器不在带里（是爱「♩=94」，页眉带也没读出）；
`Fine` / `D.S. al Coda` / `To Coda` 只出文字、没出 `<sound>` 跳转属性，播放次序不跟；segno、coda 两个图形记号不认；
独唱谱那批没生成这份缓存（回归脚本不带 `wordOcr`，读数不受影响）。
