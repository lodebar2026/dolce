# 符干、符杠与符尾（位图五线谱识别）

> [位图五线谱识别](../位图五线谱识别.md)的分篇。

## 符干要**续到符头里**（`extendVSegs`）

竖笔画的判据是「横向游程细」，而符干与符头相接的那几行游程一下子变成整个符头的宽度
——竖段就在**符头边界前一两个像素**断掉（实测缺口中位数只有 **0.06 个线距**）。
而 `findStems` / `buildStems` 要的是符干与符头**纵向相交**，差一个像素就不成立：
实测破碎 2218 个符头里只有 642 个（28.9%）配得上符干，其余全读成四分音符；
符杠也因此接不上符干（层号 0 的占 304/1042），十六分整批读成四分。

修法是把竖段的端点**沿着墨往里续**，至多 0.6 个线距，碰到白就停。
只对竖段做——横段（谱线、加线）本来就该在符号处断开。

**续过的段只进 `SPage`，不回写 `prims`**：`blobImage` 按段的包围盒抹墨，
续进符头的段会把符头啃掉一条，符头就认不出来了
（实测直接在 `findPrimitives` 里续，小节自检 27.4% → 31.4% 但音符 65.1% → 62.5%）。

### 正好盖满谱表的竖段：续出去的要进了头、或笔直延续才留

`barlineCore` / `bandColumns` 取出的竖段两端正落在第五线、第一线上，照样往外续会沾上别的墨：
《我一生要赞美你》第六、七行，连线收尾弯进小节线下端，续出 5px（0.35 格），过不了 `findBarlines` 的
「出界端须落谱线」（0.3 格），两刀都漏了。可这一批里也有真符干——和弦的长符干正要靠续进上下两端的头伸出谱表，
才不被收成小节线：一律不续、或封顶 0.2 格，万古磐石歌都多切（两刀 / 一刀，后一刀是符杠下的长干，
上下各伸出半格、续 0.35 格碰不到头）。

所以续照续，续出的那截（跳过谱线本身那几行）满足其一才留，否则退回线上：

- **进了头**：有一行横向墨宽过 0.6 格；
- **笔直延续**：每行都有墨，墨段中心离竖段不过 1px、宽不过线宽加 2，**逐行中心的极差也不过 1px**
  ——连线收尾每行都离竖段不到 1px，却一路往一边偏（241 → 239.5），只看离竖段多远拦不住。

## 贴着小节线的符干：按「窄的那一段」重判孤立性（`narrowPart`）

二分头的圈边横向游程也细，进了竖笔掩模，与符干连成一块，块的最宽处（`maxLw`）被撑到 10px。
`isolated` 按最宽处开邻墨窗，伸到 26px：《我一生要赞美你》第六行那根离小节线 1.2 格的符干一路碰到小节线，
判成「不孤立」扔掉；头没了干，贴着头左缘的小节线随后被 `findBarlines` 当成它的干，那一刀又没了。

孤立性没过的块，取行宽不超过平均线宽加 2 的最长连续行重做中心线、重判孤立性，过了才收。另有两条限定，缺一不可：

- **原窗里要有一根盖满谱表的整列**（`barColumnNear`，带内 ≥95% 行有墨，即小节线）：
  直接按平均线宽开窗是全局改动，谱号、升号的竖笔也过了闸（赞美三一真神 94.0 → 55.4%、敬拜万世之王 93.3 → 27.8%）；
  只按窄段重判而不看小节线，破碎干净版满拍自检 64.8 → 58.2（只因某一行偏宽就触发、原本被别的邻墨判不孤立的块也放进来了）。
- **窄段至少 3 格长**：带上小节线那条限定后，破碎仍收进来一批 1.5~2.7 格的短笔（满拍自检 61.8）；真干约 3.5 格。

这一节与上一节、[符头与加线](符头与加线.md)的「全音符」「成摞整格」一起，把独唱谱小节数补齐到 **44/44**
（我一生要赞美你 34 → 39/39、音符 79.8 → 90.3%），独唱谱音符 86.63 → **87.25%**、时值 79.77 → 80.25%，
没有一首音符掉（有一位神 77.5 → 81.7%、齐来崇拜 83.6 → 87.9%）。
像素一变歌词 / 和弦缓存按指纹失效，重跑 `gen-rasterlyrics`（三档）与 `gen-rasterharmony` 后，
独唱谱中文歌词 46.46 → 71.72%、和弦 66.2 → 89.6%——原先的缓存本就陈旧，那两档此前是虚低的。

## 假符号会**吃掉整小节**，进而抢走第一声部

一个符号误检不只是多出一个音。**全音符与全休止恰好占满一小节**：
`checkFull` 于是把整小节读成「一个长音 + 另一路旋律」，`splitVoice` 按「上面的在前」
把那个假符号排成**第一声部**，真旋律整条被推到第二声部——而逐声部对拍只取
声部号最小的那一路，那一行的音就全落在分母外了（实测宁静一首因此掉 1.8 个百分点，
27 个谱行被拆出二、三声部）。**看音符准确率时要连声部数一起看。**

两头都要修：

- **`splitVoice` 加一道**（`staffomr/notedata.ts`，两条路共用）：
  **层里只有一个和弦、且它自己就占满一小节**的，不算一个声部，并回第一声部。
  真正的「一个声部整小节长音」当然存在，但那时另一层也不会是孤例。
  试过另一条「每层都要正好凑满拍号才认拆分」，**不起作用**——
  `checkFull` 成功之后各层本来就凑得满，那条判据分不开真假。
- **空心符头收紧**（见[符头与加线](符头与加线.md)的「空心符头：宽高比 + 谱表带」）。

## 抹符杠**只抹它自己那条带，不抹包围盒**

`blobImage` 原来照符杠的**包围盒**抹墨。符杠是斜的、还常常两三条叠着，
包围盒比它本身大得多——照盒抹会把**贴着符杠的符头一起抹掉**：
实测宁静 p8 那段十六分连桁，**一半的符头因此认不出来**（裁图上肉眼可数）。

改成沿中心线逐列抹，厚度取这一块的平均厚（`lw`）加余量。余量扫过 0 / 1 / 2 / 3 px：
音符 70.83 / 71.53 / **71.59** / 71.46%——太小会留下符杠残渣混进符号块，太大又开始啃符头。

| | 音符 | 音级 | 小节自检 | 按 staff |
|---|---|---|---|---|
| 照包围盒抹 | 70.25% | 71.33% | 50.68% | 73.12% |
| **沿中心线抹** | **71.59%** | **72.61%** | **50.93%** | **74.59%** |

临时升降也跟着从 78.3% 涨到 **81.0%**（符头认出来了，紧挨它的记号才挂得上）。

## 符杠也要**沿 x 闭一道**——它被符干切碎了

符干穿过符杠的那几列横向游程很短，出了「横向游程 ≥ 一个线距」那道闸，
**符杠于是被每根符干切成小段**。实测你要等候 p2 一条符杠碎成 1.33~1.65 格的六截，
`w ≥ 1.5 格` 那道闸挡掉大半——整页 199 个符头只认出 44 条符杠。
**音符排得密的谱子尤其吃亏**：段越短越过不了闸。

与横笔画那条闭运算是同一个道理（谱线被符干断成十几截），半径同样取两个线宽
——符干就这么粗，再大会把相邻两组的符杠连成一条。

这一条是时值的**头号修复**：逐符号量的时值 79.4% → **89.7%**，
`16th→quarter` 从 249 处降到 18 处。

## 符尾：按位置自举，不查字典

字典对符尾没用：`rasterglyphs.json` 里 4144 个类**没定名**，符尾只有 8 个类有名字。
更要命的是符尾在位图上**根本不成为独立的块**——它上半截是根粗竖笔、横向游程短，
`findPrimitives` 当竖笔画抽走了；剩下的钩尾细而弯，落在窗口里的残块高度中位数
只有 0.53 格（真符尾有一格半）。

所以改从**原始像素**上量，绕开原语划分（`recognize.ts::bootstrapFlags`）：
符尾一定长在符干**远离符头的那一端**、一定在符干**右侧**（刻谱通例，朝上朝下都在右）。
量那个窗口里的墨占比——实测没有符杠的音符里，占比要么是 0（真四分）、
要么明显高出一档，中间几乎没人。

**窗口要贴着符尾的实际宽度。** 这条踩过一次：窗口原来放到符干右侧 1.5 格，
而这套底本的八分符尾是**一条细弧**——从符干尖端斜挂下来，横跨只有 0.9 格、
每行才两三个像素（实测破碎 p2 x453 那个八分，符尾占 x453~468、纵跨 2.7 格）。
窗口比符尾宽出一半，占比就被空白摊薄到 0.20、卡在 0.25 的门槛外，
**整页 172 个实心符头只补出 4 个符尾**，八分整批读成四分。
收到 1.0 格、门槛跟着落到 0.18 之后：时值 89.4% → **92.1%**，
`eighth→quarter` 由 309 处降到 **191** 处。
扫过 0.8 / **1.0** / 1.3 格：时值 92.1 / 92.1 / 90.9%；
门槛扫过 0.10 / 0.14 / **0.16~0.18** / 0.20 / 0.22 / 0.25：91.9 / 92.0 / **92.1** / 92.0 / 91.0 / 89.4%。
纵向反过来**不能放长**：放到 2.5 格（罩住整条符尾）更差，符尾下半截是根细线，
多罩进来的全是白的。

三条限定：

- **有符杠的符干不看**：符杠也横在这个窗口里，一量必中；而符杠那一路已经把层数
  算进时值了，再补个符尾反而把十六分压回八分（`buildStems` 里「有符尾的符干不接符杠」）。
  符杠斜着搭在符干中段的也算，不只远端那一小截。
- **符尾要从符干尖端长出来**：贴着远端那一小截、紧挨符干右侧必须有墨。
  没这一条，从旁边路过的连音线、下一个音的符头都会把窗口填满。
  这一档的门槛**另设、而且松得多**（`FLAG_TIP` 0.05）：符尾在尖端是**贴着符干**走的，
  而窗口从符干右侧 0.15 格外才开始数——拿整窗的门槛卡这一截，真符尾一个都过不去。
  这条闸要的只是「符尾确实从尖端长出来」，不是「这里墨很多」。
- **只看实心符头**：空心符头本来就不带符尾，给它安一个会把二分读成八分。

**第二道钩**（十六分）沿符干再错开约一格，另量一次；门槛比第一道严
（那一段窗口里还可能扫到下一个音的符干或符头）。

层数的判据有三路，满足一路就算两道钩：右缘轮廓两个峰、贴干那一窄条里墨分两段，以及**逐列竖扫黑白游程**（用户提示）：
在干右侧 0.2–0.6 格内，每一列都从干尖往头的方向扫，数这一列上有几段黑。
谱线行不计；隔不到 0.15 格的白不断开，薄于 0.15 格的去线残渣不算一段。能数出两段的列占到 1/4 以上，就是两道钩。
低分辨率放大的万古磐石歌，两道钩在干边粘成一段，右缘又对齐，前两路都判不出来；但离干 0.3 格的竖线还是会穿过两道钩。
八分在这一带全是一段，实测八分这一项为 0、十六分 ≥ 0.4。
扫到 0.8 格就不行：八分长尾回弯的尖也会被数成第二段，信心使我得胜整页 0.27–0.4。
残渣的厚度下限也要有：去线后留下的 2 像素横条会被数成一段。

**钩粘住干尖**：钩和干尖粘成一团时横游程太宽，干只认到钩团之前，少掉 1–1.7 格
（万古磐石歌低音谱表）。这时干尖处的窗口是空的，或者朝头那边只剩 0.7 格。
办法是顺着干那一列往外走，直到墨断（上限 2 格）；延出 0.5 格以上的，从真干尖再找一次符尾，再竖扫一次判第二道钩。
延出的干尖只用在这两处：普通八分的干尖本来就埋在钩里 0.6 格上下，全按延出的干尖出块、判一道钩，整批位置都会错（信心使我得胜音符 97.8 → 96.7）。
这两条合起来，独唱谱时值 95.99 → 96.18%：万古磐石歌 92.0 → 97.7，来敬拜荣耀王 96.6 → 98.9，其余不动。

> 符杠闭运算补上之后，符尾的检出数**大降**（你要等候 190 → 55、破碎 186 → 27）
> ——原先那些多半是在给**漏掉的符杠**背锅。两条一起上才对：
> 先把符杠找全，剩下真正带钩的才是符尾。

## 符尾围出来的「空心头」不要

干朝下的八分音符，干底向右弯回的符尾围出一个内腔，按内腔找的几路把它收成空心二分头
（所信有根基低音谱表每小节多一个 A2 / F2 二分）。判据：**一根干只在一端挂头**，
空心头贴着的那根干，另一端挂着实心头，这个「空心头」就只能是符尾，剔掉（`recognize.ts`，定稿 `syms` 之前）。

- 干被符头、谱线切成几段：同 x、缺口不到一格的先接成一根；接完仍可能只剩贴着符尾的那一截
  （上半截不在竖段表里），所以**在原图上沿干那一列往两头走墨**，取离它远的那一端
  （剩下那截两端离它都近，按近端判方向会判反）。
- 远端的实心头要离它 **2.8 格以上**（符尾到干那端的头 3.5~4 格；两格上下的是和弦里另一个头，
  来敬拜荣耀王加线上的空心头被误认成实心，按「远端有实心头」会把上面那个真空心头剔掉）；
  还要在谱表首末线 **2.5 格**以内（齐来崇拜：干的墨顺着断口接进下方歌词，「能」字的笔画被认成过实心头）。
- 远端距离**不设上限**：试过卡 5 格挡「顺着紧贴的小节线走过去」，所信有根基反掉 0.9，那处的病因也不是它。

所信有根基 81.4 → 84.5%、坚固保障 94.4 → 97.2%、信心使我得胜 +0.8、万福泉源歌 +0.8；独唱谱合计 92.15 → 92.36%。

## 抹笔画的宽度按**平均厚**算，不按块的包围盒宽

`prims.ts::blobImage` 原来照 `maxLw`（= 那一块的包围盒宽）抹墨。笔画中途鼓出来
一段的时候，`maxLw` 就是那一段的宽度，照它抹等于把整个符号铲掉——实测破碎 p2
钢琴行那个**四分休止**，下半截（细钩 + 一坨）过得了「横向游程短」那道闸，
被抽成一条 `lw` 3.1 / `maxLw` **11** 的竖段，一抹连带把上半截也带走，
去谱线图上明明是完整的一个休止，送去找块时只剩上面 0.76×0.99 格一小片。
改成按平均厚的两倍封顶（`PAD_LW`）：按谱行 92.19% → **92.31%**。
扫过 1.5 / **2** / 2.2 / 2.5 / 3 格：92.29 / **92.31** / 92.31 / 92.25 / 92.19%。

**根子上还得让这条竖段压根抽不出来：竖笔画的长度下限从一格提到 1.4 格。**
那个休止的下半截只有 1.1 格高，而真符干至少一格半（连桁里最短的也有两格）。
按谱行 92.31% → **92.59%**、**真扫描件 29.6% → 31.0%**——
两档同向涨，与下面「收宽度闸」那条正好相反：
**长度**分得开符干与残段，**宽度**只分得开底本的粗细。
扫过 1.0 / 1.1 / 1.2 / 1.3 / **1.4** / 1.45 / 1.5 / 1.6 格：
按谱行 92.31 / 92.31 / 92.33 / 92.46 / **92.59** / 92.59 / 92.33 / 91.99%，
真扫描件 29.63 / 29.66 / 29.91 / 30.99 / **30.99** / 31.03 / 31.03 / 31.03%。

> **顺着这条往下收竖笔画的宽度闸，干净档更好、扫描件塌了，所以没收。**
> 把 `c.bbox.w > thin * 2` 收到 `thin * 1.4`：干净档按谱行 92.31% → **92.74%**
> （扫过 thin 的 1.0 / 1.2 / 1.3 / **1.4** / 1.5 / 1.6 / 1.8 倍：
> 91.90 / 92.27 / 92.62 / **92.67** / 92.61 / 92.61 / 92.34%，`PAD_LW=2` 之下 92.74%），
> 可**真扫描件从 29.6% 掉到 19.8%**——那一档的笔画本来就粗（线宽 5.1px），
> 闸一收符干整批抽不出来。改成按线距封顶（`min(thin*2, 线距*0.4~0.5)`）也一样：
> 干净 92.49/92.76%，扫描件 23.2/22.5%。
> 换句话说「这条竖笔画有多宽才算笔画」**得跟着底本的形态走**，一个常数罩不住两档；
> 真要收，得先按 `raster.kind` 分档，那是另一件事。

> **另一条试过更差的：竖笔画不许「中途鼓包」**（`包围盒宽 > 平均厚 × K` 就判否）。
> 想法是「真符干通体一样粗，休止的钩不是」，实测 K = 1.6 / 2 / 2.5：
> 按谱行 71.1 / 78.5 / 81.8%——真符干的包围盒宽本来就远大于 `area/高`
> （掩模闭运算过、块里还常常并着相邻的一条），这个比值分不开两者。

## 扫描件粗加线不能当符杠擦

2026-09-06，`prims.ts::findPrimitives`：符杠掩模的厚度下限从 `space * 0.25`

## 半截符杠（`partialBeams`）

附点八分 + 十六分那种，十六分一侧的第二道杠只有一个头宽（1 格左右、0.5~0.7 格厚），过不了符杠「≥1.5 格、3:1 往上」的闸，
被当成实心符头挂在干上：《倚靠主永远膀臂》整曲的十六分都读成八分，还凭空多出一个高音。

它的位置是死的：贴着一条已认出的杠的**端头**、隔一道白缝、与杠平行、厚度相近、与主杠在**同一根干**上。
`findPrimitives` 末尾沿每条杠两端 1.6 格内逐列往上下两侧走：跨过杠本身、跨过 1px~0.6 格的白缝、再遇到一段厚 0.6~1.6 倍杠厚的墨，
这一列算数；从杠端（容 0.4 格）起连续够 0.5 格的收成一截杠，交给下游与整条杠一样用（抹墨后不再成头，挂干时多数一道杠）。另卡：
- 高 0.3~0.8 格：薄的是弧线、字的笔画；
- 杠端附近有一列从主杠连墨到这一截（干穿过那道白缝）：挡住杠旁边路过的别的东西；
- 落在已认出的杠上的不算：十六分那组两条杠都是整条，从第一条往外走就撞上第二条（流血歌两处读成 32 分）；同一截只收一次。
- 半杠被谱线横穿时，去线在它中间啃出一两行白：墨段先按连着的判，不合格再容一个线宽的断口数一次
  （只用后者，墨段越过断口连上后面别的墨，原本合格的反倒超厚，倚靠主 −2.9）；
- 厚度基准用这一列实际跨过的杠厚（斜杠的平均线宽估得偏薄：当我们回到天家 5.96px，实际 8~10），
  但夹在平均线宽的 1~1.7 倍（杠外侧连着别的墨时会量大）；
- 上下缘取各列中位数：杠里的白洞会让个别列读岔，min/max 会把盒拉过 0.8 格。
  这三条让当我们回到天家时值 82.5 → 85.7%、倚靠主 89.9 → 90.6%，合唱谱扫描档音符 −0.03。

## 贴着叠置空心头的干：**顺着头缘的墨柱补**

三度叠置的空心和弦，朝下的干左侧贴着两个头的圈（赞美三一真神第二行 m5 的 F4/A4 附点二分），
一半以上的行有邻墨，`findPrimitives` 的孤立性判它「属于某个符号」，不出竖段；干没挂上，二分读成全音符。
全语料「二分读成全音符」52 处，这是其中一大类。

`recognize.ts` 在建 `SPage` 前补一步：已判为二分、头缘两倍线宽内没有竖段的头，从头心沿头缘找最长的墨柱
（`notehead.ts::inkColumn`，与加线那一路同一个），伸出去 2.5~7 格的当干补进 `inkStems`；
两端都压在首末线半格内的是小节线，不算。只管 `noteheadHalf` 与 `noteheadBlack`：全音符旁边的墨柱多半是小节线或邻音的干。

**实心头同样补**（按视觉病因排查时「符头：没找到干」45 处里所信有根基占 16）：干朝上的八分三度，
细干上端连着符尾、下端连着叠头，一样过不了孤立性。放开实心头后独唱谱时值 91.05 → 91.33%
（所信有根基 +4.4、万古磐石歌 +2.8、有一位神 +2.5），向主唱新歌 −0.9、救主降生 −0.8；
合唱谱干净档音符 +0.11、小节自检 +0.54、歌词 −0.1（一个字），按接受记。
补上干之后二度错排的附点和弦要跟着修两处（见 [五线谱识别](../五线谱矢量识别.md)「附点」），否则恩友歌 −3.8。

## 挂头只留正经一侧（`notedata.ts::buildStems`）

朝上的干贴头的右缘、朝下的贴左缘；贴在反侧的是二度和弦错开的头。相邻两个十六分挨得近时，后一个头的左缘也落在前一根
朝上的干旁边，被前一根干当成错开的二度收走、并成一枚和弦。一个头挂上了两根干、其中一根在正经一侧的，从反侧那根上摘掉。
挂头窗口与 `findStems` 打 Stem 标签同口径（1/4 格，两倍谱线粗兜底）：粗线扫描件头盒右缘离干 4.5~5 像素，
只按 1/4 格（4.7）挂，干标上了 Stem、头却没挂上，落单并进邻头的和弦。合唱谱扫描档音符 +0.6、满拍 +4.5。

## 墨柱补干按头侧方向（`recognize.ts`「找不到竖段的二分头」那段）

原判据「头缘两倍线宽内有竖段」就跳过；可那根竖段若在头的反侧（左缘上往上伸、右缘上往下伸），是邻头的干。
这时按头侧方向找自己的墨柱（`inkColumn(…, sided)`：左缘只量往下、右缘只量往上）。一端扎进符杠的墨柱不当小节线
（底线上的头、干顶到首线上方的杠，两端也正好压着首末线）。代价：两声部共干的头（你的信实广大 m2）补出的干与上段连成
一根长段，没标成 Stem，丢了尾。

## 挂在杠上的干（`prims.ts::beamStems`）

孤立性量程按整段最宽那一行定，干头相接处一撑，量程超过一格，夹在两头之间的干两侧过半行有邻墨，抽不出来
（放宽量程伤谱号、升号竖笔，见「现状与待办」阈值冲突表）。换个特征：干一定挂在杠上。沿每条**已挂着竖段**的杠
（一根都没挂的多是粗体四分休止的斜笔，主我敬拜你 m8）逐列从杠的上下沿往外走，谱线行允许断开，连续伸出 2 格以上的列并成一束，
束宽不过细笔上限、离已有竖段半格开外的补一根竖段。两端各放 0.3 格（杠的中心线拟合常收不到端头那根干）。
合唱谱扫描档音符 +0.15，独唱谱音符 +0.03。

## 跨谱表书写的音不算这一行的声部（`markCrossStaff`）

钢琴左手的琶音常升进右手谱表：符头画在上面那行，符干一路伸到下面那行、与那边的音共用一条符杠。照符头所在的行归属，
这些音就混进右手的旋律——一小节多出四五个音，凑不满拍、声部也拆不开，逐声部对拍时右手那行整段错位
（是爱 p4、p5 各有一个系统多出十来个音；宁静的伯利恒也有）。

同系统上下相邻的两行之间，三样都合才标 `crossStaff`：

- 符干五格以上、远端过了两行之间的中线（上面那行的头干朝下，或下面那行的头干朝上）；
- 那条符杠上另有相邻那一行自己的音——光凭干长，下加线上的长干音也会过中线；
- 那个音是**实心头**。空心头不上符杠：爱是从神而来 p4 上行下声部的杠落在两行之间，下行二分和弦的干正好顶着它，
  不加这一条上行那两组八分被当成借地方写的（92.7 → 91.9%）。

标了的音声部号另记（5），不参加这一行的凑拍与分声部（`checkBars` 滤掉），音高仍按符头所在那行的谱号读。
按谱行：是爱 84.8 → 85.9、宁静 97.5 → 98.0，干净档小节自检 88.62 → 90.48；独唱谱 45 首不变。

没解决的另一半：右手那行自己的上下两个声部（上声部长音朝上、下声部八分朝下）凑不满拍时拆不开，下声部的音仍排在主旋律里
（是爱 p4 首系统还多 8 个）。`assignVoicesInBar` 要两个声部都正好凑满才拆，放宽成只要一个凑满以前试过更差。
