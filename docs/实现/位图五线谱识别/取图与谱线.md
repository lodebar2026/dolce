# 取图与谱线（位图五线谱识别）

> [位图五线谱识别](../位图五线谱识别.md)的分篇。

## 取图：`rasterpage.ts`

**不复用 `src/omrkit/decode.ts`。** 那条是给简谱光栅路写的，两点不合用：
它靠 `OffscreenCanvas`（浏览器专属），而本模块要能进 `src/cli/index.ts` 那条纯 Node 链；
它把整页缩到 `PDF_W = 2000` 宽，而合唱谱原始就是 1917 宽、线距 18px，
再缩一道符头与谱线就分不开了。**位图路按原始像素识别，一格都不缩。**

pdf.js 在 Node 下对这批 ImageMask 直接返回逐行 1-bit 打包的字节，
解包即可——**不需要 canvas**。

拼页眉（`pagecompose.ts`）要读文字层，pdf.js 的 `getTextContent()` 用 `for await` 遍历 `ReadableStream`。
**桌面版的 WKWebView 没有流的异步迭代器**（新 Safari、Playwright 的 WebKit 都有，网页版和回归测不出来），
破碎干净版拖进桌面版就报「undefined is not a function (near '...i of e...')」。
`pdf.browser.ts::openPdf` 加载 pdf.js 前补上这个迭代器；以后再用新的流/迭代 API 也要想到 WKWebView。

### 三种数据形态靠**数据长度**分辨

`ImageMask` 根本没有 `kind`，而长度是三者唯一都给得出、且互不相同的量：

- **ImageMask**（无 `kind`）：逐行 1-bit 打包，置位 = 盖住 = 墨。干净位图那一档是它。
- **`kind: 1`（GRAYSCALE_1BPP）**：同样 1-bit 打包，但置位 = **白**。Xerox 扫的那份是它。
- **`kind: 2/3`（RGB/RGBA）**：每像素 3/4 字节，先算亮度再 Otsu。JPEG 扫的那份是它。

认错**不报错**，只得一幅噪声——这正是要防的那种静默失败。
所以取完按墨迹占比自检一次极性：整页乐谱的墨不可能过半（实测约一成），过半就整幅取反。

## 不做几何变换（`rasterpage.ts::rasterizeImage`）

识别用的图**原样交给下游**：不推平、不纠斜。整像素的推平与错切会给横笔造台阶、在行间重复或跳过行，
细加线、附点、窄内腔跟着变形，交出的坐标也对不回原页面（叠加层、源谱版面档按位图坐标折回页面）。
弯、斜的谱线由下游按**曲线谱线**处理（见下「找谱线」「曲线谱线怎么用」）。

以前的做法（整页纠斜 `deskew`、逐列游程推平 `dewarp.ts`、纠斜后逐行再推平 `levelStaves`）已删；
去掉它们、下游仍按水平直线读的那一刻（P0），独唱谱音符 98.03 → 66.00%、新编 124 首整页一行谱都找不到——
下游对「谱线水平」的依赖就有这么深。

### 灰度底本走 **Sauvola 局部阈值**，不走全局 Otsu

`rasterizePage` 三档数据形态里，**只有 `rgb` / 灰度那一档有阈值可调**——
`mask`（ImageMask）与 `gray1`（GRAYSCALE_1BPP）本来就是逐行 1-bit 打包的，直接取位。
这批语料里：干净底本几乎全是 `mask`；扫描件里**破碎是 `gray1`**（粗线是烧进去的，
没得调），**望十架那三份是 `rgb`**——它们原来走全局 Otsu。

一页里墨色深浅不匀（装订侧偏暗、页心偏淡），一个阈值要么把淡处的细线切断、
要么把暗处的笔画糊粗。望十架线距只有 11.5px、符头才 8px 宽，粗一两个像素
就并进谱线里。换成 Sauvola（`T = m · (1 + k · (s/R − 1))`，积分图 O(n)）之后
望十架线宽 2.6px → **2.4px**、web 版 3.0px → **2.2px**。

`k` 扫过 0.2 / 0.34 / **0.5** / 0.6 / 0.65 / 0.8（`k` 越大收得越紧）：
扫描件音符 50.40 / 53.40 / **54.43** / 54.33 / 53.29 / 36.16%，
小节自检 21.72 / 23.76 / **31.00** / 32.27 / 35.20 / 31.99%。
0.2 反而把笔画**加粗**（2.6 → 2.9px），0.8 已经把笔画切断。
0.65 的小节自检更高（35.2%）、歌词也更好（44.5%），但音符低 1.1 个点，取 0.5。

> **换二值化必须重跑歌词与标签缓存**：两者都按**条的内容指纹**寻址，
> 二值化一动指纹全变、缓存整份落空——k 扫的过程里歌词一度显示 23.33%，
> 那是缓存没命中的虚低，重跑之后是 42.91%。

干净档一分不动（那一档是 `mask`，根本不过这条路）。

### 分档按**底本的数据形态**，不拿「线宽/线距」当代理量

`chorus-diff` 原来按 `lineThick <= space * 0.2` 分「干净位图 / 真扫描件」。
那个比值随谱线判据一动就翻：实测主，差遣我（线距 11.5px、线宽 2.3px）正卡在门槛上，
改一条谱线判据就整份从扫描档跳进干净档，把干净档的平均从 71% 拖到 55%——
**度量本身在跟着改动漂**。改用 `RasterPage.kind`（`mask` = 排版软件贴的 1-bit ImageMask、
`gray1`/`rgb` = 扫描件），那是底本的事实，不随识别改动。

## 找谱线：按逐列游程，不用行投影（`stafffind.ts::findRasterStaves`）

谱表在**任何一列**上都是「五段黑（线）夹着四段白（间）」，四段白几乎等长、五段黑几乎等厚——这个规律与页面斜不斜、弯不弯
**无关**，因为它是逐列量的。行投影要「一整行几乎全是墨」，2000 px 宽的页斜 0.5° 两端就差一个线距，横带抹平；
图不推平之后行投影这条路走不通，整个换掉。

1. **逐列五连**（`columnHits`，每 4 列取一列）：黑游程五连、四个间距彼此差不过两成二、每段黑不厚过 0.45 格。线距上限随页面长边放
   （`max(40, 长边/50)`：是谁那张 4958×6600 的图线距 50 像素，固定 40 的上限一列都凑不出）。
2. **串成轨迹**（`buildTracks`，相邻取样列中心差不过半格；谱号、调号、密集符杠遮住的几格宽可以跨过去），
   被密集音符隔断的几截按自己的走向外推接回（`joinTracks`）。
3. **并成谱行**：轨迹按量到的列数从多到少收；与已收的横向重叠、纵向不过 2.5 格的是**错开一条线凑出的假五连**（加线、符杠凑的），丢掉；
   横向不重叠、中心差不过一格的是同一行谱断成的另一截，并进来。量到的列数不到页宽取样列的一成二（至少 16 列）的不算。
4. **线位**：每条线的常数 `y` 取各列实测的中位；随 x 的偏移五条线共用一条（各列五条线偏移的中位：单条线的采样被符头、符杠带偏，
   五条一起量才稳），量到的列之间线性插值，两头按整段斜率（两两连线斜率的中位数）外推，再滑动中位（9 列）压掉单列的跳变。
   左右端内起伏不过 1.5 像素、整体偏移不过一像素的行不挂曲线（照常数 y 走）。
5. **左右端**：从轨迹两头沿曲线逐列往外验墨，五条线里四条以上有墨的列算谱线还在，断口容半格；
   **端点要连着一格有墨才算**——系统的花括号、乐器名擦到谱线那一带，不能一擦就把左缘拉过去
   （老行投影那一路实测宁静 p1 十行谱里六行的左缘跑到 x=2，`makeSystems` 判系统线、`makeBars` 切小节全跟着偏）。
   **虚线谱行**（扫描件谱线断成一截一截、各条线的断口错开）逐列看常常只有两三条线有墨，左端一路退到谱号后面：
   新编 026 第四行退到 268（别的行 190 上下），按左端开窗的系统线判据（`bridgeFaintSysLines`）罩进下一行的谱号，两个系统并成一个（音符 31%）。
   每条线看左右半格的小窗再走一遍，走完往里退过竖笔（系统线、方括号）与空列，比逐列走得远出两格以上才用——实线的端点一像素不动。
   试过只开四分之一格的窗（f07 那页断口宽，窗盖不住）、走到竖笔就停（谱号的竖笔也挡，f07 左端停在谱号右边）。
6. **单位**：线距取各行谱线距的中位，线宽取五连各段黑平均厚度的中位（取整）。`estimateUnit` 就是它，不再先错切一个副本量。

不靠「全页白游程的众数」量线距：原 C++ 工程 `omr/pixel.cpp::findUnit` 那样做，这本书上白游程众数落在 3~5 px
（符头内部、歌词笔画之间的小空隙远多于谱线间隙），真线距 17~19 px。这里要求**五连等距**——歌词笔画凑不出五段等距的黑白相间。

行投影那一路攒下的几条补丁随之退役：四条等距缺一条的外推、散线凑行、通长加线顶掉第五线（`groupStaves` 的「左缘一致」）、
没成组的长横线当加线（`sharedLegers` 现在只吃 `prims.hSegs`，通长加线本来就在横段里）。

## 曲线谱线怎么用（`staffline.ts`）

- `StaffLineRun.curve`（`LineCurve`：每 4 列一个偏移）、`lineYAt(l, x)`：线在 x 处的 y。
  **五条线共用一条偏移，不逐线拟合**：独唱谱 45 页量过，每行谱左右两头的线距差都不到 3%（页面透视可以不管），
  共用偏移推出的线位与逐列实测相比 95%、99% 分位都不过 0.07 格（一个像素上下，就是取整的量级）。
- `localLineCenters`（去线、补线、按游程去线共用）以曲线为种子逐列找线心；不挂曲线的线走原来那份代码，逐字不变。
- `LineGrid`（全页谱线网格）：`onLine(y, tol, x?)`、`ledger(y, x?)`（加线位置，按每行谱自己的线距往外推）、`bands(x?)`。
  判据里原先的 `gridYs.some(...)`、`ledgerGrid(gridYs)` 都换成它；收 y 的判断函数一律改成 `(y, x?)`，调用处补上 x。
- 音高吸附 `makePitchGrid` / `makePitchSteps`、加线候选 `ledgerCandidates` 按 x 取第一线往下数。
- 读音高（`Staff.middleStep(y, x)`）、谱号调号窗口用 `Staff.lineYsAt`：曲线上再叠桶内实测的整体平移（`localLineModel`）。
  `Staff.topAt(x)` / `bottomAt(x)`：小节线两端、系统线、`barvote.ts` 补线都按竖线所在的 x 取；矢量路没有 `lineYsAt`，退回包围盒，不受影响。
- 别处按 x 取线位的：休止位置（`restshape.ts` 的中线、外线、挂线判据）、附点（`findDots` 收按 x 取五线的函数）、
  头模板分「骑线 / 在间」、`contour.ts` 的谱表三分区与松叶的「在谱表里」、`findStaffForNote`（按音符 x 取首末线）、
  竖段接续与贯穿小节线（`extendVSegs` / `joinThroughBars` 收按 x 取首末线的函数）、加线链、短干两端、杠端小节线。
  只看行首几格的（谱号自举、调号区、拍号列、行首谱号窗口）取左缘往右二到四格处的线位；系统括号、花括号、按左端分系统取左端的线位。
  带一格以上余量、只是粗分「在不在谱表近旁」的范围判断仍按名义线位（斜不过一格，碍不着）。
- 弯、斜谱行用 `liftOf(line)` 拿到一个 `lift(x)`（x 处相对名义线位的偏移），文字条、简谱带都靠它随谱线走，见下一节。

### 文字条随谱线走

页面斜 1.7 格（独唱谱实测最大，45 页里 29 页起伏过四分之一格）时，相邻两段歌词只隔 1.5～2 格，
按原图的 y 切带、断行会串行，整行裁成水平矩形条子要高出一倍、罩进上下两段词。各条按用途分三种接法，**平直的谱行一律逐像素不变**（缓存照样命中）：

- **歌词**（`lyric.ts`）：块按所在 x 处的谱线偏移拉回谱表中段的高度再切带、断行（`findLyricRows` 里的 `level`），出字格时挪回原图。
  两行谱之间的偏移按高度在上下两行的曲线间插值（倚靠主永远膀臂第三行起伏 15px、下一行 5px，全按上一行拉，夹在中间的三段词切不开）；
  拉完再量**带里字自己还斜多少**（`textSkew`：试 ±3% 的斜率，取块盒纵向覆盖剖面平方和最大的那个，要比不斜高出一成才认），
  纸面卷得不匀时歌词与谱线各歪各的（同曲第一行谱下的词往右下斜 11px、谱线却往右上翘，按谱线拉反倒斜到 15px，歌词 83 → 39，修完 83）。
  只拿块心分箱量过：偏旁、标点、段号的中心乱跳，各斜率得分拉不开。行上挂 `lift`（插值偏移加斜度），`stripOf` 裁条时**逐列按偏移整像素上下挪**，
  不插值，条里的笔画与原图逐像素相同。整行几十个字，斜着送 rec 认不好，所以要挪平。
- **和弦**（`harmony.ts`）：带底贴着顶线、还要按顶线判「连着谱表伸上来的东西」，在 `levelRows` 拉平的子图里照原样切，切出的框按框心的 x 挪回原图。
- **文字带、声部标签、页眉**（`words.ts`、`stafflabel.ts`）：送 DBNet 整条检测，词框短，斜一点不碍事；带的上下界取谱线在这一段的包络
  （罩得住整行的字），带里落进谱表（连让线那一点）的像素逐列刷白，不让一头的谱线进带。声部名取谱行左端那一列的线位，页眉带底取第一线最高处。
  **页眉条另按第一行谱曲线两端连线的平均斜率逐列挪**：斜行里斜体小字的词缝找不到空白列、补不出空格（晨曦破晓页眉 62.5 → 90.6）。
  按条里字块自己的排列量斜度（同歌词那样）试过：页眉是几栏错落的短行，斜到 2.8% 也凑得出尖剖面，反倒更差。
  页眉带底压着首行谱上方的和弦行，OCR 偶尔把和弦字母读成汉字（有一位神「F♯m」读成「衡拉」），框有一半落在认出的和弦上的页眉行不收。
- **简谱带**（`jianpuband.ts`）：简谱小节线的纵向范围减掉所在 x 处的偏移再凑「同一高度」（两头的简谱小节线错开大半根，按原图凑不齐），
  带的盒按名义线位记、带上 `lift`；裁条逐列挪、抹墨与摘原语按 x 加偏移，补谱表小节线取该 x 处的首末线。和弦带的 `ceiling` 也按名义线位比。

### 谱线漏检自检（`../dev/scripts/raster-lines.mjs`）

逐列命中里落不进任何已找出谱行的，按 y 聚成带（二十个以上取样列支持才算），就是「疑似漏了一行谱」：
轨迹太短、被并错、被当成错开一条线的假五连丢掉的那几行。

> **不能拿「逐列看得见几行」直接与谱行数比**：轨迹会被符号打断、带也会被倾斜拆碎，
> 那个数两头都不准（实测干净页 100 行谱只串得出 33 条轨迹、却聚出 175 条带）。
> 只有「落不进已检出谱行的命中」才是硬证据。

## 去谱线：**上下都没墨才抹**

经典的「保符号去线」判据：谱线那一带的某一列，紧邻的上方与下方都是白的，
才说明这一段是**孤立的谱线**；只要有一侧连着墨，它就是某个符号穿过谱线的那一截。

一度只判「纵向游程短」，那会把**骑在谱线上的细笔画一起抹断**：
拍号数字、休止符、谱号都压在谱线上，笔画细的地方游程正好短，一抹断成两截，
同一个符号按断法不同散成好几个形状类（四分休止散成四类、拍号数字散成一堆碎块）。
换判据之后 4/4 拍号、低音谱号、升降号都完整了。

### 修补图：存疑的线带像素补回（`repairLineCuts`）

「上下都没墨才抹」的代价是**斜着贴线穿过的笔画**被切断：中间那几列整段落在线带里，上下都不连墨。
代码里不少路因此各自回原图再看（骑线空心头找孔、八分休止球与斜笔、还原号、拍号、谱号、弧线）。
修补图另出一张，把线带变厚、夹在线上线下两截细墨之间、拱顶压线只剩两腿的那几列补回，同时清掉去线时留下的纯线厚残段。
拱顶压线的两腿之间的缝放到 1.5 格（破碎 p4 女高两条小弧 1.17 格）；缝过一格的，线另一侧正对着缝也得空（两腿穿过线、在另一侧收成碗底的是别的字形，主我敬拜你的 U 形小记号）。
第六批起给弧线候选用（判据见[图形符号与账本](图形符号与账本.md)「第六批」），第八批推广到其余被谱线切开、事后按盒距拼回的对象，
**一页只取一次**（`recognize.ts` 里紧跟 `findBlobs`），两层各一份：

- **符号块**：`findBlobs(repaired, …)` 与去线图的符号块按像素对上（`findBlobs` 的 `labels` 出标号图），
  修补图上一块里的去线图碎块**全是未识别**的，先整块在修补图上查字典 / `judgeHeadBox`（「碎块并起来再查一次字典」那一路），
  修补图没连上的（被竖笔、横段抽取切开的）才走原来「x 重叠 + 纵隙 ≤0.4 格」的盒距合并。
- **contour**：`contour.ts::repairedLayer` 在修补图上取 contour、记下每块由哪些去线图 contour 组成；
  `candidateMap` 按某一路**那一刻**的候选集合（账本上无主，或只被谱线 / 符杠 / 歌词这类认过）把「碎块全是候选」的修补块整块换进来，
  交给原来吃 `cmap` 的检测函数，账本照旧按盒查 `cmap` 的标号，合并块的账取碎块的并集（谱线那一笔不算）。
  用它的有：弧线（同第六批，一块的也换）、八分休止（隔着一条线的球与斜笔）、演奏法记号、松叶、虚线弧（后四路只换**两块以上**真连上的）。

认干、认杠、认头、找空心头内腔照旧用去线图 / 原图——那些阈值是在「切开的」图上换来的。
被竖笔、符杠抽取切开的（谱号碎块、升降号并回竖笔、四分休止中段、拍号列）不是去线造成的，修补图帮不上；
与谱线完全重合的横笔（还原号、升号横笔、`crossRuns` / `tallStrokes` 那几路）修补图补不回来，也照旧。

## 几何原语：`prims.ts`

### 靠**游程**分笔画，不靠连通域

直接对整幅图做连通域没有用：一行谱的五条线、压在上面的符头符干符杠、
穿过去的小节线全连成**一个**块。得先按「这个像素属于横笔画还是竖笔画」分开：
纵向游程短的是横笔画、横向游程短的是竖笔画、两个方向都在符杠区间的是符杠，
分完再各自做连通域。

### 「细」的上限**卡在谱线与符杠之间**

谱线约 0.15 个线距厚，符杠约 0.5 个。一度写成 `lineThick * 3`，
那正好撞上符杠的厚度——符杠混进横笔画、与它压着的谱线连成一块，
块高一超限整条谱线跟着被剔掉（宁静 p1 五十条谱线只剩十一条，且都不是谱线）。
改成 `max(3, min(lineThick*2, space*0.4))`。

### 笔画要沿自身方向做**闭运算**

符干穿过谱线的那几个像素，纵向游程一下子变成整根符干的长度，于是被踢出横笔画
——一条谱线因此被每根符干断成十几截，后面「长度 ≥ 最长横线的 35%」那道闸一截都过不去。

### 笔画要判**孤立性**

谱号的中央竖笔、升号的两道竖笔、拍号「4」的竖笔，横向游程都很短，
一律被当成竖笔画抽走，于是**符号被自己的笔画切开**——高音谱号切成上下两半，
位置自举取到的一多半是它的上半截，高度不到 3.8 格，整批误判成低音谱号
（你要等候 76 行谱认出 69 个「低音谱号」）。

判据：沿笔画取样，两侧（横段则上下）的邻墨超过一半就判它属于某个符号，不当原语。
真符干、真小节线两侧是空的，只在符头、符杠那一小截有邻墨。

### **加线免检孤立性**——它只出现在谱线网格的延长线上

加线总有个符头压在上面，孤立性判据一律判它「属于某个符号」，
于是既抽不出来（`findLegers` 没得用）、也抹不掉（符头连着加线，
宽度从 1.3 格涨到 1.77 格，字典里凭空多出两个三百多实例的「符头」大类）。
加线有一条更硬的判据：**只可能出现在第一线上方或第五线下方整数个线距处**（容差四分之一格）。

### 符杠要够**扁**

光靠「够长、不太高」拦不住符头：实心符头约 1.3×1.0 个线距，
纵向游程落在符杠区间里、横向游程也过线，宽度还差一点点就够。
符杠是 3:1 往上的长条，符头是 1.3:1 的椭圆，长宽比一刀分得开。

## 分系统：按**左端系统线的墨**，不按连通块

`prims.ts::groupByLeftInk`。`makeSystems`（`staffomr/page.ts`）原来只认两样标记：
挂了 `SysLine` 的竖段、字形是 `bracket`/`brace` 的符号。位图路上这两样都靠不住：

- **方括号的上下衬线会把粗竖笔与细系统线连成一块**，那一块宽 20px、
  超过竖笔画的宽度闸（`thin*2` ≈ 9px），于是 `findPrimitives` 一条 `SysLine` 都抽不出来；
- 位图路没有字形，`bracket`/`brace` 这两个 code 一个都不会出现。

结果是**每一行谱各自成一个系统**——实测望十架那份 99 行谱碎成 **81 个系统**
（正确是 25 个上下）。系统一碎，`alignSections` 只能对上 GT 里那两个单行段
（GT 2695 音只对上 187 音），`buildScore` 也接不起来（游离音符 **446** 个）。

**改按墨判**：两行谱之间的缝里，逐行看「谱行左缘那一小条窗口里有没有墨」，
够九成就判这两行连着、属于同一个系统。窗口开在左缘往外两格、往里半格
——歌词与力度记号都在更右边，页边框在更左边，都进不来。

这条判据**不受碎块影响**（不管括号断成几截，墨还在），实测三个阈值
（窗口往外 1/2/3 格、成数 0.8/0.9/0.95）**结果完全一样**，说明分得很开。

| | 之前 | 按左端墨 |
|---|---|---|
| 望十架.pdf 系统数 | 81 | **25**（p1 `1 1 4 3`、p2 `4 4 4`、p3 `4 4 5`、p5 `4 4`） |
| 望十架.pdf 音符 | 14.0%（游离 446） | **27.4%**（游离 88） |
| **真扫描件那一档** | 33.01% | **40.57%**（含游离 28.65% → 34.87%） |

干净位图那一档**一分不动**：那些底本的系统线本来就抽得出来，两条路给出同一个分组。

> 顺带修了 `makeSystems` 的一处先来后到：**罩得多的标记要先分组**。
> 同一个系统上既有罩全系统的方括号、也有罩钢琴两行的花括号，
> 花括号先把那两行占走的话，剩下的行就各自成系统（实测望十架 p3
> 四行的系统因此裂成「2 + 1 + 1」）。

> **试过按连通块找「系统括号」，不够用（已撤）。** 照 `findBraces` 放宽两处
> （允许压在谱行左缘上、罩几行都算），再把共线又上下贴着的碎块并回一个：
> 望十架一份从 81 个系统降到 49 个，扫描件那一档 33.01% → 35.05%
> ——比不做好，但远不如按墨判的 40.57%。括号碎得比预想的厉害，
> 并块的规则每补一条就多一处要调的阈值，而「墨连不连着」一条就够。

## 半调网点的底本：先去网再识别（`descreen.ts`）

心领《坚固保障》那类底本（一曲一张 jpg、简谱本式的独唱谱 + 和弦字母）整页是**抖动印刷**：
符头不是实心块而是打散的网点，右半页还压着一层点阵阴影底纹。照直送进来：
整页 83 个音符**只认出 20 个**（填充率那一档全过不去），未归属块 1022 个。

去网走**标准形态学**（`omrkit/morph.ts`），三步的参数都在运行时从本页谱表带里统计（`descreenMorph`），适应不同风格的底本：

1. **面积开运算**：抹掉面积小于「墨块面积 90% 分位 × 3」的墨块（八连通）——阴影底纹是孤立小点；
   网点符头的墨点八连通成片，不受影响；
2. **面积闭运算**：填上面积小于「被围白块面积 90% 分位 × 8」的白块——符头、符杠里的网点白隙；
3. **闭运算**：方形结构元，半径取白隙边长——补上碰着外面、面积闭运算够不着的白隙（网点谱线、头的毛边）。

坚固保障实测：墨块 4018 个是单像素，被围白块 1851 个是单像素，之后空一档，空心头的内腔 25 像素起——
面积闭运算门槛 8 像素，内腔留得下来。

**旧做法（2026-09-27 换掉）**：局部密度过半（`0.6×线距` 窗口、门槛 0.42）填实 + 横纵连续的留下 + 贴着它们的墨才留。
密度那一条会把**细圈**的空心头整个填实：圈只有一两像素粗，9px 窗口里圈自己的墨就够密度，二分读成四分（坚固保障 m11、m13、m17）。
在它上面打补丁（保护「像内腔的」白块）先后撞上：网点谱线的白隙与谱间白连通、和弦字母内白被保下成了假全音符、
第三行谱去网前找不到谱线所以谱表带漏了它——换成形态学后三处空心头都认回来，音符、时值持平（新冒出两处：
斜网点杠下缘与谱线、干围出的一块真白被当成内腔收成 F5 二分；m19 连杠末端被认成别的干的符尾），小节自检满拍 72.39 → 72.75%。
按内腔找空心头时剔掉压着符杠的，坚固保障 +1.4，但我一生要赞美你 −4.5、万福泉源歌 −1.6（叠放空心和弦上压着假杠），撤了。

（最初的密度去网做完：20 → **83 个音符**，未归属 1022 → 305。）

**不是每页都做。** 判据是谱表带内的「孤立墨点占比」（3×3 窗口内墨不过 3 个算孤立）：

| 底本 | 网点率 |
|---|---|
| 心领《坚固保障》 | **0.359** |
| 合唱谱那批（干净位图 + 真扫描件）全书全页最大 | 0.157（你要等候 p3） |
| 其余多数 | < 0.1 |

门槛原取 **0.25**，落在两档之间的空档里。

**压在谱线上的孤立点不计（分母照算全部墨点），门槛改 0.13。** 低分辨率细线扫描件（数算主恩、更亲近恩主，线距 14px 上下）
的谱线断成一串点，全算进来网点率 0.263 / 0.254、刚过 0.25，整页去网把汉字笔画磨掉（歌词 94 → 9、96 → 49）。
原先行投影在这两页第一趟找不着谱行，`cleanTexture` 没做事，碰巧躲过；按游程第一趟就找得到。改口径后实测：

| 底本 | 网点率（线上孤点不计） |
|---|---|
| 坚固保障（该去网） | 0.169 |
| 求主同住（网点水印，不该去网） | 0.101 |
| 其余独唱谱 / 合唱谱各页最大 / 新编最大 | < 0.03 / 0.026 / 0.009 |

连线上的墨一起剔掉（分母也不算）试过：求主同住满页水印孤点，比值反倒升到 0.276、与坚固保障 0.341 只差一点，分不开。

**个别谱行淡**（新编 f04、320、130、400 等，补线前沿曲线有墨的列只有六七成）：淡谱线补回那一步原先「补完谱行数变多才整幅留」，
按游程找线时断续的线也凑得成行、行数不变，补的线全丢。现在逐行量补线前后沿曲线有墨的列占比，涨过 0.15 的那几行只换它的谱表带
（`rasterpage.ts::mergeFaintStaves`；独唱谱、合唱谱各行涨幅最大 0.06，不触发）。

**量要限在谱表带内**（上下各两个线距）。整页量会被空白页毁掉：几乎没墨的封面页上
几十个尘点个个孤立，量出来是 **1.000**；谱表带里有谱线、符干这些必然成片的墨，
空页与真网点页才分得开。

## `staffBandOnly`：立 GT 底稿时把谱表带外的墨抹掉

独唱谱的谱表**上方印和弦字母**。字母「C」是个圈，正落在空心符头那一档里
（`HOLLOW_BAND` 上下各让三格，字母在 1.6 格处）；谱表下方的歌词字同理被收成实心符头。
实测《坚固保障》整页多出 5~6 个 D6/E6「全音符」与若干 C3「四分音符」。

`recognizeRasterPage(…, { staffBandOnly: true })` 把谱表上下两个线距之外的墨抹掉。
带宽扫过 1.5 / 2 / 3.5 格：音符 74 / 75 / 80，其中 3.5 格那档有 5 个是和弦字母。**2 格是拐点。**

**默认关**——开了歌词就没了。它是给 `../dev/scripts/staff-image-gt.mjs`（一张图 → MusicXML 底稿）
用的，那条路本来也不出歌词。**识别判据一条不改**：抹的是输入，不是判据。
