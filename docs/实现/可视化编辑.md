# 可视化编辑：判据全录

> 模块页见 [../模块/可视化编辑.md](../模块/可视化编辑.md)。这里放点选身份、五线谱 / 混排档、`.musicxml` 模型编辑、小节操作四块的判据与踩坑。

## 点得中自己：五种身份五种认法

音符之外还有几样能单独点选的东西。它们在模型里的身份**各不相同**（同样是增时线，`.jpwabc` 与 123 就是两种），
所以认它们的办法也各走一路——下次再加一样，照这张表对号入座：

| 东西 | 模型里是什么 | 谱面上怎么认 |
|---|---|---|
| **增时线**（123 / 文本谱：独立的 `-`） | 有自己的 `ElementId`（`Chord.sustains[]` 各带一个） | 最省事：原样文档按它自己的 id 打身份标签（`kind: sustain`）；简谱引擎的输入把它压成计数（`JChord.beats`）不带 id，但排版时每条各是一个音符格、按树序跟在音符格后面，于是**按序号数**（`SyncEntry.ord`） |
| **增时线**（`.jpwabc`：写在 token 里的 `5---`） | **模型里没有它**——`-` 是音符 token 的一部分，`Chord.sustains[]` 是空的，索引里也没有 `sustain` 条目 | 谱面上照样一条一格（都是同一个和弦 id 的音符格）。这几格在 `SyncView.bindEls` 的**第二趟**兜底指向宿主音符（第一趟要先让 123 / 文本谱那种有自己条目的格认领自己），点中第几格就选 token 里第几个 `-`（`NoteParts.sustains`），`Delete` 走 `dropInlineSustain` 只短一拍 |
| **小节线** | **没有 id**（`model/doc.ts` 的 `Barline` 只有样式与 `source`，`slots.ts` 给它的 ref 也不带 id） | 借挨着的那个音符的 id + 哪一侧（`SyncEntry.edge`、`Barline.ownerEdge`），口径与 `sync.ts::addPartExtras` 一致。简谱引擎的小节线标签只带侧（`edge`），由 `ScoreIndex.build` 遍历页面树时按前后顺序借 id（树序 = 读谱顺序，跨小节跨行跨页都对）；原样文档在 `paintVoice` 的线性循环里认、直接写进标签（贯穿几个声部的一根线挂几个音，`addBarlineOwner`） |
| **圆滑线 / 延音线** | 跨元素的**一对端点**（`Mark.start` / `end`，两段原文 `openSource` / `closeSource`） | 按身份标签的 `id` / `end`（起点、终点）认。`(` 与 `)` 两条 `SyncEntry` 指向同一条弧，删除时两个括号一起删（`spansToDelete` 认 `pair`） |
| **减时线** | **不是对象**（时值的派生量，见 [模型-scoredoc](../模块/模型-scoredoc.md) 的「派生量不存进 `ScoreDoc`」） | 不建索引：照附点那套**按几何命中**（`beamAtPoint`，量音头那个数字的下缘往下一条带），选中的是 token 里那串符号（`NoteParts.beams`，123/`.jpwabc` 是 `_`、文本谱是 `/`；ABC 的时值是数字，没有单独符号可选，为 null） |

几条**别再想一遍**的取舍：

- **不给小节线发独立 `ElementId`**：要动 `IdGen` 分配、五种格式的往返与 `SourceSpan` 填充，代价远超收益。
- **不给减时线打类名**：两个引擎里它各是 `BeamLine` 与 `voice.underlines` 的一排 `rect`，打类会改 SVG 输出、
  `jianpu-svg-dump` 整片要重新定基线。
- **点 token 里的东西一律「选 token 里的一段」**：附点、减时线、`.jpwabc` 的增时线都没有独立对象，
  选中的都是原文 token 里的那几个字符，删除也都经方言的 `parseNote`/`printNote` 改 token，不做裸文本删除。
  这几支在 `handleClick` 里**都要排在音符分支之前**——音符分支先返回就轮不到它们了。
- **细线的命中放宽放在控制器侧**（`thinAtPoint`，照 `dotAtPoint` 用 `getBoundingClientRect` + pad）：
  竖线的几何包围盒宽是 0、横线高是 0，往页面树里塞透明的加宽命中条同样会动谱面指纹，不值当。
  选中框同理——按长边比例撑到看得见（`plump`）。
- **多声部谱里贯穿几个声部的小节线只画一根**（`paintVoice` 被 `skipBarlines` 跳过、另在成组那段画），
  所以各声部在这一处的小节线条目**都指到这同一根**上（按横坐标对）。

**一条链上的东西改一处就要看全链**：模型 → `sync.ts` 的条目（`edge` / `ord` / `own`）→ 两个排版器的索引
（两个排版器给图元打的身份标签 `pagetree/identity.ts`，由 `layout/scoreindex.ts::ScoreIndex` 收）
→ `VisualHost.barlineEl` / `sustainEl` / `slurEl` → 控制器的 `ownEl` / `boxOf`。
断了哪一环都不会报错，只会「选中了但框画在旁边音符上」——跑起来才看得见。

## MusicXML：改模型（`modelops.ts` → `model/edit.ts`）

没有可以局部补丁的原文 token，改的是 `ScoreDoc`，改完经唯一写出端整份重写（架构 A5「改过整份重写、表层回填」）。
与文本那一路共用动作表、选区、撤销：

- **索引建在隐藏代码区的 XML 原文上**（`SyncIndex.buildXml`）：`fromxml` 把和弦、音、歌词、小节、弧绑在原 DOM 节点上
  （`model/xmlsurface.ts`），DOM 文档序与原文里 `<note[ >]` 等标签的出现序一致，按序对上偏移即可，`fromxml` 不为编辑记偏移。
  数不齐（注释里写了标签）就不建、谱面只能看。音符条目截到第一个 `<lyric` 之前（歌词写在 `<note>` 里，不截会被一起选中）；
  普通小节线没有元素，取 `</measure>`；换行取下一小节的 `<print new-system|new-page>`；页眉取 `<work-title>` / `<credit-words>` 里的字。
- **动作**在按原文新读的一份模型上改（`freshModel`：它的原节点只为这次重写而活，改表层不碍着谱面那份），写出后只把前后不同的一段
  放进代码区（`diffRegion`）；元素 id 重写再读回会重编，按「第几声部第几小节哪个声线第几个」（`ChordPos`）认回来落选区。
- **语义对齐文本那一路**：唱名按调号换音高、八度点不变，休止改音时八度取离前一个音最近；删音就是删（不补休止，拍数自检标红）；
  增时线 = 多一拍；`|` 把小节在光标处劈开（所有声部一起，有音跨过去就拒绝）、删小节线并两节（下一小节换调换拍的拒绝）；
  换行只在小节线处（`Print.newSystem`）。改音高后重算本小节临时记号的印法（`respellMeasure`），改时值后重排本小节该声线的符杠（`rebeam`）。
- **表层作废**（`xmlsurface.ts`）：改了音高的音丢掉原文的 `<stem>` 与 `default-y`（`forgetNoteLayout`）；增删音、改时值、拆并小节后
  整曲丢掉小节宽与音符 `default-x`（`dropEmbeddedLayout`），五线谱引擎见不到坐标就自动铺排——只丢一小节会与邻近照原坐标排的小节打架。
  自动铺排的标题块在 `work-title` 已排时不再排 credit 里同名那条（否则改完结构标题印两遍）。
- **时值单位太粗**（每四分音符 1、2 个 divisions）写不出附点八分时，整个声部按最小整数倍放大单位（`scalePartDivisions`），音不变。
- **文字**：双击歌词、标题弹内联框（`inline.ts`），提交直接改 XML 原文里那几个字（纯文字改动局部补丁，不必整份重写）；
  标题在 `work-title` 与 credit 里原字相同的一起改。歌词里 Enter / Tab 跳到同一段下一个字（等五线谱档异步排完再开框，`VisualHost.whenIdle`）。
- `.musicxml` 的代码区收起（`no-code`），不再设只读：CodeMirror 的 `undo` 在只读状态下直接拒绝。
- **记号条目**（`SyncIndex.buildXml`）：弧、延音线取 `<slur|tied type="start">`（`(`/`)` 两条成对），`<direction>` 整个元素一条（带 `dir` = 声部、小节、`directions` 下标；
  力度记 `dynamic`、文字记 `annotation`、其余记 `dir`），`<harmony>` 一条，`<notations>` 里的奏法装饰各一条（名字同 `DecoKind`）。
  这些区间都在 `<note>` 里面或旁边，**删除先认「选区恰好是一条记号」**——按选区碰到的条目算会连音符一起删（以前删弧就是这样连音一起删的）。
  `<direction>` 挂在哪个音前：`afterElements` 指的那个之后第一个（同声线）和弦，小节末的借最后一个和弦（与 `edit.ts::dirAnchor` 同一口径）。
- **挪过的记号选回来**：重写读回后元素 id 会重编，`ModelEdit.moved` 记「挂在哪个和弦上、是什么」，按和弦位置 + 种类在新索引里认回那一条。
  `<direction>` 挪到别的音前改 `afterElements`，起点与写出端的游标缺省（前一个元素的终点）不同时才写 `onset`。
- 八度线（`toggleOctaveShift`，记号面板 8va / 8vb）是起止两条 `<octave-shift>` direction：**符头不动**，范围里本谱表的音实际音高挪一个八度
  （MusicXML 的 `<pitch>` 是实际音高，8va 底下记谱低一个八度；识谱漏了八度线就是符头对、音高差八度）；再点一次、或 Delete 删起止任一端都挪回。
  起点 `type` 写 down（8va）/ up（8vb）带 `size`，止点 stop——此前读入只记 start、写回成不合法的 `type="start"`。五线谱排版（`mixed/layout.ts::scanOctaveSpans`）
  照区间把符头放回记谱位置，`render.ts::drawOctaveLine` 画「8va + 虚线 + 收尾钩」，线收在最后一个音的符头右缘，跨系统的照松叶裁段、续段印「8」。
- 渐强渐弱是起止两条 `<direction>`：整条挪、删时按 `dirPartner` 连配对的一起——同声部、**同谱表**、同类（声线都写了才比），按先后排好从它往后（终点往前）数、
  套着的同类一对对跳过（两行谱表各有一条交叠的渐强时，只按先后最近会配到别的谱表上）。只挪一端时与另一端比，不许越过（`moveDirection` 的 `guard`）。
- **挂在小节末的**（最后一个音之后：小节末的力度、渐强的终点）：索引借最后那个音的 id 并标 `dirEnd`；`Alt+→` 挂到下一个音前，`Alt+←` 一格是挂到最后那个音前
  （不是再前一个）；拖动按「拖到第几个音前」换算时往前要多算一格。
- 删音符上的记号按名字从 `articulations` / `ornaments` / `technical` 里删（`removeNotation`），不走 `toggleDeco`——那边不认的名字（caesura、stress…）会被当装饰加上去。
- 谱号重读遇到小节中间换谱号就停在那一刻：读入时那条多半没记 `onset`，按写出端的游标缺省（它前面那个元素的终点）补。
- `F8` 往回找按**落点**比（空小节光标落在小节线后一格、音符只罩音头、可疑项给的是 token 起点）——按条目起点比，往回会一直找回同一处。

## 小节操作

插入 / 追加 / 删除小节、换调号拍号速度、小节线样式、房号、跳转记号（动作表「小节」组，右键菜单里收成子菜单）。

- **文本格式**（`measureops.ts`）：小节在原文里没有对象，按方向键能停的条目认——两条小节线之间、同一声部的那一串。
  小节前面**紧挨着的一串小节线条目**当一组（`|:` 后跟房号 `[1` 时是两条：123/ABC 的房号自己是一条小节线条目）：
  前插小节插在这组之前（新小节在反复与房号之外）、反复开始改组里不是房号的那条、房号增删改组里的房号；删小节连同本小节的房号一起删，
  收尾线不是普通单线（`|:` `::` `||`）时留着——它也是下一小节的开头。第一小节换调号拍号速度改头部字段（没有就在 `K:` 前补一行），曲中写行内 `[K:…]`。
  写法只差调号的值（123 `1=bB`、ABC `Bb`）与休止（各自 `newNote(0, …)`），其余共用 `abcFamilyMeasure`。
- **`.musicxml`**（`model/edit.ts`）：所有声部一起插删；前插第一小节时原来的属性挪给新的第一小节，删掉的小节里生效的属性合并给后面那一小节；
  追加小节只把**终止线**挪到新的最后一小节（带反复、房号的尾线是原那一小节自己的）。跳转记号照 MusicXML 惯例落成 `<direction>`：
  segno / coda 在小节头，D.C. / D.S. / Fine 在小节尾并带 `<sound>`（试听与演唱顺序按它跳）。房号最后一房不封口（`discontinue`）。
- **和弦与声部**（只 `.musicxml`）：`Alt+1–7` 叠和弦音；Alt+点击按**符头基线**认是和弦里第几个音（Bravura 的屏幕框是整行字体盒，取框中心既点不中也排不准）；
  `Ctrl+Alt+1–4` 定新插的音落在**光标所在谱表**的第几声线（同 MuseScore，每条谱表各有 1–4），`insertInVoice` 按光标所在时刻插，与前一个音有空当时写显式起点，后面同声线的音保持原起点。
  没按过（换文档清回去）就不指定：新音接在光标前那个音的声线里。谱表内第 k 声线 → voice 号走 `edit.ts::staffVoice`：
  MusicXML 的 voice 在整个 `<part>` 里统一编，多谱表通行每条谱表占四个（下谱表 5–8，识别写出、Finale、MuseScore 都这样），也有接着编的，
  所以按本谱表实际用到的号从小到大数。以前缺省第 1 声线、按整个 part 的 voice 号比：大谱表下谱表（voice 5）删了音再插，
  新音要往 voice 1 的这一刻塞，上谱表这一刻有音就插不进（issue 23）；小节开头插入的谱表也写死成第一条。
  带 Alt 的绑定按 `KeyboardEvent.code` 认、且先于字符绑定匹配（Mac 上 Option+3 打出的是 `£`；Windows 上 Alt+1 的 `key` 仍是「1」）。

## 五线谱 / 混排档

改的仍是原文，与简谱档共用同一份选区与撤销；不同的只是「谱面上认谁」：

- **索引与谱面分两步建**（`SyncView.buildIndex` / `bindEls`，`editor/syncview.ts`）：五线谱排版是异步的，索引却必须与原文同步——
  动作按索引改原文，索引落后一拍就按旧偏移改错地方。所以 `reload` 在五线谱档里先同步建索引，排完版（`_layoutStaff`）再绑元素、重画叠加层。
- **元素身份**：音符靠派生 XML 的 `<note id="jp…">` 回源 id（`Chord.srcId`，见[编辑器](../模块/编辑器.md)「双向定位」），对到和弦组 `STAFF_CHORD`
  （混排里五线谱层与简谱叠层各一个，两个都算）；歌词字、弧、小节线、标题行在 `mixed/render.ts` 里给图元挂身份标签（`pagetree/identity.ts`，与简谱同一套，
  由 `layout/scoreindex.ts` 收），`mixedVisitor` 的 `leafMap` 记下画出的元素。**只挂标签、不加类名不包组**：`mixedVisitor` 对叶子不写 class，SVG 输出一字不变
  （`mixed-tree-dump` 568 份逐页一致）。弧在页面树里本身是个组（`SlurTieBase extends Group`），所以 `descend` 那一处也要记。
  小节线没有 id：按「全曲第几小节 + 哪一侧」认（系统开头那条是首小节的 `before`，其余是本小节的 `after`），
  索引那边的「相邻音符 + 侧」经派生模型的和弦 → 小节下标换过来（`App._mixedMeasureOf`）。
- **框按墨迹量**（`overlay.ts::inkBoxInPage`）：符头是 Bravura 的字，`getBBox()` 给整行字体盒（一个符头量出 160 tenths 高），
  照 CLAUDE.md 那条用 canvas `measureText` 的 `actualBoundingBox*`。插入光标画在前后两音正中（贴符头右缘会压在符干符尾上），
  竖向取这一行的谱表带（`STAFF_SYSTEM.data`，混排连同简谱层，`ScorePainter.staffBand`）。
- **几何命中只在简谱路做**（`VisualHost.surfaceKind`）：减时线、附点、token 里的增时线靠简谱字形的位置认，五线谱上没有这些图形——
  在五线谱档不关掉，点歌词下方会被当成点减时线。增时线在五线谱上并进了时值，不单独选中；和弦名、装饰暂不认。
- 点击：停止时点符头走可视化编辑（同时仍记为起播点）；播放/暂停中让给跳播（同简谱档）。
