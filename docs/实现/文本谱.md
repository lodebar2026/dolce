# 文本谱：番茄简谱 / 诗歌本（`src/fanqie/`）

「文本谱」指两套用纯文本写简谱的记谱语言。本项目把它们当作**第一等源格式**：
编辑器里直接编原文、用它们自己的排版规则渲染、并能导出 MusicXML / `.jpwabc` / MIDI / PPTX。

> **2026-10 简谱合并成一个引擎**：旧简谱引擎（`layout/layout.ts` 的 `Layout`/`Line`、`entry.ts`、`jianpupages.ts`、`LayoutOptions`）已删，
> 原样文档布局改名 `layout/jianpu/` 成为唯一的简谱引擎（见 [模块/排版-简谱引擎](../模块/排版-简谱引擎.md)）。下文按时间记下的判据，
> 提到旧引擎的函数名是当时的实现位置；判据本身已搬进新引擎（或写明作废）。

- **番茄简谱脚本 v1.0**（下称 tomato）
- **诗歌本文本谱**（下称 shige）——番茄的变种，头部字段与若干记号全改过

两者共用一套解析/排版代码，差异**全部**写在 `dialect.ts` 的 `DialectSpec` 里（八度字符、
变音记号、节奏音符、跳词字符、小节线写法、音节分隔符、并字号、头部字段的写法与调号
prefix/suffix），版面度量的差异写在内置方言表 `src/style/books/original-<方言>.ss`（番茄 = 出厂值，没有叠加表）。
**不要在两套方言之间写 if**——加第三种方言应该只是补一份数据。
**改行为前先读这篇**——下面每条判据都是拿具体谱子换来的。

## 目录结构与数据流

```
fanqie 原文（编辑器，第一等源格式）
  └─ parseFanqie（内部 parseFanqieAst ─→ fanqieToScoreDoc）─→ ScoreDoc
                                            ├─ docView ─→ layoutOriginalDocument（ScorePainter）「原样」预览（连续长图）
                                            │     └─ relayout（按乐句重排改写原文，列号取视图上的原文区间）
                                            ├─ jianpuInputOfDoc ─→ ScorePainter     「展开」预览
                                            ├─ toxml ─→ MusicXML / emitJpwabc ─→ .jpwabc / emit123 ─→ .123
                                            └─ playSourceOfSong ─→ 试听 / MIDI
```

| 文件 | 职责 |
|---|---|
| `dialect.ts` | 方言嗅探与差异表（`DialectSpec`） |
| `ast.ts` | AST 类型。每个节点带 `source` 区间——高亮、点选、诊断全靠它 |
| `parse.ts` | 单趟字符扫描 → AST。不额外造 token 流（没有第二个消费者） |
| `metrics.ts` | 版面常量 + `print`/`slide` profile + 谱面 `FontSize:`/`Margin:` 的应用 |
| `layout.ts` | AST → 定位结构（只算位置，不碰绘图） |
| `painter.ts` | 定位结构 → PageItem 树 → SVG；并建播放高亮索引 |
| `glyph.ts` | 记号 → Bravura 码位；PUA 一律 `String.fromCharCode` |
| `highlight.ts` | CodeMirror 语法高亮（独立宽松扫描，不复用 parse） |
| `slots.ts` | `ScoreDoc` → 排版行视图（原样档排版器、展开档投影、双向定位共用） |
| `phrasesong.ts` / `jianpu/playsong.ts` | 断句输入 / 演唱顺序与试听输入（简谱形状；播放入口各格式共用，放在 `model/`） |

展开档的引擎输入由 `jianpu/jianpuinput.ts::jianpuInputOfDoc` 投影（不带和弦、力度、多声部并排——展开档本来就不画）；
导出一律从 `ScoreDoc` 出，和弦与力度都在（《圣哉三一歌》导出 MusicXML 28 个 `<harmony>`）。

## 两方言的差异

`Q:`曲 / `C:`词 / `W:`文字 / `#`注释、`-`增时 `/`减时 `.`附点、`~`/`^` 强制连断拍、
`()` 弧线与 `(y…)` 多连音、`&xx` 记号、`|`系列小节线、`"hx:和弦"`、`|"p:2/4"` 临时拍号、
`|"k:2"` 曲中转调、`&zkh/&ykh`、`{bz…}`/`{dsb…}` 两家一致（不写 bz/dsb 的 `{…}` 按并排块读，层首紧跟外面那条小节线的 `|` 不进层——
番茄原谱《太阳出来喜洋洋》`{ | 6, - } 2, -` 与 `{dsb 6, - } 2 -` 印得一样）。分歧如下：

| | 番茄 | 诗歌本 |
|---|---|---|
| 头部 | `V:` `B:`(多) `Z:`(多) `D:`调 `P:`拍 `J:` | `T:`(多) `1=Cb4/4` `Z:` `J:` `XL/XR` `TL/TR` `BL/BC/BR` `FontSize:` `Margin:` |
| 高低音 | `'` / `,` | `g` / `d` |
| 升降还原 | `#` / `$` / `=` | `#`♯ / `b`♭ / `♮` / `𝄪` / `𝄫` |
| `8` / `9` | `8`=隐藏休止；**`9`=节奏音符 X** | `8`=隐藏休止(跟词)；`9`=隐藏休止(不跟词) |
| 节奏音符 | `9` | 字母 `X` |
| 倚音 | `1[2]` / `1[h2]` | `1"yy:2"` / `1"hyy:2"` |

倚音里的音符走的是与主音同一个修饰符循环，所以八度（`3,`）、时值（`3/`）、**升降号**（`3#`）都写得出来，
排版也都画（升降号 2026-09-04 补上，见 [简谱纵向栅格](简谱纵向栅格.md) 的「倚音」一节）。

| 歌词跳音符 | `@` | `@` 或 `/` |
| 歌词连字 | `~` | `{哆啊}` |
| 歌词说明 | 前置 `"…"`，空格写 `_` | 前置 `<狼:1.%40>`，`%50`=50% 字宽间隙 |
| 声部名 | `Q1"女高":` | `Q1<女高>:` |
| 未闭合跳房子 | `[` 后加 `/` | `]` 后加 `/` |
| 分页 / 分曲 | `[fenye]` 独占一行 | `-----` 分割（其后是另一首） |
| 终止线 | `\|\|` | `\|\|\|` |

**`9` 是硬冲突**：同一个字符在两家意思不同，所以必须先定方言再解析。
嗅探读头部字段（两家互不兼容，够判），认不出就报错——`.txt` 太泛，宁可不认也别硬解。

## 曲中转调 `"k:N"`

写在小节线后面：`|"k:2"` 从下一小节起转到「原调的 2 级当 1」，`k:#4` / `k:b7` 带升降，`k:1` 回原调。
`;` 后面是谱面上要印的标签（`|"k:2;1=D"`、`|"k:5;【升G调】"`），不写就印「转1=X」。

- **级数始终相对首调**（头部 `1=X`），不是相对上一次转调——连转两次也各自对首调算。
- 读入不另造字段：`fromfanqie.ts` 按五度圈把级数加到首调 fifths 上，落成线后那个小节的 `Measure.attrs.key`
  （行末的线落到下一行行首；`model/keyshift.ts`）。级数与 fifths 一一对应，`#4`/`b5` 两种拼写都保得住；
  超出 ±7 的按同音换拼写。标签留在小节线的 `annotation` 上。
- 转调是全曲的：只在一个声部写了的，别的声部同一小节一起转（读入时补齐）。
- 播放、展开档、混排、MusicXML/123/ABC 写出都吃 `attrs.key`，无需另接；`tofanqie.ts` 写回时把
  `attrs.key` 变化处写成 `"k:N"`，线上的注记并进去当标签，往返不变。
- 原样档把标签印在新调首音上方、和弦那一行，左缘对齐数字，不占横向宽度（行尾转调自然落在下一行行首）；
  进上方带第 2 层（`place/band.ts`）：与和弦同在时转调标记在外（上）、和弦在内贴音（用户定：全局信息在外、局部信息在内）。
- 写在音符上的 `"k:…"` 不认，按普通注释印出并给诊断。

## 排版

「原版」用文本谱自己的坐标系与栅格，**不**沿用 [简谱纵向栅格](简谱纵向栅格.md) 那套
`jpStackGap`——那是 `.jpwabc` 谱面的尺子。两种预览各用各的规则，混用只会两头不像；
共用的只是「按墨迹居中」这个手法。

### 横向步进

实测（在未被拉伸的行上逐点吻合）：

| 情形 | 步进 |
|---|---|
| 同一拍组内、前后都带减时线 | 25 |
| 其余音符之间 | 37.5 |
| 音符与小节线之间（两侧） | 35 |
| 每个附点额外 | +12.5 |
| 首音锚点 | 版心左缘 + 3 |

「同一拍组」与减时线连断是同一把尺子（`layout.ts::beatGroups`）：**x/4、x/2 一拍一组**，
**复拍子**（分母 8、分子是 3 的倍数：3/8 6/8 9/8 12/8）**三个八分一组**（1.5 个四分拍），
移植自原 C++ 工程 `MusicData::processJpBeam`；简谱那路的 `score.ts::autoBeamGroup` 早有同一条。
9/8 的一小节九个八分因此排成 3+3+3 而不是 2+2+2+2+1，紧排也跟着按三个一组走。
拍号取行首那个，曲中的 `"p:6/8"` 逐小节改写，跨行接着算。三点没照搬原 C++ 工程：

- **残节按小节末尾对齐**（弱起，或被反复切开的那半个）：拍位整体加上
  `整小节时值 − 本小节时值`，组界才落在谱面该断的地方。三种不补：整曲末小节
  （原 C++ 工程的 `this == measures.back()`）、下一小节的时值正好等于要补的那一截
  （首尾配对的两个残节，同原文）、行末那个开口小节（跨行未收，后半在下一行接着算）。
  这些判断要认得出**整首**的头尾，故 `layoutSong` 把 `songStart` / `songEnd` 一并带进
  `BeatCtx`。
- **跨行的小节要接着上一行算**。文本谱一行 `Q:` 就是谱面一行，跨行小节的续行以 `|/` 开头、
  拍位却从 0 重来（`layoutVoiceLine` 在每条小节线处归零），不接上就会在续行头一个音上错开
  一组。故 `beatGroups` 顺手带出行末那个开口小节算到的拍位（`tail`，含弱起补的那一截），
  由 `layoutSong` 传给下一行当 `carryIn`。原 C++ 工程的 measure 本来就是整的，没有这一层。
- **`~` / `^` 仍然管用**：源码里的强制连断覆盖上面算出来的分组（诗歌本谱面上写了就照写），
  复拍子这类分组不必再靠它们顶。

**行不自动断行**——一行 `Q:` 就是谱面一行。两种方言都**两端对齐**（每个 system 拉到版心右缘，
整首末行不足 `justifyMinFill` 就不拉，免得几个音符被扯得满行都是；超宽一律压缩）。
番茄这里**刻意背离原版**：原版短行就是短的，但短行留一大截白比排得散更难看，
识别结果尤其常出短行。
对齐的目标宽度要扣掉 `bodyLeftPad` 与末音符的字形半宽，末音符墨迹右缘才正好落在版心右缘。

### 纵向：照 `.jpwabc` 的栅格算，别用固定槽位

- **弧线** = 两端「音符堆叠顶」的较高者再上一个 `slurStackGap`（= 字号/6）；
  堆叠顶 = 数字墨迹顶，有高八度点则抬到最上那点的上缘。厚度 6（同 `slurTieThickness`），
  端点落在音符**墨迹中心**（同 `addSlurTie`），端点还挂别的弧时各内缩 字号/14。
  罩住的音符数够 `slur-flat-notes`（成书用，0 = 只按跨度）就不论跨度画扁平式（同 `Line.slurNoteCount`）。
  **小节线不因弧缩短**（用户定；简谱引擎的 `clipBarlinesUnderSlurs` 不搬）。
- **松叶**几何同简谱引擎（`engrave/hairpin.ts::JP_HAIRPIN`）：起止在音符墨迹中心外 0.3 个墨迹高，全开口 0.7、线宽缺省 0.07 个墨迹高；
  跨行的行末那截渐强张到六成、下一行从行首第一个音左 0.9 个墨迹高接着张到全开，渐弱反过来（行末收到四成、下一行从四成收尖）；
  起止音上有力度字就从力度字右边起、收在力度字左边（`marks.ts::wedgeSpan`）。起始底边在跨度里音符那一摞之上一道叠层的空。
- **高低音点与减时线**走三引擎共用的叠层（`engrave/stack.ts`，见 [简谱纵向栅格.md](简谱纵向栅格.md)）：
  数字墨迹 → 减时线 → 低音点、数字墨迹 → 高音点，相邻两件墨迹之间一律一道 `stack-gap × 数字墨迹高`；
  低音点挂在最低那条减时线之下（十六分音符的两条减时线不会和低音点叠在一起）。
  从前这里另有一套 `underlineGap − underlineWidth/2` 派生的净距（`alignNoteMarks`），已并进叠层。
- **上方那一带按墨迹堆叠**（`place/band.ts::placeBand`，判据搬自简谱引擎 `Line.collectBandItems` / `placeDirections` / `addEnding`）：
  层 0 弧、连音、奏法记号（延长记号等，起点在叠层顶之上一道 `slur-gap`、有临时记号再让 1.6 道），层 1 和弦与注释
  （起始基线在本音那一摞墨迹顶之上 `chord-gap`；注释排在和弦之后），层 1.5 松叶（用户定：贴音，跨度里有和弦撞上才抬到和弦之上），层 2 转调标签（在和弦之外）；
  **同一行的和弦在同一条基线上**（用户定：起始取最高的那个，堆叠里有一个被抬整行跟着抬）；堆叠前和弦先横向让位（不压小节线、挨上就右挪，搬 `spreadChordsHorizontally`）。
  一次堆清后力度/术语/跳转字贴最近那个和弦的基线（撞了先往左让、不越过小节线，让不开抬一层），`{bz}` 临时伴奏行贴带顶之上，
  房号全行一条车道，竖脚对齐小节线线位；车道按段让（左端房号与竖脚那一截让「0.7 房号字号 + 竖脚」，其余横线底下只让一道空，落在小节线上的竖脚让过线顶）——同一首歌二房罩住并排块，横线贴在上行之上（同原书）；车道不为力度/跳转字抬，房里的 `Fine` / `D.S.` 反过来排到房号线之上（用户定）。
  小节线上的跳转字右缘贴线，线右边下一小节的和弦隔着线不算挡路（它离线只有和弦让线那道空，按净空判永远撞上）；本小节末尾有和弦挤着就把小节撑宽
  （`spacing.ts::BarEndRoom`，搬 `Line.spreadForBarEndMarks`：justify 前先问 justify 之后放不放得下，预演按 `spreadChords` 把和弦挪一遍再量，撑出版心不撑）。房号与连音括线同一个线宽（尺子 `bracket`，没设同小节线）。
  房号字号、竖脚、房号离左脚的距离同简谱引擎（`size.ending`、`bracket-foot`，`engrave/ending.ts` 的 `endingDrop` / `endingLabelDx`）；房号照原文印（`1,2` 不改成 `1.2`，用户定；简谱引擎才按 `normEndingText` 规整）；
  竖脚下面按竖脚与房号墨迹底更深的那个让。连音括线（`tuplet-style: bracket`）让开**跨度里每个音**那一摞（含临时记号、奏法记号，`vertical.ts::articStack`）之上一道 `slur-gap`，同 `Line.addTuplet`；两段弧仍按「简谱弧只看起止」。
  注释与转调标记在同一个音上时排在转调右边同一行，本小节放不下才摞到它之上（用户定）。
  **音符注释一律按段落词排**（用户定）：歌词字、`section-word` 字号、标点挤压同简谱引擎；落点判据与简谱引擎同一份（`engrave/sectionword.ts::placeSectionWord`，原样文档的换算在 `place/sectionword.ts`）——
  按墨迹摆（半身档下「（」的墨迹在笔位右边约半个字身，按字面盒算会离左边的和弦老远），与和弦之间留和弦与和弦那道空（0.28 个和弦字号；简谱引擎是 0.6 个段落词字号、按字面盒）——段落词在保持间距的前提下尽早出现（用户定）；
  字号同和弦（原样主题 `sectionWord` 0.85em，成书量到的 0.65em 屏幕上太小，用户定）；
  和弦那一行、本小节里横向找不撞和弦的空档，音符自己头上有和弦就排在它右边（`G（副歌）`），找不到才摞到和弦之上；没抬的与和弦同基线（不压回自己那一摞的让位之下），被弧、连音压住单独上提。
  横向不够时 `spacing.ts` 在 justify 前先问「justify 之后放不放得下」，放不下才按判据二分撑开本小节（撑出版心就不撑）；行首那一条在 justify 之后从行内线性衰减地匀。
  行末那个音上的段落词挪到下一行行首（只改行视图，`song.ts::moveTrailingSectionWords`）。`W:` 行离下面谱行 0.8 个说明字号。源码里的 `+` 抬高级别先按级预抬 `levelStep` 再进带。y 全在定位端定死，`compose/` 只照画；
  头顶留空（`groupHeadroom` / `voiceHeadroom`）读带的最高墨迹，`W:` 行贴首声部带顶之上。
  从前的固定槽位（和弦 −26、记号 −17、松叶 −44、房号 −53、临时伴奏 −40、`W:` −34，按 25 号字量）与逐处补丁已删。
- **system 间距只空一行字**：诗歌本 `gapGroup` 40（末行歌词墨迹底 → 下一组数字墨迹顶 = 一行歌词字高；
  折算要算上歌词墨迹下伸 ≈ 0.15 字号，取 36 时实测只有 23）。随面板字号等比缩放。
- **页首各行之间同样只空一行字**（`lyricSize`）：
  - 页眉整块由 `place/header.ts::placeHeader` 定位、`compose/header.ts` 只照画，排法同简谱引擎的 `jianpupages.ts::bookHead`：
    标题居中、副标题与经文跟在下面；词曲署名（`TR:` 在上）逐行右对齐、紧接在标题块下面；**调号拍号在左、与最后一行署名同基线**
    （左边有 `TL:` 块时排在它下方；只有一行署名时离标题墨迹底至少半行）。没有署名与 `TL:` 时：标题墨迹底 → 调号拍号墨迹顶空一行；
    窄纸装不下最宽一行时标题与署名整块等比缩；
  - 页首墨迹底（`PlacedHeader.bottom`，有拍号取分母墨迹底）→ 首组**真正的墨迹顶**
    （`place/song.ts::layoutSong` 的 `firstTop`：数字/高八度点、和弦等头顶记号、`W:` 文字行取最高者）。
    只按数字顶算的话，首组头顶有「引子」这类文字行就会贴上拍号（小兔子乖乖）。
    layout 不再拿 `marginTop + bodyTop` 兜底。
- **距离参数以基础字号为基准**（`metrics.ts`）：面板的字号（`digitFontSize` → `scale`）同时缩放
  `JianpuMetrics` 的 `note`（音符栅格，含 `+` 抬高级距、楔形开口）、`size`（字号）、`lyricSpacing`
  与 `spacing`（系统/声部间距）四组——组就是缩放规则；页首与首行的「空一行」本就按 `size.lyric` 推算，自动跟随。
  标题/作者的绝对 y 仍从页边量，不缩。
- **调号拍号**：分数线与减时线同粗、对准「=」墨迹的竖直中心；「=」两侧各让 0.2 字号；
  调号 → 拍号的墨迹间距等于「=」→ 调号的墨迹间距。
- **增时线**落在 baseline（数字本来就是按墨迹居中于 baseline 画的）。
- **临时升降号**用 Bravura 的 SMuFL 字形，按墨迹定位（字号取到墨迹高≈数字墨迹×0.78，
  墨迹右缘贴数字墨迹左缘、竖向中心在数字墨迹顶稍下，降号再低一点）。固定偏移会随字体漂。
- **附点、高音点、低音点共用同一半径**。
- **跨行的弧线两截都画**：一行 `Q:` 末尾还没等到 `)`，行末那截画到末音右侧半格，下一行从行首起弧画到 `)`。
  早先照《太阳出来喜洋洋》第 1→2 行（`… (6, - | 6,) (-`）的印刷原版只画后半条，可起头那个音在行末就看不出有弧，已改回两截都画。
- **未闭合的跨行弧线整条丢弃**：开弧的 `(` 若一直等不到 `)`（《同一首歌》里源码换了
  声部号：`Q3` 开弧、下一组只剩 `Q1/Q2`），连已经登记在前面各行的半条弧一起撤掉，
  原版此时什么都不画（`parse.ts` 的 `OpenMark.pending` / `dropUnresolvedCurves`）。
- **跨行弧线按声部号承接**：`carriedCurves` 是 `Map<声部号, OpenMark[]>`。
  用一个全局栈会把 `Q3` 的开弧接到下一组的 `Q1` 上，画出一条横贯整行的假弧。
- 组内声部之间用 `voiceHeadroom()` 给下一声部头顶的弧线/记号留位，
  否则四声部谱里第 3 声部的弧线会画进上方歌词块。

### 字号比例按方言分开

以数字墨迹高（数字「1」的墨迹高）为 1。番茄那列量自它的参考渲染，诗歌本那列量自
**诗歌本 App 自己导出的《圣哉三一歌》长图**（`testdata/fanqie/ref/圣哉三一歌.pdf`，
一页里嵌一张 4960×9629 的位图；四声部、四段歌词、四个 system，与
`testdata/fanqie/圣哉三一歌.pu` 逐音符对应）：

| | 番茄 | 诗歌本 |
|---|---|---|
| 歌词墨迹 | 0.82 | 1.15 |
| 和弦墨迹 | 0.78 | 0.90（底本的和弦全隐藏，量不到，沿用旧值） |
| 小节线高 | 1.62 | 1.90 |
| 词行间距 | 1.51 | 1.68 |
| 声部间距 | 2.57 | 2.07 |
| 数字字重 | 常规 | **粗体**（中部笔画/墨迹高 0.227，苹方常规只有 0.126） |

**量行距要用小节线段的竖直中心反推**，别按墨迹带估——带里混着八度点和弧线会偏
（曾把声部间距估成 23，实际 42）。**字号 ≠ 墨迹**：底本上只能量到墨迹，换算回字号要
拿本项目的 `Font.charBound` 量同一个字（PingFang SC 的「圣/哉/清」墨迹分别是字号的
0.829 / 0.905 / 0.917，三条路都指向歌词字号 24.6）。表里那 1.15 就是这么来的，
但当时**实际落值是 27**（连带行距 35），见下面「有意偏离底本的几处」（已作废）。

数字用什么字：底本的数字比苹方常规粗得多，各系统字体里最接近的是 Helvetica/Arial Bold
（笔画比 0.21 对 0.227）；黑体（Heiti SC，0.111）反而更细更窄，试过不合适。
故 `original-shige.ss` 单配 `note { family }`（落 `font.note`），与歌词那支字分开；字重是出厂的 `font.noteBold`（加粗）。

`.jpwabc` 谱面那一路同理，但那边 `numberFont` 还派生出和弦、房号、调号拍号行，
不能整支换粗体——`LayoutOptions.noteBold` 是个开关，只有音符数字与倚音走
`noteFont`（= `numberFont` 加粗）。`style/jianpu.ts` 的 `pptx` 预设与 `style/book.ts::bookJianpuStyle` 各自关掉它：
展开档要保投影的既有观感，成书要逐像素复刻印刷底本。混排（`src/mixed`）另有一套
`jianpuFont`，不经 `LayoutOptions`，天然不受影响。

#### 有意偏离底本的几处（已作废）

> **作废**（2026-10 简谱合并）：方言不再各带一套数值，（一度改由界面上选的风格样式表给，后来风格选项也去掉了，只留音符字体），
> 尺子是各格式共用的 `JianpuStyle`；下面这些数（27 / 35、写死的边距等）是当年方言数值表里的，不再是现行值，只留作取舍的来由。

照着量不等于照着抄。下面几处是当时权衡过留下的差异：

- **整体版面缩放没跟**：底本的版心宽 = 37.4 × 数字墨迹高、连续长图左右留白 35.5 / 41.7、
  上下 28.3 / 40.2、标题基线 ≈ 60、`TL/TR` 字号 ≈ 19.6；我们分别是 46.9、96（写死）、
  16（`titleY` 110、`marginTop` 80）、12.8。也就是我们的音符相对页宽小约 25%。
  改它会动到每一份诗歌本文本谱的观感，这次只改行内度量。
- **歌词字号与行距用旧值 27 / 35**（底本 24.5 / 29.6）：底本那一对在屏幕上偏小。
  这两个是**一对**，改一个必须改另一个——只收行距不降字号，四段歌词会挤成一团。
- **增时线与附点的 y 仍与音符对齐**：底本把它们分别画在锚点下 1.35 与 3.6
  （四个 system / 8 个样本一致，`1.` `2.` `4♯.` `5.` `6.` 都量过，与数字字形无关）。
  跟这两个要各多一个旋钮，不值。
- **弧线维持旧值**：底本的 `dotOffsetX` 10.6、弧峰值厚 1.73、弧顶 4.14、`slurStackGap` 6.8；
  实际渲染下旧值更耐看（弧太细在屏幕上发虚）。八度点的 y 不跟底本（15.0），按上面「净距统一」派生。
  `slurStackGap` 现在只管「弧端点离音符堆叠顶」，「低音点离减时线」改用统一净距。
- **带弧线的声部间距比底本紧 2.7**：底本里上方有弧的声部与上一声部隔 39.6（无弧时 36.9），
  我们靠 `voiceHeadroom` 动态让位算出约 30.6，于是 `gapVoice` 兜底。
  底本大概是给弧线加了一段定额，证据只有这一首，不足以定判据。

### 歌词的联合括号 `}`

行末的 `}` 把相邻几段歌词用一个右向花括号括起来（《同一首歌》：`…角落}` / 下一行 `…传说`）。

- **`}` 只写在领起的那几行上**：带号的一段连续行 **加其后紧跟的一行**才是一个括号的跨度。
  只按「带号的行」取跨度，单个 `}` 就成了 1 行，什么都画不出来。
- 尺寸对照印刷原版量得（单位 = 歌词字号）：墨迹宽 `0.40`、与末字右缘留 `0.09` 的缝、
  纵向从首行基线上方 `0.78` 到末行基线**上方** `0.16`（括号底不到基线）。
- 字形是**轮廓数据**（`layout/jianpu/compose/braceglyphs.ts::BRACE_GLYPHS`，词括号与并排块大括号各左右两向），
  横向轮廓固定、纵向按跨度 `scale(1, k)` 拉伸——番茄原版就是这么配的，等宽描边或非等比缩放的
  SMuFL `brace`(E000) 都画不出那个粗细分布（从前用过后者，已换掉）。
- **承载缩放的那层必须是裸 `PageItem`，不能是 `Group`**：`Group.update()` 会把子项归一到
  组包围盒的原点（子项空间平移、父级反向补偿），而这一层带非等比缩放，补偿量对不上，
  字形会被挪到别处去。

### 四声部版式

判据来自**印刷原版**（App 的渲染在小节线上与印刷版不一致，以印刷版为准）：

- 源码里 `C1–C4` 写在 `Q2` 与 `Q3` 之间，谱面上歌词就排在那个位置——
  **歌词夹在声部 2 与声部 3 中间**，不是每个声部各挂各的词。
- **小节线贯穿声部对、在歌词块处断开**（`barlineBlocks()`：带歌词的声部就是一块的末尾）。
- **连谱号整组一根到底**，用 SMuFL 的 `bracketTop`(E003)/`bracketBottom`(E004) 两截花头
  加中间竖线拼成（竖线长度随声部数变、花头尺寸固定，不能整体缩放一个字形）。
- 连谱号右侧还有一条**起始细竖线**，整个 system 共用一条，**不**像小节线那样断开。
- 细竖线、连谱号离音符起点多远，看段号占位要多宽——**按整页最宽的那组留**（`systemMetrics` 的 `page`）。
  段号常只印在第一个 system，按各组自己留的话只有那一组往左凸出去，同页各 system 左缘对不齐（原谱一律对齐）。
  段号文字照旧贴着本组歌词首字。
- **自动段号**（同简谱引擎 `Line.addVerseNumbers`，样式键 `verse-numbers` / `verse-number-auto-min`）：叠排的几段歌词每一行行首补「1.」「2.」…
  （`place/song.ts::autoVerseNumbers`，补成一条普通说明，版心左缘照样整份让出、不按行缩进——用户定）；源里一行写了说明（`<1.>`、`<狼:1.>`）就整行照源、不补；
  这一行有字的段不到两段不补。
- **多声部里的 `8`/`9` 可以是不占时值的占位**（`fanqie/fromfanqie.ts::markPlaceholders` → `Chord.placeholder`）：四声部本里下面的声部常写
  `3 8 -`——女高这里唱两个字，这一声部只有一个长音，`8` 垫一格好挂字，后面的 `-` 延的是 `3`。照占一拍读，这一声部比女高多出几拍，
  按拍位对声部时后面的音全错开。判据按**整声部的总时值**：每个声部有「占一拍」「不算那一拍」两种读法，全曲总时值取第一声部
  哪种读法能让更多声部对上（一样多取占一拍——各声部都垫着同样几拍的弱起，是真休止）；定了之后，照占一拍对不上、不算那一拍正好对上的声部，
  隐藏休止全记成占位。占位在对拍位（`ast.ts::elementQuarters`）与试听（`playdoc.ts`）里不算自己那一拍；123 写出与五线谱投影不认这一位。
  单声部曲不判。验：新编赞美诗四声部 438 首逐声部与 GT 转换脚本原来的两遍读法一致，GT 重生成逐字不变。
- **声部行标签的变体后缀写在段号前后都认**（`Q!2:`、`Q2!:`，`parse.ts::BODY_PREFIX`）：以前只认前一种，后一种整行被丢
  （四声部本 41 行，多在「阿们」段）。乐句重排重写标签时保留原来的位置（`relayout.ts::labelOf`）。
- 多声部同拍位的音符 x 必须一致：各声部的符号按「小节序号 + 小节内累计拍数」（小节线按「第几条」）**归成同一列**
  （`place/spacing.ts::placeColumns`），列宽取各声部里最宽的那个，单声部是它的特例。
  早先的写法是各声部各排一遍再按拍位把落后的声部右推（`alignVoices`），用「位移前的 x」预先算目标时一行被推右后续列不会跟进，越往后越歪。

### 页面

- **纵向分页走公共的 `jianpu/vertical.ts::paginate`**（与 `.jpwabc` 同一份）：`layoutSong` 只产出
  `PlacedGroup` 块，占位盒就是光标推进的那一段（头顶让位、声部、歌词、组间距都已算在块里，`gap` = 0），
  自己不再 `breakPage`。从前整组挪下页时先把光标重置到页顶、再减位移，下一组被排到页顶之上（相压 41~62pt）。
- **连谱号的花头**上下各伸出首/末声部 ≈1.5 个墨迹高（粗线探出 0.85 + 花头字形 1.18 线距）。末声部底下有歌词时
  歌词块早把它盖住；展开档里末声部这一遍没词时，相邻两组的花头会相压，`layoutSong` 只在真会相压时
  把上一块往下撑——不压的不动，原样档的行距是对过原书的。
- **原样**档（`print`）出厂是一张**连续长图**：页宽页高都按实际墨迹裁紧、左右等距留
  `continuousSideMargin`，不按纸张分页；`[fenye]` 只当额外留白。也可以换实际纸张分页。
- **展开**档不走这里的排版器：见下文「反复展开（展开档）」。
- `TL:`/`XL:`/调号拍号对齐的是 **system 左缘**（多声部时是连谱号，单声部时取音符起点与
  歌词说明左缘的较小者），不是页边距——它们不跟着音符走。
- 页宽会变，所以 `paintHeader` 里标题居中/词曲右对齐必须用上下文的 `pageWidth` 并减去整页
  平移量，不能用 `metrics.pageWidth`。
- **App 侧**：`.score-page-wrap` 的 CSS `aspect-ratio: 960/540` 是 `.jpwabc` 的版式，
  文本谱长图必须在 `renderPages()` 里按实际页面尺寸（`ScorePainter.pageSize`）设内联 `style.aspectRatio` 覆盖它，
  否则 SVG 按高度缩放，左右各留一大片空白。

### 横向排列与歌词防重叠

`layout/jianpu/place/spacing.ts::placeColumns`，**与简谱引擎同一套排法**（简谱合并成一个引擎的子计划 3c，判据整段搬自
`layout.ts::Line.calcXPos` / `adjust` / `adjustLastBarline`）：

1. **归列**：同一拍位的各声部符号一列，列的左右占位取各声部最大——数字按**字面宽**占位（锚点是数字墨迹中心，左占位 = 墨迹中心偏移），
   附点按 `·` 的字面宽、前倚音硬让位、小节线按组的包围盒（线心起一个线宽，反复点按墨迹）、行中转拍前后各空 ¼ 字号。
   行尾转拍号的，下一行行首再印一遍（`voice.ts::layoutVoiceLine` 的 `leadMeter`，挂在行首线上，没有线就补一条不画的）。
2. **紧排**：落笔原点挨着上一列的占位右缘；小节线前空「组里第一个图元高」的 1/5。行首那一列的升降号、倚音整个让出来。
3. **歌词避让**：按声部各一道游标，各段一起取最左左缘、最右右缘（字面框，不是墨迹）；前置标点悬挂 `hang ≤ lyric-gap`、
   跨音符标点挤压、西文补空格，判据与曲例见简谱引擎那边。
4. **两端对齐**（水位法）：空档按「已有宽 ÷ 权重」从窄到宽灌平，音符间权重 2、挨着小节线的 1；临时记号想多空的那截先填。
   加的总量最多是自然宽的 `max-horizontal-scale` 倍；末一条小节线贴版心右缘（离前一个音最多三个字号）。末行也照样拉。
   放不下不压缩（紧排已最紧），由窄纸重断行保证放得下。

从前是另一套：步进只按拍值走（音符 37.5、同杠 25、小节线 35、附点 +12.5，按字号缩放），再整行乘系数、歌词按墨迹撑列、
光歌词就超宽时按比例打折（会微叠）。《圣哉三一歌》长图对照原书 PDF 对过的是那一套；合并后文本谱、MusicXML 原样档的横向观感与 `.jpwabc` 一致。
`{bz}` 临时伴奏层（小字号一行）仍按旧步距自排（`voice.ts::layoutVoiceLine` 的 `x`），语料 0.05%。
验（合并期间）：`xpos-compare.mjs` 单声部与旧简谱引擎逐音比、多声部同拍位 x 相等；旧引擎删后脚本随之删掉。

### 反复展开（展开档）

**展开档没有文本谱专用的排版**：整份 `ScoreDoc` 交给与各格式同一个简谱引擎的展开档（`layout/jianpu/place/expand.ts`）——排出来就是 `.jpwabc` 的 PPT 效果（音符与歌词同为基础字号、
第一页词曲标题页、无和弦、首调号拍号不画、曲中转调/转拍号照画），设置也与 `.jpwabc` 展开档共用一份。
试听高亮按元素 id 认。

- **同号歌词顺延**：展开档一遍只挂一行词。同一条曲行下写了两行同号歌词（《同一首歌》两行 `C1:`，
  内容其实是第 1、2 段）时，`forExpanded` 把后一行顺延到下一个空闲段号（`distinctVerses`），
  各成一遍——否则两行画在同一位置相压。原样档与导出不做这一步，段号照原文。
- **只排一条旋律**：Layout 只排 `parts[0]`。`forExpanded` 把带歌词的声部换到最前
  （圣哉三一歌的词挂在 Q2）；其余声部试听照响，只是不画。导出不传这个选项，声部顺序照原文。
  `W:` 说明行、力度、和弦，展开档一律不出现。
- **遍次序列不自己推**：跳房子转成 `endingLeft/endingNum/endingText/endingRight`（房号取原文里的数字），
  `&dc/&ds/&fine/&hs/&ty` 转成 `playData.jumpTo/segno/coda`
  （「从这里跳走」的记在本小节末；「跳到这里」的挂在小节线上就是下一小节开头；两处 `&ty` 前一处是 To Coda），
  然后同 MusicXML 一样推（`score/playorder.ts::playOrderOf`），推理抛错才退回「按段数逐遍」。
  换算在 `jianpu/playsong.ts` 里、直接吃 `ScoreDoc`，投影只把结果填进 `playData`。
  `&ds` 没有 `&hs` 时回曲首（世上所有的民族），等同 D.C.。
- **换页**：往回跳（反复、D.C./D.S.）与 `endOfPass` 由 `walkPlay` 判（与 `.jpwabc` 同一口径）；
  遍号变了但往前接着唱的（二房之后 pass 归 1 的尾段）不换。源里的 `[fenye]` 写成换页（`forExpanded` 下）。
- 演唱顺序推理（`score/playorder.ts`，各格式共用）的两条判据：段数取各声部的最大值
  （圣哉三一歌的词挂在 Q2，从前只推出 1 遍）；写在 `:|` 小节上的 D.C. 先把反复唱完再跳，跳回之后不再跳
  （小兔子乖乖从前一直绕到 pass 上限，推出 10 遍）。

## 按乐句重排（`src/jianpu/phrase.ts` + `relayout.ts`）

工具栏「按乐句重排」对文本谱也生效，**两档一起变**。断句本身是格式无关的
（`score/phrase.ts::computePhraseBreaks` 只经断句输入接口读谱，与成书共用同一套权重与
同一套分页口径 `applybreaks.ts::pageBreakLines`），文本谱这一侧只做三件事：

1. **断点 → AST 位置**（`jianpu/phrase.ts::fanqiePhraseLines`）。断点是「第 n 小节之前」/
   「某个和弦之后」，文本谱的行是 `ScoreLine`，落点得换算成「某声部的第 k 个元素之前」，
   桥是「断句输入的和弦 → 元素 id → 行里的元素」（`docView` 的 `elementOf`，元素带原文区间）。
   跳词符 `@` 与超出对位格的音节不挂在元素上，切歌词用的是 `LyricLineInfo.sources`。多声部按**累计时值**对齐（`elementQuarters`），不按元素下标
   ——各声部元素个数本就不同；小节线时值为 0，按时值找过来会正落在它身上，所以还要
   `alignCut` 把它归回上一行行尾（只有 `|:` 留给下一行行首）。行内断点落在连音中间的挪到连音之后
   （`pastTuplet`）：MusicXML 拆不开连音、只能顺延到小节线，单声部的 `.jpwabc` 照原样写回就两边对不上
   （多声部全特性夹具的 `(3: 7_ 6_ 5_)` 第 2、3 个音之间有乐句信号）。
2. **行长尺子**（`FitMeasure`）。引擎量出的跨度（键为元素 id，`painter.ts::measureDocument`：只量带歌词的旋律声部、不清换行、逐行接着量）
   按元素 id 换回断句输入的和弦（`applybreaks.ts::fitForIds`）；对不上的和弦没有跨度，`chooseLineLayout` 会以为「怎么都放得下」，一律并成两句一行。
   **文本谱只有展开档给尺子**：原样档要的是印刷原版的一句一行，没有尺子就按小节数目标断，正是这个。
3. **写回原文**（`fanqie/relayout.ts::relayoutFanqieText`）。

### 为什么落到原文，而不是往引擎输入插换行

原样档走原样文档布局，吃的是排版行视图、不经过简谱引擎，那一层的断点够不着它。而文本谱里
**一行 `Q:` 就是谱面一行**，重切原文的行两档就同时就位——展开档那边行边界照旧由投影转成换行条目。改的又是用户看得见的原文：可存、Ctrl+Z 可整体撤销，
按「原样」按回去与原文逐字相同（`App._origLayoutText`）。

### 切在哪一列

元素自己的 span **不含**跟在后面的和弦与注释（`1"hx:E♭"` 的 span 只有 `1`），
按 span 直接切会把和弦切掉。所以刀落在**元素之间的间隙**里，判据是
「收口的（`)` `]`、和弦、注释）留给上一行，起头的（`(` `[`）归下一行」。跨行的弧线与跳房子
因此天然成立——上一行以未闭合的 `(` 收尾，解析器自己会接到下一行（`carriedCurves` /
`carriedVoltas`），不必补任何续接记号。**渐强渐弱是例外**：`<`…`!` 不跨行，切在中间要在
上一行行尾补 `!`、下一行行首重开一次（`pieceText`）。

### 歌词跟着切

切点按「该断点之前有几个跟词元素」（`takesLyric`）定位到 `LyricSyllable` 下标，再按音节的
列切原文子串——音节之间的原文（跳词符、分词符、括号、并字号）都跟着走。几条源行并成一行时
按**段**把切片接起来，段的身份是「段号 + 它在源行里是同段号的第几条」：`C1:` 在同一条曲行上
出现两次是番茄谱的常态（《同一首歌》两段词都写成 `C1:`），只按段号并会把两段揉成一段。
接的时候还要**补齐音节数**（歌词行常比曲行短，《卖报歌》14 个字配 15 个音），短了不补，
后面接上来的字就整体前移一个音。反过来，重排后一个字都不剩的段**不占行**
（73《我主耶稣是生命源》的副歌只有第 1 段有词，照印就是三行空白）——段号写死的才敢丢，
番茄的裸 `C:` 按出现顺序编号，丢一条后面全串位。

### 两条判据

- `jianpuinput.ts::marksEdgeAt`：跨行的续接端**不是真端点**。一条弧被换行切成两个 Mark
  （`continuationFromPrevious` / `continuationToNext`），照直取两头会在行尾收一次、行首再开一次，
  就成了两条弧——谱面上明明只有一条。多连音同理。
- 源里的 `[fenye]` 在展开档写成换页（只在 `forExpanded` 下），否则展开档只会按页高自己折，作者标的分页全丢。

### 已知边界

- 重排**重建行结构**：原文的空行分组、`[fenye]`、行内手工留白会被覆盖（这正是这个功能的语义）。
  头部字段、`W:` 文字行、`-----` 原样保留；一键切回「原样」无损。
- `{bz…}` / `{dsb…}` 临时层是顶层元素，断点只落在顶层元素边界，不会切进它内部。
- 多首（`-----`）逐首各自断句。

## 与其它格式互通

### 公用代码

- **和弦符号**：`engrave/chord.ts` 是五线谱与文本谱共用的。`layoutHarmonySegs()` /
  `harmonyWidth()` 从 `mixed/render.ts::drawHarmony` 抽出（五线谱已改为调用它）；
  `chordTextSegs()` 把文本谱的和弦**字符串**解析成同样的分段。
  规则一致：根音升降号用 SMuFL csym 字形、`m` 留基线、后缀上标、`/低音` 跟后面。
  导出侧另有 `src/score/harmonyxml.ts`（和弦字符串 → `<harmony>`，解析不出根音退回
  `<direction><words>`），文本谱直出与简谱 OMR 共用同一份。
- **弧线**：直接用 `layout.ts` 的 `Slur`（`SlurTieBase.init`），不另画。
- **OMR 和弦**：图片识别出的和弦经 `"hx:…"` 落进文本谱原文，见
  [OMR 简谱识别 · 和弦符号](OMR-简谱识别.md#和弦符号chordlinets)。
- **增时线上的和弦**：`"hx:…"` 不止能挂音符，也能挂增时线（`1"hx:G" - -"hx:C/G" 0/`）——
  长音里逐拍换和弦时，谱面就把后几个印在增时线上方。解析挂到 `SustainElement.chord`，
  排版留头顶、按同一套富文本分段绘制，导出 MusicXML 时折成带 `<offset>` 的 `<harmony>`
  并插到所辖音符**之前**（`<harmony>` 必须排在它所属的 `<note>` 前）。
- **写出端**：`ScoreDoc` → 文本谱原文在 `src/fanqie/tofanqie.ts::emitFanqie`，判据见下一节「写出端」。
  `src/fanqie/` 自身只做解析那一半；识别结果也先转模型再由它写（`omr/emit.ts`）。
- **PPTX**：`buildPptx` 吃结构类型 `PptxSource`（页面、`stackGap`、页面尺寸），由 `ScorePainter.pptxSource` 给出，
  页面取简谱引擎展开档那一份（见 [排版-展开与原样两档](../模块/排版-展开与原样两档.md)）。

### 写出端（`fanqie/tofanqie.ts`）

照 `fanqie/fromfanqie.ts` 反着写，每一处写法以 `fanqie/parse.ts` 为准。方言差异全在 `DialectSpec.header` / `DialectSpec.emit` 两张表里。
回归 `fanqie-emit-roundtrip.mjs`：文本谱自身往返（音乐投影不变、第二轮文本逐字不动）与 123/ABC/`.jpwabc` 跨格式（投影一致，
丢失清单报了的方面不计），两方言各一遍。弧线例外：报了 `nestedArc`/`oddTuplet` 时只许少 `fanqieArcLosses()` 那么多条、不许多；
速度两边都折成四分再比（`♩.=60` 写成 `♩=90` 是对的，文本谱只认 ♩）。

- **先投成简谱形状**（`projectForJianpu`，同 123 写出端）：ABC/MusicXML 的时值才有减时线/增时线/附点，ABC 的延音线才配成弧；
  只有绝对音高的补度数（`fillDegreesFromPitch`，在克隆上补）。
- **没有左线**：文本谱的小节线一律「收」一个小节。模型里的左线（123/ABC 的 `|:`）并到前一小节的右线上写
  （`:|` + `|:` = `:|:`），不然两条线夹出一个空小节；曲首的 `|:` 照写在行首（文本谱原文本来就这么写，读回是一个只有线的空小节）。
  同一种线有几种写法的，取方言表里**最后**那条（`:||` 之于 `:|`、`||/` 之于 `||`：长的是规范外写法，只认不写）。
- **括号是一个队列**：弧线、延音线、多连音共用 `(` `)`，`)` 永远收最早开的那条（`curves.shift()`）。
  所以「先开的不晚于后开的收」才写得出；一条完全包住另一条的写不出，按「多连音 > 延音线 > 圆滑线」留（`planArcs`），
  丢的条数进丢失清单（`nestedArc`）。多连音里 n 个符号一律占 n−1 个基本时值，别的比例写不出（`oddTuplet`）；
  文本谱读进来的多连音没有显示数字，本来就是 n:n−1，不校验。
- **括住相邻两个同音的括号是延音线**（`(2/ 2)`、跨小节线的 `(4'// | 4'//)`）：模型里照旧存 `slur`（编辑的 `openSource`、
  写回 `planArcs`、简谱画法都不动——给 `Note.tie` 会让 `jianpuinput.ts` 再画一条弧），到用的地方才判：
  投 MusicXML 时 `xmlproject.ts::normalizeMarks` 改成 `tied` 并补两端 `Note.tie`（五线谱画延音线、导出带 `<tie>`），
  试听在 `jianpu/phrasesong.ts` 标 `tieStop`（见 [播放](../模块/播放.md)）。后一个音没写记号算沿用（`(4# 4)` 是），写了不同的不算（`(4 4#)` 不是）。
  123/`.jpwabc` 的括号经同一处投影，也一样。**ABC 与 Muse `.jcx` 不判**（它们的延音线写 `-`，括号就是圆滑线；
  `xmlproject.ts::hasTieSyntax` 按 `ScoreDoc.sourceFormat` 定，投影的 `slurTies` 选项、试听 `buildMeasures` 的 `pitch.slurTies` 都看它）。
  反过来简谱口径的歌写成 ABC / `.jcx` 时，写出端先用 `slursAsTies` 把这种括号换成 `-`（`(1 1)` 写成 `C- C`），读回才还是延音线；
  ABC 的 `(A A)` 写成 123 / 文本谱则成了延音线（简谱写不出相邻同音的圆滑线）。
- **跟词**：音符一律跟（写不出「不跟」）；休止缺省不跟，带字或 `lyricAnchor` 才写 `0@`；承接的 `-` 与增时线跟词写 `-@`；
  不可见休止写 `8`（跟词），诗歌本不跟词的写 `9`，番茄没有这种写法只能写成显形 `0`（写 `8` 会多吃一个字、整行错位）。
  对位格**按写出顺序**收集，歌词行照它逐格写，不另算一遍。
- **歌词**：单个汉字、纯 ASCII 单词裸写，其余包 `{}`；收尾标点（含 `.jpwabc` 连在字里的「恶，」）拆到括号外，读回照样贴前字。
  文本谱读进来的按原来的行版式写（`Print.lyricLines`：段号区间、段说明、间隙、联合括号、同段多行）；
  别的来源按字上的段号归行，同一格同一段挂了几个字（`.jpwabc` 同一段写了两行词）按出现次序分成几行 `C1:`。
  诗歌本的中英对照谱（第 1 段汉字、后面几段全是拉丁字母的译词，都不带印刷段号）各行都写裸 `C:`——诗歌本把译词与中文
  同算第一段；裸 `C:` 读回来按出现顺序编段，段号不变（青年诗歌 22《将一生奉献》）。英文词尾带半角标点的照样补词间分隔（`You, dear`）。
- **房号**：123/ABC 的 `[1 … [2` 前一个没有收尾记号，新房号起头处与曲末由写出端收口；文本谱读进来的不收（原文里开着就开着）。
  番茄的 `]` 写在线前，补的收口也插在刚写的那根线前面——否则读回来收尾挂到线上、下一轮写到线前，文本不幂等。
- **减时线连断**：原文就有 `~`/`^` 的（文本谱读进来的）照写；别的来源照诗歌本谱本的范式补（复拍子三个八分一组、切分处写 `^`，
  见 [OMR 简谱识别](OMR-简谱识别.md) 的「减时线的连断」）。跨行开口的小节拍位**接着上一行算**，否则读回来成了两个小节、
  续行从 0 重算，补的记号就挪了位置。补的记号不往多连音里插（会算进多连音的符号个数）。
- **行**：一行 `Q:` 就是谱面一行、不自动断行，所以模型里一处换行都没有的曲子（整首写在一行的 ABC）先按乐句断好
  （`relayoutDocBreaks`，出厂小节数目标）再写。
- **头部**：曲号在番茄拼回标题前、诗歌本写 `XL:`；ABC 的 `X:` 是文件内编号，不写。调号优先原文（`♭A`）、其次拼写、最后按 fifths 推；
  诗歌本的 `1=` 行写字母在前；读入时升降号前后都认（`1=Eb` / `1=bE` / `1=♭E`，手工谱库里三种都有），
  前缀式要求后面紧跟**大写**音名，`1=Bb` 仍是 B 加后缀降号。诗歌本空的 `TR:` 也照写（谱本拿空行把右侧的字往下顶）。
  **小调写 `6=e`**：主音唱名是 6 的，诗歌本写小写音名（`6=e4/4`、`6=c#4/4`），读入不分大小写；调号按「唱名 6 是 E」
  退到 `1=G`（`keyshift.ts::fifthsOfSpelling`）。没有拼写的（识别出的小调只记 fifths + 主音唱名）取主音音名
  （`tonicSpelling`），不取同调号的大调名。番茄的 `D:` 写不出主音唱名，退成同调号的大调名（丢失清单「主音唱名」）。
  番茄不写页眉页脚与版面指令字段——写了会被 `sniffDialect` 判成诗歌本。自由文字行只写读回不会被当成字段/曲行/注释的。

### 换算要点

- 时值 `dur = beats × (附点) ÷ 2^减时线 × (多连音比例)`，与 `.jpwabc` 导入端同构。
- 反复线 `|:` 挂到**下一小节**的 `repeatForward`，不写进本小节的 `barline`（`.jpwabc` 写出端认不得 heavy-light）。
- 小节与弧线状态必须**跨行存活**（放在 Builder 上，不能按行重置），否则整行并成一小节。
- 行末 `|` 紧接下一行 `|:` 会连着两条小节线，中间没音符——**不能凭空造空小节**，
  要合并并把房号顺延到下一小节的左侧小节线。
- 播放高亮：播放器给的是元素 id，两档谱面都按 id 索引；**同一份文本只解析一次**（`App.currentScoreDoc` 缓存），
  重新 parse 会得到另一批 id，高亮就对不上。
