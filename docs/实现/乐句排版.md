# 乐句排版（`src/score/phrase.ts`）

工具栏「按乐句重排」：不用导入时的行结构，按乐句重新断行。`computePhraseBreaks(part)` 在候选断点上跑
类 Knuth-Plass 的 DP（行长以**小节数**计，目标 4、下限 3、上限 7），断点强度来自歌词标点/延长号/长音/
休止/终止线/重复段边界。

> **2026-10 简谱合并成一个引擎**：旧简谱引擎（`layout/layout.ts` 的 `Layout`/`Line`、`entry.ts`、`jianpupages.ts`、`LayoutOptions`）已删，
> 原样文档布局改名 `layout/jianpu/` 成为唯一的简谱引擎（见 [模块/排版-简谱引擎](../模块/排版-简谱引擎.md)）。下文按时间记下的判据，
> 提到旧引擎的函数名是当时的实现位置；判据本身已搬进新引擎（或写明作废）。

**断句只经输入接口 `score/phraseinput.ts` 读谱，与源格式无关**。输入由 `ScoreDoc` 拼，两个适配器，
口径分别与简谱引擎输入的对应分支一致（简谱形状那一路由 `../dev/scripts/phrase-dual-check.mjs` 逐字段对拍）：

| 适配器 | 吃什么 | 口径同 |
|---|---|---|
| `model/phrasedoc.ts::phrasePartOfDoc` | MusicXML 形状的 `ScoreDoc`（成书） | 原 `jianpuInputOfXml` 的口径（已删）；另读段落标记，跳转小节 `phraseJumpMeasures` |
| `jianpu/phrasesong.ts::phrasePartOfSong` | 简谱形状的 `ScoreDoc`（文本谱/123/ABC，经 `docView`） | `jianpuInputOfDoc(…, { forExpanded: true })` |

两个适配器都给 `idOf`（输入和弦 → 元素 id），断点与量宽都经它换到别处：

| 消费者 | 输入 | 写回方式 |
|---|---|---|
| 文本谱 `.pu`（编辑器） | `phrasePartOfSong` | `fanqie/relayout.ts::relayoutFanqieText` 重切 `Q:`/`C:` 行（经 `idOf` 回原文），见 [文本谱 · 按乐句重排](文本谱.md#按乐句重排srcjianpuphrasets--relayoutts) |
| 123 / ABC（编辑器） | `phrasePartOfSong` | `jianpu/docrelayout.ts::relayoutDocBreaks` 把断点写进 `Print.newSystem`/`newPage`，整份按 `emit123`/`emitAbc` 重出，注释再由 `spliceComments` 缝回去 |
| `.jpwabc`（编辑器） | `phrasePartOfSong` | `jianpu/docrelayout.ts::relayoutJpwabcText` **只挪 `.Voice` 里的 `$`**，别的节一个字不动 |
| 成书（pdflayout） | `phrasePartOfDoc` | `applybreaks.ts::applyPhraseBreaksToDoc` 按元素 id 把断点写进文档克隆 |

**注释要缝回去**（`spliceComments`）：注释不进模型（解析器读到 `%` 就跳），整份重出自然就丢了。
每条注释跟着**它后面那条音乐行**走（注释说的是下面那段谱），落点用「第几个和弦」认——两份文本
内容一样，序号对得上、行号对不上；文件开头那一批留在开头，全曲之后的追加在末尾，`%%` 指令
不当注释收（等价 `I:`，已经进了模型、写出端自己会写）。

编辑器那三条的落点由 `jianpu/phrase.ts::phraseCuts` 给（新行从哪个元素起：`id` 给写模型那条路、
`source` 给改原文那条路）。**小节中间的断点**（弱起谱的乐句尾常落在这儿）三种格式都**原位保留**：`.jpwabc` 的 `$`
写在小节中间；123/ABC 记成 `Chord.lineBreakAfter`，写出端在那个音后写 `$` 并收一行、各段歌词跟着归行
（123 §9）。早先 123/ABC 挪到下一根小节线（顾虑代码行中间的 `$` 让歌词块跟着断），结果弱起句的头几个字
留在上一行行尾，与 `.jpwabc` 排得不一样；改原位后 `phrase-relayout-check` 与 ABC 重排的音符/歌词指纹、
幂等均不变（62 份 123 里 21 份行结构变了）。
排版那一侧同样认原位：展开档原来只有 `.jpwabc` 断在行末那个符号之后，其余格式顺延到小节末
（`place/expand.ts::sourceBreaks`，为的是文本谱一行排不下自己在小节中间折的）；现在行末那个和弦带
`lineBreakAfter`（源文写明的小节中间换行）就原位断，「脚步」123 展开档与 `.jpwabc` 一致。
文本谱一行 `Q:` 就是谱面一行，行在小节中间收尾本来就是写明的换行，展开档同样原位断（`expandSong` 的 `rowIsLine`）。

**编辑器四种格式用同一把尺子**（`App._fanqiePhraseMeasure`，`.jpwabc` 原来不接尺子）：乐句行在原样档放不下时，
排版器会整首按宽度重断（`reflowLineStarts`），乐句结构全丢——不量的 `.jpwabc` 与量了的 123 就排得不一样。
量了还得真去切：编辑器那条路 `chooseLineLayout` 格数传 0、只给尺子，而 `evenLayout` 原来见格数 0 就原样返回，
放不下的行照样交出去；现在有尺子就照尺子补刀（「脚步」原样档第 3、5 行在「信心，」「顺服你，」处补一刀，行首仍是乐句起头）。
文本谱原样档原来不给尺子（怕「两句并一行还宽绰」，73《我主耶稣是生命源》一行排了 8 小节），于是同样被整首重断。
现在原样档各格式都给尺子，但尺子带 `noPairs`、`chooseLineLayout` 不走两句一行，只判放不放得下——73 重排结果逐字不变。

量宽：引擎量出每个音（键为元素 id）的自然跨度（`place/reflow.ts::naturalSpans`；编辑器经 `painter.ts::measureDocument`、成书经 `measureBookSpans`），`applybreaks.ts::fitForIds` 换成断句输入的键。
跨度带两个右缘：`x1` 到音为止（匀度、行宽比用），`x1b` 含紧跟的小节线（与版心宽比「放不放得下」用，同引擎折行），见 [成书排版](成书排版.md)。

换页同一个口径：`applybreaks.ts::pageBreakLines`（段末行号 + 每页至多 `pageLines`（编辑器 4）行）。

- **一页 4 行是分页与断句共用的那个数**（`PhraseOptions.pageLines`）：
  - **末页排满**（`computePhraseBreaks` 第一遍 DP 之后那一道）：整首排下来若剩个半空的页，
    就把行数凑到 4 的倍数再排一遍。001《圣哉，圣哉，圣哉》16 小节原来排成 4+6+6 三行
    （行长代价 8，正好被「少断一次」省回来，默认权重下打平），而一页装得下 4 行——
    投影时空掉四分之一页、两条 6 小节的行还挤。凑满之后是干净的 4+4+4+4，正是它的乐句结构。
    重排用 `lenWeight × 4`（道理同 `tryWant`：行长权重是 1 时断点代价一压就把行数拉回去），
    且**凑出来的每行仍得够厚实**（`MIN_MEAS` / `MIN_CELLS` 满足其一），否则维持原判
    ——5 行的曲子不会为了凑 8 行被切碎。成书那条路不传 `pageLines`，一分不受影响。
  - **段界换页是「放不下才换」**（`balanceVoicePages` 里把相邻段并组）：逢段必换会把
    006《颂赞归与耶稣圣名》的一遍（主歌 2 行 + 副歌 2 行，正好一页）拆成两页各 2 行；
    005《荣耀归与天父》主歌 4 行 + 副歌 4 行一页放不下，那才在副歌前换页。

- **段落分段**：`Measure.sectionMark`，**各格式同一个判据**、在 `ScoreDoc` 上判（`model/helpers.ts::sectionMarkOf`）：
  MusicXML `<direction>` 的 `<rehearsal>`/段落词 `<words>`，123/ABC 的 `"^Chorus"` 与文本谱的段落注记（和弦/增时线的
  `sectionWord`），去掉【】（）[] 括号再认；段落词表 `SECTION_WORD_RE`——**不含 Fine/D.S.**，那是终止记号不是段落起点。
  两个断句适配器都读它（编辑器那条路 `phrasesong.ts` 原来写死 null，123 标了 Chorus 也不分段——「脚步」）。
  标记挂在哪个音上不作数（常挂在副歌弱起、甚至上一句收尾那一小节），只当大致位置，段界由下面的 `aroundSectionPickup`
  按句号定。写在小节**所有音之后**的 `<direction>`（`afterElements` 到了小节末）标的是下一小节，断句输入
  （`phrasedoc.ts`）按 `sectionMarkOf(m, prev)` 归过去（433《福杯满溢》「（副歌）」写在「福 无 边。」之后）。
  成书语料里 133 处带括号的「（副歌）」随之认得了；起初 135/433/446/491 四首段界切在主歌末字之前、断句变差，
  按下面「收尾占了新小节开头」两条修回后整本断句与排版快照逐首不变 →
  `PhraseBreaks.sectionStarts`。段首**硬换行 + 另起一页**（主歌/副歌不同页），且**每段独立跑 DP**
  （否则 DP 会为凑均匀行长把上一段末尾并进本段首行）。只有 1 行的段（如前奏）不单独占页、并入下一段。
  段界落在段首小节前；那里若 slur/tie 未闭合（长音 tie 连到段首音，如 `5__|5---|5`）**顺延到弧闭合处**
  ——延续音留在上一页、弧才画得完整（跨页的弧渲染不出来）。**只顺延到弧闭合，不再往后凑整小节**：
  段首小节就此拆成两半，但段落的起句（超长音收尾之后、重复段的第一个音、带唱词的那个音）留在新页
  行首。凑整小节会把整个起句让给上一页，反而丢了段落开头。
  **展开档副歌前换页**（`place/expand.ts`）读同一个 `sectionMarkOf`：标了 Chorus/副歌 的，换页落在离它最近的行首
  （标记小节或下一小节里起头的第一行——源里的行首，按乐句重排后就是乐句起头），不逐音认弱起；源里附近没有行首的才在标记小节前断行。
  这样不写换页的源文（换页只在模型里、源文没写）也按副歌分页：「脚步」各格式展开档都是主歌 2 行 + 副歌 4 行。
  `.jpwabc` 没有段落词的写法，只能靠「这一小节起只剩一行词」那条判据。
  **副歌（refrain）起点同样是段界**：副歌首音之前的段界由 phrase 自己给（`PhraseBreaks.refrainCut`）。
  早先另有一处写出端在副歌前强制断行并分页，phrase 不知情就按自己的乐句信号在别处断，两者叠加把中间
  那点内容甩成孤零零一行（「从前所珍爱」曾一行只剩一个休止）；那处强制断行已随旧写出端删掉。
- **重复优先作行首**：旋律指纹与**歌词指纹**各自按位移扫出**极大**重复连续段（≥2 小节，逐个长度枚举
  会把所有子段边界也塞进来、等于没有边界），其两端给 `BASE_BREAK` 满分 → 在此断行完全免罚。
  重复乐句排进相同行结构是简谱惯例，也最贴近原谱分行（日光之下前两行因此与原图一致）。
  边界要**按弱起回退**：重复段的起句常写成弱起，第二遍的第一个音落在上一小节末，边界压在它
  之后就把那个字留在了上一行——009《荣耀归与至高神》的 `…天下万有赞祂不休， | 天上众军…`，
  「天」是下一句的头一个字，却被留在行尾，「天上」被拆开。故往前找最多两个音，那里若有句读
  标点就把边界移过去（`retreatToPunct`）：断在标点上，两句相同的旋律也各自从行首起唱。
  只跨得过**短音**——一遇长音就停，那是上一句的收尾，边界本就该落在它之后。
  这条对编辑器那条路同样生效：15 首基线里「从前所珍爱」由 `…贪爱这世界，危 | 害我命…`
  改成断在「曾以为有益，」之后，其余 14 首分行不变。
- **slur/tie 先栈式配对**：识别出的弧常不成对，一个悬空起始就让 depth 永不归零、此后再无候选断点，
  整曲退化成一整行（「主祢真伟大」第 13 小节起）。未配对的起始/收尾一律不计深度。
- **行长目标可以由容量折算**（`targetMeasForCells(part, cells)`，成书重排走它，编辑器那条路不用）：
  一行放得下 `cells` 格、本曲平均每小节 `x` 格，目标就是 `cells / x` 小节（钳在 3~12），
  且 `targetMeas` 一旦大于默认的 4，`MAX_MEAS` / `MAX_SENTENCE_MEAS` 也跟着目标按 ×1.3 / ×1.4 放大
  ——那两个固定值是按「目标 4 小节」调出来的，配上 9 小节的目标就成了硬顶，DP 只能改断在别处。
  **配套要把 `lenWeight` 调小**（成书用 0.25）：目标已经就是版心宽，行长代价再重就会压过
  「断在乐句收尾处」。判据与实测见 [成书排版](成书排版.md)「数据重排版」里行长的那几段。
- **行长约束是软惩罚**：可断点稀疏时（副歌里弧线跨小节连成一片）硬禁会无解。除小节数外还限
  **每行格数** `MAX_CELLS=25`（格 = 音符 1 + 每根增时线 `DASH_W=0.7`——增时线渲染得比数字窄，
  按 1 整格算会高估长音行、把「超长音收尾」挤到下一行去），否则密集副歌会排出 28 格的行、超页宽被折行。
  **一整句独占一行**（行尾恰是句末、行内不跨句末）时上限放到 `MAX_SENTENCE_MEAS=8` / `MAX_SENTENCE_CELLS=33`
  ——实测 8 小节 32.5 格仍进得了版心（「我們成為一家人」副歌 `因著耶穌得潔淨，…同享復活的生命；`）。
  配套惩罚「在句中提前拆行」（`SPLIT_SHORT_SENTENCE_COST`），但**只在断点处没有乐句收尾的音乐凭据时**：
  凭据 = 长音 ≥`LONG_NOTE_BEATS=3` 拍 / 延长号 / 休止，**歌词逗号不算**（句子内部本来就有逗号，拿它当
  凭据等于允许任意在句中拆）。作曲家在真正的气口上留的音明显更长：「耶稣普治」每句中间的逗号落在 4 拍
  全音符上 → 照拆，维持一句两行；「我們成為一家人」副歌句中的逗号只有 2 拍、4 拍留给句末 → 整句一行。
  段落标题若落在新小节、而上一句的 1~2 个收尾音占用该小节开头，则段界移到句号之后。收尾音**长短都认**
  （135 `方。` 3 拍、491 `安。` 4 拍；从前只认 1 拍以内的短音），句号被 `carryOn` 顺延到紧跟休止上的也算
  （446 `虑？`，`endsSentenceAt`）；段界落在句末字上时，同小节里紧跟的四分及以上收气休止一并留在上一段
  （`pastBreathRest`，否则与副歌歌词那条段界切在休止前后两处，成书不许行内断，夹出一小节一行）。
  `MIN_MEAS` 对非段末行是硬约束，但**与 `MIN_CELLS=14` 满足其一即可**：行从小节中间起头时（前一行
  在长音 tie 收尾处断）按小节数算会偏小，内容量其实够。段末/曲末行虽可短，也**加软罚**——否则会
  甩出只有一小节的尾巴——该软罚**同时认格数**（`MIN_CELLS`），因为小节短促的谱按小节数量不出来
  （「基督更美」每小节才 4 格，末行 3 小节合规、实则只有 7.7 格）。
- **行内断点（非小节末）另加罚 6，但只压弱信号**：简谱通常在小节线换行；而句号/长音/延长号/重复边界
  （score≥4）落在小节内时，那本就是乐句真正的收尾处，不该因「没赶上小节线」被罚。弧收尾本身只给 1 分
  （让它进入候选——密集副歌里小节末全被跨小节的弧封锁时，那是唯一能切开长行的地方）；但**它收的若是
  一个长音**（`5---|5)` 这种 tie 延续），把长音的 4 分带过来 → 乐句就在这里收尾，断点跟着落在小节内。
- **重复边界/段界顺延过长音 tie 组**（`advancePastLongTie`）：边界之后若紧跟 `(5---|5)` 这样的长音弧，
  那是上一乐句的延音收尾、歌词也还是上一句的末字（「手心中」的「中」），不该充当新乐句的开头 →
  顺延到弧闭合之后。**段落标记（Chorus）落在这种长音的小节上时同样顺延**：「立定心志」的
  `…来呼喊哈利路|(2'- 2'_) 我立定|心志…` Chorus 标在「亚！」那一小节，顺延后「路亚！」留在上一页行尾。
- **分号 `；` 与句号同级**（`PUNCT_END`）：分号并列的是两个完整分句（「…忧伤的权利；我要宣告…」），
  乐句同样在此收尾。改后「立定心志」第 3、4 行同以「我要…」起头、旋律对齐（「爱是不保留」的
  「…刺穿的手；| 看！血在流…」同理）。
- **副歌弱起放宽到 3 个音**（`aroundSectionPickup`）：副歌唱词从「心志」起标，乐句实际从「我立定」起唱
  ——回看 3 个短音、落在句末标点（「亚！」）之后切段。副歌段界只由 phrase 这一处给
  （`PhraseBreaks.refrainCut`，判副歌首音的两道护栏在 `score/phrase.ts`）：若别处再断一次，会在
  副歌前甩出「我立定」这样的半行。
- **弱起休止归下一段**（`retreatPastPickupRest`，套在 `aroundSectionPickup` 入口）：段界断点落在
  **八分及更短的休止**上时，那休止是新段弱起组的起拍留白（「再次将我更新」副歌前的
  `(2'-) | 0_ 5_ 1'_ 2'_ |3'.`，休止与其后三个八分同属一个弱起组），挂在上一行行尾——尤其页尾——
  很难看 → 回退到休止之前，让它随副歌起句进新页。**四分及以上休止相反**，是上一句唱完的收气
  （「基督更美」的 `1 0`、「世上所有的民族」句号后的 `0`，`punctAfter` 的 `carryOn` 本就把句号顺延
  到它们之后），仍留在上一行。回退处若落在弧中（不可断）则维持原判。15 首里只有本曲受影响。

- **换行条目必须带 `position`**（`jianpuinput.ts::breakAtMeasureEnd` / `breakAfterChord`）：
  引擎装载小节时按 `position` 稳定排序条目。position 留 0 的断点会被排到
  **小节第一个和弦之后**（同为 0，稳定排序保相对序），小节后半的和弦就落到断点之后 → 行尾切在
  句末长音与标点之前，「宰！」「乐无尽；」这样的收尾字被甩到下一行行首。规律是
  **只有断点小节含多个和弦时才错**（001《圣哉，圣哉，圣哉》的 M4/M12 错、M8/M16 只有一个 4 拍音没错）。
  故小节末换行取本节各条目的最大 `position + duration`，行内断点取 `断点和弦.position + duration`。
  三个投影分支与成书写回都走这两个函数。

- **反复房（ending）整体不可拆**：房是「这一遍才唱的那几小节」，断在房中间，反复记号与房号就没法画了
  （010 的第一房只有一小节 `苍。我要`，断点落在「苍。」后面就把它劈成了两行）。
  只有房的**最后一个小节末**可断——那里正是 `:‖`，还额外加 6 分（房收尾是天然的换行处）。
  **房必须闭合才算房**：OMR 识别出的谱常只认出房号的一端，把「开着的房」一路认到曲末，
  那样整首都成了不可断区（15 首基线里「爱是不保留」「沧海一声笑」曾被封死）；房也不该长过 `MAX_MEAS`。
- **前奏/间奏与唱段的交界**加 6 分（按**小节**判：连续 ≥2 个无词小节之后的第一个有词小节）。
  按音符判会把断点定在唱段第一个字之前、把小节劈开——唱段的第一个字常是弱起、写在交界小节的末尾。
- **行首不留孤零零一个休止**（回溯之后的收尾，`applybreaks.ts::tidyLineHeads`）：断点之后只剩一个
  休止就到小节线的话，下一行开头是个「空拍」，把它并到上一行（193 首；15 首基线里的《脚步》
  也跟着变好）。整小节都是休止的同理。放不下时容量保险会再切开。
  这一条是**兜底**——同样的判据在 DP 里已经罚过一遍（下面 `headPenalty` 的 (a)），
  但 `enforceLineCapacity` / `mergeShortLines` 会在 DP 之后造出新的行首，那些 DP 管不到，
  所以成书那条路在并短行之后还要再调一次 `tidyLineHeads`。
- **行首长什么样：`headPenalty` 的三条**（2026-08-25 加，两条路都生效）。都是「断点之后那一行的
  头好不好看」，做成断点代价而不是事后搬音符——这一行放不下时 DP 会自己改在别处断：
  - (a) **行首残小节里一个音符都没有**（半小节休止 + 小节线）+12。整小节的休止不在此列
    （整节归上一行或下一行都行）。同源地，段界的 `retreatPastPickupRest` 遇上「休止正好收在
    小节线上」时不再回退——回退过去下一行就只剩这个空拍（020《向主歌唱》）。
  - (b) **行首是半拍及以下的休止、且这一行的弱起与本曲的弱起不一样长** +8
    （本曲弱起 = 首小节不完整时它的时值）。372《跟随耶稣》弱起是整 1 拍，第 2/4 行却从
    `0_ 今. 已_` 起头（1.5 拍）。**「半拍休止 + 半拍音符」本身没问题**——只要与本曲弱起一样长就不罚；
    四分及以上的休止也不罚，那是上一句唱完的收气。（这一条曾按「残小节长度差多少就罚多少」写，
    范围太宽，把「一生中最可 / 贵」劈成了两行。）
  - (c) **行首是带句读标点的长音**（≥2 拍）+10：那是上一句真正的收尾，该留在上一行
    （373《跟随我》每行都收在「跟随我，」上）。只罚带标点的——不带标点的长音也罚会把长音多的
    谱切碎（「主祢真伟大」多出一行只有 2 小节）。
- **出几种方案再评分选优**（`evenWeight`，默认 0 = 关，成书传 2）：第一遍 DP 只保证「放得下」，
  一段顶着版心、另一段只有半幅（051 排成 12/14/24 格）。开着时以第一遍的行数为底，
  每段各试「+0/+1/+2 行」，逐个组合跑一遍 DP，再按「行长方差 + 断点弱度 + 每行 20 分」评分选优。
  超容量罚 100 起（排版器会硬折出两三格的尾巴，比多排一行难看得多）。
- **`cellsAreItems`**（默认 false，成书传 true）：`maxCells` 的单位。`cellsOf` 把增时线折算成 0.7 格，
  而成书的容量是排版器**数出来的个数**；两把尺子混用会把长音多的行判成「放得下」而实际折行。
- **别把一句话的最后一小截甩到下一行开头**（`tailWeight`，默认 0 = 关，成书传 1）：
  断点之后不到一行三成就到句号的话，那截尾巴该留在本行（419 的「却成了祝福。」）。
  默认关——15 首基线里它会把「…尽见于刺 / 穿的手」劈开。
- **行末别只挂着下一句的头一两个字**（同 `tailWeight`）：断点前一两个字就是句号的话，
  那是下一句的起唱（062《神的保护》行末挂着「从」，下一行从「上主而来」起唱）。与上一条对称。
- **末两行别一长一短**（`lastPairWeight`，默认 1）：一段的最后两行长短悬殊最扎眼，而普通的行长
  代价管不到它（末行本来就允许短）。DP 倒着算，评估 `a→b` 时 `nextB[b]` 已定，据此看得到
  「在 b 断的话末行会有多长」，按差的平方罚（封顶 40）。前瞻启发式，不保证全局最优。
- **标点顺延也过八分休止**，并把长音的分带过来（`carriedFrom`）：句子收尾的长音后面跟半拍休止、
  再接下一句弱起时（`…呼， | 0_ 今. 已_ |`），标点原来只顺延到四分及以上的休止，
  于是「断在长音后」比「断在休止后」还便宜，那半拍休止就挂到了下一行行首。
  休止之后再跟休止仍在原处落定（「世上」句号后 `0` 落定、不吞下一句 `0_`）。
- **两条成书专用的权重**（`PhraseOptions`，默认关，编辑器那条路的基线不动）：
  - `shortSentenceWords`（成书传 5）：从上一个标点起 ≤5 字的分句，句末标点的分**减半**。
    「哈利路亚！」这种呼语句句带感叹号，与整句同权会主导整个行结构
    （015 结尾三句「哈利路亚！」，按句末断会把第一句留在上一行、与第 2 行开头那段更长的重复对不齐）。
  - `repeatLenBonus`（成书打开）：重复段边界按**重复长度**加分（`min(10, 6 + 小节数)`）。
    封顶 10 —— 再往上会盖过「句末长音」（6 + 4）那种最硬的乐句收尾，把下一句的弱起拽到上一行行尾
    （基线里「爱是不保留」的「惟求」就是这么被拽走的）。
