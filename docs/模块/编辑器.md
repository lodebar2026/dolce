# 编辑器

**判据全录** → 无单独实现篇；各格式的差异见各源格式页

## 职责

编辑器控制器（编辑 ↔ 实时重排 ↔ 翻页 ↔ 文件 I/O）、源格式适配、点选高亮与双向定位、设置、Tauri 外壳。

**谱面上直接改谱**另见 [可视化编辑](可视化编辑.md)，**试听与导出 MIDI** 另见 [播放](播放.md)。

从 `app.ts` 切出来的几个控制器（OMR、播放、可视化编辑、文件会话、混排会话）各自通过一个**列全了的**宿主接口向 App 要能力——
那个接口就是「这摊事到底依赖编辑器多少东西」的清单，**加东西前先想想**。
`formats.ts` 的 `FormatHost` 也是同样的接口。文档本身的状态（原文、格式、`filePath`）与读进来的内容怎么落地
（`importBytes` / `openProject` / `adoptText`）留在 App；无头回归经 `window.__app` 调的方法名不变（App 上是转发）。

## 源格式适配器（`formats.ts`）

打开的源格式有六种（`.jpwabc` / 文本谱 / `.123` / `.abc` / `.jly` / `.musicxml`，`docFormat` 记当前是哪种）。
**因格式而异的那些差异全收在这张表里**：高亮扩展、读写编解码、默认扩展名、标题取法、
格式标签、档位旋钮（`jpProfile` 还是 `originalProfile`）、能力位、重排入口。

以前这些是 `app.ts` 里散在约二十处的 `docFormat === "pu"` 三目式，加第三种格式
每处都要再分一次叉。**别再往 `app.ts` 里加这种三目式**——该加的是 `FormatCaps` 的一位。

**能力位与方法的搭配写在类型里**：`layout: "scoredoc"` 必须给 `toScoreDoc`，`phraseRelayout: true` 必须给 `relayoutText`，
漏配在注册这张表时就编译不过（`FormatAdapter` 是按 `caps` 判别的联合类型）。要 `.musicxml` 那份读入端直接用 `musicXmlFormat`。

| 能力位 | 含义 |
|---|---|
| `textEditor` | 有没有代码区。`.musicxml` 没有：谱面上照样可视化编辑，改的是模型（`VisualHost.modelEditing`，见 [可视化编辑](可视化编辑.md)），整份重写进隐藏代码区；换成文本格式编辑走打开时的格式选择或「另存为」（`App.convertToTextDoc`，与格式下拉同一条路、切得回原文） |
| `layout` | 谱面走哪套排版：`scoredoc`（文本谱、123、ABC、jianpu-ly、MusicXML：展开档 `jianpuInputOfDoc` → `ScorePainter`；原样档看 `originalLayout`）或 `jpwabc`（`jianpuInputOfJpw` → 简谱引擎两档） |
| `originalLayout` | `scoredoc` 原样档用哪种布局（排版器都是 `ScorePainter`）：`jianpu`（123、ABC、jianpu-ly；投影成简谱引擎输入，多声部回落原样文档布局）或 `document`（文本谱、MusicXML，`layout/original/`） |
| `phraseRelayout` | 有没有「按乐句重排」。怎么写回原文由 `FormatAdapter.relayoutText` 给：文本谱搬原文片段（`pu/relayout.ts`）、123/ABC 写模型再整份重出、`.jly` **只重断曲行**（`fromjly.ts::rewrapJlyText`，词行/页头/注释一个字不动 —— 写出端还不认识 `R{ }`、倚音、`chords=`，整份重出会抹掉它们）、`.jpwabc` 只挪 `.Voice` 的 `$`（`model/relayout.ts`）；`.musicxml` 没有代码区，不给。开着时五线谱/混排另按乐句断、用五线谱的尺子（`App.staffPhraseLineStarts`） |

五线谱/混排**不是能力位**：所有格式都有。`.musicxml` 用打开时读的那份模型；文本格式（含简谱识别落地的 123）
进这两档时由 `MixedSession._ensureMixedDoc` 把当前源文经 `export.ts::sourceMusicXmlBare` 投成 MusicXML 再读回（源文没变不重做），
在这两档里代码区仍可编辑、改了就重新派生重排；打开文件时原来在这两档就留在那档（`.musicxml` 同口径）。
派生的 XML **不带**版面坐标，混排排版器见不到坐标就自动铺排（`layoutpass.ts`）；换行照**简谱视图实际排出的行**
（`App.jianpuLineStarts`：另造一个排版器按当前档与纸排一遍取各行首音，经 `ToXmlOptions.lineStarts` 落到小节上），
自动铺排拿它当优选断点。纸取设置里五线谱/混排自己那张（`App.staffPage`，主题 `staff` 出厂 A4；选长图时按 A4 宽、不分页）。**不借原样档的纸**：那边出厂是长图（宽 1000pt、页高随内容），MusicXML 转成简谱再打开时丢了 `<page-layout>`，短曲子会排成一张扁图，看着像横版。
派生缓存按「源文 + 简谱的档、纸、字号」（`_mixedDeriveKey`），这些一变就重新派生。

真正因格式而异的**算法**（`reloadPu` / `reload123` / 乐句重排 / 播放高亮走 AST 索引）
仍留在 `app.ts`，适配器只负责分派。

## 声部面板（`parts.ts`）

参照 MuseScore「乐器」面板、Sibelius「Arrange / Reduce」、Dorico「演奏者」。判据：

- **能改到哪一步看格式**（`App.partsEditable`）：MusicXML、123、ABC 改结构；文本谱（`Q1–Q4` 行）、`.jpwabc`（单声部）只给试听设置。
- **改名、简称、谱号只改 `V:` 声明行**（`patchVoiceLine`，声部按 `V:` 号第一次出现的先后排，与解析同口径）——整份重出会把原文规范化
  （`5 - - -` 成 `5---`、歌词连写），只为改个名不值当。单声部没有 `V:` 行时在 `K:` 后补一行。ABC 的谱号解析不读（音名就是实际音高），不给改。
- **增删、排序、拆合、歌词复制在新读的一份模型上改**（`model/parts.ts`），MusicXML 经唯一写出端整份重写（并丢掉整曲版面坐标，改由自动铺排），
  123 / ABC 经各自写出器整份重出（原文有 `%` 注释先问一声；版本声明 `%abc`/`%123` 与 `%%` 指令不算）。只把前后不同的一段进代码区（`App.replaceText`），撤销照常。
- 123 / ABC 的写出端不写小节内临时声部（`&`），「并入上一个」只对 MusicXML。123 的声部名与谱号读写：`V:n name="…" subname="…" clef=…`
  （多声部才写名字，单声部不写，免得转来的谱都多一行 `V:1`；多声部的低音、中音谱号也写，五线谱档要它）。
- 简谱形状（123/ABC）没有「整小节休止」的写法：新建声部、拆出来缺音的小节按拍各写一个四分休止。
- **试听**：静音 / 独奏叠在声部音量上（`PlaybackController.options`），只存会话；播放中改了从当前位置重播（同改速度）。原来设置面板里的声部音量挪到这里。
- **简谱旋律取自**（`App.melodyPart`，会话内）：混排的简谱叠层画在这个声部上（`formatMixedScore(score, jianpuPart)`）；MusicXML 的简谱档投影前把它挪到最前
  （`withMelodyFirst`，浅拷贝、元素 id 不变）。换文档时复位。

- **可见、歌词来源只在会话里**（`App.hiddenParts` / `lyricPart`，换文档清掉）：可见在五线谱 / 混排铺排前按它滤声部（`withVisibleParts`，起止落在藏起来的声部里的记号一起去掉，简谱层下标跟着往前挪）；
  歌词来源在 MusicXML 投影简谱前深拷旋律声部、清词、按时刻从来源声部抄（`withLyricsFrom`，同「歌词复制」）。都不写文件。
- **移调乐器**写 `<transpose>`（第一小节的 attrs，`TRANSPOSE_PRESETS`），试听按 `chromatic + 12 × octave-change` 换成实际音高（`playdoc.ts`）。谱表数只显示（`<staves>`）。

## 源码格式下拉（`formatswitch.ts`）

代码区标题栏的格式标签位置上是一个下拉（`#doc-format-field`，有可切的格式时顶掉标签），
**打开的文件与识别结果共用**。下拉本身（控件、显隐、「手改过会丢」的确认）只有一份，切换怎么做由来源各自实现 `FormatSource`：

| 来源 | 真身 | 切到别的格式 | 切回 |
|---|---|---|---|
| 打开的文件（`FileFormatSource`，`App.importBytes` 装上） | **原文** | 从原文的模型写出；先列装不下的（`planSave`），文件路径清空（存盘走另存为，原文件不动） | 「原文」那一项：**逐字还原**原文与文件路径 |
| 识别结果（`OmrController`） | `RecognizedScore` | 从识别结果重出文本，**不重跑识别**；选择记进 `omrFormat` | 同左（没有「原文」） |

- 目标清单是转换目标表 `model/convert.ts::CONVERT_TARGETS`（123 / JPWABC / ABC / 番茄 / 诗歌本），另存为也用它。
- **在原格式里改过再切走，以改过的文本为准**（它就是新的原文，模型重建）；在转出来的格式里改过再切，先问一声再丢——
  转出来的文本不是真身，从它再转一次只会越转越丢。
- `.musicxml` 原文没有代码区，下拉里的「MusicXML（原文）」切回去时代码区收起；从「另存为」换成文本格式进来的是同一个来源。

## 打开单声部 MusicXML 时选格式（`App.promptMusicXmlImport`）

用户**亲手打开**（打开对话框、拖入）单声部 MusicXML 后弹单选框：转成 123 / JPWABC / ABC / 番茄 / 诗歌本编辑（默认 123），
或保持 MusicXML 进五线谱档。转过去走 `convertToTextDoc`（先列装不下的，取消就留在 MusicXML）。
取消对话框 = 保持 MusicXML，不中断打开。多声部不问（照旧进混排）。
「记住选择」存进 `PersistedSettings.musicXmlImport`，设置面板「打开 MusicXML」一栏改回「每次询问」。
重开上次文件、回归脚本直接调 `importBytes`，不弹框。

## 导出与另存为（`export.ts`）

两个按钮分工：**导出 = 别的媒介**，**另存为 = 源格式**。以前导出框里还混着「转成 X 编辑」「X（源格式）」两组，
单声部 MusicXML 一开能列十几项。

- **导出**（`EXPORT_ITEMS`）：简谱档 PPTX / MIDI / MusicXML / jianpu-ly 文本；五线谱/混排档 PNG / PDF / MIDI / MusicXML。
  MusicXML 是给第三方软件的交换件，算媒介；jianpu-ly 文本同理（交给上游生成 LilyPond，单向）。
- **另存为**（`showSaveAsDialog`）：当前格式另存一份 + `CONVERT_TARGETS` 里其余几种。换格式先列装不下的（`planSave`）。
  换格式时换行照简谱视图实际排出的行（`App.convertTo` → `breaks.ts::applyBreaks`，与导出 MusicXML 同一口径：
  版面宽度在小节中间折的顺延到下一小节）；走原样文档布局的（文本谱原样档）照源文的行。
  文本格式写一份新文件、编辑器仍是原文档（`App.saveAsFormat`）；`.musicxml` 没有代码区，另存成文本格式就是
  转过去（`convertToTextDoc`）再落盘，之后编辑的是新存的那份。
- 落地统一走 `App.adoptText(format, text, filePath)`（识别产物的 123 另走 `importOmrDoc`，报它装不下的东西）。

## 双向定位（`sync.ts`）

代码区光标移到某个音符上，谱面上那个音符亮起来；点谱面上的音符，代码区光标跳过去。
选区同理（区间内的音符全亮）。适用于有代码区的四种格式（文本谱、123、ABC、`.jpwabc`）的简谱两档。

索引条目分七种（`SyncEntry.kind`）：音符、歌词、增时线、小节线、挂载记号（和弦名、装饰、注记、圆滑线的 `(` 与 `)`）、换行符、页眉字段（页眉见 [可视化编辑](可视化编辑.md)）。
后四种的原文位置是为可视化编辑补记的（`AttachedSource`、`Mark.openSource/closeSource`、`Part.breakSources`，
只给编辑用，排版与写出端不读）。和弦名、装饰、注记按类名在音符格里认出自己的
（`chord-group`/`artic`、文本谱排版器的 `chord`/`ornament`/`annotation`，`App._markPartEl`）；
增时线、小节线、弧各有自己的图元，按各自的身份认（`sustainEl` / `barlineEl` / `slurEl`，那张表在 [实现/可视化编辑](../实现/可视化编辑.md)「点得中自己」）。
**`syncEntries()`（`sync-check` 用）只给音符与歌词**。

| 方向 | 怎么走 |
|---|---|
| 文本 → 谱面 | 光标偏移 → `SyncIndex.range()` 二分 → 条目 → 已缓存的 `<g>` → 加 `.cursor-at` |
| 谱面 → 文本 | 点击事件从 `ev.target` 往上找 `<g>` → 条目 → `view.dispatch({selection})` |

**几条判据**：

- 索引建在 `ScoreDoc` 的 `source: SourceSpan` 上，条目按**元素 id** 认；音节配给哪个音符取排版行视图
  （`pu/slots.ts::docView` 的 `syllableOwner`），与排版器、引擎输入同一份。`ScorePainter.entryEl(id)` /
  `lyricEl` / `partEls`（简谱引擎输入的和弦带元素 id；原样文档按音符 id）取 `<g>`，不必动排版；两路页面树的类名差别由排版器消化。试听高亮同样按 id。
- 谱面那侧**按 `<g>` 认、靠冒泡**，不依赖 `pickPage` 的几何拾取——原样档根本没有 `pickPage`，
  两档因此共用同一条路径。`_onSyncClick` 必须留在 `onPageClick` 最前面。
- 走 CSS 类、**不重渲染**；`.cursor-at` 排在 `.playing` 之前，试听时发声的那个盖过光标色。
- **五线谱 / 混排档（文本格式）**：`mixedDoc` 是源文写成 MusicXML 再读回的，元素 id 另编一套。
  派生时 `sourceMusicXmlBare(app, { sourceIds: true })` 给每个 `<note>` 写 `id="jp<源 id>"`（只这条内部路径写，导出不带），
  `fromxml` 读成 `Chord.srcId`，`App._indexMixedSrcIds` 建两向对照：点五线谱和弦组（`painter.staffChordAt`）→ 源 id →
  `SyncIndex.spanOfNote`；代码区光标 → 条目 id → 五线谱和弦组加 `.cursor-at`。歌词、小节线、弧也对得上（图元身份见
  [实现/可视化编辑](../实现/可视化编辑.md)「五线谱 / 混排档」），所以五线谱档照样能可视化编辑。`.musicxml` 没有代码区，不做。
- **切档要清选中**：简谱档与五线谱档的元素 id 各编各的（都从小整数起），选中的 id 带过去会撞上别的音当起播点（`_setMode`）。
- 防回环：`_syncing` 标志；文档变更时不在监听里同步（索引还是旧偏移），
  等 `reload` 重建索引后由 `_buildSync` 刷一次。

## 界面分区（`index.html`）

按「作用于谁」分四条，**电脑上能摆出来的不往菜单里藏**：

- **顶栏**：返回开始、品牌；应用级的 声部 / 简繁 / 设置 / 帮助（`button-tool`）；保存 / 另存为 / 导出。
  手机宽度（≤680px）应用级四项收进「⋯」（`#btn-header-more`，弹出层 `editor/toolpop.ts`，`position: fixed`）。
- **工具栏**：只放随上下文出现的操作组——分行、识别（原图页、识别类型，识别过的谱才有）、试听。电脑上放不下就**折成第二行**
  （`flex-wrap`），不横向滚、不收「更多」；手机宽度仍横向滚。
- **排版标题栏**：编辑 / 插入模式标记、作用于谱面显示的开关（面板、拍数自检、格式标记）与四档视图。
- **状态栏**（`#statusbar`，底部）：左边状态文字（`#status`，`role="status"`，`App.setStatus` 写的就是它）；
  右边是看一眼就够的读数与视图控制——选中读数、拍数不对的小节数、可疑项计数、**核对**下拉、缩放、翻页。
  **核对**下拉（`editor/comparemode.ts`）把对着原图核对的几种方式合成一个平铺的选择：不核对（只看排版稿）/ 并排原图 / 原图片段 / 附近浮窗 / 原位叠加 / 仅原图
  （并排与片段仍在可编辑的排版稿里、二选一；后三种进核对视图）。它不另起状态，驱动的是藏在 `.compare-legacy` 里的
  原图对照钮、并排钮、片段钮与叠加方式下拉——那几个的显隐仍表示「这一项现在能不能用」（不能用的选项灰掉），
  按下状态与 `body.recognize` 表示开着哪个，下拉从它们读回，别的入口改了也跟得上。
  **源码**复选框（`#chk-code`，`OmrController.hideCode`，设置键沿用 `sideHideCode`）任何模式下都能收起代码区（`#body.hide-code`），
  不进核对下拉；手机宽度不显示，那里有自己的源码 / 预览切换。
  手机宽度只留状态文字、计数与缩放翻页。

元素挪位置时 **id 不变**：显隐（`data-context-control` 按所在 `.context-tool-group` 同步）、事件接线、
无头脚本都按 id 找。帮助里写控件位置的条目（`help.ts` / `help.en.ts`）要跟着改。

## 界面语言（`src/i18n/`）

中文 / English 两种界面，乐谱内容、记谱关键字、示例谱不译。

- **词典**：`i18n/zh.ts` 是键的权威清单，`i18n/en.ts` 类型是 `Record<MsgKey, string>`——漏键 tsc 直接报错。
  占位写 `{name}`，`t(key, { name })` 替换。键按区分前缀（`toolbar.* / settings.* / status.* / vis.* / diag.* …`）。
- **两种用法，不混**：静态 DOM（`index.html`）打 `data-i18n` / `data-i18n-title` / `data-i18n-aria` / `data-i18n-placeholder` / `data-i18n-label`（`<optgroup>` 的组名），
  由 `applyI18n` 刷；代码里建的文字一律 `t()`，**不在界面代码里写中文字面量**。
- **定语言**：`initLang()` 在 `boot()` 最先调，顺序 URL `?lang=` → localStorage `dolce-ui-lang` → `<html data-ui-lang>`
  （英文落地页 `/dolce/en/` 为 `en`）→ 浏览器语言（`zh*` 中文，否则英文）。设置「其他 → 界面语言」可选跟随系统 / 中文 / English。
- **切换不重载**：`setLangPref` 刷静态 DOM 并广播 `onLangChange`；`main.ts` 关掉已开对话框，`App.relabel()` 让格式下拉、
  试听按钮、记号面板、对照按钮重出文字。对话框与帮助每次打开现建，自然跟随。
- **模型层也可以调 `t()`**（`i18n/index.ts` 模块级不碰 DOM）：解析诊断、另存为丢失清单、拍数自检说法、
  转换目标名（`TargetSpec.label` 是 getter）都随界面语言产出；CLI 不调 `initLang`，恒为中文。
- **帮助**：中文内容在 `help.ts` / `help123.ts`，英文在 `help.en.ts` / `help123.en.ts`，主题与示例顺序一一对应（示例源码共用，只译说明）。改帮助两边同改。
- **桌面窗口标题**随语言（`core:window:allow-set-title`）。
- **英文落地页 `/en/`**：`vite.config.ts` 的 `emitEnPage` 在构建后从 `dist/index.html` 生成 `dist/en/index.html`——
  `<!-- seo:start -->…<!-- seo:end -->` 换成 `seo/head.en.html`，带 `data-i18n*` 的静态文字按英文词典预译。
  改 `index.html` 的 SEO 区记得同步英文版；发版脚本两处 `softwareVersion` 一起改。
- 未译：诗集样式表（`.ss`）的解析报错、少数内部异常文字。

## Tauri 外壳（`src-tauri/`，只有 2 个 `.rs`）

**不只是文件 IO 与对话框**，有三块原生能力：

| 命令 | 作用 |
|---|---|
| `export_pdf_cmd` | 各页 SVG → `svg2pdf`/`usvg` → `lopdf` 合页；载系统字体 + 随包 Bravura |
| `omr_onnx` / `omr_onnx_batch` | `ort` 跑 rec/det 模型，二进制 IPC，`mode=1` 在 Rust 侧做逐时间步 argmax。比浏览器 wasm 多线程快 ~3× |
| `midi_play_cmd` / `midi_stop_cmd` | macOS `AVMIDIPlayer`（player 必须存活，放进托管状态）；用它的是 [播放](播放.md) |

文件 IO 与对话框用**插件**（`tauri_plugin_fs` / `dialog` / `opener`），权限在 `capabilities/default.json`。
**新增插件要同改四处**：`Cargo.toml`、`lib.rs`、capabilities、`package.json`。

Windows 桌面包的 VC++ 运行库随包内置（`src-tauri/tauri.windows.conf.json` + `scripts/win-crt.mjs`），
DLL 清单改那份 conf；来龙去脉见 [实现/OMR-简谱识别.md](../实现/OMR-简谱识别.md) 的「桌面版（Tauri）也内置 VC++ 运行库」。

**应用图标**：斜体 d 即线上的二分音符，白底蓝字、垫五线谱。源图由 `../dev/scripts/app-icon.mjs` 画出两版四份——
macOS 版（四周留白 + 投影，进 `icon.icns`）与满版（`icon.ico`、各 PNG、`public/favicon.svg`），各分常规档与**小尺寸档**
（64 像素及以下谱线加粗，否则缩小后线不足一像素就没了；`favicon.svg` 兼作界面左上角 30px 的标志，用小尺寸档）。
换图标要同改：`src-tauri/icons/` 整套、`public/favicon.svg`、分享图 `public/og-image.png`（`../dev/scripts/og.mjs`）、
README 两张截图左上角的标志。

## 更新检查与反馈入口（`editor/update.ts`、`editor/feedback.ts`，只在桌面版）

两者都挂在帮助对话框的第三个标签页「关于」（`editor/help.ts` 的 `buildAboutPane`），
按 `isTauriRuntime()` 判：Web 版那页只剩版本号与主页——刷新即最新，也没有邮件客户端可唤起。

- **版本号**：只在 `package.json` 维护一处，`vite.config.ts` 的 `define` 注入成 `__APP_VERSION__`；
  `release.sh` 把它同步到 `tauri.conf.json` / `Cargo.toml` / `index.html` 的 JSON-LD。前端别再抄常量。
- **更新检查是「只查不装」**：查 GitHub Releases API 比版本号，有新版问一句，确定就用 `opener` 打开
  release 页由用户自己装。**没上 `tauri-plugin-updater`**——那条路要生成并保管签名密钥、改
  `.github/workflows/build.yml` 注入 `TAURI_SIGNING_PRIVATE_KEY` 并产出 `latest.json`（动 workflow），
  而存量用户照样得手动装一次新版才享受得到。要换只换 `update.ts`。
- **节流判据**（独立 key `dolce-update-state`，不进 `PersistedSettings`——那份是
  `App.saveSettings()` 整对象覆盖写的，从别处补字段会被抹掉）：启动后延迟 8 秒查一次，
  距上次检查不足 24h 不查，同一个新版本只提示一次，用户可在关于页关掉自动检查。
  查询失败（断网 / 限流）一律静默返回，不弹错误框。
- **反馈走 `mailto:`**：预填收件人、带版本号的主题与一段可删的环境信息；不自建上报服务——
  这个应用全程本地运行，不该为一条反馈开网络通道。唤不起邮件客户端时在关于页显示邮箱明文兜底。
- `opener` 的 `open-url` 默认 scope 为空，`capabilities/default.json` 里显式放行了
  `https://github.com/*`、主页与 `mailto:*`——**换仓库 / 换邮箱要同改那里**，否则点了没反应。

## 识别项目与自动保存（`omrproject.ts`、`autosave.ts`）

识别会话（原图 + 识别结果 + 在改的原文）只存文本就丢了原图对照、「切输出格式不重跑识别」与关联表，所以识别过的谱
「保存」存 `.dolce`（zip）；「另存为」照旧只存文本格式。

| 条目 | 内容 |
|---|---|
| `manifest.json` | `version`、应用版本、识别路 `kind`（`jianpu` / `staff` / `vector`）、`docFormat`、输出格式、识别为、对照方式、源文件名 |
| `source/<k>.<ext>` | 原图 / 原 PDF 原样（`level: 0`，本来就压过） |
| `doc.txt` / `emitted.txt` | 在改的原文；刚识别出来那份（判手改过没有） |
| `result/recognized.json` + `result/bin.raw` + `result/meta.json` | 只简谱：识别结果、二值图逐像素、已随编辑迁移的点选映射（`Map` 写成 `{__map: […]}`） |

- 会话状态的唯一出入口是 `OmrController.snapshot()` / `restore()`，`sessionKind` 记这次走的哪条路（识别完、`clear()` 时设 / 清）。
- **五线谱的对照数据不入包**：第一次进原图对照时 `ensureStaffResult` 从 `source/` 重跑识别补回逐页位图与音符坐标——
  同一输入、同一代码，`<note id="omr<k>">` 编号确定，对得上存的 MusicXML；原文不动。
- 读到 `manifest.version` 比代码新的拒绝；缺条目按能还原多少还原多少。撤销历史不入包。
- **草稿**：代码区每次改动 3 秒后存一份（与 `_cleanText` 相同则删）；识别会话把 `packProject` 的字节一并存进去，恢复走 `openProject`。
  `markClean` 在存盘、打开文件、打开项目、载入示例谱（走 `importBytes`，按 `.jpwabc` 读）时调。启动时 `offerDraftRestore` 排在「恢复上次文件」之后，草稿与当前原文相同就不问。
  只留一份；所有 IndexedDB 读写包 try/catch，存不了就静默不存。
- **未保存保护**（`filesession.ts`）：`isDirty()` = 原文与 `_cleanText` 不同（刚识别完、恢复的草稿没有那样一份，也算没存；启动时的示例算干净）。
  要换掉当前文档的入口——打开、拖入（文档或图片）、选图识别、载入示例——先 `confirmReplace()`，取消就不换；
  `importBytes` 本身不问（启动恢复、无头脚本直接调它）。关页 / 关窗同样先拦：浏览器 `beforeunload`，
  桌面 `onCloseRequested`（权限 `core:window:allow-destroy`），草稿照存、真关了下次还能恢复。
  无头浏览器（`navigator.webdriver`）不挂 `beforeunload`。桌面版在保存对话框里取消不算存过（不 `markClean`）。
  回归 `unsaved-check.mjs`。

## 关键判据

- 点选高亮走 **CSS 类、不重渲染**。
- 双指缩放在 `main.ts`（ctrl+wheel / WebKit `gesture*`），按页内归一化坐标锚定；
  `--score-zoom` 设在 `#score-pane` 上，**整条 calc 不能挪到 `:root`**。
- `.jpwabc` 读时 BOM 探测、存 UTF-16LE + BOM（兼容 JP-Word）。
- 能打开哪些扩展名**只在 `src/common/filetypes.ts` 写一次**。
- `window.__app` 运行时暴露，供脚本化测试。
- **简繁转换五种格式通用**（`App.convertHanzi` → `model/hanconv.ts`，判据见 [模型-scoredoc](模型-scoredoc.md)）：文本格式只改原文里文字所在的位置、
  一个 transaction（Ctrl+Z 整体撤销），写不回的处数报在状态栏；`.musicxml` 改模型后经 `editScoreDoc` 整份重写（改的是一份新读的模型，不原地动 `currentScoreDoc()` 那份——行视图与投影按对象身份缓存）。
