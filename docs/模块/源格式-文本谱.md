# 源格式：文本谱（番茄简谱 / 诗歌本动态谱）

**判据全录** → [../实现/文本谱.md](../实现/文本谱.md)；语料里的规范外写法另有清单（本地私有，不入库）

## 职责

两种纯文本简谱记谱语言作为**第一等源格式**：解析、排版（原版观感）、转出其它格式、按乐句重排原文；
也是**写出目标**：任何格式打开后都能在代码区标题栏切成番茄/诗歌本原文看、另存为文本谱，识别结果同样由它写出。

## 入口

| 函数 | 文件 | 作用 |
|---|---|---|
| `parseFanqie(text, opts)` | `src/fanqie/parse.ts` | 文本 → `ScoreDoc`（对外入口；元素、音节、曲行/歌词行/文字行带原文区间） |
| `parseFanqieAst(text, opts)` | `src/fanqie/parse.ts` | 文本 → 语法树 `FanqieDoc`（中间结果，只给 `fanqieToScoreDoc` 与 AST 级校验脚本） |
| `sniffDialect(text)` | `src/fanqie/dialect.ts:164` | 方言嗅探（打平偏番茄） |
| `fanqieToScoreDoc(ast)` | `src/fanqie/fromfanqie.ts` | 语法树 → `ScoreDoc`（**无损**，`fanqie-scoredoc-check` 全语料逐字段还原零差异） |
| `docView(scoreDoc)` | `src/jianpu/slots.ts` | `ScoreDoc` → 排版行视图（原样档排版、展开档投影、双向定位共用，行里符号带 `ElementId`） |
| `jianpuInputOfDoc(doc, opts)` | `src/jianpu/jianpuinput.ts` | → 简谱引擎输入（展开档；不带和弦/力度/多声部并排，和弦带元素 id） |
| `scoreDocToMusicXml(doc, opts)` | `src/model/toxml.ts` | → MusicXML（唯一写出端，经 `model/xmlproject.ts` 投影；保和弦/力度/多声部） |
| `layoutJianpu(doc, cfg)` | `src/layout/jianpu/compose/index.ts` | 简谱引擎（各格式共用，见 [排版-简谱引擎](排版-简谱引擎.md)）：页面树 + 身份标签；由 `ScorePainter` 调用，高亮 / 定位按 id |
| `layoutSong` / `layoutDocument` | `src/layout/jianpu/place/song.ts` | 版面计算（定位结构） |
| `relayoutFanqieText(text, scoreDoc, opts)` | `src/fanqie/relayout.ts` | 按乐句重排**原文字符串**（读排版行视图上的原文区间） |
| `emitFanqie(doc, dialect)` | `src/fanqie/tofanqie.ts` | `ScoreDoc` → 文本谱原文，**唯一的写出端**（打开别的格式后切格式、另存为、识别结果都走它）。判据全录在 [../实现/文本谱.md](../实现/文本谱.md)「写出端」 |
| `fanqiePhraseLines(scoreDoc, i, opts)` | `src/jianpu/phrase.ts` | 断点 → 新行划分 |

## 吃什么吐什么

```
fanqie 原文
  └─ parseFanqie（parseFanqieAst → fanqieToScoreDoc）→ ScoreDoc ─┬─ docView ─┬─ layoutOriginalDocument →「原版」连续长图（ScorePainter）
                                                    │           ├─ jianpuInputOfDoc →「展开」（ScorePainter）
                                                    │           └─ relayoutFanqieText（按乐句重排原文，用视图上的原文区间）
                                                    ├─ scoreDocToMusicXml / emitJpwabc / emit123（保和弦/力度/多声部）
                                                    └─ playSourceOfSong → 试听 / MIDI

任何格式的 ScoreDoc（123 / ABC / .jpwabc / MusicXML / 识别结果）
  └─ projectForJianpu（简谱形状）→ emitFanqie(doc, "tomato" | "shige") → 文本谱原文
```

## 关键判据

- **方言差异全部收在 `dialect.ts::DialectSpec` 一张表里**——「**不要在两套方言之间写 if**，
  加第三种方言应该只是补一份数据」。
- **`9` 是硬冲突**：番茄是节奏音符 X，诗歌本是隐藏休止（不跟词）。**必须先定方言再解析**。
  `8` 两家一致：隐藏休止、**跟**歌词。
- 扩展名白名单 `FANQIE_EXT = ["fanqie","fq","jps","txt"]`；`.txt` 太泛，嗅探失败**宁可报错不硬解**。
- 导出一律从 `ScoreDoc` 出，和弦/力度/多声部都在（《圣哉三一歌》导出 28 个 `<harmony>`）；展开档的引擎输入不带它们，本来就不画。
- 试听与谱面必须是**同一份 `ScoreDoc`**（`App.currentScoreDoc` 缓存），高亮按元素 id，重新解析会对不上。
- 原版观感用**文本谱自己的坐标系与栅格**，不沿用 `.jpwabc` 那套 `jpStackGap`。
- 前景色随一次排版的上下文（`compose/ctx.ts::OriginalCtx`）传给各画笔，不再是模块级可变量。
- **原样档的样式值与 123 同一份**（`style/jianpu.ts::jianpuStyleOf`，print 主题照 500 首）：字号、字体、笔画、点、间距都从尺子取；
  原版量来的栅格（步进、记号槽位、页头基线）按音符字号 / 25 等比缩放（`metrics.ts::gridOf`）。
  长图宽同简谱原样档那张（`LONG_IMAGE_WIDTH`），**纸宽固定**，墨迹段在纸宽里居中（放不下才撑宽）。
  文本谱方言（番茄 / 诗歌本）只影响解析，不各带一套数值，各格式同用 print 主题；要别的观感用歌本样式表。
- **源里的行放不下就整首重新断行**（`place/reflow.ts::reflowLineStarts`）：每组按歌词足额量所需宽度，全放得下照原文的行；
  有一组放不下，就把各小节的所需宽度串起来，只在小节线处断、求各行余白平方和最小（同简谱引擎），
  断点写进文档克隆的换行位（`model/breaks.ts::applyBreaks`）整份重排一遍（`compose/index.ts::layoutOriginalDocument`）。
  多声部文本谱（各声部小节对不齐）`applyBreaks` 不重断。
- `Fine` / `D.S.` 与小节线右对齐、基线不低于线顶一道空（`compose/note.ts::paintOrnaments` 的 `bar`）；段号让开首字前挂出去的引号。

## 已知限制

- 展开档不画和弦/力度/多声部（引擎输入按简谱形状投影）
- 重排**重建行结构**：原文的空行分组、`[fenye]`、行内手工留白会被覆盖（这正是该功能的语义）
- `{bz…}`/`{dsb…}` 临时层是顶层元素，断点不会切进其内部
- 重新断行后，挂在源里行首那条小节线上的 Segno 会跟着小节线留在上一行行尾（记号挂线、不挂下一小节）
- 展开档**只排一条旋律**（`Layout` 只排 `parts[0]`）
- `Space:`/`Off:` 已解析但**语义未实现**
- 原样档页脚 `BL/BC/BR` 由 print 主题的 `song-foot` 区域排（`style/themes.ts`）（`-` 占位视为空）；长注释不折行，会越出版心
- `Z:` 署名按标签定词曲类型（`作词：`/`X 词曲`/`制谱：`…，`model/metakeys.ts::creatorTypeOf`），认不出的仍记作曲；原文不改
- **写成文本谱装不下的**（`convert/capability.ts` 的 `tomato` / `shige` 两行，转换前列给用户）：样式表引用、演唱顺序、
  扩展 meta（没有字段可落）；音符堆（和音）只写简谱印的最高音；同谱表第二声部写成 `{dsb…}` 并排块
（`model/innervoice.ts::voicesToLayers`，连续几小节并一块、换行处断开，块里不可见休止写 `8`；番茄的块是括起的那一路在上，与 123 `&` 的上下相反），
第二条谱表、第三声部起、节奏音符的谱表位置与叠音写不出；
文本谱的倚音是音符的属性（`1[2]` / `1"yy:2"`），弧落不到倚音上：端点在倚音上的弧改挂到它所属的主音（前倚音挂后面那个、后倚音挂前面那个），
改挂后起止重合的（倚音连到自己主音的那条）写不出，丢失清单报 `graceArc`；和音只写最高音，挂在别的音上的延音线不写，
同一对音上延音线与圆滑线重了只写延音线（`tofanqie.ts::writableMarks`）；一条弧完全包住另一条
  （括号先开先闭，按「多连音 > 延音线 > 圆滑线」留）；比例不是 n:n−1 的多连音。番茄另外没有页眉页脚与版面指令字段
  （写了会被嗅探成诗歌本），不跟词的隐藏休止只能写成显形休止 `0`；
  震音、弓法、排练号、多小节休止文本谱的记号表里没有（番茄脚本规范同，用户定不扩），要的走 123。
  顿音只有一个 `dy`：楔形（`<staccatissimo>`、123 `!wedge!`）与点状并成一个，读回都是点状（丢失清单「楔形顿音」）；
  小节线没有「终止线 + 起反复」的合写，`|] |:` 只留 `|:`（反复照旧，少的只是那根粗线）。
  规范里有的都写：MusicXML 的 `<direction>`（力度、文字、渐强渐弱、曲首速度）先经 `directionmarks.ts::directionsAsMarks` 换成挂在符号上的写法（同 123），
  声部名里的换行写成空格（原样写会把 `Q` 行拆断）
- 读入：`(y…)` 组内各音的 `duration.timeMod` 收尾时按 tuplet Mark 补（`model/tuplets.ts`，与 123 同一份；没写数字的 n 个符号占 n−1 个）。
  节拍自检、排版、写出只认这一份——以前只记 Mark，同一首识别稿 123 报 1 处拍数不对、文本谱报 4 处。
