# 播放

**判据全录** → 无单独实现篇，判据都在本页

## 职责

试听（前端掌钟 + 光标跟随、两路音源）与导出 MIDI。编辑、双向定位、可视化编辑见
[编辑器](编辑器.md) 与 [可视化编辑](可视化编辑.md)。

## 入口

| 文件 | 作用 |
|---|---|
| `src/editor/playback.ts` | 播放控制器（入口 `app.playback.*`）：播放/暂停/停止、进度条与时间、速度、点音符定位；经一个**列全了的**宿主接口向 App 要能力 |
| `src/editor/player.ts` | `ScorePlayer`：前端掌钟 + 光标跟随，两路音源；一次会话内暂停、续播、按秒定位 |
| `src/score/timeline.ts` | `buildTimeline` / `playTempo` / `partGain` / `SPEED_STEPS`；只经输入接口 `PlaySource` 读谱 |
| `src/model/playsong.ts::playSourceOf` | `ScoreDoc` → `PlaySource` 统一入口（各格式共用）：按形状分给 `playSourceOfSong`（简谱形状）/ `src/model/playdoc.ts::playSourceOfDoc`（MusicXML 形状，带全部声部、voice 与力度） |

原生音源那条命令（`midi_play_cmd` / `midi_stop_cmd`，macOS `AVMIDIPlayer`，player 必须存活、放进托管状态）
与其余两块原生能力一起放在 [编辑器](编辑器.md)「Tauri 外壳」。

## 关键判据

- **试听与导出 MIDI 读同一份 `App.playable()`**，由各格式共用的 `model/playsong.ts::playSourceOf` 从 `ScoreDoc` 拼：MusicXML 形状（`isXmlShaped`）走
  `playSourceOfDoc`——全部声部（mixer 的声部序号 = `Part` 序）、各 voice、和弦全部音，力度记号（pp…ff）落成 note-on 力度，
  光标只跟第一声部 voice ≤ 1；简谱形状（文本谱/123/ABC/`.jpwabc`）走 `playSourceOfSong`，展开档那份带歌词的声部当主旋律。
- **ABC `&` 的临时多声部先投影再播**（`playSourceOf`）：简谱形状那条路一个声部行只走一条旋律，
  并行的分支会被当成接着唱的音（这一小节凭空多出几拍）。带 `&` 的先 `projectForMusicXml` 投成
  MusicXML 形状走 `playSourceOfDoc`，各 voice 分轨同时发声；投影是克隆、元素 id 不变，高亮照样认得。
- **多声部按组对齐**（`model/alignparts.ts::alignPartsBySystem`，试听与导出 MusicXML 共用，对齐的是克隆）：文本谱一组不一定含全部声部，
  各声部按小节序号叠起来会错位（issue 11：只在末组出现的 `Q2` 从第一行就响）。按 `print.system` 切段、每段以小节最多的声部为参照，
  缺席或偏短的声部补无声小节（小节线、房号、跳转照抄，和弦改休止换新 id；voice/staff 取**本声部**的，照抄参照声部会让 P1 补出 voice 2 的小节，导出再读回后旋律档只取 voice ≤ 1，成了空小节、试听抛 `measure has no chord`）。演唱顺序给展开档用的 `playDataOfSong` 不对齐（小节下标要对得上引擎输入）。
- **延音线只延长、不再起音**（`timeline.ts::buildTimeline`，issue 11）：`TimelineNote.tieStop` 的音若与同声部同音高的上一个音首尾相接，
  就把那个音的 `t1` 拉长；不相接（反复跳转后、中间隔了休止）照常起音。`tieStop` 的来源：MusicXML 形状取 `Note.tie.stop`
  （`playdoc.ts::chordEntry`，旋律档 `phrasedoc.ts` 同口径）；简谱形状的文本谱在 `pu/phrasesong.ts` 判——
  **一条弧恰好括住相邻两个同音高的音**（中间只隔 `-`、小节线、换行）就当延音线（简谱里两者同形，番茄 `(2/ 2)`）。
  以前整条播放链不看延音线，ABC/MusicXML 的真 tie 也会重新起音。
  **播放器回调与起播点都是 `ElementId`**：一律 `ScorePainter.highlight(id, pass)`。
  **光标各视图统一是竖直播放线**（`painter.ts::movePlayhead`，同 Sibelius / MuseScore / Dorico），不给音符着色；播放器跟**各声部起音**走（`player.ts::onsetAnchors`，同刻取声部序最前的），女高休止、别的声部在唱也照走。横向取音的包围盒，纵向：五线谱 / 混排取谱表带；简谱引擎取音符所在谱行组（按遍次取音符格）；原样文档取它所在的 `g.system`（多声部是连谱号括起的整组）。这一视图里没画的音（展开档只排带歌词的那个声部）不挪线。
  识别核对（原图对照）也能试听：播的仍是代码区那份，播放线由 `OmrController.highlightPlaying` 画在识别图上（横向取识别框，纵向贯穿本系统各声部行）——元素 id ↔ 识别音序靠**元素源区间起点 ↔ `meta.noteRanges[i].from`**（编辑后随变更集迁移，改了文本也对得上），对不上按遍历序兜底；再从 meta 序换到框序（`flatOrder`：框按谱面逐行编号，模型按声部，四声部两者交错）。没有点选映射的产物（`.jpwabc` / ABC）只播不显示播放线。点识别框同点音符：定起播点 / 播放中跳过去。
- **八度谱号的声部低八度发声**（`playsong.ts`，123 `V:3 clef=treble-8`，见 [123格式](../格式/123格式.md) §7）：
  四声部简谱的男高、男低照惯例按高八度记，以前照谱面出声，男高比女高还高。度数 → 音高的另一处（`xmlproject.ts`，
  五线谱 / 混排与 MusicXML 导出）同样落回实际八度。
- **曲中转调**（简谱形状那一路，`playsong.ts::keyChangesOf`）：模型小节上的调号（`Measure.attrs.key`，123/ABC 的行内 `[K:]`）
  按元素 id 交给 `pu/phrasesong.ts::buildMeasures`，到了那个音就换调（基音重算、小节内临时记号清空）。以前全曲只用头部调号推音高，
  转调后半首都是错音（谱面早已按模型小节画出转调）。MusicXML 形状那一路（`playdoc.ts`）本来就逐小节认。
  回归 `play-check` 的 `1=G → 1=D` 夹具。
- **速度 = 谱面 `♩=` × 工具条倍率**，两者都在 `score/timeline.ts::playTempo` 折算；谱面没标速度时按 `TEMPO = 90`。
  - 谱速来源：`.Title` 的 `Expression`、123/ABC 的 `Q:`、MusicXML `<sound tempo>`（小节级的也认，记成 `Direction.sound.tempo`），
    经 `playdoc.ts::tempoOfDoc` 进 `PlayData.tempo`。附点四分等拍单位随文档保存（`Song.tempoBeat`），`.jpwabc`、文本谱只认 ♩，写出时换成四分等值。
  - `.jpwabc` 按 JP-Word 原生规范把速度记进 **`Expression`**（它兼记速度与表情，值可以是纯表情文字），不另立 `Tempo` 键；
    写出端写真 Unicode `♩`（U+2669），读取端 `J` 与 `♩` 都认（JP-Word 存 `{J=80}`、靠音乐字体显示成 ♩），从 JP-Word 拿来的谱速度不丢。
  - 倍率是工具条「试听」旁的下拉（`SPEED_STEPS`，×0.5~×2），存进渲染设置，经 `App.playOptions()` 同时喂给试听和 MIDI 导出。
- 两路音源：`SamplerSource`（Web Audio + smplr SoundFont）/ `NativeSource`
  （macOS `AVMIDIPlayer` + 系统 DLS GM 音源，经 Rust；支持按秒定位）。
- **试听不联网**：采样那一路的钢琴音色随应用分发（`public/redist/soundfont/`，FluidR3 GM 大钢琴的 MIDI.js 格式，
  `player.ts::PIANO_SOUNDFONT` 经 smplr 的 `instrumentUrl` 读）。以前点播放时从外站现下，连不上就卡在「加载中」
  （没有超时），网页版、Windows 桌面版都受影响（issue 13）。只带 mp3 一份：各家浏览器与桌面 WebView 都能解，
  ogg 那份 Safari 不认。
- **会话、暂停与定位**（issue 12）：一次 `play()` 把时间线换成秒（`Session`），会话内 `pause / resume / seek(sec)`。
  - 采样：AudioContext 与音色**跨会话保留**（停止只挂起），定位、重播、改速度都不重新载入音色。暂停 = `ctx.suspend()`，
    排好的音原样留着。音不再一次全排进 smplr，而是按 `FEED_AHEAD`（2 秒）窗口陆续递、记下各音的撤销函数——
    smplr 的 `stop()` 只停已发声的 voice，**不清它自己排队的事件**，一次全排就没法在定位时撤干净。
  - 原生：暂停 = 停播放器、记位置；续播与定位 = 从那一秒重新 `midi_play_cmd`（Rust 侧本就支持 `startSeconds`）。
  - 改速度：有会话时把当前位置按倍率反比折算（谱面 ♩= 不变），从那儿按新速度接着播；暂停中改仍停着。
  - 起播点优先级：停止状态下拖进度条 / 点音符定下的 `cueSec` > 选中的音 > 曲首。播放或暂停中点音符直接 `seek`。
    原样档（原样文档）没有几何拾取，起播点按命中的同步条目记（点第 n 段歌词 = 第 n 遍）。
  - **播放 / 暂停中点音符要赶在可视化编辑之前**：简谱档的点击先过 `_onSyncClick → visual.handleClick`，点选会接走音符点击，
    跳转就轮不到了。所以会话进行中（`PlaybackController.active`）先认音符：简谱引擎按几何拾取取音符格的遍次（`App._seekByPick`），
    原样文档按同步条目；点中了只 `seek`、不选中，没点中音符再照常走点选。
- 工具条：播放/暂停/继续一个按钮，■ 停止（回曲首），进度条拖动时只改显示、松手才定位，时间显示点一下切「已播 / 剩余」。
- **循环与节拍器**（工具条「循环」「节拍」）：循环段 = 谱面选区第一个音起音到最后一个音收尾（`player.ts::spanSeconds`，按 `allAnchors` 认，
  五线谱 / 混排把源 id 换成画出来那份），没选区循环整首；播到段尾 `tick` 里 `seek(段首)`，采样递音的窗口截在段尾。
  节拍器拍点由 `buildTimeline` 一并给出（`Timeline.clicks`，按第一声部的拍号：复拍子 6/8、9/8、12/8 按附点四分打，小节第一拍重），
  **嘀嗒与音符必须由同一个时钟排**，两路音源各出各的：采样那一路是 WebAudio 正弦嘀嗒，与采样音同排在 `AudioContext` 上；
  原生那一路把嘀嗒写进 MIDI（`midi.ts::clickTrack`，打击乐通道的高 / 低木鱼），与音符同一个定序器播——
  WebAudio 的嘀嗒配原生播放器会错拍。这条轨只在试听时加（`toMidi` 第三个参数），**导出的 MIDI 不带节拍器**；
  声部从第 10 个起让过打击乐通道。节拍器持久化，循环只在会话内。
- **移调乐器按实际音高发声**：MusicXML 声部的 `<transpose>`（`chromatic` + 12 × `octave-change`）加到记谱音高上（`playdoc.ts::timelinePartOf`）。
- **起播点**：点过的音优先；没点过取可视化编辑选区的第一个音（键盘选的、切档后留下的也算，`App.startPoint`）。
- **五线谱 / 混排档也试听**，播的是画出来的那份 `mixedDoc`（元素 id 与五线谱和弦组对得上）；播放线见上。
- **谱面高亮不在 `PlaybackController` 里**——那属于「谁在画谱面」，留在 App。
- 文本谱试听必须复用排版时那份 AST。
