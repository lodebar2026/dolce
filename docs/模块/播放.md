# 播放

**判据全录** → 无单独实现篇，判据都在本页

## 职责

试听（前端掌钟 + 光标跟随、两路音源）与导出 MIDI。编辑、双向定位、可视化编辑见
[编辑器](编辑器.md) 与 [可视化编辑](可视化编辑.md)。

## 入口

| 文件 | 作用 |
|---|---|
| `src/editor/playback.ts` | 播放控制器（入口 `app.playback.*`）：播放/暂停/停止、进度条与时间、速度、点音符定位；经一个**列全了的**宿主接口向 App 要能力 |
| `src/editor/player.ts` | `ScorePlayer`：前端掌钟 + 光标跟随，两路音源；一次会话内暂停、续播、按秒定位 |
| `src/score/play.ts` | `buildTimeline` / `playTempo` / `partGain` / `toMidi` 门面（判据在 `crates/dolce-play/src/timeline.rs`、`midi.rs`，经 dolce-wasm）；只经输入接口 `PlaySource`（`score/playtypes.ts`，另有 `SPEED_STEPS`）读谱 |
| `dolce-view/src/playsong.rs::play_source_of` | `ScoreDoc` → `PlaySource` 统一入口（各格式共用）：按形状分给 `playSourceOfSong`（简谱形状）/ `dolce-view/src/playdoc.rs::play_source_of_doc`（MusicXML 形状，带全部声部、voice 与力度） |

原生音源那条命令（`midi_play_cmd` / `midi_stop_cmd`，macOS `AVMIDIPlayer`，player 必须存活、放进托管状态）
与其余两块原生能力一起放在 [编辑器](编辑器.md)「Tauri 外壳」。

## 关键判据

- **试听与导出 MIDI 读同一份 `App.playable()`**，由各格式共用的 `dolce-view/src/playsong.rs::play_source_of` 从 `ScoreDoc` 拼：MusicXML 形状（`isXmlShaped`）走
  `playSourceOfDoc`——全部声部（mixer 的声部序号 = `Part` 序）、各 voice、和弦全部音，力度记号（pp…ff）落成 note-on 力度，
  光标只跟主旋律声部的主分支（`dolce-view/src/phrasedoc.rs::main_voice_of`：该声部最小的 voice 号——文本谱 `Q2:` 投成的 part 全是 voice 2，写死 voice 1 会整段滤空、抛 `measure has no chord`）；简谱形状（文本谱/123/ABC/`.jpwabc`）走 `playSourceOfSong`。
- **试听 / 导出 MIDI 不随视图档变，一律按投影档的口径**（唱几遍、每遍唱哪段词与投影档谱面一致，在哪一档导出的 MIDI 都一样）。
  以前简谱形状只在投影档传 `forExpanded`，简谱档、五线谱档各推各的，三处会分叉：
  文本谱同一段曲下两行 `C1:`（其实是第 1、2 段）简谱档 / 五线谱档只唱一遍、第二行词丢掉；
  词写在第 2 声部（第 1 声部是伴奏）时五线谱档按第 1 声部推遍数，少唱几遍。现在：
  - 简谱形状（简谱档、投影档、识别核对）一律 `forExpanded`：带歌词的声部当主旋律、同号歌词顺延。`.jpwabc` 单声部、段号本就不重，照旧不传。
  - MusicXML 形状（五线谱 / 混排档播的 `mixedDoc`、`.musicxml`）：演唱顺序的段数按**主旋律声部**（`dolce-view/src/playdoc.rs::lead_part_of`，
    第一个带歌词的声部，都没词取第一声部）推，反复与跳转记号仍读第一声部；同一个音底下段号重复的词顺延（`dolce-model/src/helpers.rs::distinct_numbers`，
    只试听这份顺延，断句与引擎输入不动）。**主旋律声部只给试听用**（`playDataOfDoc` 的 `lead` 参数）：投影档与
    `.jpwabc` 写出端画的、写的都是第一声部，演唱顺序必须按同一个声部推——`PlayItem.limit` 数的是这个声部的和弦，
    按带词声部数、截在第一声部上会截错音。所以 `.musicxml` 第一声部没词、词在后面声部时，投影档（画第一声部、无词）比试听少几遍，
    要统一得让投影档改画带词声部，没做。
  - **声部按模型顺序交出去，主旋律另记 `PlaySource.lead`**：声部面板（音量 / 静音 / 独奏按 `Part` 序）、MIDI 轨序都对得上。
    以前投影档把带词声部挪到第一位，词不在第 1 声部时声部面板调的是另一个声部。光标锚点、`PlayItem.limit` 数的和弦、
    节拍器拍号都取 `lead`；同刻起音播放线先停主旋律（投影档只画它）。回归 `play-check` 的「试听三档一致」。
- **ABC `&` 的临时多声部先投影再播**（`playSourceOf`）：简谱形状那条路一个声部行只走一条旋律，
  并行的分支会被当成接着唱的音（这一小节凭空多出几拍）。带 `&` 的先 `projectForMusicXml` 投成
  MusicXML 形状走 `playSourceOfDoc`，各 voice 分轨同时发声；投影是克隆、元素 id 不变，高亮照样认得。
- **多声部叠在共用时间轴上**（`crates/dolce-model/src/timeaxis.rs`，试听、演唱顺序、导出 MusicXML 共用；文本写出端也照它切行：文本谱按轴对齐各声部的行、缺席的组不写，123 / ABC 在缺席的格上补不可见休止，见 [123 格式](../格式/123格式.md)「多声部」）：文本谱一组不一定含全部声部，
  各声部按小节序号叠起来会错位（issue 11：只在末组出现的 `Q2` 从第一行就响）。轴上一格一小节，各声部的小节按「组号（`print.system`）+ 组内第几小节」落格，
  每组占该组各声部小节数的最大值；缺席或偏短的声部在那几格上**没有小节**，什么都不补（`PlaySource` / `PlayPart` 的 `measures` 那一格是 undefined）。
  从前在克隆上补无声小节（新 id、照抄小节线房号跳转），试听与投影档的小节下标也因此不同；R7 去掉。
  `dolce-view/src/playsong.rs` 把行视图切出的小节按首个和弦的元素 id 找回模型小节、取它的格；演唱顺序在轴上推，读反复、房号、小节线用「每格的代表小节」
  （第一份声部的，它这一格没有就取后面第一个有的，引用原小节不复制）；`playDataOfSong`（投影档、`.jpwabc` 写出）再折回第一份声部自己的小节序，
  第一份每格都有小节（常见情形）时两者下标完全相同。非文本谱来源（没有组号）按小节序号一一对应。曲中转调（`fanqie/fromfanqie.rs` 补到各声部）按轴上的格补，这一格缺席的声部补到它往后第一个小节，试听（`keyChangesOf`）也认后出场声部头一小节上的调号。回归 `play-check` 的「共用时间轴」。
- **延音线只延长、不再起音**（`crates/dolce-play/src/timeline.rs::build_timeline`，issue 11）：`TimelineNote.tieStop` 的音若与同声部同音高的上一个音首尾相接，
  就把那个音的 `t1` 拉长；不相接（反复跳转后、中间隔了休止）照常起音。`tieStop` 的来源：MusicXML 形状取 `Note.tie.stop`
  （`dolce-view/src/playdoc.rs::chord_entry`，旋律档 `dolce-view/src/phrasedoc.rs` 同口径）；简谱形状的文本谱在 `dolce-view/src/phrasesong.rs` 判——
  **一条弧恰好括住相邻两个同音高的音**（中间只隔 `-`、小节线、换行）就当延音线（简谱里两者同形，番茄 `(2/ 2)`）；ABC / `.jcx` 来源不判（它们的延音线另写 `-`，`buildMeasures` 的 `pitch.slurTies`）。
  以前整条播放链不看延音线，ABC/MusicXML 的真 tie 也会重新起音。
  **播放器回调与起播点都是 `ElementId`**：一律 `ScorePainter.highlight(id, pass)`。
  **光标各视图统一是竖直播放线**（`layout/playhead.ts`，同 Sibelius / MuseScore / Dorico），不给音符着色；播放器跟**各声部起音**走（`player.ts::onsetAnchors`，同刻取声部序最前的），女高休止、别的声部在唱也照走。横向：五线谱 / 混排的五线谱层按符头中心居中、定宽（和弦组 `data` 记的 `StaffChordData.cx`，跨谱表只画符干的组也带上；不随符尾、错开的头、整小节休止撑宽），简谱取音的包围盒；纵向：五线谱 / 混排取谱表带；简谱两条路取音符所在那一行（`system` 身份标签，多声部是连谱号括起的整组）里音符格、增时线格与歌词格墨迹的并集（按遍次取音符格；只有一段词的反复两遍同段号时，再按「这个音这一遍号第几次出现」取第几格——时间线锚点的 `occ` 与页面树顺序一一对应，`ScoreIndex.note`；不取行组本身的盒——弧、房号会把线撑得忽高忽低）。五线谱 / 混排与简谱同一份身份索引（`layout/scoreindex.ts`）。这一视图里没画的音（投影档只排带歌词的那个声部）不挪线。
  识别核对（原图对照）也能试听：播的仍是代码区那份，播放线由 `OmrController.highlightPlaying` 画在识别图上（横向取识别框，纵向贯穿本系统各声部行）——元素 id ↔ 识别音序靠**元素源区间起点 ↔ `meta.noteRanges[i].from`**（编辑后随变更集迁移，改了文本也对得上），对不上按遍历序兜底；再从 meta 序换到框序（`flatOrder`：框按谱面逐行编号，模型按声部，四声部两者交错）。没有点选映射的产物（`.jpwabc` / ABC）只播不显示播放线。点识别框同点音符：定起播点 / 播放中跳过去。
- **八度谱号的声部低八度发声**（`dolce-view/src/playsong.rs`，123 `V:3 clef=treble-8`，见 [123格式](../格式/123格式.md) §7）：
  四声部简谱的男高、男低照惯例按高八度记，以前照谱面出声，男高比女高还高。度数 → 音高的另一处（`xmlproject.ts`，
  五线谱 / 混排与 MusicXML 导出）同样落回实际八度。
- **曲中转调**（简谱形状那一路，`dolce-view/src/playsong.rs::key_changes_of`）：模型小节上的调号（`Measure.attrs.key`，123/ABC 的行内 `[K:]`）
  按元素 id 交给 `dolce-view/src/phrasesong.rs::build_measures`，到了那个音就换调（基音重算、小节内临时记号清空）。以前全曲只用头部调号推音高，
  转调后半首都是错音（谱面早已按模型小节画出转调）。MusicXML 形状那一路（`dolce-view/src/playdoc.rs`）本来就逐小节认。
  回归 `play-check` 的 `1=G → 1=D` 夹具。
- **速度 = 谱面 `♩=` × 工具条倍率**，两者都在 `crates/dolce-play/src/timeline.rs::play_tempo` 折算；谱面没标速度时按 `TEMPO = 90`。
  - 谱速来源：`.Title` 的 `Expression`、123/ABC 的 `Q:`、MusicXML `<sound tempo>`（小节级的也认，记成 `Direction.sound.tempo`），
    经 `dolce-view/src/playdoc.rs::tempo_of_doc` 进 `PlayData.tempo`。附点四分等拍单位随文档保存（`Song.tempoBeat`），`.jpwabc`、文本谱只认 ♩，写出时换成四分等值。
  - `.jpwabc` 按 JP-Word 原生规范把速度记进 **`Expression`**（它兼记速度与表情，值可以是纯表情文字），不另立 `Tempo` 键；
    写出端写真 Unicode `♩`（U+2669），读取端 `J` 与 `♩` 都认（JP-Word 存 `{J=80}`、靠音乐字体显示成 ♩），从 JP-Word 拿来的谱速度不丢。
  - 倍率是工具条「试听」旁的下拉（`SPEED_STEPS`，×0.5~×2），存进渲染设置，经 `App.playOptions()` 同时喂给试听和 MIDI 导出。
- 两路音源：`SamplerSource`（Web Audio + smplr SoundFont）/ `NativeSource`
  （macOS `AVMIDIPlayer` + 系统 DLS GM 音源，经 Rust；支持按秒定位）。
- **试听不联网**：采样那一路的钢琴音色随应用分发（`public/redist/soundfont/`，FluidR3 GM 大钢琴的 MIDI.js 格式，
  `player.ts::PIANO_SOUNDFONT` 经 smplr 的 `instrumentUrl` 读）。以前点播放时从外站现下，连不上就卡在「加载中」
  （没有超时），网页版、Windows 桌面版都受影响（issue 13）。只带 mp3 一份：各家浏览器与桌面 WebView 都能解，
  ogg 那份 Safari 不认。
- **会话、暂停与定位**（issue 12）：一次 `play()` 把时间线换成秒（`Session`），会话内 `pause / resume / seek(sec)`。
  - 采样：AudioContext 与音色**跨会话保留**（停止只挂起），定位、重播、改速度都不重新载入音色。暂停 = `ctx.suspend()`，
    排好的音原样留着。音不再一次全排进 smplr，而是按 `FEED_AHEAD`（2 秒）窗口陆续递、记下各音的撤销函数——
    smplr 的 `stop()` 只停已发声的 voice，**不清它自己排队的事件**，一次全排就没法在定位时撤干净。
  - 原生：暂停 = 停播放器、记位置；续播与定位 = 从那一秒重新 `midi_play_cmd`（Rust 侧本就支持 `startSeconds`）。
  - 改速度：有会话时把当前位置按倍率反比折算（谱面 ♩= 不变），从那儿按新速度接着播；暂停中改仍停着。
  - 起播点优先级：停止状态下拖进度条 / 点音符定下的 `cueSec` > 选中的音 > 曲首。播放或暂停中点音符直接 `seek`。
    起播点按命中的同步条目记（点第 n 段歌词 = 第 n 遍）。
  - **播放 / 暂停中点音符要赶在可视化编辑之前**：简谱档的点击先过 `_onSyncClick → visual.handleClick`，点选会接走音符点击，
    跳转就轮不到了。所以会话进行中（`PlaybackController.active`）先认音符：按同步条目（点第 n 段歌词 = 第 n 遍）；
    点中了只 `seek`、不选中，没点中音符再照常走点选。
- 工具条：播放/暂停/继续一个按钮，■ 停止（回曲首），进度条拖动时只改显示、松手才定位，时间显示点一下切「已播 / 剩余」。
- **循环与节拍器**（工具条「循环」「节拍」）：循环段 = 谱面选区第一个音起音到最后一个音收尾（`player.ts::spanSeconds`，按 `allAnchors` 认，
  五线谱 / 混排把源 id 换成画出来那份），没选区循环整首；播到段尾 `tick` 里 `seek(段首)`，采样递音的窗口截在段尾。
  节拍器拍点由 `buildTimeline` 一并给出（`Timeline.clicks`，按第一声部的拍号：复拍子 6/8、9/8、12/8 按附点四分打，小节第一拍重），
  **嘀嗒与音符必须由同一个时钟排**，两路音源各出各的：采样那一路是 WebAudio 正弦嘀嗒，与采样音同排在 `AudioContext` 上；
  原生那一路把嘀嗒写进 MIDI（`crates/dolce-play/src/midi.rs::click_track`，打击乐通道的高 / 低木鱼），与音符同一个定序器播——
  WebAudio 的嘀嗒配原生播放器会错拍。这条轨只在试听时加（`toMidi` 第三个参数），**导出的 MIDI 不带节拍器**；
  声部从第 10 个起让过打击乐通道。节拍器持久化，循环只在会话内。
- **导出 MIDI 带歌词**（issue 16：导进 X Studio 等歌声合成软件，字自动落到音符上）。
  - 字从哪来：和弦第一个音的 `TimelineNote.lyrics`——简谱形状就是 `dolce-view/src/phrasesong.rs::build_measures` 挂的那份（`nextSyllables` 已把收尾标点并进字），
    续记号由 `dolce-view/src/playsong.rs::mark_extends` 按元素 id 从模型补上；MusicXML 形状取断句输入那份（`dolce-view/src/playdoc.rs::lyrics_of_part`：
    段号已顺延、`findRefrain` 判过副歌，同 MusicXML 投影档，副歌各遍都唱），字、收尾标点与续记号取模型的。
    简谱形状的引擎输入不判副歌（文本谱用 `C1-2:` 区间、123 逐段各抄一遍），某段词写得短，后面那几遍靠下面的借词补上。
  - 哪一段：`crates/dolce-play/src/timeline.rs::lyric_of_pass` 按演唱顺序的遍次取段号相同的那段，没有就取副歌；这一格在这一段整首最后一个字之后
    （副歌只写在第 1 段：190《凡愿意者可来》、020《向主歌唱》第 2 遍的哈利路亚）借段号最小的、这一格写了字的那段，
    **与投影档同一判据**（`place/expand.ts::afterVerseEnd`）；
    印刷段号前缀（`.jpwabc` 的 `{1.[圣]}`）去掉。反复、房子、D.C./D.S. 都由演唱顺序处理，这里不另判。
  - 一字多音：本遍没字、但与同声部上一个起音的音首尾相接、且那个音有字（或也是拖腔）的记 `-`——歌声合成软件通用的「延续上一字」，
    不记的话没字的音会被唱成默认字（「啦」）。还要满足下面一条，否则是**这一遍的词已经唱完**（段词比曲子短），不挂：
    起头的字带续记号（`TimelineLyric.extend`：123 的 `_`、MusicXML `<extend>`）；或这个音在连音弧里（`TimelineChord.slurStart/slurEnds`）；
    或这一遍后面还有字（行中间的 `_` / `/`）。隔了休止、换了一遍不挂（拖腔不跨遍）；
    同一声部里与主旋律重叠又没字的副 voice 不打断拖腔。延音线并掉的音本来就不起音、不挂字。
  - 写法（`crates/dolce-play/src/midi.rs::part_track`）：note-on 同一 tick、紧挨在它前面写 Lyric（`FF 05`）与 Text（`FF 01`）各一条，UTF-8；
    同刻排序 note-off → 歌词 → note-on，免得字落到上一个音的收尾前。声部轨开头写轨名（`FF 03`，`Part.name`，没有不写）。
  - 试听那份（`toMidi` 第三个参数）不带歌词。回归 `play-check` 的歌词一组。
- **导出 MIDI 写拍号与调号**（PR 43）：指挥轨在速度之后写拍号（`FF 58`，分母不是 2 的幂的不写）与调号（`FF 59`，小调 mi=1），
  否则接收软件一律当 4/4、C 大调。变化点由 `buildTimeline` 按演唱顺序展开给出（`Timeline.signatures`，读主旋律声部的小节，与前一个相同不写）。
  小节上的拍号 / 调号在拼小节时就记下，不事后按 id 反查：简谱形状 `dolce-view/src/phrasesong.rs::build_measures` 按行里符号的来源小节（`SlotRef.measure`）
  读模型小节的 `attrs.time`（口径同 `jianpuinput.ts`；原先 `MeasureOut.time` 全曲取页眉一个，曲中转拍号节拍器与 MIDI 都不跟），
  调号随 `dolce-view/src/playsong.rs::key_changes_of` 的曲中转调；MusicXML 形状 `dolce-view/src/playdoc.rs::timeline_part_of` 读 `attrs.key`。
  调号写**实际发声**的调：移调乐器按 `keyshift.ts::soundingFifths` 换算（降 B 单簧管记 D 大调 → C 大调）；fifths 走 `keyFifths`（文本谱的调号只记拼写）；
  小调按 `isMinorKey`（调式 minor / aeolian，或没写调式、主音唱名是 6）。曲首弱起也从 t=0 起算拍号（MIDI 没有弱起的写法）。
- **移调乐器按实际音高发声**：MusicXML 声部的 `<transpose>`（`chromatic` + 12 × `octave-change`）加到记谱音高上（`dolce-view/src/playdoc.rs::timeline_part_of`）。
- **`<forward>` 空出的拍子要认**：读入后它只记在后面那个元素的 `Chord.onset` 上（不是隐形休止），`timelinePartOf` 起点取 `onset`，
  没有才按本声部累加。原先只累加，合唱谱识别结果（声部从小节中间起、中间空一拍都用 `<forward>`）播出来后面的音往前挤（宁静的伯利恒钢琴左手）。
- **起播点**：点过的音优先；没点过取可视化编辑选区的第一个音（键盘选的、切档后留下的也算，`App.startPoint`）。
- **五线谱 / 混排档也试听**，播的是画出来的那份 `mixedDoc`（元素 id 与五线谱和弦组对得上）；播放线见上。
- **谱面高亮不在 `PlaybackController` 里**——那属于「谁在画谱面」，留在 App。
- 文本谱试听必须复用排版时那份 AST。

## 段落顺序 `P:`

语义见 [123 格式](../格式/123格式.md) §6.1。这里记怎么接的：

- `crates/dolce-play/src/playorder.rs::section_play_order` 每次进入一段**新建一个 `RepeatProcessor`** 跑这一段的切片（`structureOnly`：不看歌词），它的遍号只用来挑房；交出去的 `PlayItem.pass` 是这一段第几行词。房号与歌词因此不用拆字段：`pass` 的消费方只把它当歌词行用。不跑 `repeatByLyric`、`lastVerseTail` 这些按词推的步骤。
- 借词判据多一个范围：`PlayItem.scope` 是这一段的小节，`crates/dolce-play/src/timeline.rs::build_timeline` 的借词判据与 `place/expand.ts::afterVerseEndIn` 只在里面数（否则 B 在 A 前、A 的行比 B 多时，B 第 2 次进入借不到词）。
- 三条路都接：简谱形状 `dolce-view/src/playsong.rs::play_data_of`，MusicXML 形状 `dolce-view/src/playdoc.rs::play_data_of_doc`（元素 id 投影后不变），五线谱 / 混排的 `mixedDoc` 是 MusicXML 读回的，`mixedsession.ts::_ensureMixedDoc` 用 `model/sections.ts::carryPlayOrder` 按 `Chord.srcId` 搬过去。
- 同段每次进入行号递增，`Anchor.occ`、`ScoreIndex.note` 不用改；每段末 `endOfPass`，`walkPlay` 据此另起一页。`.jpwabc` 写出端不用 `P:`（`useSections` 关掉）。

## 按参照歌词生成段落与 `%%sing`

歌词网站、歌本配套的歌词按实际唱法逐段写全（空行分段），谱面只印一遍、靠反复 / 房 / 跳转表达。拿这份歌词在 123 里切出段落 `[P:x]`、
写出逐遍演唱顺序 `%%sing`（语法见 [123 格式](../格式/123格式.md) §6.3）。用户定（2026-11-24）：歌词与谱面反复对不上时**以歌词为准**，
差异只报告、不改音符；段落名按角色；分遍尽量密排、优先在副歌唱完后换页。

| 入口 | 作用 |
|---|---|
| `crates/dolce-view/src/singfit.rs::fit_sing` | 生成本体（纯逻辑）：回段落标记、`SingPass` 列表与差异；`apply_sing_fit` 写进 `Song`（标记整套换掉、`sectionOrder` 清掉） |
| `crates/dolce-view/src/reflyrics.rs::ref_lines` | 参照歌词文本 → 歌词行（解码、`.lrc` 按时间展开、去信息行 / 段号 / 结构标注），记每行第几段与段前的结构标注；与识别的参照歌词互证（`omr-todoc::reflyrics`）共用 |
| `crates/dolce-session/src/sing.rs` | 接上投影档排版（分遍要知道每段占几行）；`sing_from_lyrics_json` 是 wasm `singFromLyrics` 与桌面排版线程命令 `layout_sing_from_lyrics` 共用的入口 |
| `dolce omr … -f 123 -l 歌词` | 识谱命令行顺带生成（`--no-sing` 关掉；别的格式写不下，只提示）；量字走系统 |
| 编辑器工具栏「演唱顺序」 | `editor/dialogs.ts::showSingDialog`（歌词一改、停顿 0.4 秒自动预览，没有单独的「生成」步）→ `App.previewSingFromLyrics`（门面 `layout/rustlayout.ts::singFromLyrics`）；各格式都能生成（在 `ScoreDoc` 上算）。123 由 `editor/singapply.ts::applySingFit` 写进原文（光标所在那一首）；别的格式见下「挂在模型上」 |
| `dolce-dev sing-fit <谱.123> <歌词>` | 开发对拍：打报告与写回后的 123，`--svg=` 出投影页 |

判据：

- **原子**：谱面按印的次序在结构处切开——`|:`、`:|`、房头、双纵线、跳转记号、已有段落标记，以及谱面默认走向（`walk_play`）里跳过去的地方。
  每个原子的每条 `w:` 是一串字（只取有字的音，繁简归一同 `dolce-base::hanvariant`）。
- **对齐**：动态规划，状态 =（原子，词条，词条里第几个字），逐个吃参照字。配对不同、参照多字、谱面多字各 1 分；
  原子末尾按谱面能接上的（下一原子、`:|` 回 `|:`、房身进同一串房的各房、D.S. 回 segno、D.C. 回开头）不罚，
  其余跳转 2 分、从原子中间进或从中间离开再加 0.5、跳进别段的房再加 1；经过无词的音每个加 0.02（同分时少带间奏小节）。
  一条词在原子里唱完、后面还有音时，接着唱别的词条在这之后的字不罚（一段副歌只印一行词、每遍都唱它）。
  所以歌词与谱面一致时照谱面走，对不上时（如桥段谱面 AABB、歌词 ABAB）照歌词走，不照谱面的那几次转移报 `offScore`。
  同字不到参照的一半就当不是这首的词，不生成。
- **段界**：参照新一段的首字落在的音往前退过休止（不退过上一段末字），退到的那串休止里有小节线就切在最后一条小节线上——
  弱起句头切在弱起音前，不带上整小节的间奏休止。跳转、中间接入也照此切。
- **合段**：所有切点切成小段；总是前后相连出现、配的词条相容的相邻小段并成一段。`@n` 是段内第 n 条有字的 `w:`；段里只有一条词的不写 `@`。
- **角色与段名**：路按参照的段落成组（只在小段边界与参照段界重合处断组），每组一个角色：参照段前写了副歌标注、
  或这一组开头那段的第一小节谱面印了副歌字样（`【Chorus】`、副歌；「接副歌」这类跳转提示不算）、或唱得最多的那组 → 副歌 `C`；
  第一个副歌之前的、与主歌共用段的 → 主歌 `V`；其余 → 桥段 `B`。段名取第一次唱它的那组的角色，同角色按谱面先后 `V`、`V2`…；
  一遍都没唱到的段（如歌词 ABAB 时用不上的一房）记 `X`、`X2`…（标记照写，免得并进前一段）。
  无词的小段（间奏、尾奏）随下一组；但它紧接前一组、而下一组不从它后面接着唱（如 D.S. 跳走前的末小节）时算前一组的尾巴，
  不另起段名、不随下一组。
- **分遍**：每组单独一遍（`[rows=99]`）试排投影档（编辑器开着「按乐句重排」时按乐句断行试排，命令行按装满），量出各组占几行；贪心装页（一页缺省 4 行，同投影档）：
  装得下就并，副歌唱完后只有下一个非副歌单位**整段**装得进本页才并，否则换页。同一遍里组与组之间写 `/`。拿不到排版时副歌唱完就换遍。
- **写回原文**（编辑器）：只动三样——曲内 `[P:x]`（旧的删掉，新的插在段首和弦及挂在它前面的和弦名、注记、装饰、从它起的弧 `(` 之前）、
  整行的 `P:`（写了 `%%sing` 就不起作用，留着指向旧段名）、`%%sing` 行（换成生成的，写在这一首末尾）。其余原文不动，一次改动可撤销。
  有标记在原文里定不了位时不写。
- **挂在模型上**（123 以外，用户定 2026-11-24）：别的格式写不下 `%%sing`（ABC 只写得下 `P:`，见 `crates/dolce-formats/src/capability.rs::gone`），
  不改原文；`editor/singoverlay.ts` 把结果记在 App 上，每次读出模型（`currentScoreDoc`、`_reloadScoreDoc`、`.jpwabc` 那份、`.musicxml` 五线谱档读的那份、转格式的真身）
  都经 `App.withSing` 补上——投影、试听、导出、五线谱档（`carryPlayOrder` 搬）都照它，另存为 123 时随写出端写进去，存回原格式走保存前丢失提示。
  段落标记按位置（第几声部第几小节第几个元素）记，改了原文元素 id 重编也对得上；有标记的位置没了就整份作废、状态栏说一声。换文档、换成 123 时清掉。

限制：只认汉字（英文歌词不参与对齐）；谱面已有的段落标记整套换掉；不照谱面的跳转（如第二次进桥段前没有印好的弱起）只报告、不补音；
分遍按生成时的投影档样式试排，之后改了样式行数可能变（`%%sing` 一页装不下时照常续页）。

## `.Repeat` 在五线谱这一路

`.Repeat`（`Song.playOrder`）的小节号指源文的小节。五线谱 / 混排档读的模型投影时小节会拆会并，读回后元素 id 也换了，小节号不能直接用，所以按**首尾和弦**定位：

- `crates/dolce-model/src/sections.rs::anchor_play_order` 趁小节号还对得上定 `PlayPass.fromAnchor` / `toAnchor`（`project_for_music_xml` 一开头做）；读回的 `mixedDoc` 由 `carryPlayOrder` 按 `Chord.srcId` 换成新 id。
- `dolce-view/src/playdoc.rs::play_order_of_doc` 从锚点找回小节，`skip` / `limit` 照音算（小节拆开时最后一个音不在小节尾、并起来时第一个音不在小节头），优先于按记号推。
- 一项的音都找不到才丢这一项，一项都不剩交回按记号推。回归 `sections-check.mjs`：简谱、投影、五线谱、混排四档音序与歌词逐一相同。

## 谱面有、试听没有的小节

源文改过后（`App.reload` → `_reportPlayHint`）状态栏提示两种情况：演唱顺序里一遍都没有的小节（`crates/dolce-play/src/playorder.rs::unplayed_measures`）；封口却没写 `:|`、紧跟下一房、按反复回头唱的房（`PlayData.impliedRepeat`）。写了 `.Repeat` 的不报，顺序来自 `P:` 的不报没唱的小节（没排进去的段落是作者定的，漏写 `:|` 照报），混排档不报（`mixedDoc` 异步排）；解析告警优先，识别核对视图不报解析告警、只报这个。
