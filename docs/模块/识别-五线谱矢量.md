# 识别：五线谱（矢量 PDF，文字层完整）

**判据全录** → [../实现/五线谱矢量识别.md](../实现/五线谱矢量识别.md)

## 职责

Finale/Sibelius 直出的矢量五线谱 PDF → MusicXML。**已接编辑器**，产物只进混排视图。
移植自原 C++ 工程的 `qtomr/`。

## 入口

|---|---|
| `src/staffomr/index.ts` | 对外入口 |
| `src/staffomr/pagerun.ts` | 一页识别（顺序照 musicpp `Score::process`）、页眉文字层 → `<credit>` |
| `src/staffomr/song.ts` | 整曲识别（判路 `isStaffPdf`、跨页沿用拍号、跨系统连接） |

| `src/staffomr/notedata.ts` | 符头/符干/时值 |
| `src/staffomr/textanalyze.ts` | 正文与歌词分析 |

## 关键判据

- `isStaffPdf` 判该走哪条路；产物只进混排视图。
- **凡是数 XML 元素的正则，一律写 `<name[ >]`**（这条铁律就是在这个文件里立的）。
- 「**三个工具都读不到」不等于「文件里没有**」——三个工具可能共用同一层没打开的开关。
- **原图对照**（编辑器里，`browser.ts::vectorOverlayResult`）：`recognizeStaffPdf({ noteIds })` 同位图那一路逐页逐音写 `<note id="omr<k>">`、记源框（PDF 点，y 朝下），
  页面用 pdf.js 按 2 倍渲成位图（透明处按纸算，不然没画到的地方读成黑），框乘 2，拼成 `review.ts::StaffReviewResult`（与位图那一路同一形状）交给对照视图、并排原图、关联表；
  谱线坐标仍是点，`pages[].scale` 告诉用的人乘多少（`omrctl.staffBand`）。项目重开时重跑一遍矢量识别拿框（不用 OCR，快）。
  歌词字、弧、力度、文字的源框（`markBoxes`）同位图那一路编号写 id、同样乘 2，见[识别-五线谱位图](识别-五线谱位图.md)「原图对照」。
- **写出的谱面信息**：stem 方向、`<beam>`（只给接杠的音，挂符尾的不写，靠它分开杠与尾）、圆滑线 `placement` / 连音线 `orientation`、
  速度文字与节拍器合在一个 `<direction>`、人声方括号 `<part-group>`（判据见实现篇「符杠 / 符尾、弧方向、速度一条、人声方括号」）；
  符干端点、力度与松叶的原位原大小、钢琴 `<part-symbol>` 与位图路同一份写出（见[识别-五线谱位图](识别-五线谱位图.md)「符干、力度、松叶也照原图写」）。
- 反例备忘：**「跨行小节合并」量过了，这本书用不上**——别为这一条去动 `toxml.ts` 的小节结构。
- **矢量 GT 的覆盖审计**（`../dev/scripts/vector-gt-audit.mjs`）：PDF 里每个对象在 GT 里都要有着落，逐系统、逐谱行、逐小节按类对账。
  新增矢量 GT 谱例照「识别稿 → 审计 → 对图补 → 审计归零」走，流程与口径见实现篇「矢量 GT 的覆盖审计」。

## 转曲的矢量谱（`src/outlineomr/`）

文字与音乐字形都转成了路径、没有文字层也没有内嵌位图的五线谱 PDF（祢話如甘霖單頁譜：Ghostscript 转出，一个字形一个路径对象）。
`isStaffPdf` 判否之后由 `outlineomr/song.ts::isOutlinedStaffPdf` 判（无文字层、无内嵌图、路径里有五条一组的等距长横线），
编辑器（`omrctl.adoptStaffPdf`）与回归（`node-harness.mjs::recognizeStaffSong`）同一判据；从前这种 PDF 判不进任何五线谱路，整份落到简谱识别。
**不栅格化**：对象之间本来就分开，位图路最费劲的粘连（弧压着歌词字、八度点贴着数字）在这里不存在。

| 文件 | 作用 |
|---|---|
| `outlineomr/glyphs.ts` | 线与字形分开（`isGeometry`）、一个对象画了几个字形的拆块（`splitPieces`）、跨字体认音乐字形（`OutlineGlyphLookup`） |
| `outlineomr/page.ts` | 一页：建页接矢量路后半段（`pagerun.ts::recognizeBuiltPage`）；简谱行、和弦带、歌词、页眉、速度、房子 |
| `outlineomr/raster.ts` | 送 OCR 的小条：只画条里的对象，自写扫描线（浏览器与 Node 逐像素相同，OCR 缓存指纹才对得上） |
| `outlineomr/song.ts` / `browser.ts` | 整曲（交出与矢量路同形的 `StaffPdfResult`，对照视图照用）/ 编辑器入口（在线 OCR） |

- **线与字形**：无曲线、≤5 段的是线（谱线、符干、加线、符杠、减时线、房子）；有曲线的弧是**拆不出第二块**的扁长对象，
  或细（签名里墨占外框不到 0.15）且宽过两格的斜弧（跨行延音线行末那半截往右下拐）。一整串字画成一个对象的（「Badd9」「D.S.al.Fine.」）同样扁长但拆得开，算字。
  低音斜着连到高音的短弧（裴克经文诗歌八分音符对之间，1.8×1.4~2.3 格）不扁也不够两格宽：曲线不过 4 段、总段数不过 6（两条曲线首尾相接的月牙）、
  细、宽一格以上且不比高窄过四成的也算弧（括号又窄又高）。后段 `staffomr/slur.ts` 的陡弧闸同时放到「宽不小于高的 0.75 倍」（两路共用；符尾靠干尖那条挡）。
- **音乐字形**：轮廓签名对 `glyphmap.json` 各类**跨字体**找最近（尺寸按 1 em = 4 线距归一）：符头 15~28、符尾 5~11、谱号 26，文字 90 开外，门槛 60；
  近乎同形（≤20）的尺寸放宽到 0.25 em（这套字体的升号比 Opus 矮三成）。只认谱表上 4.5 格、下 4 格以内、不在简谱行里的；
  调号一串升号画成一个对象，整个认不出再拆块认，**拆出来的块不收形状简单的**（横杠、点、短竖：「話」的言字旁被认成保持音）。
- **文字**：和弦带（简谱行之上 4.5 格）按横向缝分记号、歌词按字行切字格（**整个对象**进字格，字宽卡 1.1 个字高）、页眉整块，
  画成条送位图路同一套 OCR（`RasterLiveOcr`：编辑器在线、回归查缓存、缺条当场在 Node 里认）；简谱行照位图路找带、互证。
  条按每点 6 像素画，**按绘制算子**填或描（`fill`/`stroke` 颜色不代表要描，字形描一圈会糊成一团，「慕」读成「暴」）。
- **速度**「♩=64」页眉 OCR 读不出音符字形、连带丢了数字：按几何找（窄高的音符块 + 两道短横 + 数字），数字送拍号数字 OCR，同一行后面的字记成速度文字。
- **房子**：矢量路 `findVoltas` 要钩底贴谱表、房号是文字层，混排谱两样都不满足；这里按横线 + 左端竖钩（钩底在简谱行之上三格内）找，
  横线被房号断开的隔过去接，房号按反复线推（同位图路 `repeats.ts`）。
- 简线混排谱（认出简谱行）单行系统归第一声部（`buildScore` 的 `soloToFirst`），编辑器进混排档。
- **只认页上一段**（歌本切分逐首识别，`omr/booksplit/recognize.ts`）：`recognizeOutlinedDoc` 的 `segments` 给「页号 + 页内范围」序列，
  当连续页认，页眉只取第一段；`recognizeOutlinedPage` 的 `clip` 只留中心落在范围里、不在剔除框（页脚页码）里的对象，末行歌词带下界改到范围底。
  不给 `segments` 照旧认全部页。
- **签名前细分曲线**：有的排版软件转曲后一个符头只用两段三次曲线画椭圆（裴克经文诗歌，CorelDRAW），控制点远在曲线外；
  签名外框按控制点取，形状被压小、与字典对不上。控制点外框比曲线外框大出 5% 以上时把各段曲线等分 8 段再算签名（字体转出的字形段短，不受影响）。
- **空心符头按本页实心符头认**：同心两个椭圆画的二分符头，签名离字典各字体（内腔斜着）都远。本页认出 ≥3 个实心符头时，
  外框与其中位差 15% 以内、两道子路径套在一起的认作空心符头，宽到 1.5 倍上下的认作全音符。
- **谱号、调号、拍号字典认不出时按位置补**（`page.ts::bootstrapHeadSyms` / `readTimeSigs`）：
  谱号、调号直接调位图路 `rasteromr/rasterglyphs.ts` 的 `bootstrapClefs`、`bootstrapKeyAccidentals`（只看外框与线位、按线距写，矢量对象外框直接喂）。
  这套字体的升降号**拆成几个对象**：竖笔是单独的直线（归进了线），字形块只剩升号的横杠、降号的肚子——同位图路 `rejoinAccidentalStrokes` 的病，
  先把中线落在字形块左缘到右缘内的细竖线并回去（并进的竖线从线里拿走，不当符干；下一个降号的竖笔贴着前一个肚子右缘，不并）。
  升降不按位图路的墨迹重心分（转曲降号的肚子是细线空心，重心偏不下去），按结构：两道竖笔 + 无曲线横杠是升号，一道竖笔 + 带曲线肚子是降号。
  拍号是谱号右边上下紧挨着叠在同一 x 的两块（先从调号候选里剔掉），分子分母各画一条送位图路同一个拍号数字 OCR，按 `timeDigit` 的合法值收。
  候选按并回竖笔后的外框判：中心落进简谱带框、但伸进谱线半格以上的照收（E 调高悬在第五线上的 ♯G 贴着近处的简谱带，首页只数出三个升号）。
  从一个对象拆出来的块认成「两竖」（打击乐谱号、双小节线）也算简单形状不收：「到」「判」的立刀被摘走，「到」读成「至」八十多处。
  还原号也是两道竖笔 + 无曲线块，两笔上下错开（左笔朝上、右笔朝下，错开约笔长三分之一）；它的右笔就画在横杠右端，
  贴右缘（往外 0.1 格内）的竖笔在没有别的字形按左缘到右缘那条收它时也并进来。
  **行中转调**：谱号右边之外的小节线右缘也当起点按同一判据补（裴克经文诗歌 040 一房「♮♮ + 五个升号」转 B），
  带还原号的一串比六格窗口长，收下一批就从最右那个接着找（只接两格内挨着的）；小节线与记号之间隔着符头的是临时记号，不收。
  同一处小节线（连同转调记号）之后两格内上下叠着的一对按行中拍号读（二房行中 4/4）。
  **临时记号**同样拆块：调号收完后，剩下按结构认得出的升降还原号，大小过调号那一判据、右缘落在符头左边 1.2 格内、
  字形块（升号横杠、降号肚子、还原号横杠）中心与符头中心同高（差不到 0.35 格）的收作那个音的临时记号（只收结构认得出的，墨迹重心猜的不收）。
  纵向按符头上下一格卡、不按谱表卡（加线上的音，记号整个在谱表外）；降号的盒纵向收到肚子上（同位图路）。
  这套字的临时记号离符头 0.4~0.7 格，后段 `analyzeAccidental` 只挂半格以内的，转曲路经 `recognizeBuiltPage` 的 `afterNotes`
  再走一遍位图路 `keysig.ts::attachAccidentalsByPitch`（同高、1.5 格内），文字层矢量 PDF 不走。
  降号结构另加一条：肚子底与竖笔下端齐、竖笔上端高出肚子一截——倚音的符尾挂在符干上端，「一竖 + 带曲线块」也像降号（084「⁴5」）。
  行首调号同行中一样按链收（从左往右、相邻不过两格）：六格窗口里会落进头一个音前的倚音，符干符尾按墨迹重心被猜成升降号（178）。
  字典整块认成反复记号两点 / 附点、对象却没有一段曲线的不收（点是圆的）：还原号那两道平行四边形横杠在小节线右边被读成「|:」（150）。
  并回竖笔的升号框比字距宽，相邻两个压上一点：`staffomr/notedata.ts` 收调号时「紧跟前一个调号升降号」容压上四分之一个记号宽（五个升号只数出四个）。
- **歌词先于和弦带收、按整行归**：段数多的歌词末行贴着下一行谱的简谱行，中心落进它的和弦带，被切成和弦条
  （裴克经文诗歌第三段词与和弦字混成「尽♭E」「头Ccm」，和弦与那段词一起丢了）。歌词行收对象放宽到下一行谱的简谱行，
  顶边还在歌词带里的整行归歌词；整行落在和弦带里的留给和弦。和弦带按简谱行往上 4.5 格划，谱行排得紧时会伸进歌词：
  顶边过了界、但底边离下一行简谱行还空一格以上的行仍算歌词——这行谱还没收到词，或与上一行词同字号（下一段）；
  字小一号的是印在下一行上方的说明字（祢話如甘霖「桥段反復時…」），留给和弦带那边（裴克经文诗歌 106 首三行词连同和弦一起丢过）。
- **谱号左边起头的那串字归页眉**（`headOfLine`）：和弦记号不会印在谱号左边，那是速度记号、速度术语印得低落进了首行和弦带
  （「欢快地」被并进和弦行、整行判成文本，和弦全丢）；从中心在谱号右缘以左的字起，同行一个挨一个接下去的都算（「♩=72」的「2」伸过谱号）。
  与前一个字同字高（差两成内）的，隔一个词距（1.5 个字高内）也接上：速度术语常是两个词（015「宽广　歌颂地」，后一词留在和弦带里，
  四个和弦全丢）；和弦字母比汉字矮一截，接不进来。按「整个在首音左边」切试过：行首和弦常比五线谱首音还靠左 1.5~2.5 格，切掉了 20 首的行首和弦。
- **首行和弦带里整行在和弦行之上的页眉字归页眉**：页眉排得紧时右上「作曲：裴克」、速度术语后半「以崇敬的心」落进首行和弦带（129、013），
  汉字一多整行判成文字行。和弦贴着简谱行印在带里最低那一横行（不算单个碎块、扁横，字高至少 0.8 格）；整行都在它之上、
  字高到它 1.2 倍的是页眉字（汉字比和弦字母高；漏检简谱行时最低一行是简谱数字，和弦行比它矮，不动——112）。只管首行谱。
- **简谱带顶罩进来的和弦字还给和弦带**：带顶按小节线顶再往上放 0.8 格（罩高音点、弧顶），小节线竖得高、和弦贴得近时和弦字中心落进带里，
  首行和弦整行漏认（069、070、106、110）。顶端探出带顶、底端离本带简谱数字顶（带里 0.8 格高以上的字的顶边中位）还空 0.3 格的字归和弦带，
  不进简谱条、不当说明字；高音点、弧上的三连音数字整个在带里。和弦字母不扁（宽不过高 1.4 倍）、不小（0.8 格高以上）：
  简谱的延长记号（13×8 的扁弧与其中的点）也探出带顶，不卡会读成和弦「D」「C」。
- **简谱小节线离谱表顶线只要 0.3 格**（位图路 0.5 格，`findJianpuBands` 的 `clear`）：矢量路竖线是精确的独立对象，符干从谱表里伸出、不悬空；
  112 简谱行紧贴谱表（0.44 格），整首没检出简谱行，简谱数字混进和弦带，54 个和弦只认出 2 个。
- **速度记号**的音符符头与符干分开画的（符干是直线、归进了线）：符头右缘搭着往上的竖线就合成音符块；数字与「=」的缝放到一个「=」宽；
  数字串只收与第一个数字同字号的（紧跟着的速度术语「中速」字身更高）。三位数（110、120）靠拍号数字 OCR 的整条兜底读出，兜底收到三位，
  拍号那边仍由 `timeDigit` 只认合法拍号。
- **填充的扁矩形当文字**：汉字「一」、连字符「-」转曲后是无曲线的填充矩形，被当成线；谱表区与简谱行以外、填充（不是描边）、不长过 3 格的扁块并进文字。
  也按同一行的字收：横向八格内有歌词字高以上的字、扁块纵向落在那个字的上下沿之间，厚不过那个字高两成、宽不过 1.3 倍的也收
  （标题的「一」比歌词大一号，按线距卡不进，OCR 把「有一件事…」切成「有」|「件事…」，前一截还成了署名；
  紧贴谱表的第一行词落在谱表区里，要离开谱线一格以上——谱表区里的扁填充块是符杠，不夹在一行字的字身里）。
- **简谱行条上下扩到包住收进来的对象**：连音弧顶高出带框，按带框裁只剩两头一小截，读成高音点。
- **行首空小节**：`staffomr/page.ts` 量行首空当时量到右端小节线组最左一笔（`|:` 的粗线），不再量到细线（2.6 格量成 3.5 格，过了「三格以上是真空小节」的闸）。
- **休止符**字形认不出时由简谱互证按简谱的 `0` 补（`rasteromr/jianpufuse.ts`，与位图路共用）。简谱那一小节不满拍（弱起、反复切开的半小节）时，
  其余数字都配上了才只补 `0`、补到简谱那一小节的拍数为止。互证按小节头一个音处生效的调换算（`fifthsAt`，行中转调前后各按各的调）。
- **行末多出来的字**（最后一个音之后还印着字，008「帐幕的」的「的」在全音符小节右端）：`staffomr/textanalyze.ts::attachLyrics` 里同一段接连两个音节落到同一个音时并成一格
  （123 写成 `{幕的}`），不再挂成同一音上的两条同段词、写出时被拆成新的一段（两路共用）。
- **短谱表**：谱线先按页宽三成以上找五条一组、得出线距，剩下的横线再按「五条间距同本页线距、左右端都齐、长过 12 格」补认（末行只剩两小节，线宽才页宽 29%）。
- **全音符的加线**按符头中心判横跨（`staffomr/page.ts::findLegers` 的 `wholeByCenter`，只矢量路开）：`px` 是字形原点（左缘），这套字的全音符加线
  比符头还窄一点（墨迹起点比符头左缘右 0.46 点），按左缘量整个落选，下加一线的 C4 全音符被删、整小节空掉。只收加线不比符头长（1.15 倍内）的。
  位图路不开：一律按中心、只全音符、左缘让 0.1 格都试过，合唱谱各有几首多一两步。
- **歌词行与页脚小字**按本页字行行高的中位分（矮过八成的是版权小字），不按线距：祢話如甘霖歌词 3.3 格、版权 2.1 格，裴克经文诗歌歌词才 2.2 格。
