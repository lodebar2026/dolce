# 排版：五线谱与混排

**判据全录** → [../实现/混排.md](../实现/混排.md)

## 职责

MusicXML → 五线谱排版；可叠加简谱层成「混排谱」。移植自原 C++ 工程，单位 tenths。
所有可打开的格式都有这一路：文本格式（123、文本谱、ABC、`.jpwabc`，含简谱识别产物）由源文经唯一写出端投成
**不带版面坐标**的 MusicXML 再读回（`App._ensureMixedDoc` / `export.ts::sourceMusicXmlBare`），走自动铺排。

## 吃什么吐什么

```
MusicXML → ScoreDoc（fromxml）→ StaffLayout（layoutStaff）→ 页面树（五线谱层 render.ts + 简谱叠层 jianpuoverlay.ts）→ mixedVisitor → SVG
```

`五线谱` 与 `混排` 是同一个排版器的两种状态，差别只在要不要叠简谱层（`mixedShowJianpuLayer`）。

## 关键判据

- **叉形、圈叉符头**（`model.ts::ChordLayout.crossHead`）：整个和弦同一种 `<notehead>`（x / circle-x）才换，照时值取 SMuFL 的实心、二分、全音符那一款；
  打击乐谱的节奏音符按 `<unpitched>` 的显示位置画（`layout.ts::processNote`，不跟移调）。琶音画法与简谱共用 `engrave/arpeggio.ts`，画在符头与临时记号左边（`ARPEGGIO_LEAD`），排版按 `ARPEGGIO_RESERVE` 给它让出横向的位（`layoutpass.ts::entryReach`），首音的琶音不压小节线。
- `mixedVisitor` 把 matrix 加在**叶子**上、线与文字写死 black、只递归 Group；
  谱面那路的 `svgVisitor` 每个 item 都产生 `<g>`、颜色取 item、无条件递归。
  **两者的差别不许收进 `walkPageItem` 骨架**，理由写在两个 visitor 的注释里。
- 简谱层的纵向叠层与谱面同口径（`engrave/stack.ts`，`stack-gap`）。
- **页脚 credit 不当页眉**（`staffpages.ts::footerCredits`）：落在页面下四分之一的 credit 照原坐标画在它那一页、不让位；
  整页 credit 都在页底的是 Sibelius 把标题块压到页底的导出 bug，仍当页眉重排。以前页脚算进页眉墨迹，首行让到页脚底下，第一页的谱全出了纸（《八段锦》分谱）。
  页脚虽不占版面，**装页时要让开**（`staffpages.ts::contentLimit`）：Sibelius 的页脚常在下边距线以上，这一页内容只排到页脚墨迹顶之上一道空，
  不然末行下方的力度压在页脚上（八段锦扬琴第 1 页 m30 的 *mf*）。
- **谱表上方的记号**（波音、颤音、回音、上下弓，`NotationItem.outside`）一律在上、摞在符头/符干顶与谱表顶线之上；
  单音震音（`Notations.tremolo`）压在符干 3/5 处；全音符照原谱（Sibelius，用户定照原谱）画在假想符干那一侧：斜线组中心在符干起端的音头
  （符干朝下是最高的头）往符干方向 1 格、音头中心右边约 1.7 格，和音落在两头之间；斜线不用 Bravura 字形（太平），照原谱自己画陡一些的平行四边形
  （`render.ts::drawWholeTremolo`）。八段锦九份分谱量下来原谱逐处手调过（竖向 −0.5～2 格），通则取的是多数；
  原文记了位置的（`<tremolo default-x default-y>` → `Notations.tremoloPos`，斜线墨迹中心相对符头左缘 / 谱表顶线）照它画，矢量识别照原位写出。
  GB/T 46846 7.8.3.3 b) 的画法是居中画在假想符干上（音头正上 / 正下方），没照它；
  排练号是套方框的粗体文字块（`MeasureText.boxed`）；文字自带方头括号的（「【A】」，`enclosure="none"`，`deconames.ts::rehearsalBracketed`）照原样排字、不套框（`frameless`）；同一拍上的文字、速度记号接在框右边排成一行（「【A】欢快 热烈地 ♩=144」，文字与速度分成几条 direction 也照接）；
  segno / coda（原文没写坐标的）记在小节头、小节末的居中骑在那根小节线上（行首小节不骑系统起始线，免得压小节号与括号；贴谱表的接在行首小节号右边、谱号上方，照八段锦钢片琴 m33），竖向按局部轮廓贴着谱表（有和弦行的不贴），
  不随整行文字抬高（原谱 m77|m78、m32 末的 ⊕，【E】在它右边，`placePartAboveStaff`）；
  多小节休止排版前并成一小节（`model/multirest.ts`，模型不动），画 H 形横杠，小节数照原谱用正文衬线体（`render.ts::drawMultiRest`）。
  奏法记号原文写了 `placement` 的照写的上下（`Notations.articPlacement`，落在符干一侧的贴着符干端），没写的照通则；
  断奏楔（staccatissimo）照原谱画 0.54×0.77 格的实心三角（Bravura 的楔太瘦，像一道竖线）；打击乐谱号照原谱画两道细竖线（`drawPercussionClef`）。
  新字形要进 `smufl.ts` 的 `GlyphCodes` 与 `codeToName`，否则取墨迹盒报「unknown smufl glyph」。
- 没有版面坐标的谱（自动铺排）里：倚音挨着主音排（`layoutpass.ts::gracesOf`，主音前的槽宽留出这串倚音），倚音的加线
  在渲染时按小号符头补画（倚音不进 `NoteEntry`）；松叶缺省放谱表**下方**（`autoPlaceWedges`），歌词让开它；
  文字块（速度记号、力度）横向撞上就往上摞（`staffpages.ts`，乐谱字体按字号 0.6 估墨迹高，不能按字体度量）。
- 八度线（`<octave-shift>`）：MusicXML 的音高是实际音高，8va / 15ma 底下的符头按记谱放低一 / 两个八度（`layout.ts::scanOctaveSpans`，按谱表配对、止点前的音算在内）；
  画法 `render.ts::drawOctaveLine`：起头 8va / 8vb / 15ma / 15mb 字形、虚线收在最后一个音的符头右缘、末端钩朝谱表，高度让开范围里的符头；跨系统裁段、续段印「8」「15」。
  文字块与歌词还不给它让位（语料里还没有带八度线的谱）。
- 拍号的竖向只认拍值字号——混排字号是 0.75 H，按谱面档（0.5625 H）反算的常量在这里会挤成一团。KL2020 为对齐原 C++ 工程成品，由该书 `@jianpu { legacy-time-sig: true }` 单独恢复旧版数字基线、左对齐和按 advance 取分数线长度，不改其他歌本。
- 系统行尾的预告调号/拍号只按各自的 `keyChangeWidth` / `timeChangeWidth` 向左放置；额外 5 tenths 是小节线与预告属性的间距，已在数据区和小节线位置中预留，绘制时不再重复扣除。
- 混排视图的纸宽也取全仓那一份 `--score-page-max`（从前单独写 620px，同一首歌切过来纸就窄三分之一）。
- **歌本**（`songbook.ts`）的几何以成品 PDF 为准，不以原程序的式子为准：标题块里经文的位置、行距与块高是按
  KL2020-1219 p2/p4/p17 量回的（原式算出来经文低 9.4pt、谱面低 18~23pt，见 `kl2020.ss` 的注释）；
  页脚块照原式（成品逐点对上）。字高按字号算（原程序 `Font::height()` 就是字号），ascent 取字体的。
  标题居中轴和页脚右栏右缘取**每曲 MusicXML 的 `page-width`**（原程序是 `titlePage/lastPage->width`），不是
  歌本模板的 1322；最终输出纸张仍固定为 A4。《受苦圣徒，到基督前》的源宽是 1354，误用 1322 会让标题左移
  16 tenths、右栏左移 32 tenths。flow 与单曲成品的这两块相同，不需要为它们设置不同样式。
- 混排读几项标准位置/样式属性：和弦 `relative-x`、文字 `relative-x/relative-y`、segno/coda `relative-x`、歌词 `<text>` 字体、
  和弦内单音 `<type size="cue">`（简谱层选旋律音时跳过 cue 音）、`<words>` 文字里的换行拆成多行。
- **自动段号**（`layout.ts::autoVerseNumbers`，样式键 `verse-numbers`，与简谱同一键、同一口径；issue 24）：一个声部唱两段以上
  （`auto` 多于 3 段）就在每段**第一个字**前印「1.」「2.」…——照诗歌本惯例只印一次，不像简谱逐行补；源里任一段首字带了段号（`1.圣`）的声部整个不补，
  副歌与非数字段号不标。源里的段号（`Lyric.verseLabel`：123 `<1.>`、ABC `1.~`、MusicXML 首字里的 `1.`）照源印，与补的同一种画法
  （`LyricLayout.prefix`），按墨迹摆：右缘离首字左缘 0.3 字号（`MixedOptions.verseLabelByInk`；歌本关掉，照 musicpp 的固定偏移）。
  识别结果、123/ABC 转来的谱都不带印刷段号，从前五线谱一个也不印。歌本（`songbook.ts`）缺省 `never`，照书里原样。
- 歌本（`songbook.ts`）开 `textLineHeightBySize`：谱行包围盒里文字行高按字号算（原程序口径）。缺省按 ascent−descent（约 1.45 个字号），
  那样《我心等候祢》拆行后会挤成两页；编辑器混排视图不开（开了 568 份里 104 份版面会变）。
- `formatMixedScore` 与原 C++ 工程 `formatScorePAO` 同语义：谱表间距照 MusicXML `staff-distance` 原值，**不按包围盒抬高**。
  从前有一段跨声部「包围盒 + 12」的兜底，原程序没有；成品各行谱表间距正是 staff-distance + 40，兜底让《受苦圣徒，到基督前》
  第 1、2 行各多出 13、9 tenths，末行谱挤到第二页。删掉后 KL2020 40 首里 20 首帧高变小、全都向成品靠拢（抽 4 首逐谱线量，差 ≤3 tenths），
  mixed-tree-dump 568 份逐页不变。（`guessOctaveKeyA` 不在这里：八度点由语义层 `degree.octaveShift` 给）
- 歌本出 PDF：混排里文字的角色就是字体族；CFF 轮廓的字体（思源黑体、Bravura）pdf-lib 子集化后不合规，走轮廓画。
- `<words>` 的 x 照原 C++ 工程 `parser.cpp::processTextPos`：有 `relative-x` 相对拍位；**只有 `default-x` 就是小节内坐标、不加拍位**
  （`MeasureText.relative=false`）。Sibelius/Finale 写的都是小节内坐标；一律加拍位时《求主藉异象激动我》的「(副歌)」
  （default-x=-1）被推到首音上压住简谱。500 首里 11 份右对齐 Fine/D.S. 随之挪几个像素。力度仍按拍位。
- segno/coda 同一口径：只有 default-x 是小节内坐标（default-x 与 relative-x 都写了就相加，歌本改谱脚本写的 `x += n`），
  再右移 15；字号取 `<music-font font-size>`，字形照原程序的 Bravura Text（= Bravura × 0.8）。
- 和弦里的 csym 升降号/质量记号必须用真实 `Bravura Text`：它与 Bravura 的逐字形比例并不统一，不能整体乘 0.8
  代替。简谱调号的升降号也必须用 `accidentalSym(acc, true)` 的 csym 字形，不能换成普通五线谱
  `accidentalFlat/Sharp`。前者决定字体变体，后者决定字形本身。
  按拍位、固定 20pt Bravura 时《基督是锚》的 segno 压在 D/F♯ 上、大一圈。
- `<words>` 的 `font-style="italic"` 一路到量字、SVG、出 PDF（角色名带「 Italic」，fontres 按原样全名找到
  Times New Roman Italic.ttf；只按首词找会落到 Times.ttc）。
- `font-weight="bold"` 同理，角色名带「 Bold」（`songbook.ts::roleOf`）：出 PDF 是逐字画轮廓、没有「合成粗体」这回事，
  不带标志《为基督大业》的 `D.S.` 会画成常规字重。思源黑体的 Bold 与 Regular 同在一个 ttc 里，
  `kl2020.ss` 为它单开一条 `@font-face hei-bold`（face 名不同）；`@font-face georgia` 的族名本来就叫
  Georgia Bold（角色名成了「Georgia Bold Bold」），所以 `kl2020-book.mjs` 找不到整串时再按「基名 + 字重」找一次。
- 和弦居中宽度照原 C++ 工程 `TextBlock::width`：上/下标按 0.75 缩放后的宽。按未缩放算，A(sus4) 这类长上标整体左偏。
- 歌本（`songbook.ts`）三项与编辑器视图不同：不印简谱调号「1=X」（成品曲首、转调处都没有）；和弦字体用思源黑体
  （原 C++ 工程 `Engraver::wordFont` 缺省值，编辑器仍 Times New Roman）；开 `textLineHeightBySize` 时记号行高也按原字号
  （`TextBlockItem.nominalSize`），按墨高算《基督是锚》segno 那行谱上移约 11 tenths。
- 只留旋律分**两步**，次序照 `util/pao.cpp`：读谱前只裁声部（`keepFirstPart`），删非旋律音要等混排引擎
  把弧与延音线配完对、方向也推断完（`removeNoneMelody`，`MixedOptions.melodyOnly`）。删早了
  `guessTiedPlacement` 看到的全是单音 Entry：方向退化成按符干猜，还会多加 `yOffsetType` 的 8 tenths
  （《祂怜悯更多》《所有美善力量》末两行的延音线）。和弦符号不受影响——它在小节表里，不挂音符。
- 延音线配对里「已用过」只记 stop：连续链 A(start) → B(stop+start) → C(stop) 的 B 既是终点又是起点，
  把两头都记进同一个集合会把 B→C 整条丢掉（《那一天正来临》末行）。
- 整小节休止比的是**当前拍号**折算的小节长，不是本小节实际最大时值：弱起/不满小节里一个四分或二分休止
  会恰好等于后者，被换成全休止字形并居中（《赞美祂名》第二行末小节、《奇异的爱》《我心灵得安宁》）。
- 附点无条件照 `ent.dot.dots` 画：加「本小节得有非休止的附点音符」这层外条件，只有附点休止的小节
  （《那一天正来临》）附点会整条吞掉。
- 简谱层附件（高音点／低音点／减时线／附点、临时记号、倚音、调号）的画法与落点走公共那一份
  （[排版-谱面元素](排版-谱面元素.md)：`engrave/stack.ts` 墨迹到墨迹等距、`augdot.ts`、`accidental.ts`、`grace.ts`），
  间距是 `stack-gap × 简谱层数字墨迹高`，随谱高缩放；原 C++ 工程的 tenths 常量（`jpOctaveUpY` 等）与对应样式键已删。
- 谱表上那层简谱的字（`MixedOptions.mixFont`）是**派生 getter**：`jianpuFont` 按 `mixStaffHeight / 40` 缩小。
  以前构造时算死一次，改了谱高或简谱字体它不跟；样式表换字体写 `note { font: … }`，不单独设它。
  **不要**改回「按减时线墨迹底往下均分」的自算口径：谱高 30 时减时线比成品高 1.5 tenths，
  低音点跟着整摞错开，红蓝对照里每个音都带红蓝边。八度点与附点画的是矢量圆而非 `.` 字形，
  圆心要落在该字形的**墨心**上（原实现给的是基线笔位）。
- 同一本书两种装页口径的版式差异走**叠加样式表**：清单 `styleByFlow.<档>` 指一份只含差异的 `.ss`，
  解析后接在 `style` 之后（KL2020 接排版印简谱调号「1=X」、单曲版不印 → `kl2020-flow.ss`）。
  不要为此复制整份样式表。
- 开 `textLineHeightBySize` 时，`<direction>` 多行文字块**画的**行高也按字号（与包围盒同口径），否则画得比包围盒高，
  《那一天正来临》开头的楷体引言压进简谱与歌词。
- 歌本标题块/页脚逐字笔位（`songbook.ts::placedToTextFrames`）用单字 advance、**不挤压标点**（成品「内。（来6：19）」都是全宽），
  西文连续段按整段前缀量（保住 kerning，两头垫「|」防首尾空格量成 0）；开 `features: hwid` 的角色里全角标点占半格、

    OCR 读出、没量到墨迹框的力度不再按歌词字号缩（Bravura 16pt 缩到 10pt 只剩一半大）。
  - **歌词、文字照原图高度**：歌词写了 `default-y`（识别稿量的基线，`LyricLayout.srcY`）就取本行这一段的中位数，与让开音符的自动高度取较低的那个；
    文字写了 `default-y`（声部标签「Alto」「Men」、「rit.」）同力度一样记 `sourceY`、照原字号，谱表上方的只按横向跨过那段轮廓让，
    不再抬到整行最高处之上（从前「Alto」抬到顶线上 53，女高到女低要 122，原谱 88）。
  - **延音线朝向照源**：自动铺排时读 `<tied orientation|placement>`（`layout.ts` 收 `tied` Mark → `Tied.srcDir`），`guessTiedPlacement` 不再猜；
    带坐标的原文照原 C++ 工程按声部与符干猜（那边从不读这个属性）。
  - **符杠中间的休止让开符杠**（`BeamGroup.clearRests`，自动铺排定完横坐标与符干长之后）：读入时休止不带 `<beam>`、不进组，按本小节同声部同谱表、
    拍位落在组首尾之间的找；字形碰到杠内缘（离 2）就按整线往离杠方向挪，最多四格。杠的几何同 `render.ts::drawBeamGroup`。
  - **临时记号与朝下的符干**：自动铺排排临时记号时（`NoteEntry.layout` 的 `stemClear`），符干朝下的和弦那根贴在符头左缘的干记成边界，
    临时记号离它再让 `ACC_DOWNSTEM_CLEAR` 2（只隔 1 时还原号的竖笔与干并成一根粗线，用户提的）。带坐标的原文不变。
  - **照原图的松叶**：止端的 `relative-x` 是原图上的间距，重排紧了会推过小节线、伸出系统（破碎 m80 钢琴），画时收在止端小节里（`WEDGE_BAR_CLEAR`）；
    `settleSourceMarks` 判撞时拍位横坐标取那一拍和弦的实际 x（`getEntPos` 的拍位表那时还没按铺好的音符更新，量出来左右颠倒、从不判撞，破碎 m81 女低渐弱压字）。
  - 合唱谱 8 份都与原谱逐页一致。望十架第三页曾排不下一行，是识别稿把没印的长笛谱表当成空谱表印了出来（见识别-五线谱位图「多谱表声部只印了其中几行」），
    不是避让口径太松。

- **简谱层叠在哪行谱上按系统定**（`staffpages.ts::mixedHostsBySystem`）：缺省叠在「简谱旋律取自」那个声部；它的谱表在某个系统里藏着
  （`staff-details print-object="no"`，单行与两行谱表交替的简线混排谱只印了另一个声部）时，这一系统改叠在**第一个可见谱表**上，不留空。
  `notation` 按 tick 切（系统首拍切过去、下一系统首拍切回），和弦 y、文字抬升（`placeAboveStaff`）对借去的声部只在它叠着的那几个系统里算；
  整首都可见的混排结果不变。

## 已知限制

- 简谱路径同样**丢弃跨谱行的连音**（原 C++ 工程亦如此）
- 设置面板的字号/前景色不作用于混排（它用 MusicXML 自己那套）
- 文本格式的五线谱/混排视图里，和弦名、装饰、增时线在五线谱上点不回原文（音符、歌词、小节线、弧可以，见 [实现/可视化编辑](../实现/可视化编辑.md)「五线谱 / 混排档」）
