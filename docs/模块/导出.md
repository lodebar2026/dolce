# 导出

**判据全录** → 无单独实现篇；页面树的遍历契约见 [../架构.md](../架构.md) §3.2

## 职责

页面树/模型 → PNG / PDF / 矢量 PPTX / MIDI / MusicXML / `.jpwabc` / 文本谱原文 / jianpu-ly 文本（`.jly`）。

## 关键判据

- **跨格式另存为要先问**：换的是源格式本身，目标装不下的东西会永久丢。
  `planSave` 算清单、`showConfirmDialog` 列出来、确认了才写。
  **存回原格式不问**——那是原文进原文出，不会丢。
- **谱面出图按档二选一**：展开档只出 PPTX；其余各档（简谱原样档、五线谱 / 混排、识别核对视图）按排版效果出图——
  纸为长图（简谱 `App.jpLongImage`、五线谱 `staffPage.heightPt === null`）出整张 PNG，分页纸出全部页 PDF（桌面版走 `export_pdf_cmd` 矢量、浏览器版逐页栅格化进 jsPDF）。
  **识别核对视图导出的是排版稿**，不是二值图叠加：简谱会话按当前原样 / 展开档另排一份（核对视图里 `reload` 不重排屏幕上的排版器，那个是旧的），
  五线谱会话（`.musicxml`）按五线谱 / 混排的设置另排一份。
- **桌面 PDF 的页 SVG 宽高不带单位**：`usvg` 把 `pt` 按 96 dpi 折成 px（×4/3），`svg2pdf` 默认按 72 dpi 把 px 当 pt，
  写 `width="420pt"` 整页放大 4/3（A5 出来近 A4）；无单位的用户单位在这条链上 1:1 落成 pt。
- **PPTX 取展开档**那一套（`export.ts::pptxPainter`，请求由 `App.expandedRequest` 组），哪怕屏幕正停在原样档。
  简谱引擎为 PPTX 对位留的口子：减时线记两端的 `JpNumber`（`leftNum/rightNum`），展开档数字共一条基线、增时线是数字字体的「-」，
  SMuFL 字形挂 `smufl`（转曲），标题页与页脚文字不带逐字笔位（带了会拆成逐字文本框）。
- **PPTX 有一层字体度量修正**（`TARGET_ADVANCE`/`TARGET_DESCENT`）：排版是拿浏览器里的 PingFang SC
  量的，而 .pptx 里写的是 Microsoft YaHei（投影机与 Windows 上真正会用的那份）。
  两套字的 descent（0.357 vs 0.2617 em）与数字宽（PingFang 的「1」只有 0.401 em，YaHei 等宽 0.5864 em）
  都不同，不修正则文字整体下沉一格、「1」的八度点与减时线明显偏左偏短。
  做法：**按目标字体的 descent 定文本框底、把音符数字居中到目标宽度的框里**（框心落在 `JpNumber.cx`）。
- **歌词收尾标点并进前一个字并换半角形**（`TRAIL_PUNCT`）——YaHei 的全角逗号墨迹在字身正中，
  单独成框会顶到下一个字。
- 倚音底缘按目标字体的墨迹顶对齐（`jpLegacyDigitInkTop`）。
- 背景色白底一律不铺；非白则 PNG 铺画布底、混排 PDF 插满幅 rect、PPTX 写 `<p:bg>`。
- `.jpwabc` 只支持单声部，多声部时只导第一声部并 `setStatus` 提示。
- MusicXML **只有一份写出端**（`model/toxml.ts`，判据全录见 [../实现/MusicXML-导出.md](../实现/MusicXML-导出.md)）。
  **`.musicxml` 文档**里存的就是 XML，没改过存回原文、改过的已整份重写（表层从原节点回填，见 `model/xmlsurface.ts`）；
  **简谱识别核对**出的是普通 123 文档（识别直出 `ScoreDoc`，没有 MusicXML 底本），同样整份写出。不再有增量 patch。

## 已知限制

- 没有 ABC 导出
- **jianpu-ly**：导出**是单向写出**、读回来是另一条路（`parseJly`，`.jly` 是一等源格式，见
  [源格式-jianpu-ly](源格式-jianpu-ly.md)）。**语法只有一个来源：上游 `jianpu-ly` 自己的 README**
  （`--markdown --chinese` 生成的那份，v1.890）。
  ⚠ **jianpu-db（语料站）的曲谱只是 jianpu-ly 的一种方言** —— 它多出 `%<文件名>`、`status=`、`source=`、
  `%--`、`subtitle=` 与收尾 `%END`；**这些一律不写**（曾经照语料样本抄过 `%END`，是错的）。
  装不下的东西（多声部只写第一声部、和弦符号 `chords=`、演奏法记号、反复跳跃 `R{ } A{ }`、
  拉丁歌词的连字符）**写进 `.jly` 的 `%` 注释里**，随文件走、不静默丢。
  两条从真工具跑出来的硬约束：① 上游**强制 barcheck**（每小节时值必须严丝合缝），所以写出端必须忠实还原
  每个音的时值；② 倚音组内**不能有空格**（是 `g[#45]` 不是 `g[#4 5]`）。
  歌词对位另有三条实测判据（缺格写 `""`、圆滑线 `(` 必须后置且只用于真一字多音、拉丁音节一律加引号），
  见 [格式/jianpu-ly](../格式/jianpu-ly.md)「最容易踩的三个坑」。
- MusicXML：skip/limit 不表达、承接前音的增时线按普通音符写、多声部只保 `parts[0]` 往返
