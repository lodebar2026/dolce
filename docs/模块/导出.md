# 导出

**判据全录** → 无单独实现篇；页面树的遍历契约见 [../架构.md](../架构.md) §3.2

## 职责

页面树/模型 → PNG / PDF / 矢量 PPTX / MIDI / MusicXML / `.jpwabc` / 文本谱原文 / jianpu-ly 文本（`.jly`）。

## 关键判据

- **跨格式另存为要先问**：换的是源格式本身，目标装不下的东西会永久丢。
  `planSave` 算清单、`showConfirmDialog` 列出来、确认了才写。
  **存回原格式不问**——那是原文进原文出，不会丢。
- **谱面出图按档二选一**：投影档只出 PPTX；其余各档（简谱档、五线谱 / 混排、识别核对视图）按排版效果出图——
  纸为长图（简谱 `App.jpLongImage`、五线谱 `staffPage.heightPt === null`）出整张 PNG，分页纸出全部页 PDF（桌面版走 `export_scene_pdf` 矢量；浏览器版有本地字体授权出矢量，否则逐页栅格，都由 dolce-export-wasm 写）。
  **识别核对视图导出的是排版稿**，不是二值图叠加：简谱会话按当前简谱 / 投影档另排一份（核对视图里 `reload` 不重排屏幕上的排版器，那个是旧的），
  五线谱会话（`.musicxml`）按五线谱 / 混排的设置另排一份。
- **矢量 PDF 吃场景不吃 SVG**：页面大小（pt）随场景一起给，场景的 viewBox 按它缩放（五线谱的 tenths 在这里换成 pt）。
  文字带逐字笔位的照笔位落；连排的整串整形，含全角标点相邻时照浏览器的 `text-spacing-trim` 挤半格（`dolce_engrave::text::han_kern_shifts`，与量字同一份），
  整形宽与排版宽差过 0.5 pt 才摊字距对齐。私用区码位不进不可见文字层（GBK 字体给那些码位配了字形）。
- **字体嵌入**（`dolce-layout::export`，krilla 写、fontdb 找系统字体、rustybuzz 整形——找字体与整形这层在 `dolce-engrave::text::fontfile`，Linux 的系统量字也用它；字体样本 `dolce font-probe` 写一页再用 PDFium 读回核对）：
  - **嵌不了的退转曲**：第一次用到某个字体面时试嵌一次，写出报错的面改转曲并叠一层不可见文字（照样可选可搜），整份重试；Bravura 一律转曲。
  - `.ttc` 按面取；可变字体按要的字重 / 斜体取实例；AAT 字体整形时关 `vert`；粗体标记位没设的面靠子族名认粗；没有斜体面的合成斜。
  - 场景路径 `d` 走完整 SVG 路径语法（相对 h / v 读错曾把整页画成黑三角）。
- **在线版 PDF**：有本地字体访问授权（`queryLocalFonts`）就把场景要的族交 wasm 出矢量；没授权或缺字退逐页栅格，容器也由 wasm 写（不用 jsPDF）。桌面一律矢量。
- **PPTX 的 zip 自己打**（deflate、时间戳固定 1980-01-01）：同料同字节，wasm 与命令行出的一样。
- **PPTX 取投影档**那一套（`paintreq.ts::pptxPainter`，请求由 `App.expandedRequest` 组），哪怕屏幕正停在简谱档。
  简谱引擎为 PPTX 对位留的口子：减时线记两端的 `JpNumber`（`leftNum/rightNum`，场景角色里是 `BeamLine.ends` = 两个音符组在同一父节点里的下标，
  数字是组的头一个子节点），附点记挂哪个数字（`JpOctaveDot.aug`，场景里记第几个、数字是父组头一个），数字记墨迹中心（场景角色 `JpNumber.cx`）；
  投影档数字共一条基线、增时线是数字字体的「-」，
  SMuFL 字形挂 `smufl`（转曲），标题页与页脚文字不带逐字笔位（带了会拆成逐字文本框）。
- **PPTX 有一层字体度量修正**（`dolce-layout::export/src/pptx.rs` 的 `target_advance` / `TARGET_DESCENT`）：排版是拿 PingFang SC
  量的（浏览器里或 Node 侧的系统文字引擎），而 .pptx 里写的是 Microsoft YaHei（投影机与 Windows 上真正会用的那份）。
  两套字的 descent（0.357 vs 0.2617 em）与数字宽（PingFang 的「1」只有 0.401 em，YaHei 等宽 0.5864 em）
  都不同，不修正则文字整体下沉一格、「1」的八度点与减时线明显偏左偏短。
  做法：**按目标字体的 descent 定文本框底、把音符数字居中到目标宽度的框里**（框心落在 `JpNumber.cx`）。
- **歌词收尾标点并进前一个字并换半角形**（`trail_punct`）——YaHei 的全角逗号墨迹在字身正中，
  单独成框会顶到下一个字。
- **文本框高 = 排版字体的 descent − ascent**（只定框顶；框底按目标字体 descent 定）。wasm 里没有量字器，度量表由 `pptxexport.ts` 按场景里用到的字体量好随料给。
- **SMuFL 转曲**逐字取 Bravura 轮廓，框按轮廓紧包围盒（曲线取极值）；各轮廓写 `<a:close/>`（旧 TS 写出端经 opentype.js 读 CFF 不闭合，填充结果一样）。
- 倚音底缘按目标字体的墨迹顶对齐（`jpLegacyDigitInkTop`）。
- 背景色白底一律不铺；非白则 PNG 铺画布底、混排 PDF 插满幅 rect、PPTX 写 `<p:bg>`。
- `.jpwabc` 只支持单声部，多声部时只导第一声部并 `setStatus` 提示。
- MusicXML **只有一份写出端**（`model/toxml.ts`，判据全录见 [../实现/MusicXML-导出.md](../实现/MusicXML-导出.md)）。
  **`.musicxml` 文档**里存的就是 XML，没改过存回原文、改过的已整份重写（表层从原节点回填，见 `model/xmlsurface.ts`）；
  **简谱识别核对**出的是普通 123 文档（识别直出 `ScoreDoc`，没有 MusicXML 底本），同样整份写出。不再有增量 patch。

## 回归

脚本在私有仓库（从本仓库根跑 `node ../dev/scripts/xxx.mjs`，先 `npm run build:cli` 与 `cd crates && cargo build --release -p dolce-dev`）：

- `pptx-ref-check.mjs`：量 Rust 出的片子，对 2019 年成品的数字宽、增时线宽、框底、减时线两端；`pptx-check.mjs` 查页面树笔画。
- `dolce-dev pdf-compare <a.pdf> <b.pdf>`：两份 PDF 逐页栅格差与文字层；成书整本见 [排版-成书](排版-成书.md)。

## 已知限制

- 没有 ABC 导出
- **jianpu-ly**：导出**是单向写出**、读回来是另一条路（`parseJly`，`.jly` 是一等源格式，见
  [源格式-jianpu-ly](源格式-jianpu-ly.md)）。**语法只有一个来源：上游 `jianpu-ly` 自己的 README**
  （`--markdown --chinese` 生成的那份，v1.890）。
  ⚠ **jianpu-db（语料站）的曲谱只是 jianpu-ly 的一种方言** —— 它多出 `%<文件名>`、`status=`、`source=`、
  `%--`、`subtitle=` 与收尾 `%END`；**这些一律不写**（曾经照语料样本抄过 `%END`，是错的）。
  装不下的东西（多声部只写第一声部、和弦符号 `chords=`、演奏法记号、反复跳跃 `R{ } A{ }`、
  拉丁歌词的连字符）**写进 `.jly` 的 `%` 注释里**，随文件走、不静默丢。
  两条从真工具跑出来的硬约束：① 上游**强制 barcheck**（每小节时值必须严丝合缝），所以写出端必须忠实还原
  每个音的时值；② 倚音组内**不能有空格**（是 `g[#45]` 不是 `g[#4 5]`）。
  歌词对位另有三条实测判据（缺格写 `""`、圆滑线 `(` 必须后置且只用于真一字多音、拉丁音节一律加引号），
  见 [格式/jianpu-ly](../格式/jianpu-ly.md)「最容易踩的三个坑」。
- MusicXML：skip/limit 不表达、承接前音的增时线按普通音符写、多声部只保 `parts[0]` 往返
