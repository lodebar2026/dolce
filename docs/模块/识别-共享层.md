# 识别：共享层（`src/omrkit/`）

## 职责

简谱（`omr/`）、矢量五线谱（`staffomr/`）、位图五线谱（`rasteromr/`）三路识别共用的底层：类型、几何、连通域、二值化、
解码与推理运行时、矢量 PDF 对象层、和弦与页眉的纯文本文法、核对视图的 SVG 小件。**一样东西只在这里写一份**，三路各自的判据留在各自目录。

## 依赖方向（架构决策 A6）

```
omr/ ─┐
staffomr/ ─┼─→ omrkit/        omrkit/ 不 import 三路任何一个
rasteromr/ ┘   rasteromr/ → staffomr/（下游复用）、rasteromr/ocrlive.ts → omr/jianpu.ts（简线混排借简谱识别）
```

新东西两路以上要用，就放这里；只有一路用，就留在那一路。别为了复用一个函数去 import 别一路的业务文件。

## 入口

| 文件 | 作用 |
|---|---|
| `types.ts` | `Binary`、`Rect`、`Component`、简谱识别结果类型（`RecognizedScore`、`JpNum`…）、`rcx/rcy/rright/rbottom` |
| `geom.ts` | 矩形并、重叠、按 y 聚类、`median` |
| `ccl.ts` | 连通域（8 邻接，`connectedComponents`） |
| `preprocess.ts` | 灰度、Otsu、Sauvola、`rgbaToBinary` |
| `surface.ts` | RGBA 画面（送 OCR 的条图）、二值图 → 画面、缩放拷贝 |
| `decode.ts` / `decode.browser.ts` / `decode.node.ts` | 字节 → 二值图；解码器注入点与两端实现 |
| `runtime.ts` / `runtime.browser.ts` / `runtime.node.ts` | ONNX 推理运行时注入点与两端实现 |
| `browser.ts` | `installBrowserOmr()`：装浏览器运行时与解码器（幂等）。`omr/index.ts`、`rasteromr/browser.ts` 各调一次 |
| `ocr.ts` / `paddleocr.ts` | OCR 后端接口与 PP-OCR 实现（rec / DBNet det、裁图送 rec、Tauri 原生通道） |
| `vector.ts` / `vectext.ts` / `glyphdict.ts` | 矢量 PDF 对象层（路径、文字层、形状签名与字典） |
| `chordgrammar.ts` | 和弦记号文法 `CHORD_TOKEN_RE`（唯一一份）、`blankNonChord`、注记行判定 `isAnnotationLine`、切词、归一 |
| `headertext.ts` | 页眉纯文本判据（署名正则、有效字高、标题比法）；五线谱页眉 OCR 行 → `<credit>` 各条（`headerCredits`，位图、矢量两路同走） |
| `charcells.ts` | 汉字字格（一行连通块按 x 并成字，`mergeToChars`）：简谱歌词 / 页眉、位图五线谱汉字歌词共用 |
| `svgkit.ts` | 核对视图：二值图底图 `baseImage`（data URL 按图缓存）、整页 svg 根、矩形 |

## 约束

- **`vector.ts` / `vectext.ts` / `glyphdict.ts` 及其 import 链不得触碰 canvas / OffscreenCanvas / document**——Node CLI 要 import 它们。
  碰 DOM 的只有 `decode.browser.ts`、`runtime.browser.ts`、`browser.ts`、`svgkit.ts`，不进 `src/cli/` 的链。
- **`runtime.node.ts` / `decode.node.ts` 不得进浏览器入口的 import 链**（会把 `fs`、`sharp` 拖进网页产物）。
- 推理与解码都是**注入**的：浏览器侧先 `installBrowserOmr()`，Node 侧先 `setOmrRuntime(nodeRuntime)` + `installNodeDecoder()`。
  不要依赖「别的模块先 import 了谁」的副作用。
