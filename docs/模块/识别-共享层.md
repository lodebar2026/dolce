# 识别：共享层（`src/omrkit/`）

## 职责

简谱（`omr/`）、矢量五线谱（`staffomr/`）、位图五线谱（`rasteromr/`）三路识别共用的底层：类型、几何、连通域、二值化、
解码与推理运行时、矢量 PDF 对象层、和弦与页眉的纯文本文法、核对视图的 SVG 小件。**一样东西只在这里写一份**，三路各自的判据留在各自目录。

## 依赖方向（架构决策 A6）

```
omr/ ─┐
staffomr/ ─┼─→ omrkit/        omrkit/ 不 import 三路任何一个
rasteromr/ ┘   rasteromr/ → staffomr/（下游复用）、rasteromr/ocrlive.ts → omr/jianpu.ts（简线混排借简谱识别）
```

新东西两路以上要用，就放这里；只有一路用，就留在那一路。别为了复用一个函数去 import 别一路的业务文件。

## 入口

| 文件 | 作用 |
|---|---|
| `types.ts` | `Binary`、`Rect`、`Component`、简谱识别结果类型（`RecognizedScore`、`JpNum`…）、`rcx/rcy/rright/rbottom` |
| `geom.ts` | 统计（`median` 上中位、`quantile` 取 `floor(n·p)`、`meanFinite`）、区间与矩形重叠（`overlap1d`、`overlapFrac` 占 a 的面积比）、矩形并、行内有墨、按 y 聚类 |
| `ccl.ts` | 连通域：`connectedComponents`（墨 8 邻接，盒 / 面积 / 质心 / 标号图）、`components`（墨或白、4 或 8 邻接，像素表 / 碰边） |
| `preprocess.ts` | 灰度（`toGray`，RGBA / RGB / 灰度）、Otsu（阈值与类间方差）、Sauvola（窗口半径与 k 由调用方定）、`rgbaToBinary` |
| `surface.ts` | RGBA 画面（送 OCR 的条图）、二值图 / 墨条 / 灰度条 → 画面、缩放拷贝；整页二值图转画面只缓存上一张 |
| `contentkey.ts` | 像素条内容指纹 `contentKey`（OCR 离线缓存按它寻址，**格式一字不能改**） |
| `pdf.ts` / `pdf.browser.ts` | PDF 魔数、页内画图指令与图对象、取最大内嵌图；浏览器侧打开文档（worker、wasm 目录） |
| `lyrictext.ts` | 歌词标点口径：贴字尾的句读（半角也收、折全角）、开闭引号与括号 |
| `decode.ts` / `decode.browser.ts` / `decode.node.ts` | 字节 → 二值图；解码器注入点与两端实现 |
| `runtime.ts` / `runtime.browser.ts` / `runtime.node.ts` | ONNX 推理运行时注入点与两端实现 |
| `browser.ts` | `installBrowserOmr()`：装浏览器运行时与解码器（幂等）。`omr/index.ts`、`rasteromr/browser.ts` 各调一次 |
| `ocr.ts` / `paddleocr.ts` | OCR 后端接口与 PP-OCR 实现（rec / DBNet det、裁图送 rec、Tauri 原生通道） |
| `vector.ts` / `vectext.ts` / `glyphdict.ts` | 矢量 PDF 对象层（路径、文字层、形状签名与字典） |
| `chordgrammar.ts` | 和弦记号文法 `CHORD_TOKEN_RE`（唯一一份）、`blankNonChord`、注记行判定 `isAnnotationLine`、切词、归一 |
| `headertext.ts` | 页眉纯文本判据（署名正则、有效字高、标题比法）；五线谱页眉 OCR 行 → `<credit>` 各条（`headerCredits`，位图、矢量两路同走） |
| `charcells.ts` | 汉字字格（一行连通块按 x 并成字，`mergeToChars`）：简谱歌词 / 页眉、位图五线谱汉字歌词共用 |
| `svgkit.ts` | 核对视图：二值图底图 `baseImage`（data URL 按图缓存）、整页 svg 根、矩形 |

## 看似重复、实则不同（别合）

- 分位数：`omr/bookprofile.ts` 用 `round((n-1)p)`，与 `geom.ts::quantile` 结果不同；`staffomr/barlines.ts` 故意取**下**中位。
- 矩形「重叠」：`overlapFrac`（占 a 的面积比，非对称）、`rasteromr/notehead.ts::overlaps`（比中心距）、`vector.ts::intersectRect`（开区间，贴边不算）语义各异。
- `rasteromr/prims.ts::close1d`（单向补缺口）与 `rasteromr/morph.ts::close`（方形结构元闭运算）不是一回事；叠加层底图灰度（固定阈值、看 alpha）不并进识别用的灰度。
- `rasteromr/prims.ts::binSig`（像素）与 `glyphdict.ts::shapeSig`（矢量）是成对设计，不是重复。
- 三路的弧、房子、反复点**候选判据**（像素 / 线段 / 矢量三种输入，阈值各自拿样本调）；找孔 / 内腔的八处背景泛洪（墨的口径、窗口、判定各不同）。
- 速度记号三份正则各吃各的输入：位图 OCR（数字带空格）、矢量文字层（音符字母 q/h/e、`c.`）、简谱 OCR（♩ 读成 J）。
- 简谱页眉 `omr/header.ts::classify` 逐条分支要原样输出、回源图补空格，不改用 `isCreditText` 这个谓词。
- 和弦归一：简谱 `normalizeChord`（M 折 m）与位图 `rasteromr/harmony.ts::normalizeChordText`（OCR 形近字 卜→F、尾 i→7）管的是两种误读。

## 约束

- **`vector.ts` / `vectext.ts` / `glyphdict.ts` 及其 import 链不得触碰 canvas / OffscreenCanvas / document**——Node CLI 要 import 它们。
  碰 DOM / 浏览器构建的只有 `decode.browser.ts`、`runtime.browser.ts`、`pdf.browser.ts`、`browser.ts`、`svgkit.ts`，不进 `src/cli/` 的链。
- **`runtime.node.ts` / `decode.node.ts` 不得进浏览器入口的 import 链**（会把 `fs`、`sharp` 拖进网页产物）。
- 推理与解码都是**注入**的：浏览器侧先 `installBrowserOmr()`，Node 侧先 `setOmrRuntime(nodeRuntime)` + `installNodeDecoder()`。
  不要依赖「别的模块先 import 了谁」的副作用。
