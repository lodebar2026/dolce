# 识别：五线谱（整页位图，合唱谱）

**判据全录** → [../实现/位图五线谱识别.md](../实现/位图五线谱识别.md) + [同名子目录](../实现/位图五线谱识别/)各分篇

## 职责

整页是一张位图的五线谱（合唱谱 PDF、独唱谱图片）→ MusicXML。**编辑器已接**：拖入、选中的图片 / 扫描 PDF 按有没有五线谱表自动分流（可手动改判），
结果落地同打开 `.musicxml`（谱面上改模型）。
下游复用矢量路（`adapt.ts` → `staffomr/page.ts`，**下游一行不改**）。

## 关键判据

- **多页并行，结果与逐页串行逐字一致**（`pagepool.ts`）：跨页只靠沿用（上一页的拍号、调号，前面有没有页眉，`PageCarry`），
  `recognizeRasterPage` 第一处要用的地方在 `buildPageStructure` 里的 `shareOctaveClefs` 之前，之前那段约占单页耗时的九成。每页在一个 Worker 里先跑前段，
  到那一点才 await `opts.carry`；主线程按页序收结果，收到第 k 页就把第 k+1 页的沿用发过去（流水线）。
  主线程从 pdf.js 取出页图（`rasterpage.ts::pageImageOf`）交给 Worker，栅格化（`rasterizeImage`）在 Worker 里做；
  OCR 与拼页眉带（`composeHeaderStrip` 要 pdf.js 页对象）发 RPC 回主线程——桌面版 OCR 走 Tauri `invoke`，只在主线程能用。
  页结果是类实例图，经 `pagetransfer.ts` 打包：**新加进页结果的类要登记到它的 `CLASSES`**，闭包字段要用 `portablefn.ts::definePortable` 造，
  否则打包时直接抛错。**各 Worker 的模块级状态互不相知**：弧号（`staffomr/slur.ts::markSlurNotes`）因此按「页码.页内序号」发，
  不用进程里的全局计数（同号会被写出端配成一条）；以后加跨页唯一的编号同理。编辑器按核数开（最多 4 路，`browser.ts::pagePoolSize`），
  Node 回归按 `RASTER_WORKERS`（缺省 4，=1 串行；`src/cli/rasterpool.ts` 包在 `recognizeRasterSong` 外面，脚本不用改）。
  合唱谱七份（OCR 走缓存）合计 125 s → 62 s；浏览器在线识别（OCR 现跑、仍在主线程排队）破碎扫描 61 s → 43 s。

- **半调网点（抖动印刷）的底本先去网**（`descreen.ts`）：符头是打散的网点，填充率那一档全过不去
  ——《坚固保障》整页 83 个音符原本只认出 20 个。去网走标准形态学（面积开运算 → 面积闭运算 → 闭运算），
  参数运行时从本页统计（墨块、白隙面积的分位数）。**不是每页都做**：先量谱表带内的「孤立墨点占比」
  （`halftoneRatio`），心领那本 0.359、合唱谱那批全书全页最大 0.157，门槛取 0.25，
  **合唱谱没有一页会触发**。量要限在谱表带内——整页量的话几乎没墨的封面页量出来是 1.000。
- **和弦字母先认领、再找符头**（`harmony.ts`）：独唱谱在谱表上方印和弦，`C`/`D`/`G`
  都是圈，正落在空心符头那一档里（`HOLLOW_BAND` 上下各让三格）——实测《坚固保障》
  整页因此多出六个 D6/E6 全音符。带的窗口是顶线上方 1.0~3.2 格，**列投影切簇、
  逐簇送 rec**（不请 DBNet：这个尺度上 42 个和弦它只框出 30 个），
  切成记号靠 `CHORD_TOKEN_RE` 的文法而不是簇边界。**只在 OCR 缓存命中时才认领**，
  所以合唱谱那批一块墨也不动。一行里多数条都往上长出一格以上（和弦行整体排得高），
  就把带顶挪上去**整行重切**——否则列投影只看到字脚，♭ 的肚子、「7」被切掉。
  **和弦与文本分开交**：记号词（Fine、D.C.，与简谱路同一张表 `blankNonChord`）、
  与小写字母粘连的单词、汉字串认成文本（`harmonyTexts`）；再**按整行**判和弦行还是文本行
  （同简谱路 `isAnnotationLine` 的覆盖率口径），被切成几条的署名「(John B. Dykes)」整行归文本。
  详见 [和弦](../实现/位图五线谱识别/和弦.md)。
- **简线混排谱：简谱行先认领、再互证**（`jianpuband.ts` / `jianpufuse.ts`，详见
  [简谱混排与独唱谱补认](../实现/位图五线谱识别/简谱混排与独唱谱补认.md)）。
  简谱行按「悬在谱表上方的短竖线与谱表小节线同 x」定位，整块落在带里的墨抹掉
  （不挡就被收成全休止和加线上的符头），和弦带改贴到简谱行上方。简谱离线认（`gen-rasterjianpu.mjs`
  缓存），逐小节按 x 与五线谱配对：**音高信简谱、时值只在五线谱不自洽时改**、配上的音所在和弦的
  其余音删掉（符干另一头的假头）、缺拍时照简谱补音。《是谁》音符 88.5% → 100%。
- **被谱线切开的对象在修补图上取整块，不切碎再按盒距拼**（`prims.ts::repairLineCuts`、`contour.ts::candidateMap`）：
  去线「上下都没墨才抹」会把贴线斜穿的笔画一起抹掉。修补图把存疑的线带像素补回，一页取一次，弧线、八分休止、演奏法记号、松叶、
  虚线弧与「碎块并回再查字典」都先在它上面取连成一块的候选，没连上的才退回旧的拼法；认干、认杠、认头、找内腔仍在去线图 / 原图上。
  详见 [取图与谱线](../实现/位图五线谱识别/取图与谱线.md)「修补图」。
- **多段歌词的「链式收段」只在位图路开**（`textanalyze.ts::buildLyricLines`）：
  独唱谱一页印八段，第五段起就出了「三个谱表高」那道闸，于是按「接着上一段、
  中间没有空当」续收。**但这一条要认合成字体**（`#` 打头，位图路自己造的文本对象）
  ——矢量路每首最多两段，开着反而收进本不该收的行（实测赞美之泉歌词 94.95% → 94.88%）。
- **拉丁歌词绕开方块字格**（`lyric.ts`）：汉字那套立在「等宽见方」上，英文词宽差着数倍。
  判「这是拉丁行」要三道闸——字母占比 ≥0.9、字母 ≥20 个、**至少一个连字符**；
  最后那道专挡页眉与版权行（它们是货真价实的整行英文，前两道拦不住）。
  词界按**条子里真的空白**判（0.7 个字号），不按 `xFrac` 的间距判。
- **`staffBandOnly`（默认关，排查用）**：谱表上下各留两个线距，带外的墨抹掉。
  从前立 GT 底稿要靠它挡住和弦字母，现在和弦带在找符头之前就认领掉了，那条理由没了。
  开了**歌词与和弦都没有**。
- OCR 缓存按**条的内容指纹**寻址——判据一动缓存落空，**掉一点先别当退化**。
- 两笔**算错过的账**（记下来免得再算）：「休止漏检」是一笔算错的账；
  `eighth→quarter` 那条不会让音符档动一分，**别拿它冲 71%**。
- 「小节自检从 33.2% 掉到 32.5% 不是退化」。
- 结构性结论：**折叠这条路已经 87% 正确，剩下的 45 组不吃这几个旋钮**——
  要动得先把「独头和弦」的建立时机与合并顺序理一遍，那是结构改动，另开一轮。
- **识别结果带源谱版面**（`staffomr/toxml.ts::sourceLayout`，矢量路同一份）：`<scaling>` 取全曲谱表高中位数、`<page-layout>` 取首页纸
  （上边距 = 各页墨迹顶最小值，下边距一律 5mm——末行歌词本就印在最低谱表线以下）；每个系统首小节写 `new-system` / `new-page`、
  系统左右缩进、离上一系统（页首离上边距）与各谱表离上一谱表的距离。谱表距离按**引擎叠放次序**（声部次序）取「上一谱表」，
  与原图上下颠倒的用本谱相邻谱表距离的中位数。tenths 取整、毫米两位小数。
  - 位图坐标折回页面按内嵌图在页上的位置（`RasterPage.imageRect`，取图时记下的变换矩阵）：排版软件出的 PDF 图常不铺满纸
    （破碎是 Letter 纸里的一块）。一像素合一点以上的（`jpegToPdf` 封的图片）页面尺寸不可信，按页宽 = A4 宽折。
  - 排版端怎么用见[排版-五线谱混排](排版-五线谱混排.md)「源谱版面档」。
- **符干、力度、松叶也照原图写**（只在写源谱版面时，`toxml.ts`，矢量路同一份）：
  - 符干端点写 `<stem default-y>`（`StaffNote.stemTip`，取符干段远离符头那一端）；同音拆两声部（`stems.ts::splitUnisons`）的两个都不写——那根干归谁不知道。
  - 力度按墨迹框（`StaffNote.dynamicBox`；矢量路取字形框，位图路取拼好的整串字母框）写 `default-y`（基线）、`relative-x`（笔位离符头左缘）、
    `font-size`（墨迹高 ÷ 同一串字在 Bravura 里的墨迹高 × 4 线距，Bravura 字母墨迹表 `DYNAMIC_INK` 取自字体元数据，不按字体盒）。
    OCR 从文字带读出来的力度没有框，照旧只写 `placement="below"`。
  - 松叶写起点 `default-y`（中线）、两端 `relative-x`、开口那一端的 `spread`（`WedgeSpan.spread`：矢量路量路径点，位图路取逐列跨度的开口中位数）。
  - `placement` 按实际位置：在所挂谱表顶线之上写 `above`（宣主荣耀人声的 f、mp、松叶都印在谱表上方），否则 `below`。
  - 多谱表声部显式写 `<part-symbol>brace</part-symbol>`：规范缺省就是 brace、Finale 与 Audiveris 导出都不写，但不是每个读入端都按缺省补；
    识别出的多谱表声部只来自花括号或「G + F 谱号」大谱表，一律 brace。
  - 歌词写 `<lyric default-y>`（该行歌词的基线）：汉字行取行底往上提一成行高（`textanalyze.ts::HAN_BASELINE_RISE`，方块字墨迹略沉到基线下），
    拉丁行有没有下伸笔说不准，不写。文字指示（声部标签「Alto」「Men」、「rit.」）写 `<words default-y>`（行底当基线）。
  - 延音线写朝向 `<tied orientation="over|under">`：认出的弧照弧的上下；和弦里按共同音补出来的（`slurattach.ts::tieChords` 规则②）比那条弧挂的音高的朝上、
    低的朝下；跨页弧改写成延音线、只找到一半补上另一头的，照那半截弧的上下（`toxml.ts`）。破碎干净版 36 条全带朝向。
- **声部方括号**（`prims.ts::findPartBrackets`）：人声几行左边那个 `[`——系统线左边一条**粗、直**的竖笔（逐行最长墨段宽 0.3~0.9 格、
  墨段中心横向跨度不过 0.25 格；系统线细、钢琴花括号弯，都过不了），罩住两行以上谱才收，打 `PartBracket`（与矢量路同一个标签）。
  `score.ts::groupParts` 逐系统看括号罩住哪几个声部，**跨系统取并集**：破碎前半首括的是女高女低两行、49 小节起女高女低男声三行另成声部，
  并成 P1–P5 一组，渲染端逐系统只括本系统可见的几行。同一系统里相接的两组是印着的两个括号，不并。
  从前位图路认不出方括号，只有「两行之间夹着歌词的上下两个声部」兜底成一对，后半首人声全没括号。
- **弧止端不跨小节线**（`pagefinish.ts`，挂音之后）：弧右端在本谱表一条小节线左边 0.3 格以上、止端的音却在线右边，止端退回线左边本谱表最右的音。
  十六分音群上的长弧常越过末音的头与干，`validateSlurNote` 把末音拒了，只剩线右边那个音（破碎 p7 m70→71 钢琴右手，又跟 m71 起的那条撞在同一个音上）。
  两端同音高的不动：跨小节线的延音线常在线上断开、只认出左半截，后面才判成延音线（望十架 p4 m33→34）。
- **只靠 `SHORT_RE` 进来的一两个字母**（`S`、`A`、`T`…）还不能压在某个音的符干那一列上（头左右一格、上下一根干长）：
  带尾的干顶会读成 `T`（破碎 p5 m53 女低末一个八分音符，挂成女高歌词下面的「T」）。
- **字号**也照原图量：歌词、文字指示取全曲中位数写 `<lyric-font>` / `<word-font>`，文字指示、和弦（`<root-step font-size>`）、
  页眉（连同原图位置 `default-x/y`、`valign="bottom"`）逐条写，取到半点。矢量路是文字对象的真实字号；位图路量**墨迹高**
  （`rasteromr/textsize.ts`，OCR 框带留白、页眉小字的框高能有字高两倍），汉字墨迹按 0.85 字号折，整行无汉字的按字母上下伸展
  （x 高 0.5、大写/升部 0.72、下伸 +0.21）折。页眉在页眉带自己的像素上量（排版软件出的 PDF 页眉不在谱图里）；
  页眉来自 PDF 文字层的（`pagecompose.ts`，条里没有这些字的像素）用文字层的真字号。
  - **小型大写**（破碎扫描版「BROKEN」）：OCR 读成全大写，逐字按列投影量墨迹高，每词首字母高出其余一成多、其余齐高的认成小型大写，
    改成首字母大写其余小写（`textsize.ts::smallCapsCase`，干净版文字层给的就是「Broken」），字号按首字母的大写高折。字号表达不了小型大写，
    小写的 x 高与小型大写相近。切出的块数与字母数对不上就原样留。
- **声部名**：每个系统谱行左边那一段（首行缩进里的全名、之后页边的缩写）切一条声部名带（`words.ts::findNameStrips`），认字与文字指示带
  同一个缓存（`rasterwords.json`）；上下叠着的行并成一个名字（「Soprano / Alto」），字号按墨迹量（`partNameLines` → `SPage.partNames`），
  归哪个声部同矢量路（`staffomr/score.ts::nameParts`，按纵向落在哪个声部的谱表范围）。全名写 `<part-name font-size>`。
  声部名带的指纹另用前缀 `N`、挑行口径另算（`keepStripLine`）：文字指示带只存有拉丁字母的行（`keepWordLine`，挡歌词与署名），
  声部名带汉字行也留（「女高音」），带在谱行左边，压不进歌词。现有语料行首没有印中文名的（破碎 GT 的「女低」「男低」是记 GT 时起的名）。
- **多谱表声部只印了其中几行**（望十架第三页长笛那行没印、钢琴右手照印，两行同属一个声部）：写出端逐谱表记可见性
  （`staffomr/toxml.ts` 的 `staffDetails`），没印的那行单独写 `<staff-details number="N" print-object="no"/>`。
  从前只在整个声部不印时才写，排出来多一个空谱表，源谱版面档那一页排不下。
- **印在谱表上方的歌词**：歌词行的行顶高过所挂谱表的顶线（`lyricsBelongBelow` 判给下方那行谱的，望十架独唱 / 女低共用一行谱、
  独唱的词印在谱表上方）就记 `above`，写成 `<lyric placement="above">`（`textanalyze.ts::attachLyrics`、`toxml.ts::lyricXml`）。
  从前不分上下，排出来上下两组词挤在谱表下方同一行、英文叠字。
- **跨系统连接**同矢量路走全局指派（`assignSlots`）：整曲建谱时给内容剖面（有没有词、音域中位数、谱面声部标签 `staffLabels`）。
  从前位图路没给剖面、退回逐系统 LCS，望十架第三行四个谱表全是高音谱号，钢琴左手被配到了第一声部（排出来多一个谱表）。
- **歌词还是文字先看排法**（`lyric.ts::lyricLayoutVerdict`）：按墨迹列切词块，量词距中位数（字高计）与「词块中心贴着本谱表某个音、
  只罩一两个音」的比例。词距窄且大多不对音 → 文字（脚注、版权、说明），不进歌词；词距宽且大多对音 → 歌词，不带连字符也当种子；
  其余照旧看连字符与字样（`DIRECTION_TERM_RE`，另认脚注号 `*`、`Tune;`、生卒年）。文字指示一路另挡页脚注（`words.ts::FOOTNOTE_RE`，
  望十架 p1「*Flute part is on page 43」）。

## 编辑器接入

- **同一条路**：整曲识别原在私有仓库的回归脚本里，搬进 `song.ts` 后回归脚本改调它，`staff-measure-all` 44 首逐行相同。
- **OCR 两种来法**：回归脚本读离线缓存（按条的内容指纹）；编辑器在线跑（`live`），**每页一趟**——`recognizeRasterPage` 走到哪一处要 OCR
  （整页文字框、和弦带、拍号条、声部标签、歌词条、简谱行、文字指示、页眉），缓存没给就当场把那一处切出的条送 `live`，切出来的条与离线缓存收的条同一口径
  （拍号只读头一趟、谱号列以外的那几条）。从前是每页整页识别三趟（先取和弦带与拍号条、再取其余各条、最后带全部结果出），前两趟的结果只用来切条。
  送 OCR 的代码只有 `ocrlive.ts` 一份。
  `staff-measure-all.mjs --live` 在浏览器里跑同一批：音符 97.74%（缓存路 97.70%）、时值 97.01%（97.09%）、满拍 91.63%（91.96%），和弦、歌词、挂位、
  小节调号拍号全同；差在《敬拜万世之王》《耶和华是我的牧者》两首（在线 OCR 与缓存的细差、PNG 转 JPEG 的细差）。浏览器版在线识别偏慢（44 首约 3 分钟），暂不深挖。
- **浏览器版 pdf.js 要关掉图像解码优化**（`isOffscreenCanvasSupported` / `isImageDecoderSupported` 置 false）：缺省把内嵌位图交成 `ImageBitmap`，
  `rasterpage.ts` 取不到原始像素就当这页没有整页位图（Node 版本来给原始像素）。
- **分流**（`detect.ts`）：位图路自己的谱线检测（含细线扫描件的补线 `completeStaffLines`），有一组平均线长过页宽四成的五线组就走五线谱（简线混排谱也走这条）；
  看前三页（封面、目录页没有谱表）。`omr-route-check.mjs`：testdata 简谱 56 份、五线谱 48 份全判对。顺序：矢量五线谱 PDF → 位图五线谱 → 简谱。
- **原图对照**（`rasteromr/overlay.ts`）：编辑器跑的识别给每个 `<note>` 写 `id="omr<k>"` 并记下源图框（`song.ts` 的 `noteIds`；回归脚本不开，产物逐字节不变）。
  id 记在音符对象上（`StaffNote.omrId`）而不是旁表——写出前音符会被复制（`{...n}`），按对象身份认只认到四分之一。
  写出端改模型时不管 `id` 属性，原节点上的被回填，所以改过的谱照样认得回来；对照按当前模型的音（`surfaceOf(note).id`）标音名，
  与识别时不同的标改过、对不上的标删掉。矢量 PDF 那一路也接了同一套对照（见 [识别-五线谱矢量](识别-五线谱矢量.md)）。
  - **「改过」按识别落地时的整个和弦比**（`omrctl.ts::chordSig`：各音音高、休止、时值、附点、连音、倚音；歌词另有框，不算在音上），基线是识别（或上次重建）刚落地的原文
    （`staffEmitted`，解析一次缓存）；项目重开没有基线时退回只比音高。
  - **歌词字、弧、延音线、力度、文字指示的源框**：编号时（`review.ts::numberOmrIds`，与音同一趟、同样确定性）各自编 `omrL` / `omrS` / `omrT` / `omrD` / `omrW`，
    写在 `<lyric id>`、`<slur id>` / `<tied id>`（起端；跨行接上的后半截是另一个弧对象，写在止端）、`<direction id>` 上，框进 `markBoxes`。
    框从识别中途带出来：歌词是音节左右 × 歌词行上下（`attachLyrics`），文字指示、速度 / 节拍器是字行框，力度是 `dynamicBox`
    （OCR 读出、没量墨迹框的取字行起头那几个字母的大致范围，另记 `dynamicSrcBox`，写出与挂音不用它），
    弧是 `markSlurNotes` 时记在挂上那一端的外框（`slurBoxes`）。同一个音分进两个声部时被复制，字、弧跟着写两遍，id 只给一份；
    和弦各音都起着同一条弧时 id 写在**最后一份**上（读入端并成一条、绑的是最后那个标签）。
    模型写出端不认领这些元素的 `id`，回填——**挪字、挪力度、挪弧端时 id 跟着那个字 / 记号走**（`shiftLyrics` 挪的是歌词对象本身）。
    对照按 id 认回（`omrlinks.ts::staffMarksOf`），签名是「宿主音的识别 id + 文字」（弧是起止两音），与落地时不同标改过、没了划掉；落地时就没写出来的框
    （接不上的半截弧）不画。文本格式里没有这些 id，按「宿主音 + 段号」反查、段号变了再按「宿主音 + 字」认，所以文本格式里挪过的字落成原位改过、挪过的力度落成删掉；
    文本格式投影出来的 `<direction>` 只记拍位（`offset`），宿主音按拍位找。ABC 的力度是装饰 `!mf!`（索引条目 `deco`），按力度名认。
    点框选中对应的歌词 / 弧 / 力度条目（`App._recognizeElOf` → `omrctl.staffMarkHit`），`Alt+→` 等照排版稿那一套改；
    文本格式的力度、注记条目挂在宿主音上，按「宿主音 + 种类」对框（同一个音上同类几条认成同一个框）；跨行接上的弧点 `)` 那一端对后半截的框。
  - **新插的音**没有识别 id：按同一声线前后两个有框的音插位（同一行等分，不在一行接在前一个后面），纵向按与参照音的音级差 × 本行谱线半间距，画虚框，
    命中框带 `data-id`（元素 id）。
  - **小节线**：识别出的每一小节（`Bar`）右端一条竖线，命中框带 `data-measure` = 小节里最右那个音现在落在全曲第几小节；它与下一小节最左那个音落在
    同一小节 = 这条线并掉了（划掉、不留命中框）。识别 id → 和弦要记**和弦里每个音**的（`Bar.notes` 不按横坐标排，最右那个常是和弦的第二个音）。
  - **Alt+点原图补漏识**（`sourcePoint`）：点在哪一行谱表、落在哪两个识别出的音之间；音高取横向最近、有音高的那个音**现在**的音高加纵向音级差
    （谱号调号就都算进去了，不必再认谱号），时值照选中的音。
- **系统切分修正**（对照视图右键谱行空白处，`score.ts::restructureSystems`）：合并同一页相邻两个系统 / 从某一行拆成新系统，就地改 `SPage.systems`
  后按自动指派（`profileOf`）重新 `buildScore`，不重跑识别（`StaffReviewResult.restructure`）。「这一行不是谱」走关联表的 −1。
  重建（关联表、系统切分）前按识别 id 记下手改（改过的和弦：音高、休止、时值、连音、倚音、歌词；删掉的），重建后照 id 放回。
  **问不问**：把记下的先回放到识别落地时那份上，与现在的谱按语义比（`omrctl.ts::semanticSig`：调号拍号谱号、小节线、记号文字、每个音连同奏法和弦名延音线、跨音记号端点；
  不看版面坐标、符干、临时记号印不印），对不上就是有回放不了的改动（连线、记号、调号谱号、手插的音……），先确认；对得上就不问。
  没有识别 id 的音不全是手插的——重建自己补的占位休止也没有，按「比识别落地时多出来的」算。重建后 `staffResult.score` 跟着换（关联表、右键按它认系统）。
- **谱表 ↔ 声部关联表**（声部面板，参照 Audiveris 的逻辑声部）：`buildScore` 接受外面给的指派 `slots[系统][谱行]`（-1 忽略），
  与它自己全局指派那一支同一个收尾（分声部、花括号、大谱表）；整曲结果留着逐页中间结果，`rebuild(slots)` 不重跑识别重建 MusicXML。
- **原文换成 ABC / 123 等文本格式**（格式下拉，`omrlinks.ts`）：文本里没地方写 `<note id>`，改记旁表「和弦记号在原文里的起点 → 各音的识别 id」，
  随编辑迁移起点（同简谱识别的 `JpwMeta`）。换格式时两边投成 MusicXML 形状，按「声部、谱表、绝对拍点、音高」对上带过去，拍点对不上的（删了音没补休止）
  同小节里按先后、音高再认；简谱一拍一个 `0` 拆开的休止记成「接着的」，不画新插的虚框。转回 MusicXML 时把 id 写回 `<note id>`（`stampXmlIds`）。
  「改过」与重建回放的「问不问」在文本格式下先把识别落地那份过一遍同一种格式（`App.viaCurrentFormat`）再比；重建（关联表、系统切分）回放后切回原来的格式。
  回放按和弦里任何一个音的 id 认（和音在 123 里自下而上写，记下的未必是 MusicXML 里第一个音的）。Alt+点补音在文本格式下音头改成点的音高、时值照抄选中的音（`ops.ts::retargetToken`）。
  识别项目存旁表（`result/staff-links.json`），重开接着在那种格式里改。
- **并排原图**（排版稿里，`omrctl.ts::syncSide`）：每个和弦按当前原文里的 `<note id>`（`surfaceOf`）认回识别框，改过的谱照样认得；项目重开后第一次打开时同对照视图从原图补数据。
  底图**原样画原图**，便于对比：PDF 用 pdf.js 画整页（页眉的小图块、文字层、页边都在，`browser.ts::renderPdfPages`，**开始识别时就画**、不等识别结果，画好前先铺白纸），图片输入直接画原图（不转 PDF）；
  **能看的先给**：拖进来识别时一开始就撤掉整块遮罩、离开开始页，并排先放不带框的原图，谱面区按页（分页 / 长图同铺页）放「第 n 页识别中 / 已识别」占位、代码区盖住（`omrctl.ts::showPending`，简谱、矢量两路同用；简谱并排也画原图——它的位图就是整页等比缩放），
  没识别成的还原并排开关、按原文重排，从开始页进来的退回开始页；重开 `.dolce` 同样先放原图，对照数据补完再加框；
  识别完按位图尺寸摆放（`placePageView`），框按谱图在页面上的位置缩放 + 平移对过去，取图不做几何变换，框与原图逐像素对得上。
- **识别项目重开**（`.dolce`，见 [编辑器](编辑器.md)）：包里只有原图与 MusicXML，逐页位图与音符坐标不存；第一次进原图对照时
  `omrctl.ensureStaffResult` 从原图重跑识别补回来（确定性，`omr<k>` 编号对得上存的原文），关联表也是从这时起可用。
- 图片封单页 PDF（JPEG 原样作 `DCTDecode` 流，别的格式经画布转 JPEG 质量 1.0），与回归脚本喂图片的办法同构。
