# 识别：五线谱（整页位图，合唱谱）

**判据全录** → [../实现/位图五线谱识别.md](../实现/位图五线谱识别.md) + [同名子目录](../实现/位图五线谱识别/)各分篇

## 职责

整页是一张位图的五线谱（合唱谱 PDF、独唱谱图片）→ MusicXML。**编辑器已接**：拖入、选中的图片 / 扫描 PDF 按有没有五线谱表自动分流（可手动改判），
结果落地同打开 `.musicxml`（谱面上改模型）。
下游复用矢量路（`adapt.ts` → `staffomr/page.ts`，**下游一行不改**）。

## 关键判据

- **半调网点（抖动印刷）的底本先去网**（`descreen.ts`）：符头是打散的网点，填充率那一档全过不去
  ——《坚固保障》整页 83 个音符原本只认出 20 个。去网走标准形态学（面积开运算 → 面积闭运算 → 闭运算），
  参数运行时从本页统计（墨块、白隙面积的分位数）。**不是每页都做**：先量谱表带内的「孤立墨点占比」
  （`halftoneRatio`），心领那本 0.359、合唱谱那批全书全页最大 0.157，门槛取 0.25，
  **合唱谱没有一页会触发**。量要限在谱表带内——整页量的话几乎没墨的封面页量出来是 1.000。
- **和弦字母先认领、再找符头**（`harmony.ts`）：独唱谱在谱表上方印和弦，`C`/`D`/`G`
  都是圈，正落在空心符头那一档里（`HOLLOW_BAND` 上下各让三格）——实测《坚固保障》
  整页因此多出六个 D6/E6 全音符。带的窗口是顶线上方 1.0~3.2 格，**列投影切簇、
  逐簇送 rec**（不请 DBNet：这个尺度上 42 个和弦它只框出 30 个），
  切成记号靠 `CHORD_TOKEN_RE` 的文法而不是簇边界。**只在 OCR 缓存命中时才认领**，
  所以合唱谱那批一块墨也不动。一行里多数条都往上长出一格以上（和弦行整体排得高），
  就把带顶挪上去**整行重切**——否则列投影只看到字脚，♭ 的肚子、「7」被切掉。
  **和弦与文本分开交**：记号词（Fine、D.C.，与简谱路同一张表 `blankNonChord`）、
  与小写字母粘连的单词、汉字串认成文本（`harmonyTexts`）；再**按整行**判和弦行还是文本行
  （同简谱路 `isAnnotationLine` 的覆盖率口径），被切成几条的署名「(John B. Dykes)」整行归文本。
  详见 [和弦](../实现/位图五线谱识别/和弦.md)。
- **简线混排谱：简谱行先认领、再互证**（`jianpuband.ts` / `jianpufuse.ts`，详见
  [简谱混排与独唱谱补认](../实现/位图五线谱识别/简谱混排与独唱谱补认.md)）。
  简谱行按「悬在谱表上方的短竖线与谱表小节线同 x」定位，整块落在带里的墨抹掉
  （不挡就被收成全休止和加线上的符头），和弦带改贴到简谱行上方。简谱离线认（`gen-rasterjianpu.mjs`
  缓存），逐小节按 x 与五线谱配对：**音高信简谱、时值只在五线谱不自洽时改**、配上的音所在和弦的
  其余音删掉（符干另一头的假头）、缺拍时照简谱补音。《是谁》音符 88.5% → 100%。
- **被谱线切开的对象在修补图上取整块，不切碎再按盒距拼**（`prims.ts::repairLineCuts`、`contour.ts::candidateMap`）：
  去线「上下都没墨才抹」会把贴线斜穿的笔画一起抹掉。修补图把存疑的线带像素补回，一页取一次，弧线、八分休止、演奏法记号、松叶、
  虚线弧与「碎块并回再查字典」都先在它上面取连成一块的候选，没连上的才退回旧的拼法；认干、认杠、认头、找内腔仍在去线图 / 原图上。
  详见 [取图与谱线](../实现/位图五线谱识别/取图与谱线.md)「修补图」。
- **多段歌词的「链式收段」只在位图路开**（`textanalyze.ts::buildLyricLines`）：
  独唱谱一页印八段，第五段起就出了「三个谱表高」那道闸，于是按「接着上一段、
  中间没有空当」续收。**但这一条要认合成字体**（`#` 打头，位图路自己造的文本对象）
  ——矢量路每首最多两段，开着反而收进本不该收的行（实测赞美之泉歌词 94.95% → 94.88%）。
- **拉丁歌词绕开方块字格**（`lyric.ts`）：汉字那套立在「等宽见方」上，英文词宽差着数倍。
  判「这是拉丁行」要三道闸——字母占比 ≥0.9、字母 ≥20 个、**至少一个连字符**；
  最后那道专挡页眉与版权行（它们是货真价实的整行英文，前两道拦不住）。
  词界按**条子里真的空白**判（0.7 个字号），不按 `xFrac` 的间距判。
- **`staffBandOnly`（默认关，排查用）**：谱表上下各留两个线距，带外的墨抹掉。
  从前立 GT 底稿要靠它挡住和弦字母，现在和弦带在找符头之前就认领掉了，那条理由没了。
  开了**歌词与和弦都没有**。
- OCR 缓存按**条的内容指纹**寻址——判据一动缓存落空，**掉一点先别当退化**。
- 两笔**算错过的账**（记下来免得再算）：「休止漏检」是一笔算错的账；
  `eighth→quarter` 那条不会让音符档动一分，**别拿它冲 71%**。
- 「小节自检从 33.2% 掉到 32.5% 不是退化」。
- 结构性结论：**折叠这条路已经 87% 正确，剩下的 45 组不吃这几个旋钮**——
  要动得先把「独头和弦」的建立时机与合并顺序理一遍，那是结构改动，另开一轮。

## 编辑器接入

- **同一条路**：整曲识别原在私有仓库的回归脚本里，搬进 `song.ts` 后回归脚本改调它，`staff-measure-all` 44 首逐行相同。
- **OCR 两种来法**：回归脚本读离线缓存（按条的内容指纹）；编辑器在线跑（`live`），**每页一趟**——`recognizeRasterPage` 走到哪一处要 OCR
  （整页文字框、和弦带、拍号条、声部标签、歌词条、简谱行、文字指示、页眉），缓存没给就当场把那一处切出的条送 `live`，切出来的条与离线缓存收的条同一口径
  （拍号只读头一趟、谱号列以外的那几条）。从前是每页整页识别三趟（先取和弦带与拍号条、再取其余各条、最后带全部结果出），前两趟的结果只用来切条。
  送 OCR 的代码只有 `ocrlive.ts` 一份。
  `staff-measure-all.mjs --live` 在浏览器里跑同一批：音符 97.74%（缓存路 97.70%）、时值 97.01%（97.09%）、满拍 91.63%（91.96%），和弦、歌词、挂位、
  小节调号拍号全同；差在《敬拜万世之王》《耶和华是我的牧者》两首（在线 OCR 与缓存的细差、PNG 转 JPEG 的细差）。浏览器版在线识别偏慢（44 首约 3 分钟），暂不深挖。
- **浏览器版 pdf.js 要关掉图像解码优化**（`isOffscreenCanvasSupported` / `isImageDecoderSupported` 置 false）：缺省把内嵌位图交成 `ImageBitmap`，
  `rasterpage.ts` 取不到原始像素就当这页没有整页位图（Node 版本来给原始像素）。
- **分流**（`detect.ts`）：位图路自己的谱线检测（含细线扫描件的补线 `completeStaffLines`），有一组平均线长过页宽四成的五线组就走五线谱（简线混排谱也走这条）；
  看前三页（封面、目录页没有谱表）。`omr-route-check.mjs`：testdata 简谱 56 份、五线谱 48 份全判对。顺序：矢量五线谱 PDF → 位图五线谱 → 简谱。
- **原图对照**（`rasteromr/overlay.ts`）：编辑器跑的识别给每个 `<note>` 写 `id="omr<k>"` 并记下源图框（`song.ts` 的 `noteIds`；回归脚本不开，产物逐字节不变）。
  id 记在音符对象上（`StaffNote.omrId`）而不是旁表——写出前音符会被复制（`{...n}`），按对象身份认只认到四分之一。
  写出端改模型时不管 `id` 属性，原节点上的被回填，所以改过的谱照样认得回来；对照按当前模型的音（`surfaceOf(note).id`）标音名，
  与识别时不同的标改过、对不上的标删掉。矢量 PDF 那一路也接了同一套对照（见 [识别-五线谱矢量](识别-五线谱矢量.md)）。
- **谱表 ↔ 声部关联表**（声部面板，参照 Audiveris 的逻辑声部）：`buildScore` 接受外面给的指派 `slots[系统][谱行]`（-1 忽略），
  与它自己全局指派那一支同一个收尾（分声部、花括号、大谱表）；整曲结果留着逐页中间结果，`rebuild(slots)` 不重跑识别重建 MusicXML。
- **并排原图**（排版稿里，`omrctl.ts::syncSide`）：每个和弦按当前原文里的 `<note id>`（`surfaceOf`）认回识别框，改过的谱照样认得；项目重开后第一次打开时同对照视图从原图补数据。
- **识别项目重开**（`.dolce`，见 [编辑器](编辑器.md)）：包里只有原图与 MusicXML，逐页位图与音符坐标不存；第一次进原图对照时
  `omrctl.ensureStaffResult` 从原图重跑识别补回来（确定性，`omr<k>` 编号对得上存的原文），关联表也是从这时起可用。
- 图片封单页 PDF（JPEG 原样作 `DCTDecode` 流，别的格式经画布转 JPEG 质量 1.0），与回归脚本喂图片的办法同构。

## 回归

**只量一件事：识别结果还要几步手动操作才与 GT 一致**——谱面元素（符头的线间位置、印出来的临时记号、时值、记号、连线、
文字、歌词、小节线、谱号调号拍号、页眉）的严格最小编辑距离，准确率 = 1 − 步数 / 从零录入步数，分音符 / 记号 / 歌词 / 文字 / 结构 / 页眉六档。
判据在私有仓库 `scripts/visual-ops.mjs`，简谱、五线谱、合唱谱共用一份，口径见私有仓库 `docs/识别手动操作.md`。
（2026-10-06 起旧的音符 / 音级 / 歌词等准确率回归不再跑，各实现篇里此前的读数是那套口径。）

- 合唱谱（多声部 PDF）：`chorus-ops.mjs`，识别系统 ↔ GT 段逐行比，外加「改关联」「系统没配上」；干净位图与真扫描件两档、逐份都守。
- 独唱谱图片（`testdata/五线谱`，jpg/png 按文件头判）：`staff-measure-all.mjs`，整首逐谱表比，合计与逐首都守；
  `--dump` 落盘后 `solo-ops.mjs --staff --from=目录` 几秒重算。
- 闭合谱四声部另有一整本语料（新编赞美诗五线谱，GT 由四声部文本谱转出、放私有仓库），`STAFFIMG=testdata/新编赞美诗五线谱` 换语料根后
  同一个脚本逐曲记账（不守合计基线）；判据见[闭合谱四声部](../实现/位图五线谱识别/闭合谱四声部.md)。

新 GT 可用紧凑文本手抄（`staff-gt-text.mjs`，底本放私有仓库 `data/五线谱/gt-src/`）。

  本地私有仓库的「位图五线谱现状与待办」。各类底本（SATB 闭合谱、简线混排、网纹与低分辨率扫描、钢琴伴奏）的判据在
  [简谱混排与独唱谱补认](../实现/位图五线谱识别/简谱混排与独唱谱补认.md)与[闭合谱四声部](../实现/位图五线谱识别/闭合谱四声部.md)；
  合唱谱三到七行的系统靠「各行小节线同 x、同系统调号相同」约束，见[多行系统的小节线](../实现/位图五线谱识别/多行系统的小节线.md)。
- 未完成项：跨系统连接的内容（破碎连接、歌词）、三连音的数字「3」（`findTuplets` 只靠符杠）、倚音、segno / coda、文字跳转（Fine / D.S.）的播放次序
  （逐项读数见[图形符号与账本](../实现/位图五线谱识别/图形符号与账本.md)「GT 特性覆盖表」）、`attachLyrics` 挂错谱行、
  浏览器版在线识别偏慢（在线 OCR）。
