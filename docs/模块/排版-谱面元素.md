# 排版：谱面元素（`src/engrave/`）

**判据全录** → 竖向叠层见 [实现/简谱纵向栅格.md](../实现/简谱纵向栅格.md)、歌词标点见 [实现/歌词标点挤压.md](../实现/歌词标点挤压.md)；其余判据就写在本页与各文件头注释里

## 职责

**每种谱面元素一份画法与定位判据，两个排版引擎调它**：

| 引擎 | 位置 | 文档 |
|---|---|---|
| 简谱引擎（各格式的原样 / 展开档、PPTX、成书） | `src/layout/jianpu/` | [排版-简谱引擎](排版-简谱引擎.md) |
| 五线谱 / 混排（含混排的简谱层） | `src/mixed/` | [排版-五线谱混排](排版-五线谱混排.md) |

从前同一种元素三个引擎（旧简谱引擎、原样文档布局、混排；前两个 2026-10 合并成一个）各写一份（调号名表三份、升降号三种尺寸、八度点三套阶梯、减时线分组三份、力度字形两张表……），
改一处忘一处。现在元素的**样子与相对位置**只在这里写；引擎只做三件事：

1. 把自己的尺子（`JianpuStyle` / `MixedOptions`，[架构 §6.2](../架构.md)）折成元素的参数——字号、数字墨迹高、线宽、颜色；
2. 给出锚点——音符数字的笔位与墨迹盒、弧的两端、松叶的跨度；
3. 做**整行级**的事——横向排布、断行分页、上方带堆叠（`engrave/upperband.ts`）、歌词碰撞求解。

依赖单向：`engrave/` 只依赖页面树 `pagetree/`（图元、字体）、`smufl/`、`common/`、`score/` 的乐理小件、`model/marknames.ts`、`style/header.ts`（类型），**不 import 任何引擎**（`deps-check.mjs` 守门）。
产出的叶子类型与类名照旧（`artic`、`tuplet-line`、`aug-dot`、`smufl`、`chord`、`hairpin`、`breath`…），
`ScorePainter`、成书扁平化（`pdflayout/browser.ts`）、PPTX、可视化编辑都按类名认，不受影响。

**观感以混排为准**（用户定）：统一时先把混排 `jianpuoverlay.ts` / `render.ts` 的画法与 C++ 实测定位改写成相对数字墨迹盒的规则，
再让另两路套用；混排没有的元素（换气、段落词等）才参考简谱引擎、再其次原样文档。

## 关键判据

### 盒子口径（用户定）

- **墨迹盒**：SMuFL 字形、矢量对象（点、线、弧、括线、小节线），以及**简谱音符数字**（为精确定位）。
  Bravura 的全局 ascent−descent 约 4 em，按字体盒算一个升降号就把行高撑出几个字号（CLAUDE.md 那条）——
  SMuFL 文字一律经 `musicText`（`inkBound`），量墨迹走 `musicInk` / `SmuflText.bound`。
- **字体盒**：其余一般文字——歌词、和弦文字段、页眉、文字记号（rit.、Fine、段落词）、「1=」文字部分。

### 竖向叠层（`stack.ts`）

数字墨迹顶 →gap→ 高音点 1 →gap→ 高音点 2 …；数字墨迹底 →gap→ 减时线 1 →gap→ … →gap→ 低音点 1 …。
相邻两件墨迹之间的空一律是 `gap = stack-gap × 数字墨迹高`（缺省 0.17，用户试过后定），点径、线宽各是各的参数。
**全部等距**：成书、展开档的旧阶梯与实测层距都去掉了。混排的简谱层数字小，`gap` 跟着墨迹高自己缩。
倚音内部同一套（按倚音自己的墨迹高），整块倚音再离主音那一摞一道 `gap`。细节与历史见 [实现/简谱纵向栅格.md](../实现/简谱纵向栅格.md)。

### 临时记号

csym 字形按**数字墨迹盒**定位（高约 1.4 个数字墨迹高，底比数字墨迹底高一截）；`accidental-scale` 缩放（展开档、原样档、混排简谱层 0.75）。
前面的让位是**软**的（简谱引擎 `Entry.leadWant`，在 `Line.adjust` 里从间距里扣）：硬让位会把 `.jpwabc` 定死的行挤折。
弧、连音、奏法记号的高度都算上 `accidentalRise`（升降号比数字顶高）。

### 弧：只分简谱、五线谱两种（用户定）

规则写在 `engrave/arc.ts`（`jpArcY`、`arcClearShift`、`arcRise`、`ARC_CHAIN_INSET_DIV`），两条简谱路（简谱引擎、混排简谱层）同一条：

- **简谱弧只看起止两个音**：两摞（数字、高音点；终点再算上临时记号——起点的在弧外侧）的墨迹顶取高者，
  往上**一道叠层的空**（`stack-gap × 数字墨迹高`，与八度点、减时线之间同一个量，不单设）。原样档也是简谱，同此；
  原样档多连音的两段弧也是弧，同此。连音**括线**不是弧：让开跨度里每个音（含临时记号、奏法记号）之上一道空（简谱引擎 `Line.addTuplet`、原样文档 `place/marks.ts` 同此）。
- 首尾相接的两条在接点各内缩字号的 1/14。
- **弧套弧按实际弧线判碰**：从短的画起，外弧把套在它里面的弧（延音线、更短的 slur、多连音弧）的弧顶当障碍，
  抛物线近似的弧线碰了才整条抬、高出一道空——没碰着的外弧不白抬（固定抬一格会把整本撑高）。
- **跨行两截都画**：起头那行画到行末，收尾那行从行首起弧；敞口那截高度只认真有的那一端（混排简谱层按系统同此）。

**五线谱弧**（混排五线谱层）端点照原 C++ 工程挂符头/符干，**看整个跨度**：跨度里的符头外缘、朝弧那一侧的符干尖都是障碍，
碰了整条往外挪、留半个线距（`mixed/model.ts::staffArcObstacles`）。

### 上方那一带

奏法记号、延长记号、弧、三连音、松叶都在第 0 层，和弦第 1 层，转调第 2 层，房号最后按堆叠结果定车道
（简谱引擎 `upperband.ts::stackUpperBand`）。表情/跳转记号堆叠之后再按**墨迹**避让和弦（和弦上标 `Am⁷` 的 7 比字母高，
按字号估的顶会压上去）。原样文档同一套求解（`place/band.ts`，堆叠走 `engrave/upperband.ts`），只是松叶放第 1.5 层
（用户定：贴音，跨度里有和弦撞上才抬到和弦之上）。
混排里没有版面坐标的文字块（速度记号、力度）横向撞上就往上摞；松叶缺省放谱表**下方**，歌词让开它。

- **力度字号**是数字字号 × `DYNAMIC_SIZE`（1.4，`dynamics.ts`；简谱引擎与原样文档同用）：Bravura 的力度字形很矮，
  按数字字号排只有数字一半高。Segno/Coda 仍是 0.95。
- **写在小节末尾的跳转记号（`Fine` / `D.S.`）与小节线右对齐**：右缘对到线（整组墨迹）的右缘，基线不低于线顶一道空
  ——线比数字高，照和弦基线摆会压在线头上。三路同口径（简谱 `addDirections`/`placeDirections`、
  原样文档 `paintOrnaments` 的 `bar`、混排自动铺排 `updateDataXPos`）。
- **和弦不压小节线**：小节头一个音上的宽和弦居中后探过前面那条线、又与线头上下相叠时，整块挪到线右边
  （简谱 `spreadChordsHorizontally`）。
- **混排速度记号摞在最上面**：同一行的自动文字块先排力度、文字，速度最后排（`staffpages.ts`）。

### 歌词音节

按主体居中，前后标点挂出去；三路都做标点挤压（`lrc-punct-compress`，见 [实现/歌词标点挤压.md](../实现/歌词标点挤压.md)）。
**西文词间补一个空格宽**（`latinWordBreak`）：交界任一侧是西文就补，前一个以 `-` 收尾的是词中断开的音节不补；
`主啊,` 这种中文带半角逗号的不算西文。原样文档的段号与连谱号还要让开首字前挂出去的引号（留位与画段号两处同一个量）。
**开括号领起后字**（123/ABC 读入，`isLyricOpenQuote`）：`段（副` 切成 `段` + `（副`；并到前一字的话它成了不占位的尾标点，后一个字压在括号上。
浏览器走字体 `halt`/`chws` 量笔位时，起始类标点的笔位要往左补回压掉的那截（`measure.ts::measureGlyphRun`）：
绘制端不叠特性、画的是全宽字形，墨在方框右半边。

### 减时线拍组（`beatgroup.ts`）

复拍子（分母 8、分子 3 的倍数）三个八分一组，其余一拍一组；残节（弱起、被反复切开的半个小节）按小节末尾对齐，
整曲末小节不补、下一小节正好等于要补的那截也不补。原样文档另有跨行续段（`|/`），简谱引擎、混排按整小节算。

### 只占位不印

不可见休止 `x` 的数字挂类名 `invisible`（`pagetree/walk.ts::INVISIBLE`），排版照常量它，`walkPageItem` 的四个出口都跳过。

## 样式键

`stack-gap`、`slur-gap`、`accidental-side`、`accidental-style`、`accidental-scale`、`chord-plain`、`lrc-punct-compress` 两个引擎都认
（`style/keys.ts` 的 layout / mixed / book / original 四列）。删掉不留兼容的旧键：`beam-top`、`beam-dist`、`octave-dot-dist`、
`octave-up-y`、`octave-down-dy`、`beam-top-y`、`dot-dx`、`dot-dy`、`dash-width`、`dash-half-length`、`lrc-half-punct`。

## 回归

- **测试谱**：私有仓库 `testdata/engrave/` 两个 123 母本（单声部、多声部）覆盖全部元素，`gen-engrave-fixtures.mjs` 派生
  MusicXML / `.jpwabc` / 文本谱 / ABC；`jianpu-svg-dump.mjs` 的 `engrave` 一类每档都跑。
- **每批的基线是上个提交的构建**：`jianpu-svg-dump`（指纹）、`mixed-pixel-dump`（混排像素）、`rebuild.mjs`（成书 DrawList）、
  `engrave-review.mjs`（左右对比图，缺省直出 SVG）都有 `--dist`，拿旧构建出基线再与当前比；外加 `pptx-check.mjs`。
- 改动一种元素：三路的变化页都要过目；页数变了的先查原因（展开档页数变常是演唱顺序被动了，不是排版）。

## 已知限制

- 上方带堆叠简谱引擎、原样文档共用求解器；混排按自己的规则避让，判据对齐但没有共用求解器。
- 混排自动铺排里连音与别的声部共用拍位槽，三连音间距会一疏一密（记在私有仓库待办 §3）。
- MusicXML 的 D.C. / D.S. / Fine 在文本谱视图里只投过去画（`Ornament.projected`），演唱顺序不认（同上待办）。
- **页脚不在这里**：展开档的投影片页脚（`layout/jianpu/place/header.ts::placeSlideFooter`，曲名 + 页码/总页数）与原样文档的曲谱页脚
  （`compose/footer.ts::layoutFooters`，按 `.ss` 的 `song-foot` 模板排文本谱的 BL/BC/BR 字段）是两样东西，数据与用途都不同，不合并。
