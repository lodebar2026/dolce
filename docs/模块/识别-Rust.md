# 识别：Rust 工作区（`crates/`）

判据在本页。

## 职责

识别（简谱、五线谱含混排与矢量 / 转曲档、歌本切分）全在 Rust：桌面版、网页版、命令行同一个入口（见「接入」），TS 侧只做结果落地（`src/omr/`，见「编辑器侧」）。

原先的 TS 识别（`src/omr/` 的识别部分、`src/omrkit/`、`src/staffomr/`、`src/rasteromr/`、`src/outlineomr/`、`native/omrkernels`）发布前已删，
Rust 是重新设计的实现，不与它逐字相同，按各语料 GT 判分与 TS 基线（私有仓库 `dev/data/rust-omr/ref-c7c02820/`）比。
旧实现的判据与踩坑仍留在 [../实现/](../实现/) 的 [OMR-简谱识别](../实现/OMR-简谱识别.md)、[位图五线谱识别](../实现/位图五线谱识别.md)（含同名子目录）、
[五线谱矢量识别](../实现/五线谱矢量识别.md)、[矢量PDF识别](../实现/矢量PDF识别.md)，追分时参照；文中的 TS 文件路径指删除前那一版（`git log --diff-filter=D -- src/rasteromr` 找删除提交，看它的父提交）。

## 设计原则（迁 Rust 时定下，勿轻易推翻）

用户定的口径：

- **重新设计，不逐字照搬**：准确率按各语料 GT 判分追平或超过旧基线即可，旧判据只作参考；旧实现里按具体曲目补的判据不预先搬，回归暴露出同类问题时先看能否用结构特征或本页统计解决。
  先把结构走通，精度接近基线就收口，逐例精度项记待办留后。
- **最多两条路线**：简谱（`omr-jianpu`）、五线谱含混排（`omr-staff`）。矢量 / 干净 / 扫描三档的差异收进谱面元素的证据，不另开路线。
- **按模块分阶段**：五线谱 预处理 → 框架结构（谱表、系统、小节线）→ 结构信息（谱号、调号、拍号及切换）→ 音符数据 → 文本及符号 → 线性符号 → 混排简谱互证 → 整曲；
  **小节线与系统在符头之前定**（旧实现排在全部符头之后、谱号调号夹在符头流程中间，改一处常伤别处）。简谱路线同构。每一步是一个阶段，回归能从第一个变了的阶段接着跑（阶段缓存，见「关键判据」）。
- **PDF 只走 PDFium**（取数与整页渲染都是），前端不用 pdf.js；网页版编 wasm。
- **尽量不去线**（见下）。
- **矢量页不转位图**，做矢量抽象（整页渲染后喂位图路线量过，明显更差）：谱面元素带像素与矢量两种证据，**两种证据只在「取原语」处分开，判据写一份**；
  矢量的粘连单独处理（见下「矢量档：拆与并」），目标按矢量自己的基线看，不按「接近位图档」看。
- 子集字体取不到轮廓的字形按字框渲染取位图签名兜底；PDF 的绘制次序（一行字的对象号连着）可作旁证，碰到尺寸像字的非字时再用。
- 识别结果在 Rust 里建模，直出 `ScoreDoc`（`omr-todoc`），MusicXML 只由唯一写出端写；识谱命令行不依赖 Node。

### 不去线：谱线是已知结构

旧实现先抹谱线再认符号，符头判据是在去线图上调出来的，去线方式一换就全面变差，贴线斜穿的笔画被抹断又靠修补图补回。现在不产出「去线图」作识别输入：

- **线上像素标存疑而不删**：找到谱线后得三值图（墨 / 底 / 线上存疑：纵向游程约等于线宽、上下无墨），原图不改。
- **形状判据带线感知**：模板匹配、填充率、内腔在原图上算，存疑像素不计分；模板分「骑线 / 在间」两套，从本页自举。
- **线段从原图游程取**：竖段看纵向游程（谱线只有线宽高，不干扰）；符杠看纵向厚度明显大于线宽的斜带；加线看谱表外的短横游程。
- **连通穿线**：存疑像素只在两侧都有墨时才算连通（笔画穿过谱线）。细长曲线（弧、松叶）沿原图追踪，遇谱线按走向跨过。
- 唯一等效去线的地方：送 OCR 的条若压着谱线（谱表内的文字、拍号数字），送之前把存疑像素置白。

### 归属与互斥

哪团墨归了哪个元素、哪些解释不能同时成立，显式记下来（`Claims` 等），取代按次序追加删改的旁表。**不做成每一步都必过的总闸**，只用在确有歧义处：

| 地方 | 归属 / 互斥 |
|---|---|
| 竖段 | 系统线 / 小节线 / 符干 / 升降还原号竖笔 / 方括号之一；框架层先定前两种，其余留给音符层 |
| 符头候选之间 | 同一处墨的几个解释（实心 / 空心 / 全音符、相邻音级、粘连拆法）只留一个 |
| 符头 ↔ 别的字形 | 升号的两个肚子 ↔ 两个黑头；和弦字母的圈、歌词字 ↔ 空心头；休止 ↔ 符头；符尾里的墨 ↔ 头 |
| 符杠 | 一条斜带只归符杠 / 加粗谱线 / 松叶 / 弧之一；符杠要有干撑着 |
| 点 | 附点 / 断奏点 / 反复点 / 八度点 / 句读，按相对宿主的位置归一个主 |
| 行首区 | 谱号、调号、拍号占的墨不进符头与临时记号候选 |
| 文本 ↔ 记号 | 和弦记号 ↔ 顿音、主和弦 ↔ 括号里的备选和弦；力度字母 ↔ 歌词；延长记号 ↔ 弧 |
| 线性符号 | 弧 ↔ 连音括线 ↔ 房子横线 ↔ 松叶一边；延音线 ↔ 圆滑线（同音高且时间相邻才是延音线） |
| 混排 | 简谱行的墨不进五线谱候选；简谱小节线 ↔ 谱表小节线 |
| 简谱 | 数字 ↔ 小节线（细 1）、减时线 ↔ 增时线 ↔ 连谱横笔、八度点 ↔ 附点 ↔ 顿音、弧 ↔ 字笔画 |

已归属的墨对后面的模块是「占用」：压在上面的候选要么放弃、要么提修正提案。

### 粘连拆分是被调用的服务，不是前置阶段

旧实现开头先做十几种「块手术」再按连通块认，拆错了后面无从知道。现在由正在认某团墨的模块在「按单个符号解释不通」（尺寸出本页同类范围、模板残差大、多出孔或竖笔）时发起拆分：
减去已知形状、细颈切开、按本页该类宽度等距切、按走向分离细长笔画。结果是**拆分提案**（各部分掩膜 + 手法 + 把握），不改原图与块表，可并列几种拆法由裁决选，被否就换一种。

### 候选 → 裁决 → 验收

每个模块先出带分数的候选（几种检出法并列），按归属与互斥一次裁决，再过验收；不再「认一批、后面每步追加删改」。
音符层留一个统一的再验收入口（小节拍数、跨谱表拍位）：别的模块要改音符（改时值、删假头、补漏音、改音高）一律提交**修正提案**，由它应用后重验。

- **满拍用于裁决，不只事后修**：把握不大的元素的候选按「本小节满拍、同系统各行拍位对齐」选组合（组合数有上限）；把握大的不为凑满拍改；凑不满的保持原判、记可疑。弱起、行末半截小节、变拍号先认出来再套满拍。
- **可疑清单**：裁决时一二名接近、验收不过、靠推断补的、无主墨、采纳了把握低的拆法，都记一条可疑（元素 id、源图框、原因码、落选候选），交编辑器核对视图逐个跳。
- **为手动修改留接口**：结果留在 Rust 会话里；每个元素带落选候选与源图框；用户改的（删音、改音高、改时值）记成**钉住的事实**按识别 id 作硬约束，带约束局部重跑；
  识别 id 确定且稳定（同一底本重跑、带约束重跑，没变的元素 id 不变），编辑器按 id 把手改放回去。

### 不写重复代码

| 两条路线、三档都要用的 | 只写一份，放在 |
|---|---|
| 像素运算、统计、几何；按本页统计取尺子 | `omr-core` |
| 元素、证据、探针、归属与互斥、粘连拆分；游程取横竖段与竖段成线；细长曲线追踪与拼接；点的分类；模板与形状字典；音乐逻辑（时值、满拍、连音、调号音高、延音线判定、反复与房子） | `omr-sheet` |
| 文字：字行拼装、歌词对音、和弦文法、页眉分类、速度 / 跳转 / 力度词表、标点、繁简 | `omr-text` |
| 取数、成像、判路 | `omr-source` |
| OCR 前后处理、缓存、后端 | `omr-ocr` |

- **一个判据一份实现**：同一机制在几处用（首轮找头、沿干补头、跨谱表补漏音都是「在某个窗里按模板找头」）就做成带参数的一个函数，调用点只给窗口与门槛来源。
- **档位差异只出现在证据提供者里**：路线代码里不许有「如果是矢量 / 扫描」的分支去走另一份判据；确有差异的量（容差、要不要验墨）由证据回答（`Probe::exact()`、候选分）。
- **路线之间不互相抄**：`omr-staff` 只在混排处依赖 `omr-jianpu`，反向不许；两边都要的下沉到共用层，新增依赖边要在本页写理由。
- 先找后写：开工先查共用层；新写的函数第二次要用时就下沉。

### 矢量档：拆与并

矢量页的对象本来分开画，压在一起互不影响（弧压着字、点贴着数字、符头叠着加线），所以矢量候选一律按对象认，**不做连通块、不做投影切分、不走位图的拆分提案**。
真正要处理的只有四种，都是确定性的结构操作，在认字形之前于对象库（`omr-source::vector`）一次做完：

| 情形 | 处理 |
|---|---|
| 一个对象画了几个符号（转曲的一串升号、整串「D.S. al Fine」） | 按子路径外框分块（内腔归所在外环）；整块先认，认不出再拆块认；拆出的块不收横杠、点、短竖这类简单形 |
| 一个符号拆成几个对象（升降号的竖笔单独一条线、速度记号的头与干分开） | 按结构并：竖线中线落在字形块左右缘内的并回去（并走的线不再当符干 / 小节线） |
| 同一形状画了两遍（弧 = 填充 + 描边、标题字描一圈） | 外框重合、走向一致的并成一组：弧只出一条候选，厚度取外沿；字形按填充那条取签名 |
| 一个符号由两半拼成（符头左右两个半边路径） | 单块认不出时与外框相接的邻块并起来再取签名；范围限在一个符头大小内、至多两三块，不滚雪球 |

几何关系全用精确坐标判，容差取线宽量级；同一对象只归一个元素。矢量档的漏认、错认只该来自「字形没认出来」与「挂接规则」，每页归不掉的对象数应接近 0。

## 关键判据

- `omr-core::js`：`Math.round`（半数向正无穷）、`x | 0`、稳定且比较函数不成全序也不 panic 的排序。参考旧判据、要照同一口径算的地方用它。
- **阶段缓存**（`stage.rs`）：键 = 阶段名 + 代码指纹 + 各输入的内容指纹；产物落盘时记自己的内容指纹，下游的键用上游产物的内容指纹。
  上游代码改了但这一页产物没变，下游照样命中。命中时只回指纹，值用到才从盘上解。写盘先写临时文件再改名（并行进程写同一个键）。
- 矩形坐标用 `f64`（TS 是 number，量出来的中心与折算后的框带小数）；二值图一字节一像素、值 0/1，与 TS 的 `Binary` 同排法，落盘按位打包（低位在前，同回归的二值图缓存）。

- **PDFium**（pdfium-render）：绑定特性 `pdfium_<构建号>` 必须与动态库同一个 chromium 构建号，否则绑定时缺符号（`latest` 跟着 crate 版本走，0.9.5 的 latest 是 8125，本机库是 7881，报 `FPDF_StructElement_GetRawType` 找不到）。现固定 `pdfium_7881`。
- **字形轮廓要直接调原生接口** `FPDFFont_GetGlyphPath(font, Unicode 值, 字号)`：它收的是 Unicode，PDFium 内部转字符码。
  pdfium-render 的 `font.glyphs()` 拿 0 号试探字形数，符号字体（Maestro）试出 0，之后 `get` 全失败——不能用它。
  实测（2026-11-10）：Anastasia 1684/1685（差的是空格）、Maestro 225/225 与 214/214；子集字体 `LNFFGN+Maestro` 0/54（字符码 0x87 之类没有 Unicode 映射，PDFium 回的就是码本身，反查不回字符码）。
  这类字先按字框渲染取位图签名兜底，大量出现再解字体程序（`FPDFFont_GetFontData`）。
- **PDFium 的 wasm 版**（pdfium-binaries 同一构建号的 `pdfium-wasm.tgz`，emscripten 非模块脚本）：打开的文件里有 `%PDF` 开头的才取（`worker.ts::hasPdf`；图片的取数、二值化、识别都不经 PDFium，省 gzip 约 2.3 MB）；
  Worker 把脚本当函数体跑、`Module` 由参数交进去；
  pdfium-render 0.9.5 的 wasm 绑定要 `Module.wasmExports`（脚本里是局部量，要挂出来）、认 `PDFium_Init`（这一版只导出 `FPDF_InitLibrary`，补别名）。
  绑定有两处毛病，`omr-source/src/pdfium_wasm.rs` 绕开、直接调模块：`FPDFPageObj_GetMatrix` 先在本模块内存上开视图再分配，内存一长就报 detached ArrayBuffer（八段锦必现）；
  `FPDFText_GetCharBox` 出参次序交错（左上右下 对 左右下上），字框读反（破碎页眉字号读成 −394）。
  修过之后八段锦、宣主荣耀的页面内容与原生逐字节相同；没嵌入的字体（破碎的 ArialMT）原生取系统字体、wasm 取 PDFium 内置字体，字形轮廓与字框不同，属平台差。
- **内嵌图**：`get_raw_image` 给原始尺寸、不重采样；CCITT（2482×3510，约 20 ms）、DCT（RGB / 灰度）、Flate 都取得出，页上矩阵从 `matrix()` 取，一页好几块的（星空下的祝福）各自带矩阵。JBIG2 语料里没碰到，未验。

### 五线谱：预处理与框架结构

- **成像按谱表定**（`prep/imaging.rs`）：1 位原图直接取位；灰度 / 彩色走 Sauvola 0.5，再看量到的谱表——线距 < 14 且线细（线宽 / 线距 < 0.22，或放大后再量 < 0.16）的放大一倍；
  一行谱都找不出逐档放松（0.35 / 0.2 / 0.1）；线宽 / 线距 < 0.06 的细线扫描件把松阈值图（0.2）里 1.5 格以上的纵向游程并回来；
  松阈值图里细长横向游程只补断口，多找出谱行、或某行沿线有墨的列涨过 0.15 才留（只换那一行的谱表带）。网点率（谱表带内、线上孤点不计）> 0.13 去网，
  针孔率 > 0.012 补针孔，孤点过密的块抹掉。不推平、不纠斜。
- **找谱表**（`frame/staves.rs`）：逐列（步长 4）找五段细黑四段等距 → 串轨迹（短截也收，拼完再按列数筛：压满符杠的谱行逐列五连断成许多小截）→ 两截按相邻两端接回 → 五线共用偏移曲线 → 沿线验墨定左右端。
  按列数筛时，列数不够的谱行只要过了最低列数、又横跨页宽三分之一以上也留（压满符杠和字的谱行逐列五连漏得多，原来整行漏掉）。
  **单线谱**：五线表以外的细实横线，沿线连墨、上下一两格没有平行线、两根以上上下对称各伸 1.2~3 格的竖笔穿过；建成五线表（实线当第三线，`one_line`）。
- **墨层不去线**（`frame/ink.rs`）：三值图，谱线带里纵向墨段不比线宽厚多少的像素标存疑（`LINE`），原图不改。竖段：逐列纵向墨段（接一两像素白缝）单列够总长三分之一就收，相邻列连成一段后再按总长筛。
- **系统**（`frame/systems.rs`）：两行之间左端窗口（往外 3.5 格、往里半格）有墨的行过九成算连着；不够的看松阈值图里贴左端最强的一列；再不够的看两行之间有没有一根虚线
  （顺着墨走、每行可挪一列：扫描错切的竖线是歪的；墨过半、最长断口不到 0.8 格）；左端标记断开的单行按间距并回去。
- **小节线**（`frame/bars.rs`，在符头之前定）：竖段纵贯一行谱、两端不伸出谱表（贯穿小节线只许伸进同系统邻行）、端点旁不挂符头样的墨块；
  竖笔在谱表里横向连着一团墨（挂空心头的干、降号肚子共用的竖笔）的标**存疑**，单行系统里摘掉、多行系统里要别的行有孤立的一笔作证。
  多行系统同 x 归簇互证：别的行有、本行没有的回原图验竖墨补（三行以上过半的行有就照补，记 `Vote`）；少数行有、别的行同处也没有贯穿竖墨的摘。

### 五线谱：音符数据（做到 4i：实心头、空心头、全音符、休止、符杠符尾、临时记号、附点、裁决、满拍裁决、按声部写出、贴头奏法、连音）

- **实心头在原图上找，不去线**（`notes/heads.rs`）。种子：逐行谱、逐音级位置（谱表上下各四条加线）沿 x 扫，
  以该位置为中心的小实心框（0.8 × 0.6 格，比符头的内接矩形略小）墨占比过九成的地方；框可上下挪 0.1 格取最满。
  头压着的谱线在墨层里本来是墨（纵向墨段长、不是存疑），不用管线；符杠、粗笔画不到 0.6 格厚，撑不满。
  连着 1.6 格以上都撑得满的是实心块（原来一格；放宽后多出的杠端假头交给下面的同干假头规则收；并排粘连的两个头仍会丢，未做）。一行谱只管到与邻行的中点。
- **谱表外的头要加线作证**：从谱表到头之间的每一条加线位置上，头的左或右都伸出一截细横墨（纵向不比谱线厚多少）。歌词、标题的笔画凑不齐这一串。
- **模板自举**：本页挂得上干的实心种子叠成「此处是墨的概率」图（按线距归一、各行共用，线上存疑像素不参加统计，样本不足 6 个用合成斜椭圆）；
  打分时拿得准的格子按把握加权、图上的存疑像素不计；比本页中位分低 0.2 以上的丢。符干在头哪一侧不定，那一带概率在 0.5 上下，自然不计分。
- **空心头与全音符从「孔」找**（`notes/hollow.rs`，墨块性质这一路）。孔 = 封闭的白团，在两张图上各找一遍：
  - 符号墨（存疑的谱线不算墨）：压在线上的头，孔里那截谱线不算墨，孔是完整的一个。先抹掉加线样的细横线（纵向不比线宽厚多少、横向连着 1.2 格以上），
    不然压在加线上的头被加线劈成两半；再把存疑像素里落在线宽以外的那一圈还给墨——墨层标存疑时容线带厚出一点，间里的头环的上下沿只一两像素、正贴着线，会被一并当成线。
  - 原图（谱线当墨）：间里的头，环的上下沿并在谱线里，要谱线当环壁才闭得上。与前一张图的孔交叠的不重复收（压线的头在这张图上是两半）。
    两根竖笔夹在上下两条谱线之间的方格子也是孔：孔的面积占包围盒过 0.88 的丢（头的孔是斜椭圆被线截出来的，占不满）。
  - 判据：孔宽 0.3~1.25 格、高 0.2~1.1 格，孔心落在音级格点上（差不过 0.35 个半格）；四面的环壁在孔的包围盒各边中点附近几行 / 列上量
    （先从边退到孔里再往外数：斜椭圆的孔，壁最厚处不在正中）；外圈宽 0.95~2.2 格、高 0.75~1.3 格（上下壁只算到 0.3 格：和弦里上下相邻的头共用一道壁）；
    左右壁厚到 0.8 格的不是环（一个实心头与旁边的竖笔、上下两条谱线围出的空当；全音符两侧的壁半格多）。
    原图那张上，孔的左右壁里有一列是框架层定下的小节线的，不是头（小节线与旁边的竖笔、琶音线在两条谱线之间夹出的空当）。
  - 有干是二分音符；没干、外圈宽不窄于 1.25 格也不窄于本页实心头宽 0.95 倍（粗体字的页上全音符与实心头差不多宽）、所在墨块不过 2.3 × 1.4 格（孤立的一个环）的是全音符。墨块取孔左右两壁所在墨块的合框
    （叠成「8」字的全音符去线后常劈成左右两半，只看左壁那块 0.6 × 2.1 格量不出）；合框里上下另有头那么大的孔（叠着的全音符）高放到 3.2 格。
  - 三度叠着的两个空心头：正上 / 正下另有头那么大的孔、间距不过上下壁上限的，中间那道壁两家共用，外圈只算两孔间距的一半。
  - **开口内腔**（`open_cavity_heads`，同 TS `hollowHeadsFromCavities`）：扫描件上环有缺口、内腔漏进谱间空白，找不到封闭的孔。
    改认「四向都碰得到符号墨」的白像素（往左右走不过 1.25 格、上下不过 1 格；谱线不算墨，漏进谱间的白上下碰不到），四连通拼块，
    宽 0.45~1.25、高 0.3~1 格、不与头那么大的封闭孔相交（那归上一路管，那里丢了的不再捡）、离谱表不过两格；以块心定头（盒 1.25 × 1 格）、
    盒里墨占 0.3~0.75（环），要挂得上干，且干宽不过本行已认头的干宽中位的 1.5 倍（花括号、大号字两道粗笔夹出的白，「干」是它自己的粗笔，宽 7~10 像素对 3~5）；
    上下隔 1~7 格、横向相交处有实心头的不收（弯回干的符尾围出来的）。本页没有封闭孔认出的二分头就不找。
    封闭的孔盖住内腔外框六成以上的才让给上一路（压线的头，原图上被线切出的半截孔也是头那么大，内腔却从缺口漏了出去）；
    挂不上干的按全音符判（中心行左右壁都有、外圈够宽、孤立的一个环，同上一路）。排查开关 `OMR_OPEN_DEBUG`（=2 逐个内腔）、`OMR_NO_OPEN`。
- **同音共头**：两声部同音共用一个头时，头上下各一根干（朝上的贴右缘、朝下的贴左缘，对侧那根反向且不越过头），出两个音各挂各的干（同 TS `unisonStems`）。
- **符干**（`notes/stems.rs`）：头中心上下各 0.22 格的两行量左右缘（避开中心行的加线；空心头用外圈量得的左右缘），缘内的列里找一根纵向连着的墨——
  从头中心起伸出两格以上、其中横向墨宽不过 0.35 格的细段够 0.8 格（叠在一起的头连成的墨柱没有细段；连桁的短干细段只一格上下）。
  细段在上是上干。同一列（差 0.25 格内）且纵向连着的头成和弦。
  扫描件的干常断成几截（头与干之间、两个头之间）：沿列走时断口不过线宽的照接；不过 0.4 格的，断口这头是细墨（顺着干走过来）就接，
  这头是头的、那头要是细墨（看 0.3 格、先断了的那截两行以上）才接——上下贴着的两个头之间的缝不接（平安夜歌伴奏 D4 被接进上声部 F4 朝上的干）；
  谱线上的存疑像素横向连不成墨宽，量起来都「细」，不算细墨。细段只数沿列走时离开头中心半格以外、实际走到的那些行。
  **倾斜的干**：按原列找不到干时再找一遍，沿列走时允许横移——当前列断了（白或谱线）、左右邻列接着两行以上细墨就挪过去，离起始列不过 0.35 格（至少 3 像素），
  两次横移至少隔 5 行（斜率不过 1:5，不顺着斜弧、符杠走）。扫描件轻微歪斜时竖干逐行偏一像素，按列走会断。
- **写出**（`song.rs`）：和弦按 x 落进小节，音高按那一处现行的谱号（行首 + 之前的行中切换）与调号；现只写一个声部，
  横向相隔不到 0.8 格的两个和弦（上下两声部各带干）并成一个拍点；时值只按头型（四分 / 二分 / 全）。
- **找谱表**：五连的首末两条线要往左右都延续（1.6、2.6 格处各探到墨）——一条加线加四条谱线也是「五条等距细线」，
  这种假五连把那一段的偏移曲线带偏一格，整段音级读错（宁静的伯利恒 p5）。
- 对 TS 快照（`vs_ts_heads`，线索；头型码 `noteheadBlack` / `hollow`）：实心头——干净合唱谱两份查全 99.8%、查准 99.7~100%，独唱谱 96.9 / 99.1，合唱谱全部（多为扫描）84.2 / 95.9；
  空心头（二分 + 全）——宁静 96.1 / 98.9、破碎 93.6 / 89.8，独唱谱 73.6 / 80.7，合唱谱全部 55.9 / 71.4。排查用 `dbg_heads`（某点附近的种子与孔各在哪一关留 / 丢）。
- **休止从墨块认**（`notes/rests.rs`）。休止符不挂干、不连别的符号，在墨层里各是孤立的一块；按形状分三类：
  - 全 / 二分：实心扁方块（宽 0.9~2.4 格、高 0.35~0.8 格、占满八成以上），**上沿贴线的是全休止（整小节休止同形），下沿贴线的是二分休止**；
    贴的是谱表里哪条线不限（另一声部的休止挪到别的线上）。贴着谱表底线坐着的照样读二分——有的谱面把全休止印成这样（齐来崇拜，GT 记全休止），形状上分不出，留给满拍裁决。
  - 八分及更短：上部左侧有实心圆点（0.4 格见方的实心框）；圆点那几行右边隔着一道白另有一笔（钩接斜笔顶）；最底下三成是单根细笔、落在块宽的中段。
    按块高分八分 / 十六分 / 三十二分。「隔着白」这一条分开了数字 7（顶上是通栏横笔）和带一截断干的符头。这一类形状特征强，位置放到符头的音级范围（另一声部的休止常挪到谱表外几格）。

### 五线谱：文本及符号（P5：歌词、和弦、力度、节拍器、术语与跳转、页眉、假符头回馈）

- **文字行按几何切，不靠整页文字检测**（`text/lines.rs`）。密排的五段词与谱表贴在一起，检测模型会把整个系统圈成一个框。
  - 带：相邻两行谱之间（首行上方 9 格、末行下方 24 格）。带里**不当文字的墨块**先排除：贴着谱表的（首末线外 0.25 格内）、休止、
    横向过 8 格 / 纵向过 6.5 格的、宽过 3 格而墨占外框不到 0.22 的（弧、松叶）。带干的音符都贴着谱表，这一条就排掉了。
  - 行按**像素**的纵向投影切（按该处谱线的偏移拉平），不按墨块外框：上下两行的笔画相接时两行的字连成一块，外框把谷填平。
    相邻两截合起来不过 1.15 个字高、两截各有正经字身块（不是待定的扁稀块）的并成一行（一个字的上下部件不相连；这里的字高取字身块高 85 分位与整带投影各截高中位的大者，
    扫描件的方块字常碎成几块、前者偏低，新编 009「三一上主」切成上下两行；只有扁稀块的那截是贴着字行的延音线，并进来就被弧那边剔掉）；
    一截里有深谷（不到峰的 0.12、离两头各 0.45 个字高）的在谷底切开，本身不过 1.15 个字高的不切（单字成栏时只有它自己的投影，「美」腰上那几行很淡）；仍过高的（超过行距 1.7 倍）按行距切成几行，切在预期位置附近投影最低处。
    字高取字身墨块高的 85 分位（偏旁、标点、小写字母把中位数拉低），行距取本带正常行高的中位数。
  - **横向分栏**：整条带从上到下都空着、宽过 3 个字高的白道两边各切各的行——主歌几行右边接着的副歌，行夹在主歌两行之间的高度上，
    合在一起投影就并进主歌的行。两栏的行中心相差不过全带正常行高的 0.32 的并回一行（原来按较矮那行行高的 0.2：一栏只有一两个字、没有上下伸出的笔画时，
    行框矮、中心偏，并不回去；0.32 个行高仍远小于行距和插在两行之间的副歌行）。
  - 行内横向空当超过 2 倍行高分段，逐段从**原图灰度**裁条送 rec（四周留 3 像素白边），条纵向只取这一行的范围（连到邻行的墨块在行界截断），排除的墨块抹白。
  - **词间空格**（`omr-text::spaces`）：rec 不吐空格，按条里的空白列补——空白宽度取对数按两类间方差最大切成两簇（几何均值差 2.5 倍以上才算分得开），
    宽的那簇是词界。rec 的字位是按 8 像素一格的时间步折回来的、常整体偏一点，先估整体偏移（挪到最多的字心落在墨上）再对空白。
    **等宽字体**（字母间各道空白两侧墨段的字心距九成以上落在中位 ±10%，至少 5 道）：窄字母 i、l 两边的白也宽，过了门的白还要字心距 ≥ 1.25 倍字距才算词界
    （issue 41「Chr i stmas」「E l a i ne」）。只否决、不新增——加了字距的比例字体词间字心距也只有 1.46 倍（迦南 2252），小号粘连字母也可能碰巧规整到八成（诗歌本 16）。
    **试过按墨宽把字逐词分配（不看字位）**：比例字体的字宽差太大，页眉从 91 掉到 82，撤了。
- **假符头回馈**（M4 4.7）：谱表外、字身大小的墨块上认出的符头先不定，落在成行的字里（同行另有三个以上字身）的是字（「口」「日」的框读成空心头），
  交回页识别从音符里摘掉；孤零零的才是音符、不进文字行。扁而稀的墨块（延音线、小圆滑线，也可能是字里的一撇一捺）同样处理；
  矢量页（转曲页画成的像素）不够三个字身时，横向落在本行某个字身块左右之内（两头各容 0.15 个字高）的扁块是那个字的上下部件、留下（单字成栏的「美」的大底）；
  位图页不这样留——短延音线同样落在字宽里，吃进文字行就被弧那边剔掉（破碎干净版多补 6 条延音线）。

  - 歌词行归**上面**那行谱。像歌词：两个以上汉字且汉字占一半以上，或四个以上拉丁字母占六成以上；行高不小于 1.3 格。
    整行（不带汉字、不过 32 个字符）按空白与标点切开后每个词都是术语 / 力度 / 跳转 / 数字或连接词（a、al、con、e、ma、non、with、and…）的是表情行，不归歌词（`is_term_line`）。

    主歌五行汉字在两行谱之间、副歌一行汉字一行英文上下挨着，按 y 一路数下去副歌的英文接不上主歌的英文。
  - 中英对照的闭合谱：同系统里上一行谱有汉字词、下一行谱的词全是拉丁字母的，拉丁那几行折到上一行谱。一行里左边汉字右边拉丁（都够长）的拆成两行。
  - 只印一遍的共用词（副歌排在几行主歌中间那行的高度上）：某行接连三个以上音节所占的拍点上第 1 行一个字都没有的，记到第 1 行（`song/attach.rs`）。
    TS 按第 1 行横向跨度判（`numberVersesByScript`），试过照搬：拖腔下第 2 段的字对了，但新编的小字呼应（TS 先挪去下一行谱）退了，要连同呼应词挪谱表一起迁。
  - 段落标签（`(副歌)`）不当唱词；行里夹着的跳转记号（行尾的 Fine、D.C.）单独挂成文字。
  - 和弦：比上面那行谱近、离下面那行谱不过 9 格（混排谱的和弦印在简谱行上方）的段，去掉补出的空格后整段是和弦记号（`omr-text::chords`，文法照 `omrkit/chordgrammar.ts`）。
    **整页不到三个和弦的不要**——没有和弦的谱面上延长记号、弧头偶尔读成一个 C、D。
  - 节拍器（`=` 后两三位数）归下面那行谱；术语（rit.、a tempo…）、跳转归近的那行；力度只收两个字母以上的（mp、mf、ff…）：单个 p / f 从杂墨里读出来的太多。

### 五线谱：线性符号（P6：弧、松叶、房子）

- **三样共用一批细笔画**（`omr-sheet::curves` + `spans/mod.rs`）。原图上纵向墨段不厚过 0.45 格的符号墨（「细墨」）逐列追踪：相邻两列的墨段上下挨着、
  一对一的连成一条，一分为二 / 合二为一处断开另起——得到「每列只有一段墨」的笔画。符头、符干、符杠都比它厚，不在里面；粘在音符上的弧因此自然与音符分开，
  整条连着尖的松叶在尖处分成两条边。落在字行里（P5 切出的字段框内）的笔画不要。
- **不去线，按走向跨过谱线**：贴着谱线走的那一截墨在墨层里是存疑、不算细墨，笔画在那里断开。拼接：右边那条的起点落在左边那条末端走向的延长线附近
  （0.3 格，每列断口再放 0.12 像素），断口不过 3 格，断口里顺两端连线走只许是谱线的存疑像素、一根符干宽（0.35 格）的符号墨、0.3 格以内的空白。
- **形状**（`curves::Shape`）：两端取最外三十分之一宽的中位（弧的两头是尖的，往里多取会被拉向弧背），中线离两端连线最远处往上、往下各多少、在什么位置，各列墨厚的中位。
- **弧**（`spans/arcs.rs`）：宽 ≥ 1.1 格；拱高 ≥ 0.15 格且 ≥ 宽的 3%、≤ 宽的 45%（延长记号的拱又短又高）；背面鼓出不过 0.12 格或拱高的三成；
  墨厚 ≤ 0.32 格；两端连线斜率 ≤ 1.2；拱顶不在最外 12% 里。**两端各挂一个和弦**才算：起端的和弦在弧端左 2 格到右 1 格之间（止端相反），
  弧端离和弦的某个头或干端纵向不过 2.6 格，取横向（偏 0.6 格：起端在头心稍右）加四成纵向距离最小的；各行谱各自找，取挂得最好的那一行。
  宽 7 格以上的弧（要躲开中间更高 / 更低的音，两端离头远）挂不上时放到 4.5 格再找一遍，但多出来的那段只收弧端在头的拱那一侧的（朝上拱的弧端在头上方）。
  **跨谱表弧**（花括号括着的两行之间，钢琴左右手的连线）：各行谱都挂不上时，对每个花括号的上下两行（线距取平均）再试——宽 ≥ 2 格；
  斜率放到 2.2、墨厚按垂直于两端连线折算（斜着的弧逐列量的纵向厚度偏大）；起端挂一行、止端挂另一行（各自照上面的挂法，挂不上的弧端只要在两行谱之间、
  各外扩 2 格以内，纵向放到 7.5 格）；止端的和弦要在起端右边 0.8 格以外，**止端比起端朝另一行谱那边挪过 2 格**——跨谱表弧是从一行的音斜着通到另一行的音，
  两端差不多高的是挂在某一行谱上、另一端没挂上的弧（加这条前合唱档有 10 首各多出一两条假弧，加后假弧全消，宁静的伯利恒、成为我异象的真弧都在）。
  `Arc::end_staff` 记止端那行；整曲拼接时（`song/mod.rs`）按两端的拍点记成 `CrossSpan`，合大谱表时挂到两端的事件上（`song/grand.rs::merge`）。
  只挂得上一端的：弧越过本行最外的和弦、离谱表端（行首区）不过 3.5 格的是**跨行的半条**。同样两端的几条只留最宽的。
  和弦用「x + 最上面那个头的 y」指认（同一拍点上下两个声部各带干的两个和弦 x 相同）。
- **延音线与圆滑线在整曲拼接时分**（`song.rs::row_arcs` / `mark_spans`，要音高与声部）：两端之间同声部没有别的音（时间相邻）、有共同音高、

### 五线谱：矢量档与混合页（P9：9a–9g，`omr-staff/src/vector/`、`omr-source::vector`、`omr-sheet::{element,prims,shapes}`）

- **两种证据、判据一份**：像素与矢量只在「取原语」处分开（`omr-staff/src/vector/` 只放取原语与对象拆并，不放判据），之后的框架、结构信息、
  音符、文字分类是同一份代码。差别只经探针 `Probe::exact()`（几何精确时容差取线宽量级）与候选分进到判据里，判据里没有「如果是矢量」的分支。
  - 探针（`omr-sheet::element::Probe`）：逐点答底 / 符号墨 / 只属于谱线的墨。像素页是三值墨层；矢量页按对象几何作答（落在谱线对象上、又不在别的对象里的是谱线墨）。
  - 版面 `Layout`（谱表、系统、小节线、行带、单位）与像素层分开；只读版面的函数（`text::classify`、页眉、系统互证）吃 `&Layout`，矢量页直接调。
  - 页面输入 `PageSource { raster, content, rendered }`：谱表从哪一层找到，框架与音符就以那一层为主——先试像素层，找不到谱表再试矢量层。
- **对象库**（`omr-source::vector`）：路径归成 `Line` / `Poly` / `Curve` / `Glyph`，直线段另列（同一对象里重描几遍的并成一条）；
  逐点查询走网格索引 + 几何作答。矢量对象本来分开画，不做连通块、不做投影切分；同一形状画两遍（填充 + 描边）的并成一组。
- **框架（9a）**：横线段五条等距成谱表（`frame::staves::staves_from_hsegs`），竖线段 → 系统 → 小节线走位图那份（`frame::{systems,bars}`），
  只换探针与竖段。精确几何的小节线两端落在首末线上就不再看端点挂不挂头，竖段不算连墨。
- **字形身份（9a/9b，`omr-sheet::shapes`）**：音乐字体字形先查轮廓签名字典（32×32 扫描线签名、同家族、尺寸按 em 归一差不过 0.05、汉明距离最近且不过 40），
  字典没有的家族（Doremi）按码位表兜底（Sonata 一系原始编码同一套）。字形身份直接给出谱号、升降号、拍号数字、符头、休止、符尾、附点、奏法的候选；
  其后的行首次序、调号位置自证、挂干、成和弦、数杠、挂临时记号与附点、贴头奏法、连音成组走与位图同一份（9b 把它们抽成了共用函数）。
- **文字（9c，`vector/text.rs`）**：文字层的字（非音乐字体）逐字成行（基线相差不过 0.35 字号、字号相差不过 0.45），行内空当过 2 倍行高分段，
  按谱表分带（与位图带同一划法）后交共用的 `text::classify` 与 `omr-text::header`。字是确定的，不切条、不 OCR。
  - **词界**：PDFium 补出的空格框落在前一个字的原点上、字号是 1（按 x 排会插到前一个字前面：`D.S . a l Coda`），挪到前一个字的右缘、字号借前一个字，
    两边空当过 0.25 字号才算词界；补出的换行符（`\r\n`）丢掉（曾被当成空格又排到行末字前面：`Bethlehe m`）。
    有的软件词间根本不写空格（follow him 的歌词只有补出的换行符）：**整段一个空格都没写的**才按空当过 0.25 字号补词界；写了空格的信它的空格
    （Tahoma 的 `Er` 字距就有 0.25 字号）。
  - 谱表以外的升降号字形（和弦里的 ♯ / ♭）作 `#` / `b` 插进贴着的字行；音乐字体的力度字形直接出力度（分开画的 m、f 挨着的拼成一个词），归最近的谱行（7 格内）。
  - **不可靠字体**（`omr-source::vector::unreliable_fonts`）：同一字体里不同码点画着同一轮廓（预置 CMap 的 `PMingLiU-ETen-B5-H`），
    或交出控制字符（没有码位映射的子集字体）。这种页整页渲染一张灰度图备用（每点 `VEC_SCALE` 像素，与工作坐标对齐）；
    段里过半是这种字、或夹着控制字符的，整段从渲染图裁条重读。**过半**这条不能放成「有一个就重读」：宣主荣耀的 PMingLiU 段里夹着正常标点，整段重读反而差。
  - 重读与小图拼条读出的字一律按条里的空白列补词间空格（`read_spaced`，与位图页眉同一份 `omr-text::spaces::recover_spaces`；OCR 不出空格，

### 五线谱：混排简谱互证（P8，`omr-staff/src/mixed/`）

简线混排谱上同一段旋律印了两遍：五线谱给绝对音高，简谱给级数、高低点与时值。`omr-staff` 只在这里依赖 `omr-jianpu`（反向不许）。

- **定位**（`band.rs::find`）：判据是**一排与谱表小节线同 x 的光竖条**，不看数字长什么样。候选竖段长 1.2~5.5 格、悬在谱表外
  （下端离首线 0.5~6 格；找不到再找谱表下方——闭合人声谱把简谱印在上行谱表与歌词之间）、不压着别的谱行、不是房子的竖钩
  （上端吊在一条两格以上的横线下）、**两侧紧挨着有墨的行不过两成**（汉字的竖笔总有横笔穿过）。对上本行小节线（0.6 格内）的取彼此同高最多的一簇，
  长度在中位数的 0.75~1.15 倍之间；至少两条、占本行小节线四成、且占同一高度长竖段的一半（歌词行里竖笔成排，对上的只是少数）。
  带的纵向范围相对谱表首线记（随谱线弯、斜）：小节线上放 0.8 格（高音点、弧顶）、下放 0.3 格（减时线、低音点，又不碰往上的符杠）。
  **叠印两行**（一个系统两行谱表、两行简谱都印在上行谱表上方）：上面再有一排同 x、长度相当的竖条，且下一行谱表离得不过三个谱表高——
  上面那行归这行谱，贴着的那行归下一行谱。量自下面那行谱、夹在大谱表两行之间的带归上面那行谱（闭合谱的女高音）。
- **一页要么是混排要么不是**（`mod.rs::claim`）：过半的系统带着候选带、过半的候选带照简谱路线自己的标准（多数格读得出数字）认得出数字行，
  这一页才算混排。歌词行的竖笔、页眉的年份偶尔也凑得出一排（合唱谱、新编赞美诗里各有几处），切条试认一条都认不出，整页不收。
  所以认带要 OCR；没有 OCR 时不认。
- **划出**（`band.rs::erase`）：带里**整块**落在带内的连通块从二值图（与松阈值档）上抹掉，墨层、竖段、墨块、系统、小节线照抹过的图重建——
  简谱的「0」「6」、增时线不再进符头、休止候选。从谱表伸上来的符干符杠、从上面垂下来的字母笔画，块的一部分在带外，原样留着。
  抹掉的墨另存一张（`PageFrame::band_ink`）：文字从原图取条送检时把它抹白。
- **认条**（`omr-jianpu::recognize_strip`）：条按二值图交简谱路线，只到建音（数字、八度点、减时线、附点、增时线）。
  严格那一遍没认出来的条（夹着说明文字、行首标志，读得出数字的格不过半）放宽再认一遍（`find_rows_in(known = true)`）。
- **互证**（`fuse.rs`，在整曲拼接里、满拍裁决之前）：
  - 全曲校准：数字到最近的音的 x 差取中位数作平移；扣掉平移后 0.8 格内配上的对给「1」的绝对位置投票（众数）；
    带简谱行的谱表上一半以上的和弦带着别的头或与别的和弦同拍点的是**多声部**（闭合人声谱）。
  - 逐小节（按本系统的小节线）一对一贪心配对；行首区左边的数字是简谱的调号拍号，不算音。
  - 只拿**拍数自洽**的简谱小节纠（时值和等于拍号；可以不满的小节两边拍数一致也算）：配上的音照简谱改音高
    （数字没读出八度点、又正好差一个八度的不改——多半是点漏读）；五线谱这一小节不自洽时照简谱改时值；
    配上的和弦里离简谱最远的头、同拍点别的和弦是假的；两边都印了临时记号、合出来的音不一样的照简谱改记号（简谱的 ♯ ♭ ♮ 相对本调那一级；降号调里该印还原号的地方印成了升号，简谱写的 ♯4）；超拍、没配上的删掉正好补平才删；缺拍、没配上的简谱音正好补平才补（「0」补成休止）。
    简谱不满拍的小节只补没认出来的「0」。
  - **倚音**（`attach_graces`，在逐小节纠错之后、与小节拍数自不自洽无关——倚音不占拍）：简谱行认出的倚音挂到主音数字配上的和弦
    （扣掉平移后 0.8 格内最近的）；配不上的（五线谱这里漏了头、数字与头错开）挂右边四格内最近的和弦，不丢。音高按全曲校准落位、升降随调号与本小节已有的临时记号，
    整曲里记在 `Event::graces`，写出成带斜杠的小音符排在主音前面。五线谱上自己认出了倚音（`notes::graces`）的和弦不再从简谱挂。
  - 多声部谱表上简谱只是最上面那个声部：只对各拍点的最高音、只收差一级的音高，不改时值、不增删。
- **整曲**（`song.rs`）：混排谱里只有一行谱表的系统一律归第一个声部（按谱号保序配会落到靠下的声部）；别的声部那几小节各记一个全休止，
  曲首就没印的照样交代谱号、调号、拍号（别的谱不补：行数对不上多半是多认了假谱行）。
  和弦区从最上面那条简谱行的上沿量起（`text/classify.rs`）：和弦印在简谱行之上，叠印两行时离谱表首线十格开外。
- 读数（2026-11-11，独唱谱 47 首里 9 首混排）：合计 88.23 → 88.61（基线 95.97）。祢話如甘霖 130 → 51 步（基线 32；音符 79.19 → 99.49）；
  其余八首步数不变或差一步——五线谱在配上的音上本来就对，互证全曲只改了三处；闭合谱（赞美一神、齐来崇拜、欢然颂主、来敬拜荣耀王）
  缺的是内声部的音，简谱帮不上。合唱谱、新编、简谱三套不变。
- 排查：`OMR_MIXED_DEBUG=1`（各带归哪行谱、读出几个音、校准与互证读数）、`OMR_MIXED_DUMP=目录`（各条写成 PGM）。
- 没做的：
  - 简谱条的满拍裁决（拍号在五线谱这边，条里只建音；简谱读错的小节现在只是不拿来纠）、条里的连音记号与弧；
  - 拿简谱小节线补谱表上断开的小节线；简谱 OCR 成片读错时不信拍号改信简谱小节拍数的众数；
  - 互证的改动没走修正提案（`notes::meter::Fix`）、没记可疑，P10 定结果模型时一并接；
  - 房子括线下压低的和弦字母与简谱高音点同高，行里夹着房号读不成和弦行（祢話如甘霖 m11 的 B）；
    和弦区上移后延长记号、弧头偶尔读成一个和弦（是谁多 1 步）；简谱的调号拍号（`1=B 4/4`）没并进页眉；
  - 矢量 / 转曲混排（7j 之后）。

### 整曲与结果模型（P10：10a–10h，`omr-sheet::{result, score}`、`omr-staff/src/song/`、`session.rs`）

结果模型 `omr-sheet::score` 按 web `model/doc.ts`（ScoreDoc）的层次排，字段先取同义的名字，将来 ScoreDoc 迁进 Rust 时「识别结果 → ScoreDoc」一一映射：

| 识别结果（`omr-sheet::score`） | ScoreDoc（`model/doc.ts`） | 说明 |
|---|---|---|
| `Score { title, credits, parts }` | `Song`（`work`、`identification`、`parts`） | 一首 |
| `Part { staves, measures }` | `Part { staffCount, measures }` | 大谱表是一个 `Part` 两个谱表；ScoreDoc 读入时按 `staffOf` 拆、写 MusicXML 时并回 |
| `Measure { attrs, mid, events, implicit, … }` | `Measure { attrs, laterAttrs, elements, implicit, barlines }` | 行中改谱号 / 调号记 `mid` ↔ `laterAttrs` |
| `Event`（`pitches` 空 = 休止） | `Chord` / `Rest` | `Event::src` 每个头一份出处（`HeadSrc`：音高、`Src { rid, at }`） |
| `Lyric` / `Dir` / `SpanMark` | `Lyric` / `Direction` / `Mark`（`start` / `end`） | 弧在识别结果里是两端各一个 `SpanMark`，ScoreDoc 是一条 `Mark` |
| `Rid`（元素自身的字段） | 建模时记进附件 `omr-todoc::staff::Rids`（对象 + 槽位 → id），写 MusicXML 时写成 `id` 属性，编辑器读入后在 `xmlsurface` 旁表 | id 不进模型：会话进 Rust（H 期）后附件直接随文档走 |

- **识别 id**（`result::Rid`，10b / 10f）：种类 + 序号，前缀同 TS `review.ts::numberOmrIds`——音与休止 `omr12`、歌词字 `omrL3`、文字指示与节拍器 `omrW`、力度 `omrD`、
  延音线 `omrT` 与圆滑线 `omrS`（两样共用序号）。**在整曲拼接之前按识别产物预发**（`song/ids.rs`）：按页序、页内全部谱行自上而下（不经系统表）、行内按 x 编，
  头与休止的号记在 `Head::rid` / `Rest::rid` 上随音符走。所以满拍裁决删改、改关联表、改系统切分、钉住事实之后，没动的元素号码不变；删掉的留空号，不往前挪；
  混排互证补的音接着续发。按系统表编不行：拿掉一行谱，同页后面的号整体挪。
- **源框**（`SrcBox { page, rect }`）：原图像素、`page` 1 起。写 MusicXML 只写 id，框走核对 JSON。
- **可疑项**（10a / 10f）：两条路线同一个 `result::Doubt { rid, at: Locus, rect, code, note, alts }`，原因码一张表（`result::codes`）：
  满拍 `beat.short / over / ambiguous / misaligned / fix / fix.bar`、拍号 `meter.inferred / mismatch`、`head.weak`（实心头模板分比本页中位低一个 LOW_SPAN）、
  `key.carried` / `clef.carried`（没读出、沿用上一系统的）。简谱各音的 `JpNum.doubt` 照 TS 的字符串码写，核对视图现读它。
- **落选候选**（10f）：`Event::alts`（`EventAlt { choice, cost }`）——满拍裁决那两样照原花费，另给去符尾 / 补去附点 / 实心改空心 / 删掉，休止给长短一档与删掉；
  简谱 `JpNum::alts` 同口径写出。
- **声部指派**（10c，`song/assign.rs`）：每行谱一份特征（谱号、花括号上下半、有无歌词、音域中位、声部标签）保序 DP 三遍（不看标签 → 按投票定名后带标签 → 按重估音域再排），
  行数超过槽位的系统退到对齐。参考 TS `assignSlots`，重新实现。花括号一项：这一行与槽位都在花括号里时，上下半对上加 2、对不上扣 6；这一行在花括号里、槽位不在的也扣 6（钢琴大谱表的两行别配给合唱声部的槽位）。
- **花括号与大谱表**（10d，`frame/systems.rs`、`song/grand.rs`）：系统层逐行量紧贴系统线左边那段墨的中心——花括号的臂在 −1.2 格、尖在 −0.8 格，方括号与细系统线都在 −0.5 格；
  花括号括着的两个槽位整曲拼完后合成一个两谱表声部；一处都没认出时 G + F 谱号相邻、都没有词的兜底合并。写出 `<staves>`、`<clef number>`、`<staff>`、记号与松叶按谱表编号。
- **跨行跨页**（10e）：曲首不满拍且是整拍的记 `implicit`；行末劈开的小节两半按拍数合（`song::split_bars`）；松叶画到行尾的半条走 `OpenWedge` 接下一系统。
- **约束与会话**（10g，`song/constraints.rs`、`session.rs`）：`assemble_with(pages, title, &Constraints)`——关联表（`slots`）、按 id 钉住的事实（删掉 / 改时值 / 改音高，
  落在预发号之后的音符上、标 `pinned`，满拍裁决不给钉住的出候选）、从某系统起改的谱号 / 调号 / 拍号。`Session::apply(Op)`：`rebuild`（关联表，`null` = 这一行不要）、

### 简谱路线（`omr-jianpu`，P7：7a–7i）

与 TS 那条「先做十几种块手术、再按连通块认」的路不同：**认数字不靠连通块外框**，数字与上下的线、点、弧粘成一块也不要紧。

- **成像**（`prep.rs`）：多页竖着拼成一张，过宽的缩到 2200；Sauvola（窗口约短边 1/30、k = 0.2）。
  - **彩色页取墨底差最大的颜色通道**（`omr-source::raster::ink_gray`）：彩色油墨印在同色调的底上（橙字印在浅橙底纹上）按亮度转灰度，
    墨与底差得很少，纸纹盖得过笔画。各通道量「本页中位（底）− 最暗 2%（墨）」，最大的那个比亮度大出 1.25 倍才换；黑墨、灰墨页各通道一样，不换。
  - **抹孤点**（`Ink::despeckle`）：面积不到 0.006 × 字号² 的墨（至少两个像素才算块）从二值图、标号图、块表里去掉——
    带内切格逐列看墨，深底上撒出来的一粒孤点就把增时线、小节线的格撑高。
- **数字高**（`frame::estimate_num_h`）：近方块的中位高为底；汉字碎块压低、歌词字压高时改信「夹在小节线之间的瘦高块」（沿用旧判据）。
- **数字行**（`frame::find_rows`）：与字号等高的瘦高块按纵向中心聚成排，一排里过半读得出单个 0–7 的是种子；
  种子定**行带**（上下沿同斜率的两条直线，斜率取隔得够远的两两连线斜率的中位）。带内切出的数字格六成以上真读得出数字、
  且有小节线（或四个以上数字、横跨三成页宽）才算谱行——曲号、拍号、歌词行里的段号过不了。同页不同字号的行照收（差四成以内）。
  - **字号估偏了照行带高重找**：头一遍认下的行带高中位与估的字号差一成以上，就拿它当字号再找一遍（行数不少于头一遍才用）。
    候选的高宽门都按字号开，宽体数字的页字号估小了，一行只剩几个「1」「7」定带、别的行整行丢。
  - **骑在正常行顶上的矮排是倚音**，不是谱行（底离下面那行的顶不到半个带高；伸上来的小节线也穿过它，光看「有小节线、格格读得出」拦不住）。
  - **同排隔着大空白的一小簇不是音符**（`drop_aside`）：一行里最大的空白 ≥ 8 个带高、一侧没有小节线且不过 10 格（「C/A 4/4」后面接前奏、行末的跳转字），那一簇从行里拿掉。
- **带内切格**（`frame::cut_cells`）：行带之内逐列看有没有墨切成格（八度点、弧在带上方，减时线、低音点、歌词在带下方，都不进带）。
  并排粘在一起的数字按本行数字宽在墨最少的列切开（本行数字宽的样本收到 1.15 倍带高：近方形的宽体数字也算，否则只剩「1」定宽、个个数字被切成两半）。格的种类：
  - 小节线：纵贯行带、上下都伸出去一截（各 ≥ 0.07 字号，或合计 ≥ 0.3）；与数字等高的本子里，细（≤ 0.14 字号）而填满外框（≥ 92%）的竖条也是——「1」带旗带底座，填不满；
    与数字等高的粗线（宽 ≤ 0.6 带高、填满 ≥ 90%）也是；紧挨着粗线（≤ 0.4 带高）的等高细竖条归终止线 / 反复线；
    **读成数字的细竖条按本页小节线的统计高度改判**（`settle_bars`）：确定的小节线（通高比带高高出 12% 以上、占全部小节线三分之二以上）量出通高中位，
    通高过了「带高—小节线高」中点的细竖条是小节线。反方向（矮的小节线降成「1」）试过净亏 11 步，没收；
  - 数字候选：高 ≥ 0.72 带高；增时线：扁（宽 ≥ 1.8 高）、在带的中段——说不准的短横（扁度不到 2.6）照本页的排法定（`settle_dots`）：
    本页有两条以上长增时线（宽 ≥ 0.6 带高）时，宽不到长线中位四成的是附点（细体字的附点是个扁圆）；没有长线的页（密排本一律短线）照扁度当增时线；附点：小、单截、不在带顶；冒号：上下两截小墨。
  - **印在带上部的细长增时线**（`settle_high_dashes`，在 `settle_dots` 之前）：有的本子「—」又细又长、印得比数字腰高，落在带的上四分之一里成了 Other。
    本页有四个以上扁横（扁度够增时线）的 Other 格、相对带顶的高度在 0~0.25 带高之间且彼此相差不过 0.12 带高，就是这本的增时线排法：
    这批改判增时线，同一高度上近圆的小块改判附点。只按本页统计，零星一两个扁横不动。
- **建音**（`notes::build`）：数字格缩进 64×64 送 rec（一批），读不出 0–7 的取候选里排最前的 0–7（粗体糊成 8 / B），都不是的不成音；
  **行首印的段落名**（`head_label`，「前奏」「前奏：」）：从首个数字格起贴着的格并成块，近方（宽 ≥ 0.85 高）、高到本行数字八成以上的块是字
  （字比粗体数字略矮、顶又被行带截过）；其后要有三个以上数字格（隔着增时线、小节线照收），块前没有小节线；冒号认成冒号或是一小竖块（Other）都跳过；
  整块送去读，去掉框边带进来的尾冒号后是一到四个汉字才算，摘掉那几格、字挂到首音上。
  读出是括号的（前奏括号 `(5 … 1)`）不往候选里找（候选里排着 1），记进 `RowNotes::parens`，认临时号时也跳过（括号的四角墨量判得出 ♯）；
  又高又窄的 ♯ 自成一格、rec 读成「1」的不成音、留给认临时号：格里最大的连通块（格子被带截过）顶比紧挨着的右邻数字高出两成字高、缝不过半个字号、形状判得出 ♯；
  按 x 走一遍：数字起音，增时线记到前一个音，附点记到前一个音（中间没隔小节线、离它两个字号以内），冒号在线右是 `‖:`、在线左是 `:‖`；
  并排两根线是复纵线，右边那根粗的是终止线（行末记 `finalBarline`、行中记 `endBarXs`）。
- **减时线**（`notes::underlines`）：带下方的细长横墨按**横向游程**找（每行不短于 0.4 字号的墨段，上下相邻、大半重叠的并成一条，厚不过 0.2 字号）。
  第一道离数字底不过 0.4 字号，其后每道离上一道不过 0.25 字号、不比上一道宽出去（歌词字的顶横两头都宽出去）。
- **八度点**（`notes::octave_dots`）：数字正上方、减时线之下的小圆块（宽高 0.08~0.42 字号、近圆、墨过半），一个点只归横向最近的数字，上下各至多两个；
  低音点粘在减时线底下不单独成块的，回原图在线底下开窗找一团不碰窗边的小圆墨（`probe_low_dot`）；
  **高音点粘在数字顶上的**（粗体本、印糊的，有的上头还压着弧）同一份探测朝上找（`probe_high_dot`）：过了这一团是空白或一道横贯窗子的墨，
  且贴着数字那一行不到最宽一行的 85%（圆点中间最宽；「1」「4」伸出带外的尖贴着数字那头最宽）。休止与节奏音符不带八度点。
- **连谱号**（`frame::systems`）：比两行谱还高的细长块、在它括着的各行第一个数字左边；行带挨着竖线两端一个字号以内就算括着
  （方括号的钩常收在末行顶上）。贴纸边的黑边、把整页五行以上全括进去的不算。括着的行记 `system` / `voice`。
- **歌词**（`text::lyrics`）：两行谱之间按像素纵向投影切行（顺行带斜率投影，已归音符的减时线、低音点不算字）；一行字的高取全页
  不矮于 0.9 字号的墨截的 30 分位，几行挤成一截的在等分点附近的投影谷里切开。行里隔着 1.6 行高空当的分段，各段从灰度图取条送 rec，
  字位折回页内、补词间空格；切音节与对音用 `omr-text::lyrics`（休止不挂词）。行首印在首音左边的汉字段号记段号、「副」「(副)」边注不入词（行中间夹着的「(副)」也抹掉，`strip_inline_refrain`）；
  整行是和弦记号的、下一行谱头顶上不足两个汉字的一截不是歌词；整行去掉括号说明（「（合唱）」）后只剩小节号、力度、速度表情术语的（`expression_line`）
  是下一行头顶的表情记号行（缺声部的系统下面那截谱行离下一行远，过不了「挨着下一行」那条）；比一行字矮得多又只读出横杠的是没认全的减时线。
- **谱后附段**（`text::stanzas`）：末行谱的歌词之后的字行，按栏（左缘相差 3 行高以内）从左到右、栏内从上到下读，以段号起头切段；
  左右并排、田字格排的都按栏读：段号起头（段号后跟「、.．:：·•」）的段落各自是栏头，不并进左边那栏的末行；一段字里夹着「，三.」的在段号处切开；
  切出的段按段号排序（田字格「二 四 / 三 五」按栏读出来是二四三五）。同一行出现两个段号的各为一段，每块只一个段号的左右半行连读；
  **按句对**（`omr-text::lyrics::align_phrases`）：两边按句读切句，附段连着的几句对第 1 段连着的几句成一组（各段逗号、顿号的位置不一，所以组可以并句），
  组内字数差不过 1、总差不过 3，取总差最小、同差分组最多的（对齐点越多，差错越关在组里、不往后错位）；整段一组就是按总字数对（容差 2）。
  附段只能收在第 1 段的强句读（。！？；）或一行谱的末字后——几句的注文碰巧凑上开头几句的不收。组里附段多出的字并进组末的音、少的留空；末组多出的（段后粘的页码）丢掉。
  没有句读可切的照旧按整行累计的字位数对。**都对不上的照印的行原样记成曲末歌词**（`RecognizedScore.post_lyrics` → remarks，123 写 `N:`），不丢字。
  两栏末行同排、OCR 读成一整段的，在对齐右栏起点（别的三行以上的右段起点、一个行高内）且前面空出半个行高的字间切开（只在本页有并排段号时）。
- **和弦行**（`text::chords_above`）：谱行上方带（上一行歌词底到数字顶）切行读字，去掉括号里的备选和弦后整行是和弦记号的
  （记号尾的数字只认 2/4/5/6/7/9/11/13/69 这些扩展，紧粘在记号后、不成扩展的数字是三连音的「3」，切词时跳过：`Em33`、`G#31`），
  各记号按左缘挂到底下（或左边最近）的音；音上已有和弦的记 `extraChords`（落在时值里的比例）。
- **页眉**（`text::header`）：首行谱以上 DBNet 检行、逐行读字。`1=bB`、不写「1=」的 `D4/4` / `G调6/8` / `Em3/4`（小调记关系大调的升降号数）、
  中文调名（`bare_key`：「C大調」「f小调」「d小調」「E b大調」「降A大调」——字母与升降号间可隔空格，小写字母只在带「调 / 調」时认、记小调；「小」记小调）、
  与拍号同排、单独一框的光调名字母（「F　4/4」里的「F」，看着像和弦行也照收）、
  `4/4`、节拍器、纯数字的曲号按内容认；叠排的拍号按「上下两个等高数字、横向对齐」另认（分子读成 8 的按 3）；其余交 `omr-text::header` 分标题与署名，
  印在标题左边、不低于标题的署名记左上。标题被检测切成同排两框的（字高相同、都是全页最大字号、全是汉字）先拼成一个标题再分类（`merge_split_title`）；
  调号框（含光调名）不当曲号读（叠排拍号的「4」挨着调名时）。首行谱头顶三个字号以内的和弦行、力度（去掉括号说明后是力度或两三个小写字母——斜体 `mf` 常读成 `mt`，`head_dynamic`）不进页眉。
  节拍器后面连印汉字表情的（「♩=88 富有感情的」）取头一个汉字之前那段认速度，表情照旧不收。
- **弧**（`spans::arcs`）：数字顶以上、纵向墨段不厚过 0.22 字号的墨逐列追踪（`omr-sheet::curves`，与五线谱同一层），拼断口；
  朝上拱（拱高 ≥ 0.08 字号）、宽 ≥ 0.7 字号、两端离数字顶一个字号以内、落在两个不同的音上的是弧；两端相邻且同音高的记延音线，其余记圆滑线（条数）。

- **减时线的补充**：间隔按空白行数量（小图上线一像素厚、隔两像素）；整条线量完再逐列数一遍——两道线一头斜着印粘时按整条量是一道，
  数字正下方各列里却分得开（六成以上的列数出同一个更大的数就收）；两头都顺着往下弯的横墨是下一行连线的弧顶，不是减时线。
- **贴音记号**（`marks.rs`，在收八度点之前）：都靠记号自身形状，尺寸按本行字号归一；认下的连通块不再当八度点。
  - 临时升降号：紧贴数字左边（缝 ≤ 0.35 字号）、不比数字宽、中心不低于数字腰的一块，形状判 ♯ / ♭ / ♮（`accidental_of`，判据照 `omr/accidental.ts`）。
  - 倚音：比数字矮一号（0.45~0.8）、底边贴着行带顶、底下压着减时线（逐行看有没有横贯它的墨段，连着的几行算一道）、右边 0.9 字号内紧跟主音，读得出 1–7；
    正对着某个数字头顶的不收（连音的「3」在中间那个音上方），底下那道横墨往左右都伸出 0.7 字号开外的不收（连音弧、括线的顶）。
  - 顿音 ▼：实心倒三角（逐行墨宽上宽下尖、一路不回头）；重音 >：空心楔（右缘在中间几行最靠右、两头缩回左半、中间行左缘离开左边）。
  - 波音：一个字宽的锯齿（上缘线两峰分得开、中间有谷；大档只罩一个音），小号档谷按 2 像素；中间穿一道竖杠的是下波音；弧尾粘着的小号波音在弧块两端开窗判。
  - 延长记号：拱起的小弧（上缘两端都比顶低 0.12 字号）下面居中扣一个点、再下面紧跟数字、只罩一个音。
    扁弧（高 ≤ 0.7 字号、宽高比 ≥ 1.3）点在弧下 0.4 字号内都收；尖顶拱得高的（高 ≤ 1.2 字号、宽高比 ≥ 0.9）点要扣在弧脚之间：
    点心在弧的下半截、点顶不低过弧脚——整个在弧脚以下的是和弦字母「A」与它底下的高音点。
- **房子**（`spans::endings`）：数字顶上方横跨六个字号以上的横线、左端有下垂的立脚，读房号。长而平的延音弧顶也够长、弧脚也像立脚，
  从横线两头沿笔画往外追（每列在上一列墨顶上 2、下 4 像素内找），两头都连着走出 0.3 字号、且往下落了的是弧，不是房子（括线到头是直角，外边没有相连的墨）。
  立脚的竖墨要比横线本身（在括线正中量）厚出 0.14 字号，粗横线自己凑不够。立脚短到二值化后没了的（青年诗歌 178）：左端 1.5 字号内读得出 1–7 的房号才收，
  读不出号的不按阅读序补 1、2、不当房子。认下的房号、号后的点与括线记进 `mark_ink`，上方带不当和弦读；号外的和弦字不碰。
- **三连音**（`spans.rs`）：弧顶上（或嵌在弧顶里）立着的小号数字读出来正是弧罩着的音数（3–7）——组里各音记同一份比例，这条弧不再当圆滑线。
  被数字劈成左升右落两半的「⌒3⌒」，两半缺口在 2.5 字号内就拼成一道当连音候选（青年诗歌 192 数字两边留白宽）；小号数字高到 0.9 字号。
- **弧与上方带**（`spans.rs`）：认下的弧与连音括线，墨过半落在弧笔画上的块（弧本身、弧端粘着的高音点、被数字劈开的半弧）记进 `mark_ink`，
  上方带不当和弦残渣读；顶上挨着和弦字的、和弦字自己被追成弧的（「Am」的 m 拱，竖腿占了大半）不遮。连音数字、临时升降号同样记进去。
  弧端竖钩下挂的高音点（「棒棒糖」形，青年诗歌 200）：底下一个点宽七成半以上的头、上面不到半宽的细颈，头里至少两行墨满 0.8 个点宽——
  圆滑线往下收的笔尖斜着走，外框也有点那么宽，但至多一行凑到点宽（青年诗歌 178「(6̣. 1) (2 3)」）。
- **满拍裁决与可疑清单**（`beats.rs`）：
  - 切小节：按小节线；行末没线的半截与下一行行首拼（自己就满拍的是省了行末线）；行末有线却不满、与下一行行首正好凑满的也拼（弱起的曲子逐行这样劈）；
    连谱号括着的按声部各走各的。弱起、曲末、反复线与复纵线 / 终止线边上的小节可以不满。混合拍（页眉并排几个拍号）几个时值都算满。
  - 候选（`JpNum::alts`，建音时记）：隔得稍远或宽出去的下一道线、压着数字小半边的线、厚出本行线一倍的线（多一道）；贴着门收的线、比数字窄得多的线（少一道）；
    离数字一个字号开外的点、没归上类的小墨（点 / 短横）、不到 0.4 字号的增时线。每个带代价，证据越弱越大。
  - 裁决：不满 / 超拍的小节在本小节的候选里试至多两处，唯一一组（比次优便宜 0.25 以上）凑得满就改，记 `beat.fix.<div+|div-|dot+|dot-|aug+|aug->`；
    超拍又没候选的，读成「1」的光竖条（窄、各行墨宽一样，没有旗和底座）当小节线切开、各段都满就改线（`beat.fix.bar`，挂在它上面的词交给右邻）；
    其余保持原判，记 `beat.short` / `beat.over` / `beat.ambiguous`。把握大的元素不为凑满拍而改。
  - 拍号：过半小节不合时不裁决——页眉没读到拍号的按六成以上小节的时值和定（`meter.inferred`），读到了的只记 `meter.mismatch`。
  - 可疑清单写在 `RecognizedScore.doubts`（行、音、源图框、原因码），同时记到那个音的 `doubt`（核对视图现读这个）。
- **谱行的补充**（`frame::find_rows`）：头一个数字后面紧跟等号、又至多一根竖笔的排是调号行；三行以上时比各行带高中位矮一成半的排要几乎格格读得出数字、还得有小节线。

### 歌本切分（P11，`omr-book`，`dolce split`）

分页的简谱诗歌集（扫描 PDF、页图文件夹或转曲矢量 PDF）→ 输出目录里一首一张图，只在命令行（`dolce split`）。一页多首按标题切开，
一首跨页按序竖着拼，去掉页脚页码；书内目录自动整页 OCR，用来给标题配号并报缺号、重号、起始页不符，写到 `切分报告.txt`。
`--recognize`（只收转曲矢量歌本）切完逐首识别：回原书取矢量对象交五线谱路线的转曲档。
判据照旧 TS 版（`src/omr/booksplit/`，判据见 [../实现/OMR-简谱识别.md](../实现/OMR-简谱识别.md)「歌本切分」）搬过来，参数、报告形状不变。与 TS 不同的地方：

- **取页走 `omr-source`**：位图 PDF 每页取内嵌源图（`raster::page_image`，不重采样；彩色页带 RGB，`SourceImage.rgb`），没有内嵌图的页按 300 dpi 渲；
  转曲矢量 PDF 用 PDFium 整页渲（扫描 300 dpi、出图按 `--dpi` 重渲），不再走对象 → SVG → librsvg；页图文件夹按文件名自然序、EXIF 摆正。
  判路照旧：取样 0.2 / 0.5 / 0.8 处三页，都没有内嵌图且有路径才是矢量歌本，带文字层的报错不收。
- **逐页并行扫描**：TS 读页码要拿「上一页 + 1」挑候选，只能串行。这里每页先把页脚候选全读出来、取最靠下读得出的那个扫完，再按页序顺推；
  候选里有等于「上一页 + 1」而扫描时取了别的，只把这几页重扫。目录页成片补认（相邻、歌谱区外、无标题的页）照 TS 的循环。
- **曲名拼接的两处修正**（两本书上 Rust 读对、TS 读错的名字就来自这两条）：
  - 检测框左右相叠时叠住的那个字两框各读一遍（「神是」「是爱」、「1=E4/4三」「主的羊…」——「三」是「主」被前框截去下半）：
    前框末一个汉字与后框头一个汉字左缘差不到半个字高是同一个字形，留离自己框相叠那条边远的（`drop_overlap_twins`）。
  - 首尾点号只在拼好的整个曲名上去（框常在逗号处切开，「神啊，」「愿列邦称赞祢」）；整段重读（只留汉字）读出的与原曲名汉字相同时留原曲名，不丢逗号、叹号。
- **出图**：位图歌本写 JPEG（`image` 的编码器，同质量下比 sharp 大约三成），本首用到的页有彩色的出彩色、否则灰度；矢量歌本写灰度 PNG。按首分块并行，每块留最近 4 页源图。
- **逐首识别**（`--recognize`，只收转曲矢量歌本）：每段取那一页的对象按 `PageContent::clip`（中心落在裁框里、不落在页码框里）裁出一截当一页，走五线谱 / 混排路线、`assemble` 带上切分认出的曲名，写 `<文件名>.musicxml`。
  `-f` 选别的格式时由同一份 MusicXML 读回模型再按格式表（`dolce-formats::targets`）写出，转不成的留下 MusicXML、记进失败。
- 排查：`OMR_BOOK_DEBUG=<页序号，0 起>` 打出那一页各标题候选带的检测框、逐字位置与解析结果、整段重读。

## 接入（P12）

三端同一个入口 `omr-engine`，识别、判路、会话都在 Rust；TS 只剩结果的落地（`omrrust/adapter.ts` 把会话产物包成核对视图要的 `StaffReviewResult`，简谱经门面 `omr/todoc.ts` 调 `omr-todoc::jianpu` 建模、`emit` 写出）与格式写出的门面。

| 端 | 外壳 | 前端 / 调用方 |
|---|---|---|
| 桌面版 | `src-tauri/src/omr.rs`：`omr_open` / `render` / `binary` / `recognize`（进度走 `Channel`）/ `cancel` / `session` / `close`，OCR 是 `ort` 原生会话池（`DOLCE_OCR_SESS` × `DOLCE_OCR_THREADS`，缺省 3 × 3），PDFium 动态库随包 | `src/omrrust/engine.ts`（`omrEngine()` 判宿主）→ `editor/omrctl.ts` |
| 网页版 | `crates/omr-wasm`（`OmrDoc` 与 Tauri 命令一一对应、`load_ocr` 用 tract、`set_pdfium_module`）跑在 Worker `src/omrrust/worker.ts` 里；`scripts/build-wasm.mjs` 编进 `public/redist/omr/`（不入库，vite dev / build 开头调） | `src/omrrust/webengine.ts`（取消走 SharedArrayBuffer 标志） |
| 命令行 | `dolce omr <图…>`（识谱出各格式、参照歌词）/ `split` / `run`（一首一行 JSON） | 用户直接跑；`scripts/pack-cli.mjs` 打分发包 `dolce-cli-<版本>-<os>-<cpu>`（识谱程序 + PDFium + 模型，不带 Node；CI 出 darwin-arm64 / win32-x64 / linux-x64） |

- **请求与回应的格式两端一样**（`omr-engine::Handle`）：打开是 `u32 个数` + 各 `u32 长度` + 字节；渲染回 `u32 宽高` + RGBA；核对底图回宽高、倍数（核对坐标乘它是底图像素）、底图在页上的框与页宽高 + 0 / 1 像素；识别与会话回 JSON。
- **会话操作**：`omr-staff::session::Op` 各种（rebuild / restructure / pin / unpin / choose / context），外加 `insert`（点原图补音）与 `region`（框选重读歌词 / 文字指示）。编辑器重建前把删音、改音高、改时值记成钉住（同一音上不同种事实并存），其余手改照旧按识别 id 回放。
- **取消**：识别各阶段之间查一次（`omr-core::progress::Hook`），回「已取消」；wasm 没有线程，进度回调里由 JS 查标志。
- **OCR 分轮预取**（`omr-ocr::cache::CachedOcr::rounds`）：识别里的 OCR 前后相依（先认出数字行才切得出歌词条），逐条推理只能一条条等。改成每轮只查缓存跑一遍识别、
  未命中的送检请求（`OcrReq`：文本条、条 + 逐字候选、数字格、检测）攒起来，一批并行推理写回缓存再跑，直到一轮里不再缺；最后一轮全部命中缓存，
  结果与逐条推理逐字一致（缓存按画面内容寻址）。简谱各阶段之间查 `ocr.barrier()`：上一阶段还缺就不往下算——下游拿残缺的结果切出的条与最后一轮不同、
  白推理（实测一页三成多的文本条），加了屏障后 6~7 轮、没有白推理。歌词之后的屏障只等歌词：上方带（和弦、弧）按歌词区定界，页眉只写页眉那几样、
  跟它互不相干，页眉缺的（先检测、再读检出的行，常比歌词晚一轮齐）不拦上方带，两样同一轮送检，带和弦的页少一轮。桌面版 `Handle::recognize_rounds` 分给会话池（3 个会话），命令行 `run` 同；
  网页版 `OmrDoc::recognize_round` 交出各份活（`encode_reqs` 的字节），`worker.ts` 分给本 Worker 与几个帮手 Worker（同一脚本，只载识别模块与 OCR 模型，
  核数减 3、至多 7 个，闲置 60 秒停掉）调 `ocr_exec`，结果 `ocr_put` 回来。数字格每份 8 格（份大了一轮里分不匀）；各份按估计算量从大到小派
  （宽过 320 的长条走符号计划、算四倍），最大的一份本 Worker 自己做。
  各轮都从头识别，只看图、各轮不变的中间结果留在 `Doc` 上共用（`omr-engine` 的 `Memo`，按所选页存）：简谱像素页准备好的墨层
  （`omr_jianpu::prepare`：拼页、二值化、连通块、字号、去噪点，大图一轮 70~120 ms）；自动档试五线谱没找到谱表、且那一轮没缺 OCR 的页组
  （结论只取决于图与已缓存的读数），后面各轮不再试（31 MP 的简谱页一轮约 430 ms）。两者都不改结果（同一份 OCR 缓存下逐字节一致）。
  简谱的准备不跟着自动档头一回试五线谱并行预做：它只省一轮准备的时间，五线谱页却要白算一份、整页墨层与试五线谱各页同时占着内存还抢核
  （曾经这么做过，合唱谱扫描件峰值驻留因此高出一截）。五线谱成像第一档阈值找不到谱表时，
  放松的几档二值图一趟算出（`sauvola_multi` 各档共用局部均值方差，只差最后一比），不再每档整页重算。
  切歌词、上方带时抹掉的长竖墨（`Claims::tall_runs`）整页按行扫一遍存成段表（`text::VRuns`），各处按自己的门槛挑；原先每行上方带各逐列扫整页，
  31 MP 的页一遍识别光这个就 90 ms。
  同一条既要贪心解码又要逐字候选时一次推理两样都出（`read_line_ranked`）。`OMR_OCR_SEQ=1` 退回逐条推理（对照用），`OMR_OCR_ROUNDS=1` 打各轮耗时。
- **tract 读 Paddle 导出的模型**：模型里的形状标注要 `with_ignore_value_info` / `with_ignore_output_shapes` 忽略，符号取模型自己的 `SymbolScope`，det 按形状定值后再编。
- **tract 定形计划**：rec 的常规文本条（1×3×48×320）与数字格（4 / 8 / 16 格三档，不满补空白格）加载时各编一份定形计划，比符号形状的计划快 4~5 倍（原生），
  输出差在 1e-5 以内；其余形状（长条）照用符号计划（wasm 里长条现编定形计划要 80 ms，省下的不够）。
- **OCR 提速试过不留的**（都拿精度换速度或根本不快）：文本条张量宽按内容宽、不补到 320（回归多步）；常规宽文本条每 8 / 16 条并一个张量推理（各配置都慢一到三成）；
  和弦带各段压掉段间空当拼一条读（孤立短段读丢、CTC 字位不准使和弦挂错音，速度也没变）；带候选的歌词条按 160 / 240 / 320 三档定形、拿不准的再补 320 重读
  （和弦带原先顺手命中的 320 读数得重推、重读多等一轮，合计快不到 2%）；全补窄（含和弦条，短条整行丢、`G7` 读成 `G70`）。
  会话池配置：单会话多线程最差，几个会话各少线程好；会话内线程数 1~3 差不多（三会话并发时吞吐基本是定的）。
  自动档没用「便宜判据先排除没有谱线的页」：放松阈值本是救淡印扫描件的，便宜判据难保不误排。
- **网页版两份 wasm**（`scripts/build-wasm.mjs`）：`dolce_omr_wasm` 只开 simd128，`dolce_omr_wasm_relaxed` 另开 relaxed-simd（tract 的 8×8 矩阵内核改用融合乘加，
  Chromium 里一页快一成多）；`worker.ts` 按 `WebAssembly.validate` 探到的支持挑一份（Safari 没有 relaxed-simd）。两份各用自己的 cargo target 目录。
- **PDF 只走 PDFium**：编辑器、网页版、命令行都不再用 pdf.js（P12 删了 `pdfjs-dist`）。dev 脚本里还要 pdf.js 的（矢量版面核对、截图）单独装在 dev 的 `tools/pdfjs/`。
- 留后：`pdflayout/inventory.ts` / `bookprofile.ts` 的 `VecPage` 仍由 dev 脚本经 pdf.js 取（计划里的 `dolce vecdump` 没做）。

- **原图对照**：识别给每个 `<note>` 写 `id="omr<k>"`，歌词字、弧、延音线、力度、文字指示各编 `omrL` / `omrS` / `omrT` / `omrD` / `omrW`（Rust `omr-sheet::result`，按页序、页内音序编，同一份识别重跑号码不变），
  框进核对 JSON。写出端改模型时不管这些 `id`，原节点上的被回填，所以改过的谱照样认得回来——挪字、挪力度、挪弧端时 id 跟着那个字 / 记号走。
  对照按当前模型的音（`surfaceId(note)`，`model/xmlsurface.ts`）标音名，与识别时不同的标改过、对不上的标删掉。
  - **「改过」按识别落地时的整个和弦比**（`omrctl.ts::chordSig`：各音音高、休止、时值、附点、连音、倚音），基线是识别（或上次重建）刚落地的原文；项目重开没有基线时退回只比音高。
  - 字、弧、力度按 id 认回（`omrlinks.ts::staffMarksOf`），签名是「宿主音的识别 id + 文字」（弧是起止两音）；文本格式里没有这些 id，按「宿主音 + 段号」、再按「宿主音 + 字」认，
    所以文本格式里挪过的字落成原位改过、挪过的力度落成删掉。点框选中对应条目（`App._recognizeElOf` → `omrctl.staffMarkHit`）。
  - **新插的音**没有识别 id：按同一声线前后两个有框的音插位，纵向按与参照音的音级差 × 本行谱线半间距，画虚框。
  - **小节线**：每一小节右端一条竖线，命中框带 `data-measure`；它与下一小节最左那个音落在同一小节 = 这条线并掉了（划掉）。
  - **Alt+点原图补漏识**：有 Rust 会话时交 `insert`（在那儿开窗找头，找不到按位置补四分音符）；没有会话时（`sourcePoint`）按横向最近的音现在的音高加纵向音级差、时值照选中的音。
- **系统切分修正**（对照视图右键谱行空白处）与**谱表 ↔ 声部关联表**（声部面板）：交 Rust 会话 `restructure` / `rebuild`，不重跑识别。
  重建前把删音、改音高、改时值记成钉住，其余手改按识别 id 回放；**问不问**：先把记下的回放到识别落地时那份上，与现在的谱按语义比（`omrctl.ts::semanticSig`），
  对不上就是有回放不了的改动，先确认。没有识别 id 的音按「比识别落地时多出来的」算。
- **原文换成 ABC / 123 等文本格式**（`omrlinks.ts`）：改记旁表「和弦记号在原文里的起点 → 各音的识别 id」，随编辑迁移起点；换格式时两边投成 MusicXML 形状，
  按「声部、谱表、绝对拍点、音高」对上带过去；转回 MusicXML 时把 id 写回 `<note id>`（`stampXmlIds`）。识别项目存旁表（`result/staff-links.json`）。
- **并排原图**（排版稿里，`omrctl.ts::syncSide`）：底图原样画原图（PDF 由 Rust 用 PDFium 渲整页，开始识别时就画；图片直接画），简谱按 `idMapOf`、五线谱按 `<note id>` 认框，选中互通。
  拖进来识别时先放原图、谱面区按页放「识别中 / 已识别」占位（`omrctl.ts::showPending`）。
- **识别项目重开**（`.dolce`）：包里只有原图与识别产物，五线谱核对数据第一次进对照时从原图重跑识别补回来（确定性，`omr<k>` 编号对得上存的原文）。
  旧版（TS 识别，包格式版本 1）存的五线谱项目编号口径不同：重开时不补对照数据（`ProjectSnapshot.staleIds`），并排只放原图、状态栏提示要重新识别，原文照常可改。

## 回归

```bash
cd crates && cargo test                                   # 单元测试
cargo run --release -p dolce-cli -- regress <jianpu|solo|chorus|vector|xinbian> [--only=子串] [--jobs=N]   # vector：矢量民乐分谱（八段锦，testdata/矢量谱）
cargo run --release -p dolce-omr-staff --example vs_ts_bars -- chorus|solo   # 框架结构对 TS 阶段快照（线索，不当对错）
cargo run --release -p dolce-cli -- split <歌本> --dry-run --report r.json && node ../dev/scripts/rust-omr/book-check.mjs r.json ../dev/testdata/歌本切分/<书>.gt.json   # 歌本切分对曲目清单
```

`regress` 的流程：
1. 曲目由私有仓库 `rust-omr/corpus.mjs` 列（照判分脚本同一套找曲规则，不在 Rust 里另抄）。
2. 各曲并行识别，产物落盘到 `dev/data/rust-omr/runs/<档>/`：五线谱 `<曲>.rec.musicxml` + `<曲>.rec.json`（版面摘要，形状见私有仓库 `chorus-opslib.mjs::recLayoutOf`），
   简谱 `<曲>.rec.json`（`RecognizedScore`）+ `<曲>.rec.123`（`omr-todoc::jianpu` 建模 → `with_page_meta` → `emit_123`，同编辑器落地的那份）。
3. 判分脚本离线读（`solo-ops.mjs --from`、`chorus-ops.mjs --from --out-dir`），不碰 `dev/data` 下别的报告。
4. 与 TS 基线逐曲比：基线是分支起点（main `c7c02820`）归档的读数与识别产物（`dev/data/rust-omr/ref-c7c02820/`）。
   `--replay=<归档目录下某档>` 不识别、拿归档的 TS 产物走一遍，用来自测流程（读数应与基线逐曲相同）。

`regress` 各档各用一份 OCR 缓存文件，同一档不要两个进程同时跑。
判分脚本、语料、基线都在私有仓库；判分要 `web/`（main 检出）里的 `out/cli/j123.js` / `omr.js`，`--web=` 可另指。

## 已知限制

- 五线谱做到混排互证（P8）、矢量档（P9）与整曲结果模型、会话、核对 JSON（P10），歌本切分（P11）已迁，桌面版与网页版已接进编辑器（P12）；版面分区还没有。
- 网页版 OCR 用 tract：wasm 里的矩阵内核是四路 SIMD，一条 320 宽的文本条约 40 ms（原生 7 ms，原生走 Apple SME），矩阵乘占九成；靠分轮预取 + 帮手 Worker 并行，
  一页简谱 1.1~3.3 秒（Chromium，十核机；TS 旧版 1.2~3.4 秒，合计慢一成多），Safari 1.5~4.9 秒、比 TS 旧版快。onnxruntime-web 单线程一条 43 ms，不值得换回。
  比 TS 多出的算量主要在送检的量：找数字行时整页数字大小的块都读（TS 只读行内的），歌词按真实空当切段（TS 把一行的字压紧拼条），都牵涉判据。
  wasm 21 MB（gzip 5.0 MB），PDFium 5.2 MB（gzip 2.4 MB，打开的文件里有 PDF 才取）。
- **OCR 模型的权重存 FP16**（`dolce-dev onnx-fp16`：大于 1024 元素的 FLOAT 权重改存 FLOAT16、后接 `Cast`，tract / ort 编图时把常量 Cast 折掉，推理仍是 FP32）：
  det 与 rec 都是三端（网页、桌面、命令行）共用 `public/redist/ocr/` 的一份：det 4.7 → 2.4 MB（简谱、独唱、合唱三档回归与 FP32 逐曲相同），
  rec 21.2 → 10.7 MB（gzip 18.1 → 9.1 MB）。2026-11-23 量 rec：权重舍入只在读数贴着判据边的地方翻转——青年诗歌 53 延长记号的弧 FP16 读成 `n`（`G Em nG G` 覆盖率不够、整行和弦丢），
  已改成认出的延长记号墨不进和弦带（同 segno），之后简谱档 98 首两边逐曲相同；独唱档 47 首剩数算主恩署名行一个字（FP32「词」、FP16「詞」，整行繁体、FP16 对），
  合唱档 61 首 4 首步数变了、两个方向都有（歌词分音节与选字，干净档 1561 → 1564、扫描档 32146 → 32148、矢量档不变），当噪声收下；回归 OCR 缓存已换成 FP16 的读数。tract 与 ort 读 FP16 模型照样逐位相符（`tract_vs_ort` 翻转 0）。
  比较模型用 `OMR_MODELS=<目录> dolce regress <档> --out=<另一目录> --ocr-cache=<另一份缓存>`（缓存按画面寻址、不认模型，不另指就读到旧模型的结果）；
  `--out` 给绝对路径（判分脚本在 web 目录下跑）。
- 某声部整小节没有音时（破碎前几个系统还没出现的钢琴声部），写出的 MusicXML 小节里一个 `<note>` 都没有、不补整小节休止，编辑器试听报「measure has no chord」拼不出。
- 《裴克圣经经文诗歌歌谱》逐首识别：房号 `[1 [2` 没认、和弦行个别漏、036 行首多一个空小节，行末小逗号单字条上 OCR 偶尔漏读（TS 按每点 6 像素画条，这里 4 像素）。
- 歌本切分：哈利路亚 474「羡」读成异体「羨」（rec 逐字读法，TS 读对）；位图歌本的 JPEG 比 sharp 出的大约三成。
- 线性符号（P6）没做的：**跨谱表的弧**只认花括号括着的两行之间的（没认出花括号的大谱表、合唱谱两个声部之间的不认）、**虚线弧**（等宽等距的短横划排成的弧，Holy Holy Holy 一半的弧）、
  八度线（8va 虚线及改音高）、带括号的连音括线（合唱谱补 61 步）、刮奏线、踏板线；房号不读字、跨页的房子与弧不接续；
  弧穿过符干以外的墨（被符杠、歌词压着）断开不接，嵌套弧、首尾相接的弧只按各自两端挂；倚音上的小弧挂不上；
  松叶两可端点要的音符几何（`rec.json` 的 `notes`）没写；延音线 / 圆滑线之分在漏头的和弦上靠不住。
- 裁决：定下的小节线若其实是二分音符的干（主我敬拜你 5 处、向主唱新歌 2 处，小节线层没标存疑），那个头会丢；休止 ↔ 符头、行首区没认出谱号时谱号里的假头还没进互斥。
- 扫描档：实心头还漏在裂开的头（缝通到头外）、与符杠糊在一起的头、断干短干；空心头对 TS 快照查全 67% / 查准 77%，漏在环壁糊厚、
  孔心偏离格点、孔被糊没，放大上限后假空心头也多了些；休止、断杠、淡印、网点专项没做。
- 声部：一行谱至多两个声部，三个声部的钢琴行排不通、走「依次往后排」的退路；跨谱表的声部没做。倚音的临时记号、倚音时值（一律记八分带斜杠，十六分的连杠串也记八分）没做。
- 奏法：琶音线、震音、顿音（楔形点）、换气记号没做；干端那一侧的断奏点、保持线不认；谱表里压着线的记号（被线切碎）认不出。
  连音只认带数字的三连音（三个时值相同的和弦），带休止的、二连五连六连、只有括号的没做；拍号不明或小节另有错的收不下。
- 满拍裁决：  不满拍的不补（回原图补漏音、补附点要有墨的证据，没做）；拍号存疑时按多数小节的时值和反过来定拍号没做；满而不齐只记可疑、不改；
  可疑清单还没记：符头裁决第一二名接近（裁决没留第二名）、无主墨、混排互证改过的地方、把握低的拆分。
  加线没建成元素：加线位补搜（有加线而头没认出的地方放宽种子 / 干的要求）没做，谱表外的头查全比表内低六七个点。
- 并排粘连的头、全音符的二度叠置没做；扫描档的空心头查全低（环断口、孔糊死），留给扫描档专项。空心头找孔每页多两遍整页洪泛，识别耗时涨了约四成，未优化。
- 休止：扫描档查全查准都低（断笔、糊团），留给扫描档专项；断了干的小号符头（两个头靠残干连着、头不够种子框大）会读成四分休止（齐来谢主歌一处）；多小节休止（长横杠加数字）没做。
- 临时记号：重升、重降、括号里的提示记号没做；与头粘成一块的记号（单元里含着头就跳过）认不出；破碎还剩几处升号漏认没逐个看。
- 符杠符尾：震音（杠不到干的）没做；符尾只在干右侧探，厚度下限放到 0.18 格后贴着干端的圆滑线可能被数成符尾（没逐个量）；扫描档杠断开、糊成一片的留给扫描档专项。
- 有了音符后结构档读数略降（判分把拍点与小节线排在一条序列里对齐，音符不准时小节线的配对跟着变），随音符档上来再看。
- 子集字体无 Unicode 映射的字形取不到轮廓：文字层的字已改从渲染图裁条重读（9c）；音乐字体的这种字形（`LNFFGN+Maestro`）按字框取位图签名还没做。
- 文本及符号（P5）没做的：排练号（方框字）、声部名、segno / coda 字形、按字形认的力度（单个 p / f、粘连的力度）、拉丁词的延长线、
  歌词与文字指示的字号和位置（只有页眉带字号）、一个音上换和弦、歌词改挂下面那行谱（呼应句、页顶的词）、多声部各自的词、按拼写拆跨音的英文词。
- 合唱谱的文字指示（表情术语以外的整句、中文指示）基本没收（干净合唱谱的页眉 9c 已从文字层与小图取到）。
- 歌词行与下一行谱上方的文字（和弦以外）混在同一条带里时只按内容与远近分，没有用版面分区（1.3 仍未做）。
